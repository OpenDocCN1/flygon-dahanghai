# 3.3 工程结构怎么定
# 3.3.1 先了解 MV 分层
苹果官方推荐 MVVM：Model 负责核心数据与业务逻辑（如数据库操作、网络请求）；View 负责展示画面、接收点击输入，不处理业务逻辑；ViewModel 处在 View 与 Model 之间，把数据转换成适合画面展示的格式，管理界面状态与交互，并通过双向绑定保持同步。本次入门先做简化版，只分 View 和 Model：View 管页面呈现，Model 管数据。掌握之后可逐步过渡到 MVVM。现实中也并非每个 App 都需要 MVVM，很多场景 View 加 Model 已经够用。

# 5.3 版权归属与合规设定

# 5.3.1 版权内容的填写方式

# 5.3.1.1 为什么值得认真填

版权声明是 App 知识产权布局里绕不开的一环。信息填得准确，一方面满足合规要求，另一方面也给自己的劳动成果加了一层保障。

# 5.3.1.2 谁来做版权方

# 5.3.1.2.1 单人开发的情形

以个人身份上架时，直接写身份证上的名字最稳妥。中文字、英文字母、拼音拼写都成立，不过跟注册 Apple 开发者账号时填的名字统一，后续核对会省事。张三、Zhang San、Sanford Zhang 这几种形式都行。

# 5.3.1.2.2 公司或小团队

若 App 由企业出品，版权方一栏应落公司营业执照上的全称。没注册公司、以小组形式协作的，写团队名也可以，但动笔前最好查一遍商标库，确认这个名字没被别人抢先注册。

2. 左侧导航栏里定位到项目条目。
3. 切进主 target。
4. 打开“Info”分页。
5. 需要改两处：工程配置内的 Copyright 一栏，以及 Info.plist 的 NSHumanReadableCopyright 字段。

# 5.3.2 声明该怎么写

# 5.3.2.1 通用写法

业界通行的模板长这样：

Copyright © [年份] [版权所有者名称]。 All rights reserved.

个人开发者的例子：Copyright © 2025 Zhang San。 All rights reserved.

企业出品则把署名换成公司全称，如 Copyright © 2025 科技有限公司。 All rights reserved.

# 5.3.2.2 年份的门道

刚上线就写当年，例如 Copyright © 2025；产品持续迭代的，用起止区间更清楚，如 Copyright © 2020-2025；每逢大版本更新，把末尾年份往前推一推即可。

# 5.3.2.3 App 内哪里露出

1. “关于”界面承载完整声明。
2. 启动画面底部可以放一行精简版，非必选。
3. 商店描述末尾同样值得附上。

# 5.3.2.4 后台信息对齐

1. 进入 App Store Connect 并完成登录。
2. 选中目标 App。
3. 找到“App 信息”，其中的“版权”一栏需与 App 内展示的文字对得上。

# 5.3.3 几条法律层面的提醒

署名务必真实，化名、未注册的商业名称都不建议使用。项目里引入过第三方库或素材的，记得在合适位置标注对方权利。版权登记并非强制，但在部分司法辖区，完成注册能换来更充分的法律救济。

![](img/78f11d99a36f61f3cf47e3537cf36a2d.png)

# 5.3.4 高频疑问

问：拼音署名行不行？

答：没问题，不过与开发者账号名称保持一致更省心，同时要确认这就是你在法律文书里会用的名字。

问：要不要去做版权登记？

答：软件著作权自作品完成那刻起就已产生；不过在有些国家或地区，走完登记流程能在维权和诉讼时多一分底气。

问：年份需要跟着改吗？

答：需要。出现实质性改动就同步更新，区间写法（如 2020-2025）是常见做法。

# 出海App冷启动：选品验证与ASO实操手册

想在美国区 App Store 找到竞争还没那么挤的细分产品，并把从验证需求到上架优化的链路跑通？下面按实操顺序拆解，重点放在低成本切入、避开巨头正面战场。

## 一、先到七麦实时榜里找竞争较小的位置

进入七麦的实时榜页面，把目光放到美国畅销榜。建议重点看第100到第200位：前100名往往被头部产品占满，用户认知和资源都难撬动；而100名开外的产品仍有上升空间，压力相对小。

![](img/3f878abd70acac140e8d02d246df8e6a.png)

## 二、借 Facebook 群组摸需求

在群组搜索栏输入 Best APPs、IOS APPs、Top Tools 等词，找出相关社群。筛选时盯两个硬指标：人数超过5000，且每天新帖多于10条。这样的群活跃度够，反馈也更有参考价值。

![](img/befa8962624e7f561fc167e0de54712f.png)

## 三、需求洞察的三种做法

1. **盯反复出现的问题**：把用户多次提出的需求记下来，比如“有没有能自动整理会议记录的 iOS 应用？”这类提问背后往往藏着真实痛点。
2. **拆解高赞帖**：找点赞超过500的帖子，看大家推荐应用时共同提到的痛点，例如“为什么 Notion 能替代5个工具？”这类讨论常指向功能整合需求。
3. **从差评反推**：搜索“disappointed in [App 名称]”，把用户抱怨缺失的功能记下来。比如“XX 应用无法离线使用”，这就是可补位的突破口。

![](img/0f1b4f656be5978e3be8542929cbac54.png)

# 7.1.3.2 Google Trends：判断需求够不够硬（以 AI 对话为例，巨头扎堆，不建议轻易入场，此处仅作演示）

商业环境竞争激烈，判断需求强弱很关键。Google Trends 能提供数据参考，帮你判断某个产品或服务值不值得投入。下面以“AI 对话”为例，看看如何验证需求，同时说明为什么这个方向不建议个人开发者贸然碰。

# 7.1.3.2.1 怎么用 Google Trends

基础操作不复杂：在浏览器打开 trends.google.com，输入目标词，比如 AI Chat 或 AI 对话，地区切换为美国。为什么限定美国？因为目标是面向美国市场的 iOS 应用，聚焦区域数据才有参考意义。

![](img/ffeede687a16da02354f1ec29b890e76.png)

## 趋势解读

**长期看**：输入关键词并选定地区后，图表会显示近几年热度变化。以“AI 对话”来说，过去两年热度一路走高，说明市场关注度持续提升，用户兴趣越来越浓。

**短期看**：再看最近90天的数据，热度依然没有回落。这意味着它不是短期炒作，而是有长期稳定需求。对创业者来说，稳定需求意味着持续客群，产品更容易被接受，商业价值也更容易成立。

![](img/7794c8a2980e003c84825c707644bc8d.png)

# 7.1.3.2.2 拆解相关主题与上升词

**相关主题**：从相关主题里找潜在结合点。比如“吉卜力工作室 - 动画公司”出现，可能暗示文生图产品有商业机会——大量用户搜索这个主题，说明他们对 AI 生成相关风格图片有兴趣。

**搜索量上升的词**：这是洞察新机会的窗口。例如 chat gpt action figure 搜索量飙升，说明 AI 衍生品有市场；Juicy Chat - 软件、Candy Chat & Date - 软件等词大幅上升，说明细分领域的 AI 对话需求正在多样化；另外 grok、grok ai、polybuzz、polybuzz ai 这类新词快速上涨，代表新兴技术正在进入大众视野。

![](img/f21383f3d81e990409460a2072ea2242.png)

# 7.1.3.2.3 借“时下流行”找场景

**筛选方法**：Google Trends 的“时下流行”板块很有价值。选择过去7天的数据，挑出那些7天内仍有热度的关键词——热度持续得越久，需求越稳定。

**结合 AI 对话拓展应用场景**：

- **宗教话题**：例如 vatican conclave cardinals pope francis 搜索量超过100万，涨幅高达1000%，且22小时前刚开始活跃。基于这个热点，可以开发宗教知识问答、经文讲解类的 AI 对话应用。
- **体育赛事**：knicks vs celtics、nuggets vs thunder、warriors vs timberwolves 等赛事词热度飙升，适合打造提供实时比分、数据解读、赛后讨论的 AI 对话平台。
- **人物热点**：george pickens 等词也有可观搜索量。围绕娱乐或体育明星建粉丝专属 AI 对话社区，提供动态追踪和模拟互动，能精准吸引目标人群。

总结一下：把 Google Trends 上正在流行的主题和 AI 对话结合起来，可以精准触达不同兴趣群体，大幅拓展产品的应用场景和用户覆盖面。

![](img/4ece30ba744bb1df6d2866d3477474cb.png)

# 7.1.3.3 第三方数据平台筛品标准（点点数据 / 七麦）

用第三方平台筛产品，主要看四个维度：

- **上线时间**：1到2年最佳。太新说明还没被市场验证，太老说明已是红海。1到2年既能证明存活能力，又没被巨头全面占领。
- **日流水**：小于1000美元。超过1000美元说明竞争已经很激烈，小团队很难突围。（注意：看流水需要购买 VIP，按需考虑。）
- **评分**：大于4.0。基础用户口碑在线，能降低试错风险。
- **功能模式**：优先选以付费功能为主的产品，再根据团队资源来匹配。

# 7.1.3.4 从差评里找机会

操作核心：在七麦或 ASO100 等平台下载评论，重点看“近期差评”。

举个例子：某款睡眠 App 的近期评论明显集中在 UI 体验差上，那你就可以针对这个短板做差异化，比如设计更美观的界面、更简洁的操作流程——直接踩着竞品的坑往上走。

# 7.2 ASO：把 App Store 页面打磨到位

# 7.2.1 元数据打磨

# 7.2.1.1 应用名

## 经验

应用名是元数据里权重最高的字段，必须涵盖核心关键词。

在 App Store Connect 里，名称上限是30个字符。

中国大陆地区的名称必须和 ICP 备案一致，确认后很难更改，所以定名时要慎重；海外地区没有这个限制。

名称一般由“品牌词加核心功能词”组成。品牌词方便记忆，但不宜过长，且最好和核心功能相关。如果想注册商标，去美国专利网站查一下是否已被注册。

工具类产品通常没有品牌效应，用户大多靠搜索关键词下载。如果字数不够，可以只保留核心功能词。

## 实操

新手可以直接参考竞品名称。比如要做日记类 App，可以这么做：

Step1：在七麦平台搜 diary，把排名靠前的竞品数据导出，分析它们的命名规律。

![](img/1984ff571ffd90c19c85e3000e4efe75.png)

Step2：导出前20名应用的具体数据（这里直接查看竞品列表即可）。

Step3：优化自己的名称。从竞品名称能看出，Daily、dairy、lock、Journal 都是高频词，尽量把这些词纳入你的名称里，能提升搜索匹配概率。

# 7.2.1.2 副标题（30字符）

副标题在 App Store Connect 里同样限30个字符。它的作用是增加搜索词覆盖，尽量融入 password、private、notes、notebook 这类高相关词。

![](img/36195f810691eea5835b1346f68848e2.png)

# 7.2.1.3 关键词字段（100字符以内）

# 7.2.1.3.1 选词的两条底线

1. **相关性**：关键词必须和产品功能或核心内容紧密相关，否则即使能导流，转化率也极低。
2. **搜索指数**：重点关注搜索热度。一般认为，搜索指数低于4605的关键词，日常搜索量太小，带不来多少自然流量。建议用七麦数据这类第三方平台查指数。

# 7.2.1.3.2 筛词流程

Step 1：确定行业内表现最好的 TOP5 竞品。

Step 2：导出这些竞品使用的关键词列表。

Step 3：重点筛选同时满足两个条件的关键词——搜索指数较高，且竞品在这些词下的排名靠前（比如搜索结果前5名）。

![](img/873644ffea530cf6cc61a7deb3341a54.png)

# 7.2.1.3.3 排序与填写

1. **按重要性排序**：先综合判断每个关键词对产品的价值，然后排出优先级。
2. **填写位置**：最核心的关键词放在填写区域的开头和末尾，其他关键词按重要性依次填在中间。
3. **格式**：英文关键词之间用英文逗号分隔。

# 7.2.1.3.4 覆盖注意事项

1. **避免重复**：名称、副标题、关键词区域之间不要出现重复词，否则会浪费覆盖机会。
2. **善用工具**：可以用七麦的关键词助手检查覆盖情况，确保有效位置最大化利用。

![](img/e512ef0a2fc47b60fcde94d4935efc0d.png)

# 7.2.1.4 日记本示例

# 7.2.1.4.1 主标题思路（30字符内）

思路一：品牌词 SecureDiary 放前面，再接 Daily、Lock、Journal 三个功能词，用连字符帮助系统识别。

思路二：DailyLock 搭配 Private、Notebook，突出“每日加密”卖点，用短横线便于分词。

思路三：MoodJournal 搭配 Diary、Notes，加入情感化关键词，用冒号增强可读性。

# 7.2.1.4.2 副标题思路（30字符内）

思路一：用 Password、Protected、Private、Diary、App 这组词组合。有数据称该组合月均搜索量约1.2万，转化率提升18%。

思路二：围绕 Encrypted、Notes、Daily 展开，强调加密和提醒功能，避开 Lock 的竞品重复。

思路三：融入 AI、Journal、Notebook、Tracker，迎合美国用户的科技偏好。

# 7.2.1.4.3 关键词字段示例

示例字段可以这样排：

- diaryapp：主打流量入口
- dailylock：长尾蓝海机会
- privatejournal、passwordnotes：覆盖隐私与笔记场景
- encrypteddiary、notebooktracker：功能延伸
- moodjournal、secretdiary、securenotes、aiwriter：情感与安全场景补充

优化逻辑：
- 核心组合：diaryapp 负责高流量，dailylock 负责长尾。
- 功能延伸：passwordnotes 覆盖密码笔记场景。
- 情感词：moodjournal 吸引情感记录型用户。
- 规避风险：不用复数形式（如 diaries 改 diary），节省字符。

# 7.2.1.7 应用描述

先一句话讲清楚产品核心功能，再用有吸引力的方式列出主要功能点。注意逻辑和排版，别堆砌文字。应用描述能提升搜索概率，核心关键词在描述中出现10次以上效果更好。

# 7.2.1.8 宣传文本

宣传文本和应用描述内容相似，在 App Store 里显示在描述上方，可以在 ITC 后台直接改，不用发新版本。

但它不增加关键词权重，前期可先不填，后期结合节日或推广活动灵活调整，吸引用户注意。

# 7.2.2 A/B 测试落地

# 7.2.2.1 测试优先级

苹果 App Store 提供了 A/B 测试工具，可按优先级测试以下元素：
1. 图标
2. 应用截图组合
3. App 预览视频
4. 促销文本

建议产品前期把重点放在图标测试上（等产品成熟、品牌有一定认知后，图标就不好改了），其次是截图组合。其余元素测试性价比不高。

![](img/dd385061eec54d72cd846ab34ea5858f.png)

# 7.2.2.2 创建流程

1. 先进入 App Store Connect，找到左侧“功能”菜单里的“产品页优化”。
2. 首次创建就点“创建测试”，已有测试记录则点旁边的添加按钮（+）。
3. 给测试命名，不超过64个字符。建议写清细节，方便后续在“App分析”里识别。
4. 选择测试方案数量，每次最多3个变体。变体越多，得出有效结论需要的时间越长。

![](img/bcfe23a2b6214f4478a56bd4d29b8cc1.png)

5. 设定流量比例。比如3个测试方案、选75%流量时，75%的访问用户会看到测试变体，每个变体各占25%。如果你的 App 流量很小，尽量少设方案，快速拿到结果。
6. 选择测试语言。默认选中所有支持语言。没选中的语言在对应地区的 App Store 不展示测试方案。每种语言只能进行一次测试，避免多语言混测导致数据难区分。

![](img/eab623fe38b2cd773fc9aee00924a411.png)

7. 点“估计测试时长”旁的箭头，选择产品页转化率的提升目标。系统会根据现有展示次数和下载量估算所需时长，仅供参考。测试默认90天，可以提前结束。如果估算超过90天，就减少方案数或提高流量比例。
8. 点“创建测试”，系统会自动复制原始产品页数据。你可以在测试方案里改图标、截屏和预览，没修改的部分沿用原来素材。为了知道哪个因素影响转化率，建议一次只改一个元素。

![](img/b946fd9ddd31a8a83ca9273f6246a13d.png)

9. 发布测试前，新元数据要通过苹果审核。如果测试方案只包含备选截屏和预览，可以单独提交审核，不用发新版本。如果只是调整已通过审核的截屏顺序或换图标，无需重新提交。测试备选图标时，所有图标变体必须包含在发布的 App 二进制文件里，且用 Xcode 13 以上构建。

![](img/4f502e166369d9213c7b11c738e93269.png)

10. 测试开始第二天，在“App分析”里能看到每个版本的展示次数、转化率、提升百分比和置信度。

![](img/988151344b9ae587010c0d870a9b715b.png)

11. 如果某个测试版本明显提升转化率，可以点“将处理方案应用至原始产品页”。处理方案可以应用到当前展示的产品页，或者“可供销售”“准备提交”状态的版本。每个测试只能应用一个方案，应用后不能撤销。注意：应用后只有截屏和预览生效，图标要等到下个版本才能设为默认。

# 7.2.4 应用内活动：一个常被低估的曝光位

# 7.2.4.1 它是什么，值在哪里

1.

基本定义

它是应用或游戏里带有时效属性的运营事件——赛事、新片首映、直播体验都算。苹果对这类内容有两条硬门槛：必须「重大」，也必须「时效」；日常签到奖励那样的例行任务不在其列。

2.

三点价值

不花钱的曝光位：活动卡片有机会进入商店搜索结果、Today 栏、编辑精选以及算法推荐，既触达老用户，也触及尚未下载的人。

把沉默用户拉回来：借助深层链接，点击即落到 App 内的具体场景，无需用户自己找路。

带动付费与留存：徽章（挑战、比赛等）配合视频素材，能让活动更有张力，促使更多人参与并愿意掏钱。

# 7.2.4.2 出现在哪，谁会看到

1.

三个入口

App 详情页：产品页会把已上线的活动集中陈列。

搜索结果：在商店里检索时，装过该 App 的人能看到活动卡片，没装过的人则会看到相关截图。

推荐位：Today、游戏、应用三个标签下的编辑精选与个性化推荐均可能露出。

2.

两类人群的路径

安装过的用户：通知直接在商店内触达，点开即进入活动页。

未安装的用户：搜到活动关键词后，可先下载，再一步进入活动入口。

# 7.2.4.3 从新建到上线的完整流程

# 第一步：建活动、填基础信息

1.

进入「App 内活动」模块点击创建；「参考名称」仅供内部辨认，起个自己一眼能分清的即可。

![](img/fd04bd697068b0b9a7ee3789a17341e5.png)

![](img/7269df32d2a4da1887b2139d5d2c4820.png)

1.

填写活动信息

![](img/f6a658822c444381fd22ce7adf69a052.png)

名称（30 字符以内）：埋入可被检索的关键词，比如「春节限时挑战」。

一句话描述（50 字符以内）：说清卖点，如「赢取限定皮肤」。

详细描述（120 字符以内）：交代玩法与奖励，如「连续登录 7 天解锁永久称号」。

挑一个徽章：

挑战：推动参与者在截止前完成目标。

比赛：多人比拼，争排名或抢奖励。

现场活动：赛事直播、线上音乐会这类实时内容。

主要更新：新玩法、新关卡上线。

新一季：新剧情、新内容或片库更新。

首映式：电影或音频作品首次上线。

特别活动：上面几类都装不下的限时企划，可跨活动、跨体验，例如联名协作。

配置地区与时间：可按地区分别设定时段，单个活动最长 31 天，最早能在开始前 14 天预热。

配置深层链接：把活动与 App 内某个具体位置连起来，用户点卡片就能落地到那里；嫌麻烦的话，先做成跳首页的链接也够用。

# 第二步：备好素材，送去审核

1.

媒体素材：可传图片，也可传视频，视频会循环播放。

![](img/b09609f9166d0611f385ae08daacef26.png)

2.

点「提交审核」后进入 App 审核队列，通常一到两个工作日给出结果，关注点是活动是否够新、元数据是否合规。

![](img/ca7f188eaaf6fb36be4325ce2cc36388.png)

# 第三步：上线之后怎么管

发布数量限制：同期处于已批准状态的活动上限为 10 个，其中只有 5 个能出现在产品页。

活动管理：通过审核后，可改的只有地区、时段与优先级三项；一旦删除，数据不可找回。

# 7.2.4.4 提交前的避坑清单

想顺利过审、又想让展示效果不打折，元数据环节有几条红线：

1.

如实说明活动是什么，别用「最佳」「第一」这类无从验证的形容，也别写「游戏内容」这种等于没说的词；全大写和过量标点同样要避开。

2.

素材要成体系，也要有视觉张力：

30 秒以内的短视频能让预览更鲜活。

配色与插画风格尽量统一，别加边框或渐变。

画面里少放文字和标识，活动名、产品名尤其不要压在图上。

3.

价格一个字都别提，出现具体金额大概率被打回。

4.

所用素材必须是自建或已获授权的，别夹带他人内容。

# 7.2.4.5 上线后的管理规则

1.

修改：审核前，后台里所有字段都能改，改完点「存储」或「添加以供审核」即可。过审之后权限收紧，只剩供应国家或地区、优先级，以及开始、结束、发布开始这三个时间节点可调，且必须赶在原定时间到来之前操作。

2.

删除：处于「草稿」「已归档」「已批准」状态时可以删；删掉后条目从列表消失，再也查不到。

3.

数据监控：效果数据在 App Store Connect 的「App 分析」里看，包括下载量、用户来源、参与度，以及有多少人选择了接收通知。

# 7.2.4.6 四种常见的被打回情形

1.

内容缺乏新意。没有新东西就别动用这个功能：例行任务、重复奖励，以及只为调价而做的促销都不符合要求。稳妥的做法是带来真正的新内容——功能上线、节日定制企划、新商品开售等。

2.

元数据里写了价格。条款 2.3.7 同样约束活动元数据，出现具体金额就会被拒。

3.

图片上文字堆得太满，也容易卡在审核。

4.

类型选错，比如宣传新功能却挂了「挑战」徽章。

# 7.3.1 商店内的自然流量

ASO 没有一蹴而就，顺序上建议先啃硬骨头：名称优先，其后依次是副标题、关键词、图标，最后才是商店截图。

热点则是最好的顺风车。GPT-4o 带火文生图那阵，「吉卜力风」刷屏，一批 AI Editor 立刻把标题换成「Ghibli AI Editor」，版本更新里塞进对应能力，商店截图也同步替换；DeepSeek 走红时，腾讯元宝迅速接入，并把「deepseek」写进名称，搜索曝光随之上涨。踩准趋势、把相关元素织进产品呈现，被搜到的机会自然更高。

# 7.3.2 评论维护与差评应对

# 7.3.2.1 评论框的触发时机

# 7.3.2.1.1 底层原则

挑用户情绪最高、投入度最强的节点开口，被反感的概率更低。

# 7.3.2.1.2 黄金时刻

在用户最真切感受到产品价值的瞬间，把邀请递上去：

触发条件：

核心动作累计达到三次以上，比如健身类完成三轮训练、笔记类写下三篇内容

或者刚跨过某个里程碑：连续打卡满一周、等级上升、解锁新能力

示例弹窗文案：

Enjoying [App Name]? A five-star rating helps more people find us—and keeps our team inspired!

在应用内长期留一个入口，让想提意见的人随时找得到：

位置：设置或关于页面的固定位置

文案：

# 7.3.2.2.1 响应速度

一天之内给出回应，态度先摆出来。

# 7.3.2.2.2 合规红线

回复里留一个专用邮箱（support@xxx.com）。

# 7.3.3 社交媒体的打法

# 第一阶段：找准人群，打好地基

用户画像与平台选择

北美市场有几个主流阵地：TikTok 偏年轻群体与短视频，Instagram 吃视觉内容，Facebook 覆盖家庭及大众，Twitter 适合即时资讯与互动，YouTube 承接教程类长视频。若产品偏工具或专业向，可再加一个 LinkedIn，对准职场人群。

账号门面

头像与封面用 Canva 统一出图，画面里点出产品最有用的能力，并放上下载引导。

简介栏写明「点击链接下载」，指向商店页面。

# 第二阶段：做内容，完成冷启动

三类可复用的内容

教程类短视频：录屏加字幕，三分钟讲清一个核心用法，比如「3 分钟用 XX App 管理你的健身计划」。

用户故事 UGC：找早期北美用户拍 15 秒的真实场景，比如「学生党如何用 XX App 省下 $500」。

热点借势：蹭当地节日，独立日、感恩节都能做模板，用 Canva 出一版「感恩节预算规划神器」图文。

发布节奏与标签

黄金时段：Instagram 选太平洋时间晚七点到九点；TikTok 抓午间十二点到一点、晚间七点到十一点。

标签分三层打：大词（#ProductivityHacks）、长尾词（#FreeiOSApp）、竞品词（#NotionAlternative）。

# 第三阶段：让流量滚起来

不花钱的活动设计

挑战赛：在 TikTok 开一个 #MyAppHack 话题，转发量前三名送终身会员。

抽奖引流：Instagram 做关注加转发的抽奖，奖品设一个月 VIP。

和博主谈合作

微影响者：在 Twitter 上找粉丝一万以内的测评博主，用终身会员换一条真实体验。

内容置换：也可以和 YouTube 工具区创作者做内容置换，让对方把下载链接放进视频简介。

几点心得

这件事急不得，每款产品的打法也不一样，很难给出一份标准清单，更多要靠自己边做边调。起步阶段建议先守住上面提到的几个大平台，用户密度更高；同时运营的阵地别超过三个，否则精力会被摊薄。即便不投预算，三到六个月内做到每天五十到一百的自然下载，也并非没有可能。

# 8.1 功能层面的设计

# 8.1.1 三种主流模式

订阅结构直接影响三件事：多少人愿意付、多少人退款、多少人续费。下面三种思路，各有对应案例。

# 模式一：付费免广告

把「去掉广告」当成会员最直接的权益，是最常见的一招。非付费用户在使用中被广告打断，付费后画面干净，体验落差本身就构成购买理由。

案例分析：Spotify 的免费账号听歌时会插播广告，订阅后播放连贯无打扰。正是这种对比，让相当一部分人愿意为「不被打断」掏钱，转化效果相当可观。

# 模式二：基础免费，进阶付费

基础能力开放给所有人，进阶能力锁在付费墙后，用功能差异制造付费动机。

案例分析：多邻国的免费版可以上基础课程，但想要个性化学习路径、想去掉广告，就得升级会员。对「学得更高效」的期待，成了它转化的支点。

# 模式三：用次数设门槛

给免费额度设个上限，付费后解除限制。稀缺感一旦建立，转化往往随之而来。

案例分析：Headspace 的免费用户每天只能练一次，订阅后不限次数。想多练的人，自然会考虑付费。

# 8.1.2 定价与权益配置

放到海外市场，订阅模型要同时考虑当地付费习惯、消费水平和竞品格局。

# 策略一：周期与定价

常见周期无非三档：按周、按月、按年。

短周期低价：入门阻力小，首单转化更好看，但续费要靠产品持续证明价值；

长周期高价：短期回款漂亮，代价是体验一旦掉链子，退款率会很难看。

建议：起步阶段对标竞品，跑起来之后按用户反馈慢慢调。

# 策略二：拉新优惠

早期做法：以纯免费试用为主，Netflix 的 30 天就是典型，目的是让用户先把服务用熟；

当下趋势：首周、首月或首年折扣更常见，Spotify Premium 的首月优惠就是例子——既能拉人，也能少被白嫖，拉新与收入之间更平衡。

# 策略三：老客召回

对已经退订的人做定向唤醒，是一块常被忽略的存量：

给一个更便宜的档位，或把试用期再拉长一些，降低回归门槛；

也可以定向发折扣码，Apple Music 就常向流失用户推专属优惠，把复购意愿重新点起来。

# 付费策略五：借内购实现单点收费

以 Fitness Pal 为例看会员体系怎么分层：VIP 把专业训练方案与无广告浏览组合在一起；SVIP 再往上叠加一对一教练和个性化训练安排。如此安排，基础用户能感受到入门权益的实在，高阶用户也获得了身份升级的满足感。

再说场景化的小额收费——面对荷包不鼓的人群，把使用频率高的功能单独拆出来卖，Tinder 的“让内容被更多人刷到”“超级喜欢直接置顶推荐”就是典型例子，正好迎合消费收缩阶段的用户心理。还有一条路是服务分层加价：Epic 的年鉴照片加急通道标价 5.99 美元，普通通道只要 3.99 美元；从近一个月美区内购数据看，走 AI 年鉴加急通道的订单已经占到全部付费的 20%，成了新的营收拉动点。

# 8.2 用户体感怎么升级

# 8.2.1 订阅动线如何安排

先谈周期档位：通常按周/月/年划分，时间拉得越长，折算到每周的花费越低，靠这个引导用户往长期走。

压低决策负担。并不是每家都把周、月、年三个档位同时摊开。档位一多，用户就得琢磨哪个划算，思考时间被拉长，感性消退、理性上线，决策成本反而变高。拿 AIBY 的《AI Arta》来说，首次进入只抛出一个 $29.9/年的 SKU，用户主动点免费试用之后，$4.99/周的 SKU 才会冒出来。

![](img/bfdafd1ce4d0e02feb19e5545e61124a.png)

AIBY 的《AI Arta》订阅页

降低单次支付的痛感。那是不是只留一个档位最优？未必，得结合自身产品跑分版本实验。只放短周期，续费率掉下来会伤营收；只放长周期，一次掏的钱多又压制付费意愿。摆出两到三个周期，可以搭出价格参照系，对把用户推向长期档有拉动作用。像 AIBY 的《Chat on》和 Codeway 的《Ask AI》都同时挂出短周期和长周期，终身或年度方案的优惠幅度肉眼可见地超过七成。

# 8.2.2 卸下心理包袱

留意一下就能发现，多数 App 都设了三天免费试用。这其实是个钩子——用零门槛把用户拉进来，之后总有一部分人忘了退订，系统自动扣款，这块在订阅收入里分量不轻。Codeway 的《Ask AI》会在页面上写清“现在不扣款、先开试用与计划”，实际上就是在引导用户先免费体验。

# 8.2.3 营造紧迫感

倒计时形式的限时礼包，可以搭配有吸引力的功能或内容；如果用户没在第一次订阅弹窗时买单，系统会追加一个限时降价的钩子。像 AIBY 的植物识别产品《NatureID》就曾放出一小时之内五折的窗口，用足够低的价位让用户很难说不。

# 9.4 全天候监控要点

路径：销售与趋势 → 左侧导航栏选择「产品销量 / 销售额 / 收入」

两组数字别搞混：

销售额：用户实际支付的金额（包含苹果抽成）；

收入：扣掉苹果分成后真正落袋的净收益。

监控的意义在于实时观察促销动作、版本迭代等事件对销量的拉扯。
