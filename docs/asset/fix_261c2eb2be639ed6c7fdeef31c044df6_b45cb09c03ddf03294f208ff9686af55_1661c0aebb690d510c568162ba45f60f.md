# 方法二：多维表格自带AI出图

如果不想折腾外部工具，最简单的方式其实是直接用多维表格自带的「AI生成图片」字段——把想要画面的文字描述填进去，系统就能自动出图。这个方案的优势是容易上手、交付速度快，缺点是灵活的扩展能力有限，更适合快速验证想法的场景。

## 4.3 链接转附件

想把外链图片直接收进表格？新增一列，将字段类型设为【链接转附件】，网络图片就会顺着链接自动归档。

走到这一步，小红书主图的下载、描述反推、二次出图已经形成完整闭环。想要继续进阶，完全可以自己挖掘新玩法：比如把副图也一并重绘，或导入参考图进行精修，很多方向都能延伸出有趣的作品。

## 3.操作步骤拆解

### 3.1 配置【开始】节点

首先，在起点节点上添加一个入参 api_key。它的作用相当于生成视频的通行证——价格会根据会员等级有所差异，一条 480P、5 秒规格的视频，成本区间大约在 0.4～0.7 元。密钥需要前往 www.aigcview.cn 开通；相同模型的前提下，这边的会员报价比 COZE 官方渠道更低。动工前务必先充值，否则余额不足会导致流程中止。

若采用这种设置，每次启动时都需要输入两个字段。如果觉得重复输入很麻烦，也可以换种姿势：事先把 api_key 填入后面豆包图生视频插件的配置里，这样每次运行仅需提交与诗词主题相关的内容，和演示视频的交互方式保持一致。

### 3.2 接入语言模型：文案及标题生成

插入一个新的大语言模型节点，命名为“生成文案及标题”，并与【开始】节点连接起来。

#### 3.2.1 模块职责

这是一个自动检索步骤：它根据用户给出的 input（即诗词名称），找出对应的诗词全文、作者名字与所处朝代。

#### 3.2.2 字段配置

- 模型名称：豆包·1.5·Pro·32k
- 数据入口：【开始】节点输出的 input
- System Prompt：

```
# 角色

你是一位资深的古诗词专家，对各类古诗词有着深入的研究和理解。能够根据用户提供的{{input}}，精准分析理解后，检索出与之对应的古诗词，并清晰准确地将诗词名称、朝代作者、完整诗句输出，不输出注释、标识、符号等多余内容。

## 技能

### 技能 1: 检索并输出古诗词

1\. 仔细分析用户提供的{{input}}，从中提取关键信息。

2\. 根据关键信息，在自己丰富的知识储备中检索与之匹配的古诗词。

3\. 将检索到的古诗词的名称、朝代作者、完整诗句准确输出。

4\. 将诗词名称、朝代作者、完整诗句以文本形式输出到zimu

5.以数组的形式将诗词名称、朝代作者、完整诗句（每句诗都单独输出）输出到fenjing

6.输出朝代作者时严格按照以下示例的格式输出：[唐]·杜甫

## 限制:

- 只回答与古诗词相关的内容，拒绝回答与古诗词无关的话题。

- 输出内容必须包含诗词名称、朝代作者、完整诗句，且不能有注释、标识、符号等多余内容。

- 输出内容应基于可靠的知识来源，确保信息准确。                              
```

- User Prompt：

```
{{input}}
```

- 出口参数：fengjing 请设为 array 类型；zimu 请设为 string 类型。两个变量名记得手动修改。

### 3.3 接入语言模型：绘图描述词生成

再插入一个大语言模型节点，命名为“文生图提示词”，并与“生成文案及标题”节点建立连接。

#### 3.3.1 模块职责

读取前一步给出的诗词名称、作者、朝代以及全诗原文，据此构思镜头画面，并为每个镜头输出对应的绘图描述词。

#### 3.3.2 字段配置

- 模型名称：豆包·1.5·Pro·32k
- 数据入口：来自“生成文案及标题”节点的 fengjing
- System Prompt：

```
# 角色

你是一位资深且专业的AI古诗词视频生成领域文生图提示词创作专家。擅长精准剖析用户输入的诗词{{input}}，深度挖掘每句话的细微信息，创作出高质量、高度适配的文生图提示词。

## 技能

### 技能 1: 拆解镜头并生成提示词

1\. 从多个维度对用户输入的{{input}}进行全面、深入的解析，充分理解脚本内容。

2\. 对脚本中的每个镜头细致拆解，完整涵盖场景、氛围、动作、表情等关键元素，杜绝信息遗漏。

3\. 针对每个拆解后的镜头，生成精准、生动且契合AI古诗词视频独特风格的文生图提示词。提示词要保证能同时充分彰显古诗词的韵味与意境和适合儿童观看的可爱、萌动风格。

4\. 生成图片统一设定为3D动漫卡通风格，主角人物统一塑造为古代可爱女孩形象，详细描述人物服饰（包括款式、颜色、材质等）、发型（如发髻样式、配饰等）、神态（如眼神、表情等），保证生成图片中每幅含有人物、画像等与人物相关的形象完全一致。

5.全部使用全景的景别，描述出人物与环境的位置关系，保证人物能全身出镜。

6.生成的每段提示词的人物衣着、发型、人物形象的文字描述要完全一致。

7.保证{{input}}中每个键都能生成对应提示词

提示词模板：3D动漫卡通风格，全景，【场景描述】，【人物衣着描述】，【人物发型描述】，【人物表情描述】，【人物形象描述】，【人物与场景位置关系描述】

........

## 限制:

-

- 仅围绕用户输入的脚本开展镜头拆解和提示词生成工作，不涉及无关内容。

- 生成的文生图提示词需清晰准确，完全符合AI古诗词视频生成要求。

- 输出内容应简洁精炼，突出镜头核心信息。

- 确保每幅生成的含有人物的图片中人物形象基本一致 。  
```

- User Prompt：

```
{{input}}
```

- 出口参数：变量名调整为 wenshengtu，类型指定为 array<string>。

### 3.4 加入批处理模块（出图）

通过“添加节点”→“批处理”新建一个模块，命名为“图片生成”，并与“文生图提示词”节点接上。

#### 3.4.1 模块职责

这个容器负责把上层传下来的绘图描述词汇总，再逐一分发给“图像生成”节点，从而批量产出图片。

特别提示：开工前先到智界 www.aigcview.cn 完成充值，不然绘图无法进行；图片缺席，后面的视频素材也就无从谈起。

#### 3.4.2 字段配置

- 并行数量：只允许填 1——图像生成不支持多路并发，所以这个值必须保持 1。
- 数据入口：引用“文生图提示词”节点的 wenshengtu
- 出口参数：此刻尚未在批处理容器中挂载任何节点，输出暂时空缺。

### 3.5 挂载插件：豆包文生图

点一下批处理容器，待它呈现出蓝色选中状态后，选择“添加节点”→“插件”。在搜索框里输入“智界”，找到“豆包文生图-create_image_task”，点击添加，并将其与批处理容器前方的圆点连好。

#### 3.5.1 模块职责

接收批处理发送过来的描述词并绘制成图，每张图片最低费用为 0.13 元。

#### 3.5.2 字段配置

- api_key：引用【开始】节点中的 api_key
- size：1080x1920
- prompt：取“图片生成”节点的 input
- 正向提示词：{{input}}
- 重试次数：只重试 1 次
- 异常处理方式：返回设定内容

### 3.6 插入选择器

继续选中批处理容器，然后选择“添加节点”→“选择器”，并将它与 create_image_task 节点相连。

#### 3.6.1 模块职责

选择器会接收 create_image_task 回传的 data，通过检查该参数是否有值，来判断绘图操作是否成功；随后再根据判断结果选择后续的执行分支。之所以要补上这一环，是因为 COZE 对绘图描述词中的敏感词拦截非常严格，任务时常会报错；为了不让整个流程中断、避免素材缺失，增加重试逻辑很有必要。

#### 3.6.2 字段配置

判断条件按照配图中展示的规则来填即可。
