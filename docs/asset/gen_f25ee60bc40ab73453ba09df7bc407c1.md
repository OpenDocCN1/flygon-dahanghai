**Skill 文件夹，关键不在数量**

不管 Skill 是从 GitHub 安装的，还是直接用别人打包好的资源，打开目录通常都会看到 README、LICENSE、CONTRIBUTING 这一类文件。它们是代码仓库自带的常规配件，并不参与 Skill 的实际工作。不过也别随手删：README 负责写安装方法，LICENSE 决定你能不能修改、能不能分发。

先看结构，不要只数文件总数。

对照前面提到的三个 Skill 可以发现：

• wechat-writing-style 只具备“把规则写清楚”这一种能力；

• content-risk-detector 具备“写规则 + 存资料”两种能力；

• gzh-design 三种能力都具备，其中 assets、docs 也归在资料类文件里。

但文件多少，并不能说明 Skill 好坏。

一个 Skill 需要哪些文件，取决于它要完成什么任务：只需要明确规则，一个 SKILL.md 就够；需要查阅资料，就加 references/；需要执行固定计算、校验等任务，再加入 scripts/。

[PRE0]

你在关卡 2 做的 my-writing-style 就属于第一种：一个 SKILL.md 就能完成任务。

但以后如果 Skill 要管理大量资料，还把内容全塞进 SKILL.md，就会难维护，也容易让 AI 抓不住重点。

后面的关卡会教你拆分资料，让 Skill 结构更清晰。

3.1 做法一：资料只留一个权威出处

它开头那段说明里写了：“主题清单以references/theme-index.md为单一来源”。

意思是，这件事只准写在这一个文件里，别处不能重复写。

六套主题的名字、颜色、适用场景，都以 theme-index.md 这张表为准。别处跟它对不上，一律听它的。

为什么？同一件事写在两个地方，早晚会改了一处忘了另一处，两边对不上，AI 就不知道该听谁的。

3.2 做法二：禁止凭记忆下手

还是那段说明里的原话：“具体 HTML 代码一律从组件库取，不要凭记忆手写”。

也就是说，排版要用的代码必须从存样式的文件里抄现成的，不许 AI 自己现编。因为 AI 干熟了容易即兴发挥，编出来的看着像那么回事，粘进公众号样式就丢。

这句话是不是有点眼熟？关卡 3 那个体检 Skill 的规矩是：大类标题只能照抄，不许自己概括。

道理一样：关键内容让 AI 抄现成的，别让 AI 自己编。

3.3 做法三：资料虽多，只翻当前要用的

这条要看它干活的顺序：references/ 里放着 11 份资料，可排一篇 Markdown 文章时它只读 3 份；换成 Word 或 PDF 稿，会多读一份专管格式转换的。

流程是先读主题索引表挑主题，再读挑中那套的样式文件，最后加一份所有主题都要用的公共样式。剩下 8 份不动，等用到再说。

11 份要是一次全塞给 AI，真正要紧的规矩会被淹没，弱一点的模型直接就撑爆了。

所以资料多了，要在 SKILL.md 里写清“什么情况下读哪份”。

后续你也会亲手完成这一步。

### 01. 本关关键点

关卡 4 最后，你总结了自己的 Skill 有哪几种能力，还缺什么能力。这一关我们就来补上“能记住一大堆资料”的这种能力。

关卡 1 的时候有提醒过你：改完一定要通读一遍，凡是出现“我如何如何”的句子，都要确认是不是自己真的做过。

为什么会这样？

因为 AI 并不知道你的真实经历、你的产品信息，或者你的业务规则。轮到需要写具体内容的时候，它手里没有资料，就只能根据上下文猜一个最合理的答案。

也许有人会想：

“那我就在 SKILL.md 里写一句：不许编。”

但这并不能完全解决问题。

因为 AI 不是故意骗你，而是根本没有可以参考的资料。没有真实信息，它就只能继续猜。

这一关要学的，就是把这些真实、稳定、需要长期记住的内容交给 Skill 保存，而不是每次都让 AI 临场发挥。

[PRE12]

我们要给 AI 一份能查的东西。

你的产品叫什么、多少钱、真干过什么事，全写进一份文件，再在 SKILL.md 里加一句：写到这些，去查那份文件，不许自己想。

关卡 2 的时候，你只放了一两段样本进自己的 Skill，作为 AI 的参考，这时候完全够用。

但以后，你可能会积累十几篇、几十篇案例，甚至产品资料、客户常见问题、品牌信息……这些内容如果都塞进 SKILL.md，不仅难维护，也会越来越不好找。

所以，这一关要学的，就是把这些长期积累的资料单独放到 references/ 里。以后有新的案例、新的经验，直接往里面补充就行，不用每次都修改 SKILL.md。

更重要的是，这些资料不只是写文案时的素材。

它们其实是 AI 应该知道、却不会自己知道的关于你和你的业务的信息。以后无论是写内容、回复客户，还是帮你做判断，都可以先查这份资料，再开始工作，而不是凭空猜。

后面的关卡里，你还会继续往这份资料库里添加内容。

### 02. 为 Skill 配置 references（资料夹）

1. 什么该留在 SKILL.md，什么该放进资料夹

先记住一个原则：

SKILL.md 写的是“怎么干”，资料夹放的是“干活要用的资料”。

拿关卡 2 的 my-writing-style 来看：

• 写作原则、流程、注意事项，属于“怎么干”，继续放在 SKILL.md。

• 写作样本、品牌资料、产品信息、常见问答等，需要长期积累、不断增加的内容，更适合放到 references/。

| SKILL.md 里的这几节 | 动不动 | 为什么 |
| --- | --- | --- |
| 我是谁 / 写给谁看 / 写哪几种东西 | 留下 | 三五行的事，而且每次写东西都用得着 |
| 我的写法 / 我的禁区 | 留下 | 这是干活的规矩 |
| 开头方式 / 收尾方式 | 留下 | 短，常用 |
| 我写过的（那一两段样本） | 挪出去 | 会越攒越多，而且不是每次都要看 |
| 写完之后：发出去之前先体检 | 留下 | 关卡 3 你自己加的那节，它管的是流程，不能挪 |
| 最末尾那行“本 skill 基于…” | 留下 | 它是这个 skill 的记录，别跟着样本一起搬走 |

这样做的好处是，规则和资料各放各的地方，后续新增资料时，不用反复修改 SKILL.md，Skill 也更容易维护。

挪完你会多一个文件夹、两份文件：

• 文件夹叫 references，就是“资料夹”的意思，两个词说的是同一样东西

• 我写过的.md：样本全搬进去。以后写出满意的，跟 AI 说一句“把这段加到我写过的那个文件里”就行

• 我的真实情况.md：这份是新写的，产品、价格、你真干过的事，一条条列清楚

💡文件名用中文行不行？多半行，AI 认得中文名。但文件夹那个 references 得是英文，它去找资料时认的就是这个名字。万一你的工具认不出中文文件名，让 AI 把两个文件改成 samples.md 和 facts.md，一样用。

判断标准就三句，以后你自己的 skill 也可以这么看哪些内容应该放到 references/：

• 会经常变化的，放到 references/。比如价格、案例、产品信息，更新时只改资料，不用修改 SKILL.md。

• 内容特别长的，放到 references/。几十上百行的资料都塞进 SKILL.md，真正重要的规则反而容易被淹没。

• 不是每次都会用到的，放到 references/。比如只有介绍产品时才会查价格、只有回复售后时才会看的 FAQ，按需读取就够了，不必每次都一起加载。

反过来，流程、规则和判断留在 SKILL.md。它相当于 Skill 的操作说明，每次执行任务时，都需要让 AI 完整阅读。

💡顺带认识一下 assets/

上一关拆 gzh-design 这个 Skill 的结构时，你可能注意到还有一个 assets/ 文件夹。这一关暂时用不上它，知道有这个能力就够了。

它和 references/ 的区别很简单：

• references/：放 AI 需要阅读和参考的资料，比如案例、产品信息、FAQ、你的真实经验等。

• assets/：放需要直接使用的资源，比如固定模板、图片、图标等。

举个例子，如果你有一套固定的朋友圈模板，或者公司 Logo、宣传图片这类素材，就可以放在 assets/ 里。

等以后真的需要这类资源时，再创建 assets/ 文件夹也不迟。现在先把 references/ 学会就够了。
