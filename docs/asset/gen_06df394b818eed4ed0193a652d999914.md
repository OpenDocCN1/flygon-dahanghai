# 4.1.5.2 学习git的好处

这个方法有什么用？功能越来越复杂时，Cursor 很可能把先前完善的功能改得一团糟，而且哪怕让它反复修正，也未必能回到之前满意的版本，结果每加一个功能都提心吊胆。用了这个方法，就能步步为营、稳定增加功能，以结果为导向判断 AI 的改动是否正确。

拿俄罗斯方块举例：假设我们折腾出了第一个初始版本，用 git 保存代码。现在开始做第一个功能——增加得分。AI 没做好的话，从界面上就能看出来。这时有两种情况：

1、AI 做好了，我们也觉得可以，那就直接保存代码。

2、AI 乱改，游戏直接玩不了；或者聊了很久越聊越偏；或者把原有功能改成了问题。那就放弃所有更改，代码回到上一个版本（初始版本）。开一个新的聊天框，重置上下文，重新开始聊。

重复这个步骤，直到把功能做出来。一般我们做的是小功能迭代，还是很容易做出来的。做好之后继续保存，继续下一个功能，如此周而复始。

这里有个问题：功能越来越多，要检查的点也越来越多，人会很累。怎么办？案例里给出的方案是模块化开发。把需要做的功能点放进一个文件夹，案例中一个文件夹就是一个页面。保证让 AI 修改功能时只改这个页面。如果你发现它改了其他文件夹的文件，可以问它为什么改，或者直接拒绝更改，告诉它别乱改，代码都写在这个文件夹里。看文件有没有被改也比较简单：文件变色就表示被修改过。这样检查范围就缩小到了一个页面，轻松不少。

# 4.2 用 Cursor 开发 Youtube 本地下载站点 @钱塘江鲤

# 4.2.1 背景介绍

YouTube 是全球最大的视频平台，里面有无数优质内容。有些情况下，我们需要把视频下载到本地处理，比如对标、复刻。这时就需要一个 YouTube 下载站点；在线版一是慢，二是有广告、操作复杂，而且不利于后续流程衔接和自动化。所以这里从零做一个本地 YouTube 视频下载站点：输入 YouTube 链接，把视频下载到本地设备。

功能需求：

1、主页面功能：
顶部显示标题和简介；

下方显示已下载视频列表。

视频标题、视频时长、视频作者、视频描述、文件大小。

4、本地视频管理：
列表形式展示所有下载的视频；
