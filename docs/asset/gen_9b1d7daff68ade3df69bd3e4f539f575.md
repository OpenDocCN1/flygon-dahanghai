# 3.4 第三步：做好站内优化 @哥飞

当我们经过需求分析，确定了可能做的关键词之后，下一步就要琢磨：用户在搜索引擎里输入这个词，实际想得到什么？是内容、工具、服务、商品，还是其他东西？

把用户的真实意图搞清楚，我们才能针对性地确定，该为这个关键词做一个什么样的页面，来承接搜索带来的流量。

# 3.4.1 站内内容优化

即便是做工具站，站内丰富的文字内容也必不可少，尤其是要有一个文章列表。

谷歌的抓取和收录本质上还是依赖内容，与关键词高度相关的内容更容易获得展示机会，也会影响收录速度。

因此，建站的同时就应该开始做 SEO，需要准备以下内容：

TDK：也就是 title（网页标题）、description（网页描述）和 keywords（关键词列表）

网页结构：包括 h1、h2、h3 等标题层级、正文内容和图片等

下面以电影《学爸》的影评网站为例，逐个说明每个模块的优化方法。

# 3.4.1.1 TDK 优化

① title

网页标题是搜索引擎判断网页核心内容的关键依据之一，很多时候所谓的 SEO 优化，本质上就是写好标题。

同时，标题还会直接显示在搜索结果中，一个漂亮的标题能有效提高点击率。

[PRE7]

② description 和 keywords

description 也就是网页描述，同样会展示在搜索结果里，重要性也不低。

keywords 关键词列表通常可以省略。我个人的优化习惯是不过度堆砌，一般是认真打磨 title 和 description，直接把 keywords 删掉。

# 3.4.1.2 网页结构优化

一个 HTML 页面，除了写好 title 和 description，更重要的是页面层级要清晰，要有明确的 h1、h2、h3 结构。

《学爸》影评网站示例如下：

① h1

每个网页只能有一个 h1。如果说 title 是给搜索引擎看的，那 h1 就是给用户看的。同时搜索引擎也会参考 h1 来评估页面内容，最终要不要给排名、排在哪里，很大程度上取决于 h1 和 title。

[PRE8]

② h2 和 h3

这两个标签同样是语义化 HTML 中不可缺少的部分，而且一个页面里可以有多个 h2 和 h3。

[PRE9]

③ p

h1、h2、h3 分别是一、二、三级标题，除了标题以外的正文内容，都应当写在 p 标签内。

④ img

图片也是网页的重要组成部分，合理布置图片不仅让用户更容易理解内容，还能带动搜索引擎图片搜索的流量。

img 标签一定要加上 alt 属性，这是给搜索引擎看的图片说明。图片尽量使用大尺寸，建议 300x300 以上。

[PRE10]

# 3.4.2 站内链接优化

通常，主关键词都能延伸出不少二、三级关键词。在网站首页，一般会把主关键词以及延伸出的二、三级关键词分别用 h1、h2、h3 列出，目的在于优化首页主关键词的权重。

🌰举个例子：主关键词是：Coloring pages

二级词：在 coloring pages 基础上拓展出 coloring pages christmas

[PRE11]

三级词：继续基于二级词 coloring pages christmas 拓展

[PRE12]

然后，为每个二级关键词建立独立的子目录，用子目录首页去优化对应的二级词。

接下来，在每个子目录下面，为它的所有三级关键词建立内页。

所谓内链建设，就是指首页上既要有能跳转到每个二、三级关键词的链接，同时每个关键词页面也要有指向上一级的链接。

换句话说，某个二级词的全部三级词页面都要链回该二级词子目录，而所有二级词子目录页面也要能链回首页。

# 3.4.2.1 后端渲染

上面提到的 tdk、h1、h2、h3、p、img 等内容，都必须能在浏览器查看 HTML 源代码时直接看到。也就是说，服务器返回的 HTML 就应该是一个完整的页面，包含完整的内容。

不能只让前端返回一个固定模板，再通过接口异步获取内容、在前端渲染。

# 3.4.2.2 确保 URL 唯一

一个页面经常能通过多个 URL 访问，但我们必须在网页 head 中设置 canonical，告诉搜索引擎哪个才是正确且唯一的 URL。

举个例子，微信 App 在苹果 AppStore 的页面，苹果官方指定的唯一 URL 是 https://apps.apple.com/cn/app/%E5%BE%AE%E4%BF%A1/id414478124。

但实际上下面这些 URL 也都能打开同一页面：

https://apps.apple.com/cn/app/id414478124

https://apps.apple.com/cn/app/weixin/id414478124

https://apps.apple.com/cn/app/wechat/id414478124

可以看到，不管你从哪个 URL 打开，苹果官方用 canonical 指定的规范唯一 URL 始终是同一个。

# 3.5.2 进行部署操作

用户输入域名访问网站时，会先经过 DNS 解析，找到提供服务的服务器 IP。这个 IP 可能是你买的云服务器，也可能是 Vercel、CloudFlare 等平台的地址。随后请求会发送到服务器，服务器处理后返回 HTML 页面代码，最终由浏览器渲染出网页。

所以我们买下的域名，需要有一个 DNS 服务器。域名注册商一般都会免费提供，或者也可以使用第三方 DNS 服务。这里统一建议优先用 CloudFlare 的域名解析服务。

# 3.5.2.1 配置域名解析

打开 CloudFlare，点击左侧菜单中的 Websites，进入网站列表页面，再点击右上角的“Add a site”，在弹出页面的输入框中填入你的域名，然后点击“Continue”按钮。

[PRE17]

选择免费套餐，继续点击“Continue”。

[PRE18]

复制 CloudFlare 提供的 ns1 和 ns2，回到域名注册商后台，填写到域名的 DNS 设置界面。

[PRE19]

有些 DNS 服务商会提供 5 个 NS，通常最少也有 2 个。CloudFlare 只有 2 个，那就填这 2 个，提交保存即可。

[PRE20]

接着继续下一步，三个选项都保持开启，最后点“Finish”完成。生效需要等待一段时间，当回到网站列表页面，看到网站下方显示“Active”，说明 DNS 修改成功了。

[PRE21]

# 3.5.2.2 添加域名解析记录

当你查询 Whois 信息，发现 DNS 已经切换到 Cloudflare 了，说明新的 NS 已生效，这时就可以去 Cloudflare 设置 DNS 解析记录了。

在左侧菜单栏里找到 DNS 下的 Records，也就是 DNS 解析记录。

[PRE22]

点进去后，可以看到所有解析记录。在这里可以新增记录、修改旧记录，或者删除记录。

[PRE23]

常用的域名解析记录类型包括 A 记录、CNAME 记录、TXT 记录和 MX 记录。如果只需要配置网站访问，用前两种就够了；如果要配邮箱，才需要用到后两种。另外，做域名所有权校验时，有时需要用到 TXT 记录。

一般情况下，别人让你加什么记录，你就加什么记录就好了。

# 3.5.2.3 静态网站部署

以 Vercel + CloudFlare 为例，静态网站部署步骤如下：

1、创建 Github 仓库，把网站前端代码提交上去；

2、在 Vercel 新建项目，关联刚才创建的仓库；

3、等待自动构建成功，点击 Vercel 提供的免费子域名，即可正常打开网站；

4、在 Vercel 域名设置里添加自定义域名，默认选择不带 www 的域名，把 www 域名重定向到不带 www 的域名（正好与官方建议相反），并开启 SSL 证书，设置从 http 跳转到 https；

5、在 CloudFlare 中添加域名解析记录，注意 SSL 要选择 Full 模式；

6、等待解析记录生效，通过 https://域名 能打开网站，部署完成。
