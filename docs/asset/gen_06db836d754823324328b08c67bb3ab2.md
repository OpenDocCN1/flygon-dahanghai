#### 1. Skills 是什么

💡⚠️注意：第二章所有 skills 都要在 Claude Code 环境里安装运行。如果还没装 Claude Code，请先回第一章装好部署好，再回来学第二章。

Skills 是 Claude Code 在 2.0.20 版本里加入的功能。与其说是 Claude Code 的专属能力，不如说是 Claude 整个体系的能力，因为 Anthropic 家的产品都支持，比如 Claude Desktop 也一样能用。

放到现在，Skills 已经成了一种行业标准，各家厂商都在跟进支持，颇有当年 MCP 起势的味儿。

一句话：**Skills 就是给 Claude 看的 SOP 手册。**

下面会用文字把这句解释透。能看懂就看，看不懂就当小说翻过去。

反正后面有大量实战，用着用着自然就明白 skills 到底是个啥。

SOP（标准操作流程）你应该不陌生。麦当劳全球几万家店，为什么每家做出的巨无霸味道都差不多？不是因为每个店都配了大厨，而是因为有一套写得极其细的 SOP——肉饼煎几秒、酱料挤多少克、生菜放几片，全给规定死。新员工照着做，出品就达标。

Skills 之于 Claude，就是这套 SOP。

没有 Skills 的 Claude，就像一个聪明但从没被培训过的新人。你跟它说“帮我做份年度汇报 PPT”，它会凭自己的理解做，做出来能用，但很可能字号不统一、配色不协调、排版乱七八糟——因为没人告诉它“应该怎么做”。

有了 Skills，就相当于你递给他一本《PPT 制作标准操作手册》——用什么字体、标题多大、每页放多少内容、图表怎么配色，全写得清清楚楚。它照着手册干活，输出自然又稳又专业。

从技术层面讲，Skills 本质上是 Markdown 格式的指令文档，像一份数字化 SOP，里面打包了三样东西：

• **操作步骤**：先做啥、后做啥、按什么顺序做

• **工具配置**：调哪些工具、怎么调

• **质量标准**：做到什么程度算合格，有哪些坑要避开

和现实里的 SOP 是同一个逻辑——把专家经验变成可执行的标准流程，让执行者不用自己摸索，照着做就行。

**Skills 的价值**

理解了「Skills = SOP」，它的价值就很好懂了。

想想你熟悉的连锁品牌——海底捞的服务、星巴克的咖啡、胖东来的陈列——它们能打的核心竞争力从来不是“碰巧招到了好员工”，而是把最佳实践写成了 SOP，让每个员工都能稳定输出高水平。

Skills 做的就是同一件事，核心价值三个字：**稳、准、专**。

💡

• **稳：每次都有保障，不靠运气。**没有 SOP 的餐厅，菜好不好吃全看厨师当天状态。没有 Skills 的 Claude 也一样，同样的任务时好时坏。有了 Skills，就像有了标准流程，每次输出质量都在线。

• **准：不用反复交代，一句话搞定。**以前你可能要写一大段提示词：“用这个字体、标题加粗、表格带边框、最后加个目录……”现在这些全进 Skill 了，你只要说“帮我做个 PPT”，Claude 就自动按标准来。就像你不用每次跟麦当劳员工强调“肉饼煎熟、放两片生菜”——SOP 里都有。

• **专：装的是反复验证过的最佳实践。**Anthropic 官方出的 Skills 都是经过大量测试和打磨的。比如做 Word 文档的 Skill，里面写了怎么处理页眉页脚、怎么生成目录、怎么调段落间距——全是踩了无数坑总结出来的经验。这些要自己摸索得折腾大半天，用 Skill 直接一步到位。

更要紧的是：**你可以写自己的 SOP**

这才是 Skills 最有杀伤力的地方。

官方 Skills 是“通用 SOP”，适用面广。但每个人、每家公司都有自己的工作习惯，比如：

• 你们公司写周报有固定模板——你可以写一个“周报 Skill”

• 你搞前端项目有一套命名规范——你可以写一个“代码规范 Skill”

• 你写👸号有一套排版风格——你可以写一个“排版 Skill”

写完以后，每次只需要一句话，Claude 就会按你定义的 SOP 来干活。相当于你把自己的工作经验和方法论，亲手“教”给了 Claude。

这就像连锁品牌的加盟手册——把方法论写成标准流程，Claude 就变成一个完全按你方式工作的“虚拟员工”。

**总结一下：Skills 就是 AI 时代的 SOP。它让 Claude 从“我能做”变成“我能按最高标准、稳定地做好”。**

它的**目录结构规范**：

• `SKILL.md`：定义技能的元数据、触发条件和核心逻辑（大脑指令）。

• `scripts/`：可选的可执行脚本（自动化工具）。

• `templates/`：领域特定的代码或文档模板（理论上，任何文件夹比如 `references/` 或 `api/` 都行，只要 SKILL.md 里写清引用方式即可）。

💡然后再说几个注意事项。装 skills 的时候，这几个核心要求一定要记住：

1. 尽量不要全局安装 skills，尤其是那些只在特定业务场景里用的 skill，免得模型跑任务的时候瞎激活；

1. 同一个项目里不要装超过 10 个 skills，容易互相串味；

1. 尽量不要做成“skill 激活 skill”的流程，容易套娃引用。推荐做法是在 AGENT.md 或 CLAUDE.md 里把已安装 skills 的使用场景和使用流程提前声明清楚。

**!!! 注意事项！！**

另外现在 skills 有点泛滥的趋势，特别是 OpenClaw 火了以后，冒出不少留后门的 skills，出过一些安全事故。

所以装 skills 的时候一定要核实来源。

**来历不明的 skills 千万别装，给自己的电脑和账号 token 留个心眼。**
