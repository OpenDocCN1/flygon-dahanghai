# 2.4.4 提示词里的常用格式元素

# 2.4.4.1 三引号

作用

作为分隔符使用。把要处理的文本放进英文三引号 """...""" 里，更能让 GPT 分清哪些是指令、哪些是待处理内容。

特别是有时候你的提示词里本身还带着文本内容，GPT 很容易混淆：哪句是命令，哪句是素材？如果文本内容里还有中文引号“”，它更容易把引号里的内容误当作处理对象，导致边界判断出错。

案例

# 📌

请用 3 个对仗工整、且汉字数量完全相同的排比句来概括下面这段文案：

"""在此插入要处理的文本"""

GPT 对文案内容范围的理解完全正确，给出的总结也很准确。

# 2.4.4.2 XML 标签

作用

也是分隔符。当一条提示词里需要放置多段要处理的文本时，用 XML 标签来隔开（当然用三引号也可以）。

案例

# 💡

我给你两篇同一主题的文章，用 XML 标签分隔。请你先概括每篇文章的核心论点，然后指出哪一篇的论点更扎实，并解释原因。

<文章> 在此插入第一篇文章</文章>
<文章> 在此插入第二篇文章</文章>

[PRE11]

这样一来，就算要处理多篇文本，GPT 也不会混乱了。

对于简单任务，用不用分隔符可能并不会明显影响输出质量，效果不错的话完全可以不用。但随着提示词越来越复杂，消除歧义的重要性就愈发凸显，这个技巧能帮上大忙。

# 2.4.4.3 小节标题（模块化/结构化提示词）

作用

在提示词里加入小节标题，其实就是明确告诉 GPT：每个小节都是不同的内容模块。原本一长串像小作文一样的提示词，现在被拆成多个小节，实现模块化表达。这也叫提示词的结构化（或格式化）。

当提示词很长、字数很多时，如果还用写小作文的方式堆成一整坨，AI 很难理解清楚，生成效果也会打折扣，还容易产生语义歧义。

结构化之后，提示词的层次感更分明、条理更清楚，AI 能更准确地识别每个模块在讲什么，歧义被消除，理解效果自然更好。

实现结构化有几种方式：
- 用自然语言的小节标题来分块，【推荐】；
- 用 Markdown 格式，让层次结构清晰可见，【推荐】；
- 用 JSON、YAML 格式，程序员比较常用，普通人不推荐。

这一节，我们重点讲的是用自然语言的小节标题来把提示词结构化。

案例一

结构化前：

# 💡

我一会儿给你一段文字摘要“8 月 9 日消息，快手高级副总裁、研发线负责人于冰近日表示，AI 大模型作为当下最重要的革命性技术，进入爆发期，有望开启 AGI 时代，而多模态内容生成与理解是其核心能力。他提到，短视频、直播作为最典型的多模态媒介，快手也抓住平台基因，在 AI 大模型领域重度投入。”以及对应的新闻标题“快手于冰：在 AI 大模型领域重度投入”。标题应该让读者清楚了解文字内容的主题，但也应该引人注目。如果我的标题不符合这些标准，请你给出 5 个替代方案。

看，是不是很乱？字数一多、符号一复杂，人读起来都费劲，AI 也容易看晕。

结构化后：

# 💡

我会给你一段文字【摘要】和对应的新闻【标题】。标题应当既能清楚点出文字内容的主题，又要有吸引力。如果我的标题不符合这个标准，请你给出 5 个替代方案。

【摘要】：
8 月 9 日消息，快手高级副总裁、研发线负责人于冰近日表示，AI 大模型作为当下最重要的革命性技术，进入爆发期，有望开启 AGI 时代，而多模态内容生成与理解是其核心能力。他提到，短视频、直播作为最典型的多模态媒介，快手也抓住平台基因，在 AI 大模型领域重度投入。

【标题】：
快手于冰：在 AI 大模型领域重度投入

[PRE13]

同理，任务简单时，加不加小节标题对输出质量影响不大，效果好就不用。但提示词越复杂，消除歧义就越重要，这个技巧会很有帮助。

案例二

结构化前：

# 💡

请你扮演《狮子王》的辛巴，你必须了解辛巴的所有知识。现在，请你用辛巴的语气和我打招呼。请使用辛巴的说话方式、思维、词汇和我沟通。只能像辛巴那样回答，不要写任何解释。

结构化后：

# 💡

【角色】：
请你扮演《狮子王》的辛巴，你必须掌握辛巴的所有知识。

【任务】：
现在，请你用辛巴的语气和我打招呼。

【要求】：
请使用辛巴的说话方式、思维模式、常用词汇与我沟通。只能像辛巴那样回答，不要写任何解释。

当提示词特别长或比较复杂时，比如上千字，那就一定要分模块来写。还像写作文一样全堆在一起，AI 直接就看蒙了，效果自然不好。这里举的例子比较短，堆在一起 AI 也能看懂，所以看不出明显差别。但你遇到复杂提示词时，要记得可以这样优化。

小节标题常用语法（结构化提示词模板）

最基础的模块化方式：模块名可以用特殊符号括起来，比如用【】来突出结构。具体需要哪些模块，完全根据你的提示词来定。

# 💡

【结构化提示词模板】

【角色】：请你扮演 xxx
【任务】：写一个 xxxx
【要求】：1. 500字 2. xxx 3. xxx

无序列表可以用 -、+、* 来表示，这三个符号在功能上完全等价，给用户提供了灵活性，选哪个看你个人偏好。用无序列表能让结构更清晰。

【模块名】：
- 黄瓜不要皮
- 玉米不要瓤
- 茄子不要籽
+ 黄瓜不要皮
+ 玉米不要瓤
+ 茄子不要籽
* 黄瓜不要皮
* 玉米不要瓤
* 茄子不要籽

无序列表还支持嵌套，把 -、+、* 混合使用，可以创建多级嵌套列表，让不同层级的条目在视觉上有所区分（虽然最终渲染出来的符号没有任何区别）。每个嵌套层级前需要加四个空格或一个制表符，层级关系才会更清楚。

【模块名】
* 第一级列表项 1
  * 第二级列表项 A
    * 第三级列表项 i
    * 第三级列表项 ii
  * 第二级列表项 B
* 第一级列表项 2
  * 第二级列表项 C
    * 第三级列表项 iii

有序列表是最常用的形式，表达结构的效果也很好。

【模块名】
1. 我是第一个要求
2. 你是第二个要求
3. 他是第三个要求

注意，这里的无序层级结构采用了 Markdown 语法。用什么语法其实无所谓，你哪怕直接跟 AI 说代码都行，只要 AI 能看懂，就是好提示词。后面还会单独介绍 Markdown 格式。
