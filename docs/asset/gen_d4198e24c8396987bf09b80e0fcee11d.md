最近 ChatGPT 封号潮闹得厉害，很多人辛苦调教出的会话记录可能说没就没。账号本身不值钱，但你和 ChatGPT 的对话记录、创意灵感才宝贵。好在有一个插件，能把聊天记录完整存到本地电脑。

这个插件完全由 ChatGPT 写成，作者没敲一行代码。从最基础的获取网页 HTML 开始，到保存为 TXT，再优化处理内容，继而输出为 HTML、PDF、PNG，最后还做了多语言支持。整个过程全靠对话驱动。开发花了十几天，每天和 ChatGPT 泡在一起 8 到 10 小时，期间各种卡壳、互相“不理解”，但靠着作者的引导调试和 ChatGPT 的耐心配合，一个一个都解决了。

结果就在准备上架时，作者发现被 ChatGPT “带偏”了——插件是基于 Manifest V2 写的，而 Chrome 应用商店从 2023 年 1 月 1 日起就不再接受 V2 版本的新插件。没办法，只能让 ChatGPT 一步步改成 V3 规范。折腾几天后提交审核，期间又碰到一堆问题，照样丢给 ChatGPT，它逐个搞定，连产品概述都是 ChatGPT 用 PAS 模型代写的。终于，插件在昨天正式过审上线。

这虽然只是一个小插件，但如果去 GitHub 找类似代码二次开发，也许更快；然而这次尝试证明了 GPT4 确实具备开发能力。不过用 ChatGPT 写项目，有几点必须注意：

1. **切入点一定要小**。别指望把整个项目需求直接甩给它，让它一口气写完。哪怕项目不大，只要有多个功能模块，GPT 也可能实现不了。第一步最好抽象出最小功能点，小到 GPT4 能给出完整可用的初始版本。比如这个插件的起步是从“读取当前网页源代码并显示在 popup 页面”这种最小需求开始的，然后再逐步加需求。

2. **分模块让 ChatGPT 写程序**。ChatGPT 输出经常中断，有时用“继续”“继续写”能续上，但未必每次都管用。程序是强上下文关联的内容，前后逻辑一旦错位，就容易出 bug。所以可以让它先列出需要哪些文件，再引导它分别输出每个文件的代码。

3. **不断和 ChatGPT 确认代码**。GPT4 的输出偶尔会前后对不上，所以每加一个新功能前，先让它复核需求、重新检查现有代码，确认没问题再继续加功能。

4. **适当深入代码和功能做引导**。GPT4 有时会陷在某个实现方式里打转，怎么改都不对。这时候需要你基于自己的经验，深入具体需求和代码，引导它换一种方案。

整个开发和审核过程波折不断，但作者和 GPT 合力逐一解决了。ChatGPT 不只是工具，更像是帮手或同事，需要像对接同事那样一起探讨、一起解决。这个插件功能虽然简单，但它的上线意味着我们可以借助 ChatGPT 辅助开发英文工具站。未来可以有更广阔的想象空间。

# 案例三：真自动、强批量——ChatGPT 超级写手机器人 1.0 实录 @渣渣浩

1、开发背景

1）ChatGPT 在内容创作中的常见痛点

ChatGPT 是一个基于深度学习训练出来的大模型，能力很强，覆盖很多应用场景，内容创作更是它的主战场。它可以做这些事：

- 自动写文章：学习已有文章的风格、主题、句式，生成类似的新文章。
- 内容推荐：根据用户的兴趣和历史行为，推荐相关的文章、视频、音频等内容。
- 翻译：把一种语言翻译成另一种语言。
- 内容摘要：提取文章重点，用简洁的方式呈现。
- 内容分类：把文章按主题、领域或类型归类，方便用户查找。

总之，ChatGPT 能大幅提升内容创作的效率和质量，帮助用户更快获得信息。不过，这段介绍乍一看像“水文”，但后面会用到，非常关键。后面的 chatpdf 正是利用这个能力获取大纲摘要，才实现了真正的全自动化，而不是半自动。

用 ChatGPT 写作，常常会遇到这些问题：

- 写一半就停了；
- 让它“继续”，结果上下文接不上，甚至跑偏；
- 提问和回答都要手动复制粘贴；
- 问题一多，整理起来特别麻烦；
- 对话记录没法自动保存；
- 提问和回答次数有限，不能太多也不能太快；如果开多账号、多浏览器应付，人工盯着处理各种故障又很耗精力。

模型本身很好，但最大的痛点是：大量操作依赖手工，只能做到辅助创作，离“自动化”差了十万八千里。

# 案例四：ChatGPT 海外工具站的赚钱 IDEA 拆解 @子木

1. 大白话：理解 ChatGPT 与 OpenAI

先来理解 OpenAI 的能力，可以把它类比成文字识别（OCR）、拍照、拍视频、音视频等能力。那它们之间到底是什么关系？用大白话说：

信息，就是文字、图片、音频、视频，是互联网上数字信息的表达形式。人类大脑是存储信息的容器。ChatGPT 应用里的 OpenAI 能力，就像人类大脑，能存储和生成信息，既能产出 AI 文字，也能产出 AI 图片。

不过，ChatGPT 本质上是一个网站，也是 OpenAI 的一个应用。如果把 OpenAI 的 AI 绘画能力做成应用，也许可以叫 DrawGPT。

2. 如何利用它做海外工具站呢？

我们公司目前是这样用 GPT 能力的。

用于获客：

- 做 SEO 高质量内容。类似圈友二两做的 https://www.proseoai.com/ ，谷歌 SEO 获客内容神器，自动生成。
- 做 SEM 广告词优化、落地页文案优化。
- 做社媒营销高传播文案优化，顺便可以用 AI 绘画配图。

用于产研：

- 产品上，我们做在线会议。脑暴会议支持 AI 扩展思路，会议结束后支持 AI 会议总结等。
- 开发人员用 ChatGPT 写代码、制定技术方案。
- 对于 SaaS 大型 KA 项目，用 ChatGPT 提供解决方案。

3. 如何找到普通人能做的 ChatGPT 相关的海外工具站 IDEA

这是最关键的部分。要拆解这个问题，需要考虑几个必要因素：

- IDEA：说明有市场需求；
- ChatGPT 相关：说明市场需求跟 ChatGPT 有关，或者 OpenAI 能力能更快更好地解决；
- 普通人：说明实现成本或复杂度不高。

总结下来，就是相对 niche（利基市场）的方向，可能是信息差、认知差，还没被太多人发现。基于这些因素，我分享几个 IDEA 思路。

1）围绕巨头 ChatGPT 做补充需求工具站

基于 ChatGPT 这个新晋 top 应用，肯定有很多利基需求没被满足，即使有 plugin 也覆盖不全。所以围绕巨头的客群，做细分需求，就有市场。比如：

Voice Control For ChatGPT

需求：文字交流太麻烦，能不能直接用语音和 GPT 交流？
实现：不就是加上“文字转语音、语音转文字”的基础能力吗？
总结：完善了 input/output 的方式。
延展：翻译能不能搞？Apple Siri 能不能接通？微信语音能不能打通？

ChatGPT to Notion

需求：GPT 会话会保存，但它不是知识库，需要把内容存到知识库里。
实现：和知识库应用 API 打通，提供模块，一键保存到知识库对应分类，还能打 tag。
总结：完善了 output 的最终利用闭环。
延展：to 印象笔记、to 飞书、to 其他工具都可以。

AIPRM for ChatGPT

需求：需要 prompt templates，怎么和 ChatGPT input 更好？
实现：收集高质量、分类清晰、支持搜索的 prompt 库，类似 https://sharegpt.com/ 也是这个道理。
总结：解决了如何把 ChatGPT 用得更好的问题。
延展：AI 绘画 prompt 有没有需求？有（https://promptheroes.cn/ 目前月 UV 1 万）。更细分人群、更专业的 prompt 模板有需求吗？中英文 prompt 有需求吗？

怎么找到这些需求？需求挖掘在这期的航海文档中有详细介绍。我就是在谷歌插件里搜这些关键词找到的：ChatGPT To xxx、Xxx For ChatGPT。

2）利用 OpenAI 能力，做细分场景的 ChatGPT 工具站

把 GPT 能力当成类似 OCR 的基础能力，能力和场景结合，就能玩很多工具站。比如：

ChatGPT for Mail Messages

需求：老外经常写邮件，用 ChatGPT AI 生成完整的电子邮件和消息，并支持 Gmail。
实现：基于 Gmail 写个插件，用户按 prompt 输入 topic，自动生成填充。
总结：解决了老外整天写 messages、mail 的痛点。
延展：能不能 for 各大社交媒体（TW、FB 等）？能不能 for 视频平台 YouTube？

ChatGPT for Amazon & Shopify

需求：用 ChatGPT 做亚马逊和 Shopify 的评论分析、列表优化、评论生成器。
延展：for xxx 基本上都有需求。国内有 for 小红书内容生产，国外 Amazon 也马上有种草内容平台。

那我是怎么找到这些需求的？其实就是搜“chatgpt for xxx”。
