# B端AI智能体：做项目前先对齐这四张底表

正式动工之前，强烈建议项目组先把四张底表逐一捋清。要是能拉上客户一起逐项核对，后面会省掉很多不必要的扯皮。实际上，大量项目拖期的根源，不在技术难度，而在前期信息没对齐、职责没划清。

1. **业务场景表**：要记录场景名称、归属部门、当前困扰、出现频次、单次耗时、输入资料、产出结果、风险等级，以及预期的业务价值。
2. **系统接口表**：需要写清楚系统名称、数据内容、接口形式、对接负责人、权限要求、测试环境状态，还有预计开放时间。
3. **知识库资料表**：包括资料名称、来源部门、格式、规模、更新时间、保密级别、责任人，以及是否允许用于模型训练。
4. **项目责任表**：将客户侧的项目负责人、业务负责人、技术负责人、数据负责人、验收负责人，连同服务商对应的接口人全部落实到人。

四张底表不齐，项目执行中大概率会遭遇资料迟迟不到位、接口一直没开放、需求反复摇摆等连锁问题，交付节奏很容易被拖垮。

### 03. 交付方式设计与知识库搭建

企业体量不同，交付路径也不该套用同一个模板。下面按通用与定向两类给出思路。

**通用方案：多数企业可以试“Agent+知识库+自动化+人工节点”的组合**

先把话说在前面：这只是尝试方向，不适用就不要硬上。

- Agent：专职接收任务、分析意图、调用所需工具，最终产出结果。
- 知识库：负责沉淀客户信息、产品资料、规章制度、操作流程、历史案例等背景知识。
- 自动化：承担定时触发、消息推送、任务流转、结果归档等重复性动作。
- 人工节点：负责审核高风险操作、处理异常情况，并拍板最终决策。

不要把人工节点当成系统的短板。对企业场景而言，恰当的人机协作，往往比盲目追求全自动更稳妥、更可靠，验收时也更容易让各方满意。

动手建知识库之前，建议先盘点三类关键资料：

1. CRM与客户档案：回答“谁在买”“客户画像如何”“之前的沟通历程是什么”“目前处在哪个阶段”。
2. SKU与产品资料：回答“企业提供什么”“规格和价格如何”“适用范围和限制有哪些”。
3. SOP与流程标准：回答“员工应按什么顺序操作”“什么样的产出才算达标”“哪些情况必须升级”。

如果这三类基础资料都不齐，别指望“接个大模型就能解决”。正确做法是先搭一个最小可用知识库。

最小可用知识库的含义，不是把所有文件都导进去，而是围绕第一个试点场景，只准备真正必要的信息。业务人员、销售人员根本用不上的内容，暂时不要放进去，免得白费人力物力。比如客服问答智能体，第一期只整理产品说明、高频问题、售后政策、退款规则和转人工条件即可，剩下的资料等后续迭代时再补充。

**大型企业：组织复杂，必须分阶段走**

大型企业的特点通常是层级多、系统杂、数据敏感、权限严格、决策链漫长。说白了，国企央企流程冗长，项目很容易卡在审批环节，交付和收尾款都可能受影响。

第一阶段，做企业级诊断。既要访谈老板，也要覆盖业务部门、信息科技部门、数据部门、安全合规部门以及一线使用者。访谈顺序上，先拿下老板的支持——领导定调后，下面的人才会配合。

第二阶段，建立场景库并排优先级。大企业可能一口气提出几十个场景，需要从业务价值、落地难度、数据条件、风险程度、可复制性几个维度打分排序，优先挑选使用频率最高的场景。

第三阶段，搭建统一基础能力。包括统一模型入口、统一知识库、统一权限认证、统一日志审计、统一智能体编排、统一运营看板。这块尽量选用成熟产品，避免重复造轮子。

第四阶段，选一个部门做试点。就算预算充足，也不建议一开始就全面铺开。挑一个部门、一个场景、一组真实用户，持续使用一段时间。小范围闭环跑出效果后，领导看到了成绩，二期项目才有谈的空间。

第五阶段，压力和安全性测试。要覆盖正常输入、缺失输入、异常输入、越权访问、敏感信息、网络中断、接口失败、模型不可用、并发压力等场景。技术好不好，最终还是客户说了算，关键是让客户方人员觉得好用。

第六阶段，挑典型场景推广复制。试点稳定后，把标准化能力扩展到其他部门，同时给不同业务线保留个性化配置空间。一个场景验证成功之后，复制才有说服力，老板也更愿意看到这种可复制的成果。

大型企业AI智能体项目的交付物通常包括：总体规划、业务场景地图、技术架构、数据架构、知识库标准、安全方案、试点系统、测试报告、培训材料、运营制度、推广计划等。

**中型企业：成熟平台+场景定制，求快求稳求可见**

中型企业有一定业务基础和数字化系统，但预算、技术团队和管理能力都有限。一开始不宜建设过于复杂的平台，更适合用成熟平台加场景定制的打法。直白讲，有钱，但不算宽裕。

第一步，锁定一个与收入或核心交付直接相关的场景。比如销售商机分析、客户方案撰写、客服知识问答、项目资料整理、内容创作。记住：销售优先！销售优先！销售优先！先拿下销售场景再说其他。

第二步，整理最小知识库。只整理和试点场景直接相关的客户资料、产品资料和SOP。

第三步，用成熟平台搭建智能体和工作流。减少不必要的底层开发投入，把预算花在业务规则设计、知识库质量、系统对接、员工使用体验这些真正能产生价值的地方。很多企业不习惯国外知识库产品，直接上乐享这类国内知识库更实际。

第四步，开展两到四周的试点。让真实员工连续使用，记录成功任务、失败任务、人工接管的场景和优化建议。直接用客户的数据跑任务，边跑边迭代。

第五步，验收后决定是否继续扩展。扩展方向可以是增加用户数量、增加场景类型、对接更多系统，也可以把临时工具转正为正式系统。二期项目需要有人推一把，老板也需要成绩来证明判断是对的。

中型企业项目交付的重点就是快、稳、可见，方案别搞得太复杂。

**小型企业：控制范围，快速见效**

小型企业的决策标准通常是价格、速度和立竿见影。直白讲，预算紧，能省则省，但确实想做，真正的收益在后期。

切口可以是咨询、培训、Skill、小工具或自动化流程。例如：自动汇总每日销售记录；根据客户资料生成跟进建议；根据产品资料生成短视频文案；自动整理客服问题；根据会议记录生成任务清单。

尽量沿用客户现有工具和成熟平台，别让客户一开始就背上沉重的服务器、开发和维护包袱。小型企业项目尽量在1到2个月内拿出可见成果。

交付物可以是一个可用的工具、一套提示词、一份知识库、一本操作手册、一次员工培训。小型企业项目成败的关键是控制范围。客户看到效果后，很容易一个接一个地冒出新想法，合同里务必写明第一期只解决哪些问题。

### 04. 获客渠道与报价策略

流量这件事必须放在前面。大家都认可AI智能体有价值、需要建设，但真正稀缺的能力是把它卖出去。

**公域流量**

主要阵地是公众号软文、朋友圈投放、抖音快手视频号等短视频平台。

与其宣传“我会做AI智能体”，不如讲清楚一个具体的业务问题是如何被改善的。举例来说：

1. “如何把销售拜访纪要整理时间从40分钟压缩到10分钟”
2. “怎样从两千条客户聊天记录中提取高意向线索”
3. “怎么让客服智能体只输出有据可查的企业知识”
4. “为什么企业AI项目不该一上来就追求全自动化”
5. “十万元以内的中小企业AI项目应该怎么规划”

内容应当包含：客户原有的做法是什么、痛点在哪里、用了哪些数据资料、AI承担什么职责、人工保留哪些环节、最终产生了什么样的改变。多呈现真实流程和边界条件，少放华而不实的界面截图。还要突出AI智能体的垂直行业解决方案和产品差异化优势。

**私域流量**

主要依赖转介绍、线下沙龙、行业论坛、B端大客户销售渠道。

做流量沟通时，向客户重点提三个问题：

1. 你们目前最耗时的重复性工作是什么？最担心哪个环节出错？哪个环节比较标准化、不容易出岔子？
2. 这项工作现在几个人在维护？每次要花多少时间？成本大概是多少？
3. 如果先做局部改善，你们觉得什么样的结果最值得买单？预计想省下多少成本？

第一次合作可以从诊断、小规模培训、轻量工具或短周期试点切入。小订单的意义不在于金额本身，而在于让你进入客户现场，看到老板口头表达之外的真实痛点。很多大项目都不是一上来就签约的：先做咨询打开局面，再做培训建立信任，接着做小场景验证能力，最后才有机会进入更大的智能体建设与陪跑项目。

**报价区间**

AI智能体服务的报价在市场上差异相当大。以OPC一人公司和20人以内的小团队为例，可以参考以下区间：

1. AI智能体企业咨询：2000—3000元/半天，资历更深的咨询师可以再往上提。
2. AI智能体企业培训：4000—6000元/半天，知名度更高的讲师可以再往上提。
3. AI智能体定制化开发（联合研发或纯项目外包）：10万—50万元，实际价格取决于需求范围、所用工具技术、产品与开发团队水平，更强的团队自然能报更高。
   - 小型Skill项目：约3000—5000元；
   - 小应用、小看板或单流程工具：约1万—3万元；
   - 陪跑服务：每月3万—5万元，常见周期为2至3个月；
   - 中小企业验证型项目：总预算通常控制在10万元以内。

以上均为经验区间，并非统一市场价。具体报价还要综合考虑咨询师资历、讲师影响力、行业经验、数据复杂度、客户规模等因素。

做B端项目时，报价单通常拆分成多个模块：

- 模块一：需求调研
- 模块二：方案设计
- 模块三：知识库整理
- 模块四：智能体及工作流开发
- 模块五：系统接口与部署
- 模块六：测试与验收
- 模块七：培训与文档
- 模块八：运维与陪跑

这样拆分，客户能明白钱花在了哪里，服务商也能在需求出现变化时，快速判断新增内容该归入哪一模块。账号、模型API、云服务器和第三方平台费用，建议由客户用自己的主体购买和承担；服务商负责方案、配置和交付。

### 05. 实施边界与风险管控

B端AI智能体项目里，坑确实不少，尤其是开发实施类的项目。提前有风险意识，主动设防，远比事后补救划算。

实际交付中经常遇到这些情况：客户不断追加需求、对AI能力预期过高、数据对接层层受阻、业务部门和销售觉得不好用。这些都可能让实际工作量远超合同约定，客户却不愿增加预算。怎么防？需要提前立好规则。

**风险一：需求不断膨胀**

最常见的剧本是，客户看到第一个功能后，立刻冒出十个新想法。

应对的关键不是拒绝一切改变，而是建立一套需求变更流程。

1. 在合同附件中写清本期交付范围：用户数量、业务场景、知识库规模、接口数量、自动化流程数量、部署环境、培训次数、维护周期，还要注明本期不包括什么。
2. 新增需求必须走变更单流程，写明需求内容、提出原因、对周期的影响、对费用的影响，以及是否需要调整验收时间节点。
3. 小幅度优化可以在约定修改次数内消化，但新增场景、新增系统接口、涉及重大流程调整的变更，必须重新议价。

**风险二：预期被抬得太高**

有些客户觉得，AI智能体上线就等于能做所有人的工作，永远不出错，全天候自动运转，还能马上拉高营收。当然不是这样。

1. 售前就要开始管理预期。不要承诺你无法独立左右的营收、利润或ROI，因为企业业务结果还受产品力、销售能力、市场环境、客户质量、组织执行力等多重变量影响。
2. 可以承诺的是项目边界内能被验证的改进：处理时长缩短、内容产出量提升、人工介入减少、格式合格率上升、知识检索更便捷等。
3. 涉及高风险的任务，必须明确AI只给辅助建议，最终结论仍要由专业人员复核。

**风险三：数据和接口迟迟到位不了**

很多项目卡住，不是开发做不出来，而是数据拿不到、接口没开放、权限审批走不完。

1. 项目启动当天就要列出一份数据和接口前置条件清单。每一项资料都要对应责任部门、责任人、提交时限、格式规范和验收标准。
2. 客户未按时提供资料，项目周期应自动顺延。还没开放的接口，可以先用脱敏样例数据做原型验证，但正式上线前必须跑通真实环境。

**风险四：员工不愿意用**

技术人员觉得功能全做完了，业务人员却不想碰。原因可能是操作太繁琐、输出格式不符合习惯、结果不稳定，或者系统反而增加了工作负担。

1. 验收不能只看老板和技术部门脸色，要让真正的终端用户参与需求梳理、原型测试和试点。
2. 试点期间，记录每位员工每次使用的成功、失败、修改和放弃原因。如果AI生成的结果还需要员工花大量时间重新加工，说明流程还没真正跑通——用户不想用是再正常不过的反应。

**风险五：数据安全与合规隐患**

合同和方案里要写明白：数据范围、使用目的、访问权限、存储方式、保留期限、删除机制。

1. 涉及客户隐私、商业秘密和敏感数据，必须做脱敏处理、最小权限控制、日志审计和人工审核。禁止将客户资料用于未经授权的模型训练，禁止通过不明来源的平台传递敏感文件。
2. 如果客户要求突破平台限制、自动操控个人账号、批量群发消息或使用未经授权的数据，要敢于说不，或者引导到合规替代方案。

B端项目通常要求本地化部署，数据治理方面容易出问题，偶尔也会冒出各种报错。多留个心眼总没错——对企业来说，核心系统的稳定运行比任何新项目建设都重要。

最后，祝看到这里的伙伴们都能在B端企业AI智能体服务上做出成绩，赚得盆满钵满！

### 06. 本次闯关复盘

🎉恭喜，你完成了Agent航海训练营的全部关卡！

回看整个过程，你交付的不只是一个Agent。

你从真实的业务问题出发，学会了拆解岗位、拆解流程、编写Profile、对接工具、跑通闭环，最后还掌握了如何把一个Agent包装成企业愿意试点、愿意掏钱的服务方案。

走到终点再回头望，最大的变化不是学会了几个工具，而是养成了一种全新的工作思路。

每次遇到业务问题，你首先想到的会变成：

- 底层问题到底是什么？
- 哪些环节能交给Agent完成？
- 怎么把它做成分工清晰、结果可量化的闭环？
- 又怎么一步步放大成更大的商业价值？

这正是Agent企业服务最核心的能力。

企业掏钱买的，从来不是“AI Agent”这个名字本身，而是那个原本效率低下、成本高昂、错误频出的业务流程，被你重新跑通了。

所以，不必急着去做一个全知全能的Agent。

先从解决一个具体问题的小闭环做起，让它稳稳运转、持续创造价值，然后不断迭代、不断放大。

愿你把这当作企业AI服务的起点，而不是终点。

回想这21天，你可能从第一次接触Codex、Hermes和飞书开始，一路完成了环境配置、岗位设计、Profile编写、Agent搭建、飞书接入、真实测试，最终打造出属于自己的第一个AI员工。

比Agent更珍贵的，是你带走了一套方法论：如何把真实工作拆解、交给AI、持续优化迭代。

从今天起，凡是遇到重复性高、规则清晰、结果可验证的工作，别急着自己动手，先问一句：

这件事，能不能交给Agent？

希望这次21天做出来的Agent，只是你的第一个作品。

未来，你会有第二个、第三个，甚至一整支属于自己的Agent队伍。

期待在SkillHub、黑客松的舞台上，看到你闪亮登场。
