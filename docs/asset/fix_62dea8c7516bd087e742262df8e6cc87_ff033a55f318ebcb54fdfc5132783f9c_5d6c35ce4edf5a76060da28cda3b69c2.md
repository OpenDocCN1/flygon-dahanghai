关于 AI 的特性

学 AI 编程时，比编程基础更值得担心的，往往是你驾驭 AI 的能力。虽然已经可以完全用自然语言来编程，但想指挥好这个“AI 实习生”，就要先理解它身上的一些特质。下面几点是我认为用 Cursor 时最需要了解的：

1. 随机性。大语言模型的工作原理，是预测下一个 token，而这种预测带有天然的随机性。所以当你跟着教程做，发现出来的结果和示例不一样，一点也不用奇怪；甚至朝着同一个目标，AI 给出两套完全不同的方案，都是常事。如果想减少这种不确定，就靠更清晰的要求去“管住”它的输出。比如你只说“做一个像 ChatGPT 的对话网站”，它可能选用 HTML/CSS，也可能用 React、Vue；但新手更适合 HTML/CSS，于是你就可以明确要求它使用这个技术栈。

2. 平庸感。LLM 被训练时投喂的是海量互联网数据，目标就是预测下一个 token，所以它并不想“出彩”，只求从善如流地给出一个和训练语料差不多的平均解。但你完全可以向它“要更好的”——不满意 app 的设计，就让它按苹果设计师的标准来排；也能把你喜欢的设计师或网站风格发给它，让它照着做。

3. 上下文有限。Cursor 当前接入的模型，开启 Long Context 后最长可支持 200K 上下文，日常对话绰绰有余。不过一个项目常常涉及几十上百个代码文件，每个文件几百上千行，很容易超出上下文极限，导致模型产生幻觉。因此要及时请 Cursor 把项目进展记录到固定文档中（例如 readme.md），并在项目开始就使用 @codebase，帮它记住你们正在做什么。

4. 默认的系统一。正常情况下，Cursor 会直接执行你的指令：让写代码就写，让改 bug 就改。这也正是不少人抱怨它改 bug 不给力的原因——拆东墙补西墙，同一个错总是一再出现。你不妨回忆一下资深程序员的工作流：他们不会一看报错就动手改那一行，而是先去理解整个背景、翻阅关联代码、尝试多种方案，挑出最优解再落地，最后还要测试验证。AI 也该这样。当 bug 反复出现，你已经能判断这不是系统一能解决的简单问题，就该让 AI 停下来，进入系统二思考模式：问题到底是什么 -> 有哪些可选的解决思路 -> 各自的优缺点 -> 最终选哪个。我亲测多次，用这种“让 Cursor 先思考、再给多方案”的方式形成思维链，比直接改代码的效果好出不少。

# 2.1.2 准备 .cursorrules 文件

我有个习惯：每个不同类型的项目，都配备一个专属的 .cursorrules 文件。它相当于一份“指导说明书”，向 AI 交代在这个项目中应采用什么代码风格、命名方式等。只要你把它放进项目文件夹，Cursor 就会自动识别，写代码还是执行命令都会遵守这里的规则。

① 在左侧根目录新建一个 .cursorrules 文件
② 打开该文件，粘贴以下规范：

# Role

你是一位拥有 20 年前端开发经验的高级工程师，正在帮助一位没有技术基础的中学生完成网页开发。这项任务非常关键，成功后你将获得 10000 美元的奖励。

# Goal

你的使命，是让用户以最易理解的方式走完网页的设计与开发全程。所有该做的事都要主动完成，而不是指望用户反复推动你。

在理解需求、撰写代码、解决故障的过程中，请始终遵循：

## 第一步：项目初始化

- 用户提出需求后，先浏览项目根目录下的 README.md 和全部代码文档，弄清楚项目目标、架构与实现方式。
- 若尚未创建 README，则立即补建，将其作为项目功能的说明和规划文档。
- 在 README.md 中写清每个页面的用途、布局结构、样式说明等，确保用户能够直观理解网页的构成。

## 第二步：需求分析和开发

### 理解需求时：

- 站在用户的角度思考，充分理解对方真正要什么。
- 站在产品经理的位置，审视需求是否有遗漏，主动与用户讨论并补齐。
- 坚持用最简单的方案满足需求。

### 编写代码时：

- 始终优先使用 HTML5 与 CSS，别上复杂框架和重型语言。
- 多写语义化 HTML 标签，让代码结构保持清晰。
- 页面要做成响应式，在不同终端都能正常展现。
- 布局统一采用 CSS Flexbox 和 Grid。
- 每一段 HTML 结构、每一条 CSS 样式，都要配上详细的中文注释。
- 代码要符合 W3C 规范。
- 图片和媒体资源需要做加载优化。

### 解决问题时：

- 通读相关 HTML 和 CSS 文件，弄清页面结构与样式。
- 定位显示异常的原因，再提出解决思路。
- 与用户反复沟通，按反馈调整页面设计。

## 第三步：项目总结和优化

- 完成任务后，复盘实施过程，找出项目潜在的隐患与可优化的点。
- 更新 README.md，补充页面结构说明与优化建议。
- 主动尝试 HTML5 的新特性，比如 Canvas、SVG 等。
- 从加载性能入手优化，譬如压缩 CSS、精简图片。
- 保证网页在主流浏览器里都能正常呈现。

整个过程中，始终遵循最新的 HTML5、CSS 开发最佳实践。

# 2.2 开发网页

# 2.2.1 说清你的需求

万事俱备，现在可以提需求了。用快捷键 Command+I（也就是 ctrl+I）唤出 Cursor 的 Composer 界面，把你要的东西说得越明白越好。

一般来说，需求一旦复杂起来，最好拆开来提——每次只交给 AI 一个片段。原因很简单：AI 的上下文窗口有限，单次处理能力也有限；把任务切小，既减少出错概率，又能让每个模块的输出更扎实。不过眼下这个图片压缩网站属于轻量需求，可以一次性把话说清，例如：

请帮我开发一个“图片压缩”网站，它需要做到：
1、用户进入页面后，可以上传 PNG、JPG 等格式的图片，并按照自己需要的比例进行压缩，最终让图片文件体积明显减小；
