## 关卡 3：把岗位拆成动作，串出 Agent 执行链路

### 00. 关卡目标与说明

**🎯目标：**把“岗位”拆成“步骤”，让 Agent 知道每一步具体怎么执行。

**🗒️任务简介：**

• 沿用关卡 2 的 Agent 岗位，本关不换题。

• 用 AI 对话帮你整理人工操作的全过程，形成步骤清单，经验判断也要保留。

• 给每一步标注输入、动作、输出，以及需要人确认的节点。

• 产出一版既便于人阅读、也能写入 Profile 的 Agent 作业链路。

**💡 本关作业：**串出作业链路，交付“链路卡片 + 流程图”。

**⭕️提交要求**：

• Agent 链路卡片截图（必填）：需要包含环节、验收标准、失败处置、人工接管说明。

• Agent 流程图截图（必填）。

• 说说本关最大的收获（选填）。

• 写写本关的卡点或拿不准的判断（选填）。

**💡 新手了解下：**

关卡 2 之后，Agent 已经清楚自己的职位和大致职责。

但人和 Agent 做同一件事，最大的差异在哪？

人会不自觉地做很多默认判断：你一眼就知道“这篇素材质量不行”“这位客户是比价的，少花时间”。Agent 没有这种直觉，所以每条判断都必须由你亲手写出来。

因此本关的核心任务，就是拆解动作——让它明确每一步怎么做。

先别去琢磨全自动的最优方案，优先把你平时做事的真实顺序写出来，尤其是那些“我一看就懂”的隐含经验。你讲不清，Agent 就更不可能做对。

我们仍然准备了演示样例，带你完整走一遍拆解流程，先把感觉建立起来。

**❗️要记住：演示样例只是辅助你学习流程、加深理解，不能作为最终成果提交。**

有了实感之后，再回到真实业务中，交付属于你自己的 Agent。

#### 第 2 步：把必须做决定的点圈出来

步骤拆完了，但这项工作还没有完成。

很多时候，你觉得自己只是顺着步骤走，实际上每一步都在做判断。Agent 后续能否稳定运行，很大程度上取决于这些判断有没有被还原。

所以这一步要往下继续挖：

• 为什么用这种方案，而不是另一种？

• 什么条件下走 A 路径，什么条件下走 B 路径？

• 你的判断依据是什么？

• 遇到意外情况怎么处理？

#### 第 3 步：用 RFC 2119 把经验转成 Agent 指令

前面两步已经把流程和决策依据理顺了。

现在，要把这些内容“翻译”成 Agent 实际能执行的指令。这里会采用一种行业里常见的规范——RFC 2119，用于标注要求的强度：

• MUST：**强制要做**；

• SHOULD：**建议要做**；

• MAY：**可选，做不做都行**；

• MUST NOT：**绝对不做**。

不用在这些英文术语上花心思，AI 会按这套规范帮你整理内容。

#### 第 6 步：不同类型 Agent 的侧重点

各类 Agent 的关注点有较大差别。你可以对照下面的列表，为自己的 Agent 补上合适的信息。

**6.1 文档型 Agent**

（内容创作、会议纪要、报告生成等）

• 输入素材的读取顺序与优先级；

• 输出格式、语气、篇幅等限制；

• 质检标准：事实核查、格式检查、关键信息是否遗漏；

• 引用出处、敏感信息的边界规则。

**6.2 表格型 Agent**

（数据整理、报表汇总、信息统计等）

• 字段之间的映射关系；

• 数据更新的策略：新增、覆盖或合并；

• 缺失值、重复值、异常值怎么办；

• 何种情况要告警或者请求人工确认。

**6.3 消息型 Agent**

（客服回复、通知推送、私聊助手等）

• 由什么事件触发执行；

• 回复边界：哪些问题能答，哪些不能答；

• 不同业务场景下的回复策略；

• 什么情况下必须暂停并转人工。

**6.4 流程自动化 Agent**

（审批、文件流转、多工具协作等）

• 每一步具体调用哪个工具；

• 工具失败后的重试办法；

• 上下游数据如何传递；

• 哪些环节要等结果，哪些可以并行执行；

• 中断后如何续跑。

每个 Agent 各有特点，也可能同时具备好几种类型的属性。没有一套规则能通用于所有场景。

比起一开始就追求面面俱到，更重要的是结合自己的业务，让作业链路在实践中不断生长。
