# Coze工作流实战：从响应体到飞书表格

```python
async def main(args: Args) -> Output:
    params = args.params
    body = params["body"]
    content = body["choices"][0]["message"]["content"]
    ret: Output = {"content": content}
    return ret
```
先看接口返回的骨架：最外层只有三块——业务主体 body、HTTP 状态码 statusCode、响应头 headers。body 是聊天补全结果，里面记录请求 id、服务商 Google、模型 Claude Sonnet 4.5、对象类型 chat.completion、创建时间戳；choices 数组第一项 index 为 0，finish_reason 为 stop，message.role 是 assistant，message.content 才是最终笔记内容（这里保留原占位 [PRE1]），包含标题、正文和标签；usage 则统计 token：输入 1041、输出 457、合计 1498。statusCode 为 200，说明请求成功；headers 则是 Cloudflare CDN、缓存状态、安全策略、内容类型、跨域允许、Cf-Ray 请求标识、日期、权限策略、引用策略、Vary、X-Content-Type-Options 等传输层信息。三者的关系很清楚：body 承载业务数据，statusCode 表示请求结果，headers 负责传输元数据。整份响应来自 AI 内容生成服务，用途是把原始标题转成📕笔记格式。

[PRE2]
**响应体拆解**
下面把 body 再拆一层：元数据层负责 id、provider、model、object、created；choices 是生成结果数组，第一项里的 message.content 就是实际产出；usage 是资源消耗统计。换句话说，真正要取的内容不在最外层，而在 `choices[0].message.content` 里。

[PRE3]
接下来是在 Coze 里加代码节点：入参是 body，出参是 content。示例骨架里就是用 `args.params` 拿参数、用 `ret` 返回结果，可参考下面这段：

[PRE4]
```python
async def main(args: Args) -> Output:
    params = args.params
    body = params["body"]
    content = body["choices"][0]["message"]["content"]
    ret: Output = {"content": content}
    return ret
```

上面的路径是固定的：body → choices[0] → message → content。代码里的变量名要和节点输入变量名一致，否则取不到值。输出 content 就是 AI 生成的实际内容，也就是包含📕笔记的 JSON 字符串。

[PRE5]
配置时有个容易踩的点：代码节点输入通常能解析上一节点输出 JSON 的第一层，也就是拿到 body；body 要以 `{}` 对象格式传入。测试运行时别打开 JSON 模式，粘贴内容用 JSON 格式；因为输入只能选 object 对象格式，系统会自动把 JSON 转成对象，这样运行结果那边才能识别输入。

[PRE6][PRE7][PRE8]
输出侧也一样：节点输出配置和代码里的输出不是自动一回事。先看代码实际返回什么，再回头调整节点输出配置；代码变量名和输出配置里的变量名要对上，变量类型也要和实际类型一致，才会被识别为节点输出。

### 3.常见问题的 FAQ：

Q1：工作流里运行正常，到了多维表格调用却报错：`Unexpected token 核 in JSON at position 638`。这通常是因为多维表格把输入参数按 JSON 格式传给扣子；为了让 JSON 不被破坏，输入内容里的 `{`、`"` 等符号需要转义，可以让 AI 帮你处理。

Q1：RPA 下载图片到本地文件夹时，注意 `/` 符号会影响文件夹路径。

Q1：RPA 网页元素校验没问题、单条指令测试也能跑，但整体运行找不到元素。先看界面是不是刚发生过跳转，如果是，需要重新获取 `web_page` 对象。
