**1.2 用五个维度筛选**

把候选任务依次放入以下五个问题中检验，每满足一项计 1 分：

1. **它是否每隔一段时间就卷土重来？**每周、每个项目、每次活动里都会占用时间，属于常态性投入。

2. **它收到的输入是否稳定、清晰？**提交上来的材料基本锁定在聊天记录、文档、网页或表格里，不会每次花样百出。

3. **执行流程与判定准则是否明确？**常态下都有可以照搬的步骤和标准，不必临时构思对策。

4. **最终产物是否透明、方便核验？**完成情况如何、做得对不对，能靠文档、表格、消息或链接直接确认。

5. **出了岔子能否人工接管？**Agent 交付后，你还有机会在发送、发布或对外提供之前过目，即使有疏漏也不会立刻造成严重后果。

**计分结果**：拿到 4 分及以上，非常值得作为 Agent 化的第一候选；介于 2 到 3 分，可以先化简环节、补充细则，或安排人工复核；不足 1 分，则建议放进“不做清单”，暂不优先处理。

**1.5 保存本关成果物**

接下来每一关都要在这份岗位卡的基础上继续深化，所以建议你在本地建一个专属文件夹，用来存放这个 Agent 的资料。

**虽然用 Codex 搭 Agent 时**，它会顺带生成项目及各类文件。单独再立一个项目文件夹，并不是因为 Codex 不留存档，而是为了后续复习、提交作业和长期打理都更方便，也让开发脉络更一目了然。

• **交作业轻松**：之后每关的产物都能从该文件夹里直接寻到；

• **迭代顺畅**：调整岗位、优化流程、完善 Profile 时，不用反复查找聊天内容；

• **集中管理**：岗位卡、工作流、Profile、测试记录等一律放在同一处，不会散落丢失；

• **便于长期打理**：随着 Agent 不断成长，这里就是它的完整成长档案。

### 03. 本关常见卡点

遇到障碍先别急着**撒手，先去问问 AI**。本环节**推荐优先借助 Codex 或 WorkBuddy**：把错误提示、屏幕截图或你的诉求另起一个对话窗口发过去，让 AI 判断成因、排除故障，甚至替你解决。

[PRE13]

逐渐养成“先求助 AI，再询问旁人”的行为方式，多数难题都能顺手化解。

| 常见卡点 | 默认动作 | 判断标准 |
| --- | --- | --- |
| 期望过高，想一口气构造“万能员工” | 细分为一个子岗位 | 7 天内能做出肉眼可见的结果 |
| 输入含糊，讲不清楚 | 先指定一种输入来源 | 你清楚 Agent 第一步从哪里拿数据 |
| 输出难以验收 | 调整为文档、表格、消息等可视化结果 | 能够截图、能够复查 |
| 不确定选什么场景 | 默认走内容生产 Agent | 先完整跑一轮，再做自己的方向 |

| 你卡住的情况 | 直接对 AI 说 |
| --- | --- |

### 04. 本关小结

**所谓 Agent 岗位卡，就是把“跑得通的 Demo”升级成“职责讲得清的 AI 员工”。**

第 1 关你已经见识过 Agent 完成一项看得见的任务；这关的意义，是把这份直接体感沉淀进自己的真实工作里：先找出反复出现的活儿，再判断哪项可以交给 Agent，最终写成一张职责分明的岗位卡。

第一个正式 Agent 应该从一个较小的岗位切入：任务经常出现、输入源头具体、处理步骤能说明白、产出便于验收，且出错时允许人工介入。

**四个关键动作：**

1. **整理重复事务**：先通过 AI 对话，把每日、每周以及被动触发的重复事项汇成一份候选池。

2. **五维评估筛选**：AI 先作初筛，频率、输入、规则、验收方式和风险边界由你最后拍板。

3. **明确一句话定义**：用“收到什么输入、自动执行什么操作、结果落到什么地方”把职责讲清楚。
