# 7.2.4 应用内活动推广

# 7.2.4.1 应用内活动的定义与价值

1.

核心概念

应用内活动是应用和游戏里的「时效性活动」，例如游戏竞赛、新电影首映、直播体验等。苹果明确要求活动具备「重大性」和「时效性」，常规任务或重复性活动（比如日常签到奖励）并不适用。

2.

核心价值

免费曝光入口：活动卡片可出现在 App Store 的搜索结果、「Today」标签、编辑精选和个性化推荐中，既覆盖已下载用户，也触达潜在用户。

用户召回与促活：通过活动深层链接，用户点击后可直接跳转到 App 内指定位置，从而唤醒沉默用户。

提升转化率：活动徽章（如「挑战」「比赛」）和视频素材能增强吸引力，引导用户参与付费或留存。

# 7.2.4.2 活动展示位置与用户触达

1.

展示位置

App 详情页：在产品页集中展示所有已发布活动。

搜索结果：用户搜索 App 时，已下载用户能看到活动卡片；未下载用户能看到相关截图。

推荐位：在「Today」「游戏」「应用」标签的编辑精选和个性化推荐中获得曝光。

2.

用户触达逻辑

已下载用户：直接在 App Store 内收到活动通知，点击后跳转到 App 内活动页面。

未下载用户：搜索活动关键词时，可通过活动卡片下载 App，并直达活动入口。

填写活动相关信息

填写活动名称（30 字符以内）：需包含关键词以匹配搜索，例如「春节限时挑战」。

活动简短描述（50 字符以内）：突出核心卖点，如「赢取限定皮肤」。

活动详细描述（120 字符以内）：说明奖励机制和参与方式，如「连续登录 7 天解锁永久称号」。

选择活动徽章：会显示在 App 内活动卡片和活动详细信息页面的标题上方。

主要更新：例如推出新的游戏模式或级别。

新一季：介绍新内容、故事情节或媒体库。

设置深层链接：开发者可以创建一个链接，让活动与 App 内某个位置直接关联；用户点击卡片后会跳转到指定位置。若前期觉得麻烦，也可以先做一个只跳转到主页的链接。

媒体素材：图片或视频均可，视频会自动循环播放。

2.

点击提交审核，等待最终提交至 App 审核，1-2 个工作日内会反馈结果，审核重点包括活动新颖性和元数据合规性。

# 第三步：发布与管理

发布数量限制：同一时间最多可有 10 个已批准活动，但仅 5 个能在产品页展示。

活动管理：审核通过后，仅能修改地区、时间和优先级；删除活动后将无法恢复。

# 7.2.4.4 创建注意事项

为确保 App 内活动顺利过审并取得良好展示效果，创建元数据时需注意：

1.

准确描述活动内容，避免使用「最佳」「第一」等模糊主观说法，以及「游戏内容」等冗余用词；同时避免全部使用大写字母或过多标点符号。

2.

使用风格统一且有视觉冲击力的素材：

可使用少于 30 秒的视频，提供生动的活动预览。

建议使用相似的颜色或插图样式，不要给媒体素材添加边框或渐变效果。

尽量避免在媒体素材中使用文本或标志，尤其是包含活动名称或 App 名称时。

3.

不要提及价格；元数据中包含具体价格，提审可能被拒。

4.

确保元数据中只包含由开发者创建或拥有使用许可的内容。

# 7.2.4.5 管理细则

1.

修改活动：在「App 内活动」提交审核前，可在 App Store Connect 后台修改活动的全部详细信息，修改后点击「存储」或「添加以供审核」。活动通过审核后，只能编辑供应国家或地区、活动优先级，以及开始、结束、发布开始的日期和时间；并且这些日期时间的修改必须在原定时间尚未到来前完成。

2.

删除活动：当活动处于「草稿」「已归档」或「已批准」状态时可以删除；删除后活动会从列表中移除，无法再查看。

3.

数据监控：开发者可在 App Store Connect 的「App 分析」中了解已发布 App 内活动的效果，查看下载数据、用户获取来源、各类参与度数据，以及用户是否选择通知等，从而掌握活动情况。

# 7.2.4.6 提审被拒常见原因

1.

活动不够「特殊」，没有引入新内容。App 内活动不适用于重复活动（如日常任务或奖励），也不适用于未引入新内容、新功能、新商品的价格促销。创建时最好引入新内容，例如新功能上线、为节日特别策划的活动、新的商品促销等。

2.

元数据引用价格相关信息。App Store 审核条款 2.3.7 适用于「App 内活动」的元数据审核，元数据中不得包含具体价格，否则会被审核团队拒绝。

3.

活动图片素材中使用过多文字，可能导致提审被拒，创建时应避免过多文字。

4.

选择了错误的活动类型，例如宣传新功能时误选「挑战」类型等。

# 7.3.2 评论管理与差评处理

# 7.3.2.1 应用内触发时机设计

# 7.3.2.1.1 核心原则

在用户体验峰值或参与度较高的阶段请求评论，以降低抵触心理。

# 7.3.2.1.2 黄金时刻触发

选择用户对产品价值感知最强的节点弹出评论请求：

触发条件：

用户完成核心功能 ≥3 次（如健身 App 完成 3 次训练、笔记 App 创建 3 篇笔记）

审核注意事项：建议在开发阶段设置「评论请求开关」，通过苹果审核后再启用，避免触发「操纵评分」风险。

在应用内提供长期可访问的评论入口，满足主动反馈意愿的用户：

文案：

Got feedback? We read every message. → 点击后跳转 App Store 评论页

# 8.1 订阅功能设计

# 8.1.1 核心功能规划

订阅功能的设计，是提高付费转化率、降低退费率和提升续费率的关键因素之一。下面三种设计方式及案例可供参考：

# 模式一：去广告作为付费用户的福利

把去广告做成付费会员的核心福利，是常见设计方式。免费用户使用产品时会受广告干扰，而付费会员可享受无广告体验，通过提升使用体验促进付费转化。

案例分析：Spotify 作为知名音乐流媒体应用，免费用户播放音乐时会插入广告，付费会员则享受无广告的流畅体验。这一设计吸引大量用户为无干扰的音乐体验付费，显著提高了付费转化率。

# 模式二：基础功能 + VIP 功能

免费用户使用产品基础功能，高级功能需付费解锁，通过差异化功能吸引用户为独特价值付费。

案例分析：Duolingo 是语言学习应用，免费用户可使用基础课程，但若想获得个性化学习计划和无广告体验，则需成为付费会员。该设计因满足用户对高效学习的需求，推动了付费转化。

# 模式三：次数限制

对免费用户设置使用次数或频率限制，付费会员享受无限制服务，通过制造稀缺性促进付费。

案例分析：Headspace 作为冥想应用，免费用户每天仅能进行 1 次练习，付费会员则可无限次使用。这种限制促使许多用户为获取更多练习机会而付费。

# 8.1.2 订阅配置策略

海外市场订阅模型配置需结合用户习惯、经济水平和竞争环境，以下为具体策略：

# 付费策略一：订阅周期和价格

海外主流订阅周期为周、月、年：

短周期低价：降低用户心理门槛，提升初始付费率，但需依赖产品持续价值维持续费率；

长周期高价：带来短期高收益，但需警惕因用户体验不足导致的高退费率。

建议：初期参考竞品定价，后期结合用户反馈动态调整。

# 付费策略二：新用户优惠套餐

早期策略：以免费试用为主（如 Netflix 提供 30 天免费试用），帮助用户熟悉服务；

当前趋势：首周 / 首月 / 首年优惠价（如 Spotify Premium 首月折扣），减少「薅羊毛」现象，平衡拉新与盈利。

# 付费策略三：老用户促销策略

针对已取消订阅的老用户推出定向优惠，激活潜在市场：

提供低价 SKU 或延长免费试用期，吸引用户重新体验；

发送个性化折扣码（如 Apple Music 向老用户推送专属优惠），提升复购意愿。
