提醒一句：清单不是填空表。把AI调到“顾问模式”，它会沿着你的回答继续深挖，把细节逐一确认。

**为何要让AI先发问？**

默认AI是“你问它答”。你的问法会限定它的输出范围。方向错了，它会在错误框架里给你一份看着完整、实际难用的方案。

把发问权交给AI，局面就反过来了。原因有三：

- **新手对老手**：你第一次提，它训练数据里见过大量类似情形，熟悉坑和关键决策点。
- **经验在被问时激活**：你问它答时，它的经验沉默；让它发问，它才会按经验追出你容易漏掉的点，比如“哪类内容数据最好？”
- **追问能勾出隐性信息**：每个问题像探针，把你脑中已有却未整理的想法抽出来。很多诉求不是你不知道，而是没想到要说。比如它问“灵感从哪来”，你才意识到“平时刷笔记顺手记”——这会影响Agent的输入源。

第三步：与AI对话，借追问把核心维度定清。

它发问后，你如实答。追问方向通常覆盖做Agent绕不开的五个方面，聊着聊着就定义好了：

1. 痛点：到底解决什么，避免白忙。
2. 最小范围：先做哪一段最值，确保能完成。
3. 输入：要哪些信息、从哪来，别让它空转。
4. 流程：中间经过哪些环节，保证逻辑不断。
5. 输出：结果落在哪、长什么样，确保可用。

也就是说，聊需求就是在设计Agent。拆诉求的同时，搭建所需的关键信息也被问出来了。

输入输出、流程、输出位置这些，不是额外要补的课，会在对话和拆解中自然浮现。诉求拆得够细，这些自然齐。

聊到这里，新手常犯怵：“然后呢？技术细节我不会。”

记住：

技术不用你扛。

- 你是产品经理/老板，产出是一份清晰的需求定义，即上面五方面。
- AI是技术专家/员工，负责把你的定义翻成可执行方案，并生成Agent。

聊得差不多时，让AI把方案收敛到最小，再让它开发Agent。

AI会结合完整聊天记录理解意图，给出含工具、步骤、配置方法的方案。输入输出、流程等技术实现，由AI按你的描述自动完成，不用你另学。

**路径概括：AI发问确认诉求 → 梳理核心维度 → 产出Demo → AI生成Agent。**

第四步：收敛成最小Demo

聊完可能得到一堆功能点，别全做——功能越多，Agent越容易卡。

必须做减法：砍到只剩最核心的一条链路，先跑通。

这就是“最小Demo”：不是最终产品，而是能验证想法、可运行的最简版本。像盖房先搭一间能住的小屋，确认地基稳了再加层。

到这一步，你用的就是Harness思路：先让AI帮你发散，再把发散结果收敛成可执行的东西。

先让AI把模糊想法问透，再收敛成一份最小可用Demo的图纸。发散为了打破盲区，收敛为了落地——这就是Harness思路在Agent搭建中的应用。

第五步：生成Agent

把Demo交给AI（如Codex/Coze）去做，这是关键认知转变：你不需要亲手写一行代码。

拿到Demo后，只需三步：

1. 打开AI编程工具（如Codex、Coze、Claude等）。
2. 把“最小Demo定义”文档丢给它。
3. 给出明确指令：“请根据这份需求文档，帮我搭建/实现这个Agent。请生成完整的代码/配置/工作流。”

AI编程工具会理解需求，自动生成代码、配置技能（Skill）、串联工作流，把Agent做出来。你可能要与它调试微调几轮，但核心生产力是它，不是你。

## 2.3 Agent和Skill的关系（拓展内容）

后面章节会反复出现Skill和Agent。它们相似，但不是一回事。先说清，后面不绕。

**Skill = 单一能力**

比如“把今天的日报总结成结构化要点”，这是一个Skill。它只做一件事，做得稳定，可反复调用。可把Skill理解成“专项技能”：分析日报是一个Skill，提取小红书爆款标题是一个Skill，把网页正文转成Markdown也是一个Skill。

**Agent = 把多个Skill串起来自动跑的“员工”**

比如：每天定时读取日报.txt → 调用“日报分析”Skill → 结果写入汇总文档 → 同步到飞书。整条链路不用点“继续”，它自己从头跑到尾。

在接下来的日报案例中，两者约90%重合——一个Skill自己也能“分析总结”。

Agent多出的10%，恰恰关键：

- 自动输入：自己读文件/抓网页/拉数据，不用手动喂。
- 自动触发：定时跑、监听变化跑，不用每次点开。
- 多步联动：上一步结果自动接到下一步，跨工具跨平台串成流水线。

先有Skill，再有Agent，这是做智能体最自然的顺序。
