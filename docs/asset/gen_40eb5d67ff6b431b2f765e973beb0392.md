# 7.2.4 ChatGPT写文的三条心得

心得一：从构思到发布，一篇大约花 1～2 小时。主要原因是 GPT-4 速度偏慢，最好别在晚上写，夜间不仅比白天慢不少，还常遇到网络问题。

心得二：按这套方法调教好 ChatGPT 后，大约生成 5 篇文章，就建议重新调教一遍。根据 GPT-4 API 的输入限制推测，它的对话大约能记住 25000 个 token 的上下文。token 和字数的换算没有统一说法，通常认为 1000 个 token 约等于 750 个英文单词，或者 400～500 个汉字。5 篇文章加上调教内容，一般接近 10000 字；再继续写，ChatGPT 可能就忘了最初调教的内容。所以建议一定用 GPT-4。GPT-3.5 能记住的上下文是 4096 个 token，差不多写一篇就要调教一次。

心得三：用 GPT-3.5 的话，一定要多调教。它不太能记住上下文，逻辑性也弱，容易出现上文不接下文，甚至胡言乱语。有条件就用 GPT-4；相比 3.5，它能记住上下文，也更有逻辑和人情味，相当于帮我们多走了一步。

# 第二步：把文章自动发到👸号

上一步生成的文章会保存在文件里。接着用 RPA 操作👸号完成自动发布，流程如下：

1. 登录👸号后台。用 RPA 打开网址，通过账号密码自动登录。
2. 新建图文并粘贴文章内容。可以把文章放进指定目录，让 RPA 读取后自动粘贴到新建的图文消息中。

4. 扫码发布。最后一步需要管理员手机扫码，只能人工操作。好像可以在👸号“安全中心”关闭扫码，这样就能实现全自动发布。

# 7.3.2 批量化的两个坑

批量操作过程中有两个重要问题：

1. 故事大纲从哪里来。假如操作 100 个👸号，每个号每天发一篇，就需要 100 个故事大纲，人工写几乎不太可能。
2. 文章质量差。ChatGPT 直接生成的文章质量还不太行，会有一些重复啰唆的内容，需要人工修改。
