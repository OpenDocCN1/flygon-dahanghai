# 一、这次航海：目标与打法

# 章节速览：

这一章先把航行目标讲清楚：

大约三周时间，让零基础的人完成第一款 iOS App 的上线，并尝试用付费下载或订阅方式获得收入。

为什么选 iOS 应用市场？原因很实在：审核效率高、用户更愿意掏钱、备案环节相对少、成本也比较可控。

而人工智能带来的最大便利，是即使完全不懂编程，也能明显压缩开发周期，

把时间留给理解用户需求和打磨产品设计。

实操时更适合小步推进、按模块拆解，并采用“AI+人工”的配合方式。

工具只是工具，关键判断仍要由人来做。

# 1.1 三周目标

基础目标：用大约 21 天，从零基础走到首个 iOS App 上线。

进阶目标：跑通付费下载 / 订阅的初步变现路径，拿到第一笔 App 收入。

# 1.2 为什么选 iOS App 这条路线？

# 1.2.1 选 iOS 赛道的优势：

审核流程相对简单，速度也快；上架后可面向全球分发，对个人开发者比较友好

用户付费习惯更成熟，加上 iOS 生态完善，订阅、内购、付费下载都能做

多数 App 上架时不必处理 ICP 备案、App 备案，也不需要软著（安卓上架通常要，200-300/张，周期 3-4 周）

开发者一年只交 99 美金（688 元），上架数量越多，边际成本越低

存在一定硬件门槛：需要 Mac、iPhone，以及 99 美元/年的开发者年费

开发阶段不用安装复杂环境和依赖

# 1.3 为什么借助人工智能？

即使一行代码都不会，也能靠 AI 做出 iOS App

学习门槛被拉低，精力可以更多放在用户需求、功能设计和产品思路上

开发周期明显缩短，快的时候 2-3 小时就能做出 demo，拿去市场验证想法

# 1.4 总体打法

小步迭代：先做最小可用版本（MVP），不追求一上来就大而全。

分模块开发：功能复杂后，拆成多个 Composer/Chat，一块块实现。

AI+人工结合：不要盲从 AI，关键逻辑和 bug 修复仍要自己测试、判断和复盘。

# 2.1 域名服务器准备

如果想让 iOS APP 具备前端+后端+数据库管理能力，就要额外准备域名和服务器；域名还需完成 ICP 备案，才能访问国内服务器（香港、新加坡等海外服务器不用 ICP 备案）。不同地区要求不同，备案时间也不确定：快的一周内，慢的可能 2-3 周。

海外与国内服务器的差别：

（1）海外服务器：同等配置通常更贵。比如阿里云/腾讯云国内服务器有新用户优惠，99 元/年左右就能买到同等配置、价格约 2000-3000 元的香港云服务器。

（2）国内服务器：域名必须 ICP 备案才能访问，海外服务器则不用。若只做前端+后端+数据库，国内服务器性价比更高。

# 2.1.1 域名注册

（1）在阿里云 / 腾讯云注册。com、.cn 价格 30-55 元/年，其它后缀 10 元左右

（2）如果只用于 iOS APP 前端+后端+数据库访问，后缀选什么都可以

# 2.1.2 域名 ICP 备案注意事项

备案流程：阿里云 / 腾讯云都有入口，按网页提示提交资料，个人也能独立完成。

（1）个人备案时要填网站类型和备注，建议写“个人学习使用，用于建设个人网站，记录工作和生活”，不要涉及商业用途。

（2）个人备案后，若域名被用于明显商业用途，比如搭建海外站点且无需登录就能看到完整内容，备案可能被服务商强制注销。若确有这类用途，建议用个体 / 企业执照备案。

（3）备案最好在购买服务器的服务商处操作，因为备案需要备案号，买服务器一般会送 2 个；没有的话可到淘宝搜“阿里云 icp 备”，10 元左右买一个填上。

（4）提交备案后，24 小时内注意接听服务商电话，对方会核实个人信息，有问题也会驳回并给修改建议。

# 2.4 心态预期

# 2.4.1 AI 能降低门槛，但不等于没有门槛

如果你不懂编程、觉得学代码很难，完全可以在一行代码都不会的情况下，靠 AI 做出人生第一个 iOS App。但过程中可能会遇到下面这些困难，这也是我在开发 iOS App 时踩过的坑：

1.

英文基础偏弱，看不懂 Xcode、Apple 开发者后台的界面，前期只能靠截图翻译、沉浸式翻译插件来熟悉操作

2.

iOS App 开发和 web 开发不太一样。虽然不用安装运行环境和依赖，但也很难像 web 开发那样，靠一两句提示词就迅速做出应用。多数时间都在处理编译报错，要靠多轮对话逐步实现。

3.

尽量不要一开始就做复杂应用，最好循序渐进。我曾不下六七次尝试开发玄学类应用，但其中一些业务逻辑过于复杂，AI 也不能很好理解业务场景；靠 AI 写四五千行代码，也很难有效实现核心功能。所以开发是从简到难、逐步深入的过程。

# 2.4.2 开发中的大小 bug、构建报错一定会有

过了编译报错只是第一关，只能说明应用可以装到手机上，并不代表开发结束。因为即使编译成功，应用功能也未必能正常运行，仍要不断调试。调试时可能遇到“控制台报错、内存泄漏、运行线程报错、代码警告”等多种问题。

所以，App 开发中的测试和调试非常耗时。一个版本经历几十次打包编译有时也很正常。1-2 小时不是做不出 iOS App，只是很难做出成熟、功能完整的产品。开发时间上别过度追求速度，好产品即使有 AI 辅助，也需要好事多磨。
