# Prompt 调优：先把范围说清，再反复打磨

想让 AI 输出更靠谱，先帮它把注意力框在正确范围内。背景、上下文、目标交代得越明白，它偏离方向的可能性就越低。

还有一条要牢记：Prompt 很难一次成型。首轮结果不理想很正常，别急着放弃。先拆问题——是重点理解偏了？语气风格不合？还是关键信息没给到？定位之后再去改 Prompt：缺的细节补上，指令尽量具体，角色和格式可以换，约束条件能加就加，示例也可以多给几个。有时只需动一个动词、形容词，或者重新排一下语序，效果就会明显不同。

常见坑也要避开：
- 写得太笼统，比如“帮我写个文案”，AI 根本不知道从哪下手；
- 塞进太多无关内容，真正的任务反而被淹没；
- 默认 AI 知道你没提供的信息，比如让它分析一份你压根没上传的文档；
- 一口气提太多要求，像“分析报告、写总结、再翻成法语”这种，最好拆成几步；
- 试一次不满意就收手，不做迭代。

练手时从简单任务起步：
- 基础题：用大白话给普通成年人讲清“区块链”；
- 加格式：列出 5 条提升个人效率的建议，每条不超过 20 字；
- 角色扮演：以资深旅行规划师身份，安排 3 天北京文化行程，包含故宫和长城，并给出每日安排与交通建议；
- 迭代题：让 AI 写一首关于“猫”的诗，首版不满意就继续调——是五言绝句还是现代诗？情绪要欢快还是慵懒？要不要放进毛线球、阳光这类意象？

归根结底，Prompt 工程就两件事：讲明白，持续改。你是在引导一位能力很强的助手，引导得越精准，结果越贴近预期。从明确任务、补充上下文、结构化表达、指定格式开始，勇于多轮调整，你很快就能拿到与 AI 高效协作的钥匙。

# 3. 条件判断与循环控制

# 3.1 选择器节点
无论有没有编程基础，if-else 这个概念应该都听过。选择器节点就是流程里的 if-else，用来设计分支走向。在“添加节点”里进入“业务逻辑”，选中“选择器”。

[PRE10]

数据进入该节点后，会判断是否满足“如果”区域的条件；满足就走“如果”分支，不满足就走“否则”分支。每个分支可以配置多个判断条件，条件之间支持“且/或”关系。

[PRE11]

它还允许设置多个条件分支，拖拽分支条件配置面板即可调整优先级。

# 3.2 循环节点
循环节点用于反复执行一组任务，直到某个条件被满足。

[PRE12]

循环类型
循环节点的运行模式有三种：按数组遍历、按指定次数重复、无限循环。

使用数组循环
数组循环面向数组类型数据（array）。可以把它看成一个有序序列，对序列中每个元素执行相同步骤。典型场景：批量拿到某博主主页 50 条视频信息后，逐条获取作者昵称、点赞数、转发数、无水印视频链接和文案，这时让循环节点依次处理这 50 条数据即可。

在编程中，数组用于存储一系列元素。基础概念如下：
- item：元素，即数组中的单个数据，可以是数字、字符、字符串等。
- index：索引，表示元素在数组中的位置，从 0 开始计数。第一次循环 index 为 0，第二次为 1，第三次为 2，最后一次为 n-1，其中 n 是循环次数。
- 数组长度：数组中元素的数量。

以 nums = [10, 20, 30, 40, 50] 为例：
索引 0 对应元素 10；
索引 1 对应元素 20；
数组长度为 5。

使用数组循环时，需要指定循环数组。该参数只能引用上游节点输出，且必须是数组格式。执行时，循环次数由引用的数组长度决定。例如 [1,2,3,4,5] 长度为 5，循环就会跑 5 轮。如果引用了多个数组，则以最短数组的长度为准。

数组循环每一轮都会把当前元素赋给内置变量。这些内置变量只在循环节点内部可用。目前支持：
- item<string>：数组元素，即当前轮到的元素；
- index<integer>：数组索引，index+1 即当前循环轮次。

指定循环次数
指定循环次数模式适合批量、顺序处理数据的场景。需要设置循环次数，默认 10 次，可设为 1～1000 次；也支持引用上游节点的数值型输出。
若引用值大于 1000，则按 1000 处理；小于 1，则按 1 处理。

典型场景：想一次生成 2 条小红书文案，可以放两个大模型节点；但若要一次输出 20 条，不必复制 20 个大模型节点，把循环次数设为 20 即可。

无限循环
无限循环类似编程语言中的 while 语法，需要靠终止循环节点来停下。第一轮运行后，流程会检查指定条件，满足则结束循环，否则继续下一轮。

终止循环节点通常与条件判断节点配合：条件判断节点发现某个条件成立时，流转到终止循环节点，自动跳出循环。

举例：通过自定义插件调用 API，先创建文本转语音任务，然后反复查询任务状态，一旦执行成功就停止循环。

[PRE13]

配置循环节点
多轮循环严格串行，不支持并发。每轮迭代完成后，才能启动下一轮。若某些节点需要并行执行，可使用批处理。

循环节点不支持嵌套：循环节点里不能再放另一个循环节点，但可以嵌套一个包含循环节点的工作流。
循环节点中也不允许添加批处理节点。

设置中间变量
循环节点支持设置中间变量，该变量可作用于每一次循环。中间变量通常和循环体中的设置变量节点搭配：每轮结束后为中间变量设新值，下一轮继续使用。

例如长文生成场景：通过中间变量把每轮段落总结传到下一轮，让大模型参考前文内容和下一段主题，生成上下文衔接更自然的段落。

配置如下：
- 循环节点：设置中间变量 last_paragraph，初始值填一个空格。首轮生成开头段时不需要参考大纲外内容，因此给空格即可，也可按需改成其他值。
- 循环体中的设置变量节点：中间变量选择循环节点中设置的 last_paragraph；设置值选择大模型节点的输出参数 output，表示下次循环开始前，把本轮生成的段落赋给循环变量。
- 循环体中的大模型节点：添加两个输入参数，分别引用循环节点的内置变量 item 和循环变量，并在提示词中要求生成文章段落时参考上一段内容。

注意：设置变量节点里，中间变量的数据类型必须与设置值的数据类型一致，否则无法赋值。

设置循环体
创建循环节点后，会生成一个循环节点和对应的循环体画布。

[PRE14]

循环体画布是循环节点的内部运行机制，用于编排循环流程。循环体只与循环节点相连，默认如此，无需设置。只有选中循环体时，才能向其中添加新节点，或把新节点拖入画布。循环体里的节点没有开始与结束，但需要和画布首尾蓝点图标连接。

[PRE15]

设置输出
循环节点的输出参数可以设为循环体执行结果集合：数组中所有元素跑完后，把所有循环结果打包传给下游。也支持设为循环变量的取值。

[PRE16]
