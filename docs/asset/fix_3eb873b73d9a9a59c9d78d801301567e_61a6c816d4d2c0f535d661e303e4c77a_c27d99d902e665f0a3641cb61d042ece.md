先理清基本盘：n8n 的流程由两块拼成——

触发节点 (Trigger Nodes)：整条线的入口，决定它何时、以何种方式启动。有且仅有一个。

动作节点 (Action Nodes)：入口被激活之后干活的部分，处理数据、发请求、调模型等，数量不限。

# 1. 触发器节点

Manual Trigger（手动触发）：最原始也最好理解的一种。开发调试时，你亲手按下 "Test workflow" 或 "Execute workflow"，流程立刻跑一遍。

[PRE2]

Schedule Trigger（定时任务）：给它一张时间表，到点自动开工——按分钟、按小时、按天、按周，或者指定某个日期时刻。底层靠 Cron 表达式驱动，这套时间语法相当灵活。

Webhook（网络钩子）：节点会吐出一个独有 URL，外界只要朝这个地址发起 HTTP 请求（多数是 POST），流程马上被唤醒，请求带过来的数据也一并收下。

[PRE3]

Email Trigger（邮件触发）：绑定一个邮箱（Gmail、Outlook 之类），收件箱一有新信，流程启动，发件人、标题、正文、附件都能读到。

PS：新版 n8n 里这个节点可能被合并或改名，比如改用 IMAP 节点实现，本质仍是盯着收件箱。

[PRE4]

On chat message（聊天对话框触发）：为聊天机器人量身定做。把 n8n 的 bot 挂到网站或应用后，用户在对话框里发出第一句话，它立刻响应，并把这句话抓下来。

[PRE5]

落地场景：几个高频节点的组合用法（强烈建议配合入门系列第一个流程一起练）

以聊天窗口触发为入口，就能拼出一个 n8n 版对话机器人。

整套只靠三个部件：On chat message、AI Agent、DeepSeek Chat Model。

配置 AI Agent 时，把 On chat message 输出里的 chatInput 填进 Prompt 位置。

AI Agent：它像一位调度员，本身不产出内容，而是统筹整段对话——收下 Prompt，按需调用一个或多个 Tools，再由底层大语言模型判断接下来做什么，最后把结果交出来。

[PRE6]

模型这边挑 DeepSeek Chat Model。

DeepSeek Chat Model 是一个具体的 LLM 节点：给它一段 Prompt，它借助 DeepSeek 的能力回你一段文字。

# 2. 动作节点（Action）

先看数据类：

触发端这次用 On form submission。

[PRE12]

[PRE13]

Set（原 Edit Fields）：日常用得最多的一类，增、改、删字段都是它。原始数据可以原样留着，同时另起新字段；也能就地替换某个字段的值，或者把多余的字段清掉。

示例里把「姓名」「年龄」两列改名为 name、age。

[PRE14]

[PRE15]

[PRE16]

Function/Code：用 JavaScript 或 Python 自己写逻辑。

当内置节点全都搞不定时，这个「万能口」就派上用场：直接敲代码，数据想怎么揉就怎么揉。

[PRE17]

[PRE18]

[PRE19]

Merge（合并）：把来自不同分支的多路数据汇成一路。

两种常见 Mode：Append 与 Combine。

Append：两路 item 首尾排好队输出——先吐 Input 1 的全部，再吐 Input 2 的全部，不做去重，也不做配对。

Combine：按你给的 key 字段，把两路里键值相同的 item 捏成一条；对不上的默认丢掉。

再看逻辑类：

IF：条件分流。

作用：按条件筛数据，本质上是个判断器，把不需要的内容挡在外面。

[PRE21]

Switch：多路分发。按条件把数据送往不同分支。

[PRE22]

Loop Over Items：循环。给每条数据重复执行同一套动作。

Wait：暂停。让流程停一段时间再往下走，适合那些受制于后端耗时的场合——控制 API 调用频率、等外部系统处理完、定时推送提醒。

[PRE23]

官方集成（热门那几个）：

HTTP Request：万用接口调用。凡是走 HTTP 协议的服务都能被它敲开。取第三方 API 数据、给 webhook 发通知、对接内部系统，都靠它。

Google Sheets：表格自动化。读、写、改表格数据，自动同步、生成报表、从表格反向触发流程、汇总收集，一条龙。

[PRE24]

Slack/Discord：团队消息。往频道里推消息——系统告警、任务完成提示、数据日报、流程状态通知。

[PRE25]

OpenAI/ChatGPT：AI 集成（gemini 节点）。调模型做文本处理或内容生成。
