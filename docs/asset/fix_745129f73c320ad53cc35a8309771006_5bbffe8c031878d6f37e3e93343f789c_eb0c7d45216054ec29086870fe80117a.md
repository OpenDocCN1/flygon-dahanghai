# 小红书链接自动写入飞书表格：工作流实操

先锁定工作流入口变量。在画布上单击最左侧的【开始】节点，右侧配置面板随即展开，找到【输入】区块按下【+】新增参数。接着把【变量名】填成 input，【变量类型】保持 str.String（字符串）不动。这样工作流的入口参数名就确定下来，后续所有环节都靠它取链接数据。确认后节点表面会显示 输入 str.input。特别提醒：input 这个名称后面会反复用到，别写成其他样子。

### 3.1.3 添加小红书提取插件节点

该节点负责拿到笔记详情。直接调用 Coze 官方封装好的插件，凭链接抓取小红书笔记的标题、正文等结构化信息，免去自己手写复杂 HTTP 请求代码的麻烦，是获取数据最省力的路子。

操作流程：在【开始】与【结束】两节点中间单击【+ 添加节点】按钮，弹出菜单里选择【插件】。

[PRE1]

在搜索框输入“小红书”，从结果中定位 xhs_note_detail_no_cookie 工具，单击其右侧的【添加】按钮，将它插入流程。

[PRE2]

随后在【插件】节点的输入配置中找到 url 参数，单击输入框右边的引用按钮，从 开始节点 下选中 input 变量。这一动作是在搭建数据传递桥梁——告诉插件该拿哪条小红书链接去抓取。直白地说：工作流接收到 input，插件就把它当成 url 去请求小红书。

[PRE3]

### 3.1.4 配置结束节点，仅保留标题与正文

结束节点承担筛选并输出核心数据的任务。插件抓回来的信息相当丰富（ID、时间、作者等都在其中），但我们大概率只需“标题”和“正文”。通过配置结束节点，就能从这堆数据里挑出这两项，再打包回传给飞书表格。

操作流程：单击画布最右侧的【结束】节点，确认它已正确接在小红书插件节点后面。在【输出变量】区域连点两次【+】，新增两个输出变量。

第一个变量名填 content，变量值引用 xhs_note_detail_no_cookie 节点下的 data.note_desc（笔记正文），把抓到的正文内容赋给输出变量。

第二个变量名填 title，变量值引用 xhs_note_detail_no_cookie 节点下的 data.note_display_title（笔记标题），把抓到的标题内容赋给输出变量。

配置完毕后，结束节点标签上会呈现：输出 str.content str.title。

### 3.1.5 试运行工作流并发布

这一步的目的是检验工作流能否正常运转。在对接飞书之前，先用一条真实的小红书链接把流程跑一遍，确认插件抓取正常、结束节点能正确吐出标题和正文，防止后续集成时冒出难以定位的故障。

验证流程：单击页面右上角的【试运行】，在弹窗的 input 输入框里粘贴一条真实有效的小红书笔记链接。

在电脑浏览器打开 xiaohongshu.com，扫码登录之后搜索“生财有术”，找到生财有术官方账号并点进去，选择置顶的那条笔记。笔记会在前端展示出来，这时浏览器地址栏里的地址就是小红书笔记链接。把这条链接复制下来，粘贴到输入框里。

[PRE7]

单击【运行】，稍等几秒，观察下方的【运行结果】。正常情况下 title 字段会显示笔记标题，content 字段会显示笔记的长文本正文。这就证明抓取和提取的整套逻辑运转正常，工作流配置成功。到此 Coze 工作流部分告一段落。

如果没能拿到结果，先排查三处：
第一，url 是否确实引用了开始节点的 input；
第二，可能是网络或接口波动，稍后重试；
第三，链接不纯，小红书分享链接经常带文字前缀，需要去掉（这一点很容易被忽略）。

[PRE8]

试运行通过后，千万别忘了单击右上角的【发布】按钮。工作流只有发布之后才能被外部引用。

### 3.2 多维表格引入字段捷径

#### 3.2.1 新建多维表格

这一步是在搭建数据交互界面。需要在飞书多维表格里造一个能直接唤起 Coze 工作流的“按钮”，让表格里输入链接后，系统自动触发后台 AI 流程并回填数据。

配置流程：在飞书云文档中新建一个多维表格，把第一列的列名改成 小红书笔记链接。这一列是给输入数据预留的位置，格式设置为文本。

#### 3.2.2 获取并配置 Coze 访问令牌

这一步是身份授权。飞书要想指挥 Coze 干活，必须亮出一张合法“通行证”。需要在 Coze 后台生成访问令牌并填进飞书，保证 API 调用请求不被拒绝。

配置流程：登录扣子开发平台，单击左侧菜单底部的 API 管理（也可以直接访问 coze.cn/open/playground）。在页面中选择“授权”，切换至顶部的 个人访问令牌 选项卡，单击右上角的 添加 按钮。

[PRE17]

在弹出的配置框里输入令牌名称（比如“123”），设置一个较长的过期时间，权限选择 全选 以确保存取无阻，访问空间建议选 所有工作空间。单击确认后，系统会弹出一个只显示一次的令牌字符串，务必单击复制并妥善保存。

[PRE18]

这时页面会显示你创建的个人访问令牌。该令牌只出现一次，记得单击复制按钮，保存到安全位置（如本地 txt 文档中）。

[PRE19]

回到飞书多维表格的字段配置界面，找到“扣子工作流调用”字段捷径的“认证令牌”输入框，把刚才复制的字符串粘贴进去。这一步是在验证飞书对 Coze 的访问权限。

[PRE20]

#### 3.2.3 获取并配置工作流 ID

这一步是定位目标任务。Coze 账号里可能存着多个工作流，需要准确告诉飞书具体运行哪一个。工作流 ID 就是这个任务的唯一身份证号码。

配置流程：回到 Coze 平台，打开刚才搭好的“小红书提取”工作流编辑页面，查看浏览器顶部地址栏，找到 workflow_id= 后面紧跟的那串数字（注意不要包含 & 符号后面的内容），复制这串数字。

回到飞书多维表格配置界面，把这个工作流 ID 填入“扣子工作流调用”字段捷径的“工作流 ID”中。这一步是在确定需要调用的具体扣子工作流。

[PRE21]

#### 3.2.4 配置参数字段与名称

这一步是建立数据映射。需要告诉系统：表格里的哪一列数据应该传给工作流里的哪个变量。

配置流程：在 参数字段 下拉菜单中，选择表格第一列 小红书笔记链接，指定数据的来源列。

在 参数名称 输入框中填入 input。注意：这里必须填 input，因为我们在 3.1.2 节配置 Coze 开始节点时定义的变量名就是 input。这一步是在确保表格发送的参数名与工作流接收的参数名完全一致，否则传输会失败。

#### 3.2.5 配置请求模板与输出结果

这一步是规范数据格式。API 接口要求数据必须以 JSON 格式传输，同时需要定义希望工作流返回哪些结果展示在表格中。

#### 2.2 需求来源

本项目的需求来自日常信息获取与管理中的实际痛点，主要集中在三个方面：

（1）收藏渠道分散，缺乏统一管理

现状：日常浏览的内容分散在微信公众号、小红书、生财有术等多个平台。

痛点：各平台的收藏夹相互独立，信息呈现碎片化，需要时难以快速检索和查阅，收藏的内容往往因此被遗忘。希望能聚合在一起，快速找到，最好还能分类收藏。

（2）收藏流程繁琐，移动端体验不佳

现状：看生财帖子时，在移动端看到优质内容，直接在原平台收藏，手机上打开看不方便；转发到微信文件传输助手等方式又不利于长久保存。

痛点：缺少一个跨平台、操作便捷的移动端统一入口，收藏过程耗时，体验割裂。

（3）长文阅读成本高，筛选效率低

现状：面对长篇干货文章，受时间或环境限制，往往无法一次读完，但又希望先了解核心内容，再决定是否深入阅读。

痛点：缺少辅助阅读工具，无法快速获取文章主旨，导致在低价值内容上浪费时间。

#### 2.3 需求分析

基于上述痛点，核心需求可以提炼为三点：

+ 快捷收藏：提供适配手机端的高效收藏方式，覆盖主要信息渠道。
+ 智能摘要：快速掌握文章主旨，辅助阅读决策，避免浪费时间。
+ 体系管理：建立文章分类体系，把收藏的文章分门别类，便于管理。

明确了真实需求，接下来的思路就很清晰：把需求拆解成具体功能，规划好流程，就可以落地。

（3）产品搭建原则

为了让这个方案既好用又长久，搭建过程遵守三条原则：

+ 成本效益原则：能省则省，优先用开源或免费工具，目标是实现零成本搭建和维护。

### 3 产品设计方案

#### 3.1 如何实现快捷收藏？

（1）手机端怎么快捷收藏？

绝大部分阅读场景都在手机上。经过探索，iPhone 自带的“快捷指令”不仅能自动化操作，还支持发送 HTTP 请求，可以把复杂的数据处理过程都放在后台，快捷指令只做上传和接收。

结论：利用 iOS 快捷指令作为入口，实现数据上传与结果展示。
