# 小红书链接自动写入飞书表格：工作流实操

先把入口参数定下来。打开画布最左侧【开始】节点，在右侧配置面板的【输入】区域点【+】添加参数。把【变量名】改为 input，【变量类型】保持 str.String（字符串）。这样工作流的入口参数名就确定了，后续环节都通过这个变量名取链接数据。确认后节点上会显示 输入 str.input。这里要记住：input 这个名字后面会反复出现，别写成其他名字。

### 3.1.3 接入小红书提取插件

这个节点用来获取笔记详情。我们直接调用 Coze 官方封装好的插件，用链接抓取小红书笔记的标题、正文等结构化数据，不用自己写复杂的 HTTP 请求代码，是获取数据最省事的方式。

操作如下：在【开始】节点和【结束】节点之间点【+ 添加节点】，在弹出的菜单里选【插件】。

[PRE1]

在搜索框输入“小红书”，从结果中找到 xhs_note_detail_no_cookie，点右侧【添加】按钮，把它插入流程。

[PRE2]

在【插件】节点的输入配置里找到 url 参数，点输入框右侧的引用按钮，选择 开始节点 下的 input 变量。这一步是在建立数据传递关系：告诉插件拿哪个小红书链接去抓取。换句话说，工作流收到 input，插件就把它当作 url 去请求小红书。

[PRE3]

### 3.1.4 配好结束节点，只留标题和正文

结束节点负责筛选并输出核心数据。插件抓回来的内容很多，包含 ID、时间、作者等，但我们可能只需要“标题”和“正文”。配置结束节点后，就能从杂乱数据中只提取这两项，打包返回给飞书表格。

操作：点画布最右侧的【结束】节点，确认它已经正确连接在小红书插件节点之后。在【输出变量】区域点两次【+】，添加两个输出变量。

第一个变量名设为 content，变量值引用 xhs_note_detail_no_cookie 节点下的 data.note_desc（笔记正文），把抓到的正文赋给输出变量。

第二个变量名设为 title，变量值引用 xhs_note_detail_no_cookie 节点下的 data.note_display_title（笔记标题），把抓到的标题赋给输出变量。

设置完成后，结束节点标签会显示：输出 str.content str.title。

### 3.1.5 试运行并发布工作流

这一步是测试工作流是否可用。连接飞书之前，先用一条真实的小红书链接跑一遍流程，确认插件能正常抓取数据、结束节点能正确输出标题和正文，避免后续集成时出现难排查的错误。

验证操作：点页面右上角【试运行】，在弹窗的 input 输入框里填入一条真实有效的小红书笔记链接。

在电脑浏览器访问 xiaohongshu.com，扫码登录后搜索“生财有术”，找到生财有术官方账号并进入，点置顶笔记。笔记会在前端显示，此时浏览器地址栏里的地址就是小红书笔记链接。复制这个链接，填入输入框。

[PRE7]

点【运行】，等几秒钟，查看下方【运行结果】。你应该能看到 title 字段显示笔记标题，content 字段显示笔记长文本正文。这说明整个抓取和提取逻辑运行正常，工作流配置成功。至此，Coze 工作流部分完成。

如果拿不到结果，先检查三点：
第一，url 是否正确引用了开始节点的 input；
第二，网络或接口问题，稍后重试；
第三，链接不是纯链接，小红书分享链接常带文字前缀，需要去除（这一点容易忽视）。

[PRE8]

试运行没问题后，一定要记得点右上角【发布】按钮。只有发布后的工作流才能被引用。

#### 3.2.2 获取并配置 Coze 访问令牌

这一步是身份授权。飞书想指挥 Coze 干活，必须出示一个合法“通行证”。我们需要在 Coze 后台生成访问令牌并填入飞书，确保 API 调用请求不会被拒绝。

配置操作：登录扣子开发平台，点左侧菜单底部的 API 管理（也可以直接访问 coze.cn/open/playground）。在页面中选择“授权”，切到顶部的 个人访问令牌 选项卡，点右上角 添加 按钮。

[PRE17]

在弹出的配置框里输入令牌名称（如“123”），设置一个较长的过期时间，权限选择 全选 以确保存取无阻，访问空间建议选 所有工作空间。点确认后，系统会弹出一个只显示一次的令牌字符串，务必点击复制并保存好。

[PRE18]

此时页面会显示你创建的个人访问令牌。这个令牌只出现一次，记得点复制按钮，保存到安全位置（如本地 txt 文档中）。

[PRE19]

回到飞书多维表格的字段配置界面，找到“扣子工作流调用”字段捷径的“认证令牌”输入框，把刚才复制的字符串粘贴进去。这一步验证飞书对 Coze 的访问权限。

[PRE20]

#### 3.2.3 获取并配置工作流 ID

这一步是定位目标任务。Coze 账号里可能有很多工作流，我们需要准确告诉飞书具体运行哪一个。工作流 ID 就是这个任务的唯一身份证号码。

配置操作：回到 Coze 平台，打开刚才搭好的“小红书提取”工作流编辑页面，查看浏览器顶部地址栏，找到 workflow_id= 后面紧跟的一串数字（注意不要包含 & 符号后面的内容），复制这串数字。

回到飞书多维表格配置界面，把这个工作流 ID 填入“扣子工作流调用”字段捷径的“工作流 ID”中。这一步是确定需要调用的具体扣子工作流。

[PRE21]

#### 3.2.4 配置参数字段与名称

这一步是建立数据映射。需要告诉系统：表格里的哪一列数据应该传给工作流里的哪个变量。

配置操作：在 参数字段 下拉菜单中，选择表格第一列 小红书笔记链接，指定数据来源列。

在 参数名称 输入框中填入 input。注意：这里必须填 input，因为我们在 3.1.2 节配置 Coze 开始节点时定义的变量名就是 input。这一步是确保表格发送的参数名与工作流接收的参数名完全一致，否则传输会失败。

#### 2.2 需求来源

本项目的需求来自日常信息获取与管理中的实际痛点，主要集中在三个方面：

（1）收藏渠道分散，缺乏统一管理

现状：日常浏览的内容分散在微信公众号、小红书、生财有术等多个平台。

痛点：各平台的收藏夹相互独立，信息呈现碎片化，需要时难以快速检索和查阅，收藏的内容往往因此被遗忘。希望能聚合在一起，快速找到，最好还能分类收藏。

（2）收藏流程繁琐，移动端体验不佳

现状：看生财帖子时，在移动端看到优质内容，直接在原平台收藏，手机上打开看不方便；转发到微信文件传输助手等方式又不利于长久保存。

痛点：缺少一个跨平台、操作便捷的移动端统一入口，收藏过程耗时，体验割裂。

（3）长文阅读成本高，筛选效率低

现状：面对长篇干货文章，受时间或环境限制，往往无法一次读完，但又希望先了解核心内容，再决定是否深入阅读。

痛点：缺少辅助阅读工具，无法快速获取文章主旨，导致在低价值内容上浪费时间。

#### 2.3 需求分析

基于上述痛点，核心需求可以提炼为三点：

+ 快捷收藏：提供适配手机端的高效收藏方式，覆盖主要信息渠道。
+ 智能摘要：快速掌握文章主旨，辅助阅读决策，避免浪费时间。
+ 体系管理：建立文章分类体系，把收藏的文章分门别类，便于管理。

明确了真实需求，接下来的思路就很清晰：把需求拆解成具体功能，规划好流程，就可以落地。

（3）产品搭建原则

为了让这个方案既好用又长久，搭建过程遵守三条原则：

+ 成本效益原则：能省则省，优先用开源或免费工具，目标是实现零成本搭建和维护。

#### 3.1 如何实现快捷收藏？

（1）手机端怎么快捷收藏？

绝大部分阅读场景都在手机上。经过探索，iPhone 自带的“快捷指令”不仅能自动化操作，还支持发送 HTTP 请求，可以把复杂的数据处理过程都放在后台，快捷指令只做上传和接收。

结论：利用 iOS 快捷指令作为入口，实现数据上传与结果展示。
