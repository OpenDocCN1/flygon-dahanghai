## 案例四 精准提取：键盘参数变 JSON

任务很明确：从产品详情里找出“连接模式”和“轴体参数”，整理成 JSON，两个 key 就定为“连接模式”“轴体参数”。

详情里的卖点不少，可以这样理解：

- 键盘上带一块小巧显示屏，能看 CPU/GPU 使用率与温度、网速与时间，也能显示趣味表情；支持动态编辑和自定义，配合自研驱动还能做更多个性化设置。
- RGB 全彩灯效可玩性高，驱动里能自定义动态光效，也能跟着音乐律动，灯光编程空间很大。
- 卫星轴用了镍合金记忆钢丝，主打 TO 手感，运输中钢丝弯曲的问题被重点解决，客制化玩家在意的痛点有回应。
- 机身和键帽走全透路线，纯净、清透、冷酷的极地风格。
- 97 键布局，设计精简，操作体验更顺。
- 连接方式有三类：2.4GHz 无线、蓝牙 5.1、有线；蓝牙下可多设备切换，支持 Windows、macOS、iOS、Android；侧面拨动 WIN/MAC 键就能切系统模式。
- 键帽是 PC 高透材质，光效完整透出，搭配北极元素，走可爱个性路线。
- 全键支持热插拔，DIY 自己的键盘很简单。
- COOLKILLER 冰刃轴段落感强，加长轴心带来提前触发，游戏和码字都兼顾；导通力度 45+10gf，触觉力度 60+10gf，总行程 3.30mm。

提取结果可以长这样：

    "导通力度": "45+10gf",
    "触觉力度": "60+10gf",
    "总行程": "3.30mm"
  }

## 2.3.3.15 影评快判：快速看清口碑

使用场景很直接：豆瓣上同一部电影的长评很多，想快速知道风向，就让模型逐条判断“好评”“中评”“差评”，再给 20 字以内的重点原因，并标上序号。

实操时，把几条影评交给模型。比如第一条谈纣王与殷寿的文戏、欲望放大器和成长痛感；第二条批爹味与父权叙事，认为文戏武戏割裂、女性处理草率；第三条肯定主线清晰，指出妲己与纣王的动机、殷寿的伪善，以及“劫数在人不在妖”。模型按指令输出判断和简短理由，风评轮廓就出来了。

[PRE3]

再往高级走，可以爬评论列表喂给 GPT，让它分析前几页评价，给出整部电影的风评解读。这个玩法后面可以单独展开。场景还能扩：做电商的人可用它分析自己产品评论区；普通买家也能用它过滤掉大量无用评价，只留下有参考价值的内容。GPT plus 的插件本身没有分类，也能用类似方法让 AI 自动归类，替代过去海盐手工分类的做法。再进一步，用 api 动态爬取插件 store 的变更，一旦关注的分类里新增或下架插件，就发邮件或短信提醒，程序还能自动更新推荐列表。做大数据的程序员也不必再写复杂代码给业务数据打标签，用简单代码加提示词就能做。机器学习里，这种不提供带标签训练数据、仅靠提示词给数据打标签的方式，叫零样本学习算法。形式在变，核心不变。

## 2.3.3.16 格式转换：一份内容，多种形态

使用场景很广：文本转 HTML 方便网页展示，转 Markdown 方便导入编辑器，转 JSON 方便代码开发，多种格式之间也能互转。

### 案例一 文本转 JSON：把位运算说明结构化

提示词可以很直接：请把我给你的文案转成 JSON。文案讲的是右移：

- `>>`：左侧补符号位。正负数都把符号位当数据一起右移，左侧用符号补，越界丢弃。
- `>>>`：左侧补 0。正负数同样把符号位当数据一起右移，左侧补 0，越界丢弃。

转换后可得到类似结构：

```json
{
  "位右移": {
    "1.左边用符号位补 >>": {
      "1.1.细节": [
        "不管正负数，把符号位当数据，一起右移，左侧用符号补",
        "越界了会丢弃"
      ]
    },
    "2.左边用0补 >>>": {
      "1.2.细节": [
        "不管正负数，把符号位当数据，一起右移，左侧用0补",
        "越界了会丢弃"
      ]
    }
  }
}
```

## 2.4.4 常用格式：让提示词不打架

### 2.4.4.1 三引号：圈出待处理文本

三引号的作用是分隔。把要处理的文本夹在英文三引号 `""" """` 里，GPT 更容易分清哪句是指令、哪句是素材。尤其提示词里本身带着文本，文本里又有引号时，边界很容易被认错，三引号能减少这种混乱。

案例：请用 3 个对仗工整、汉字数量一样的排比句总结这个文案：`"""在此插入要处理的文本"""`。这样 GPT 对文案范围的理解会更准确，总结也更稳。

[PRE10]

### 2.4.4.2 XML 标签：多篇文本各归各位

当提示词里有多段要处理的文本，可以用 XML 标签分隔，当然三引号也可以。案例：给两篇同主题文章，用 XML 标签分开，先总结每篇论点，再判断哪篇论点更好并解释原因。

```xml
<文章>第一篇内容</文章>
<文章>第二篇内容</文章>
```

这样多篇文本也不容易串。简单任务里，分隔符未必明显提升质量，效果可以就不用；提示词越复杂，消除歧义越重要，这个技巧越有用。

[PRE11]

### 2.4.4.3 小节标题：把长提示词拆成模块

小节标题的作用是结构化。把一大段像小作文一样的提示词，拆成【角色】【任务】【要求】等模块，层次清楚，AI 更容易识别每一块在说什么，歧义更少，输出也更稳。可以用自然语言写小节标题，推荐；也可以用 Markdown，推荐；json、yaml 程序员用得多，普通人不强推。

案例一：原先把摘要和标题揉成一大段，读起来费劲；拆成【摘要】【标题】后，让 AI 给“快手于冰：在 AI 大模型领域重度投入”这类标题生成 5 个替代方案，指令就清楚多了。

[PRE12]

案例二：让模型扮演《狮子王》的辛巴。结构化后可以写成：【角色】扮演辛巴并了解辛巴的全部知识；【任务】用辛巴的语气打招呼；【要求】使用辛巴的说话方式、思维和词汇，只像辛巴那样回答，不写解释。这样比全堆在一起更好懂。

[PRE13]

常用模板可以记成几块：【角色】【任务】【要求】。无序列表用 `-`、`+`、`*` 都行，功能等价，选顺手的即可；无序列表还能嵌套，每级前加四个空格或一个制表符，层级更清楚；有序列表也常用，表达结构效果很好。用什么语法不重要，AI 能看懂就是好提示词。再往外扩，LangGPT 模板会分 Role、Profile、Skill、Rules、Workflow、Tools、Initialization 等区块，工具区可声明 browser、python、dalle 等能力。提示词越复杂，越值得这样拆开写。说到底，核心只有一个：把边界和任务说明白。
