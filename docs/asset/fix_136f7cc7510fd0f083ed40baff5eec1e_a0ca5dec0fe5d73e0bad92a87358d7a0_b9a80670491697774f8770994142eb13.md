1. **为智能体做一张展示网页**

落地载体并不唯一，业务场景不同，呈现方式也不同。比如：
- 聊天机器人（Bot）：接入飞书、微信、Slack、Discord 等平台，在对话中服务用户。
- 网页应用（Web App）：给出一个网址，任何人点开就能用。
- 企业内部工具：嵌入公司业务系统、OA 或工作流。
- API 服务：作为后台接口，供别的系统或应用调用。
- 桌面或移动应用：做成独立软件或 App；不同平台可承载机器人、网页应用、小组件等，也能组合使用。

本期采用 Bot 作为交付入口，但方法本身并不绑定这一形态。若某个系统可以读懂目标、安排步骤、使用工具、反馈进度并守住安全边界，那么搭建思路就能复用。差别通常出现在入口、触发器、上下文维护和风险控制细度上。

接着要做的是：让这个智能体拥有一个别人能打开的链接。先说明白，这个页面并不代表正式部署。若要让外部用户长期使用，一般还需要服务器、域名、运行环境，并持续承担模型接口（Token）等开销，同时处理稳定与安全问题。其他人调用时，这些成本照样会发生。

我们即将生成的链接，性质更接近一张智能体名片：展示它的介绍、本事和产出，方便转发。它不会实际执行智能体，访客也不能从页面直接调用，自然不占用你的 Token。

先做展示页的意义在于，让你提前体验智能体由“只有自己会用”过渡到“旁人也用得上”的阶段。许多人完成搭建后，只能在个人电脑或开发环境中运行。把公开链接发出去，对方无需配置环境即可试用。此时它不再只是演示样本，而开始接近产品。后续不管是团队共用、向客户交付 AI 流程、做成内部工具，还是发展为对外服务，都很难跳过这一环。

对这期航海多数成员而言，现阶段更要紧的是先让若干智能体稳定、持续地替自己分担任务，而不是一开始就投入较多成本做部署与维护。若能力和需求都已成熟，当然可以继续上线；上线后，别人才能在线实际使用，而不只是浏览展示页。这属于打通基础闭环后的进阶内容，不在本期学习范围内。

所以这一关不要求完成部署，而是先跨出产品化的第一步：让旁人了解你的智能体、明白它能处理什么。等出现真实业务需求，再根据情况判断是否上线，把它变成可长期运行、供他人使用的线上产品。

## 交作业前逐项核对

小D 的验收线共有 7 条，全部满足才算复刻成功。若你练的是音视频转录智能体（小D），交作业前请逐条对照：
1. 可以取得公开播客/视频地址。
2. 能抓取或下载音频。
3. 能跑完 ASR 转写。
4. 产出的是分享式整理稿，不是摘要。
5. 能创建飞书文档。
6. 文档权限能落到本人账号上。
7. 最终链接可打开，目录和格式都正常。

小D 常见失误，交前逐项排查：
1. 只搬了提示词，工具链没配齐：得到的只是一个“口吻像小D”的助手，实际下载、转写、建文档都做不了。关卡5要求安装好的 yt-dlp/whisper/lark-cli 不能缺。
2. 把提纯做成了摘要：输出是一串要点，而非可读的原文整理。回关卡4核对 Profile 里“不要写成核心要点/一句话总结”的要求。
3. 专有名词未修正：长音频中的人名、机构名容易被 ASR 听错。请在 Profile 中加入常见错词对照表。
4. 飞书权限链没走通：机器人虽然建了文档，本人却打不开，这属于交付失败。
5. 敏感凭据外泄：app secret、token、cookie 都不得出现在对话、文档或截图中。

### 04. 这一关的收尾

所谓跑闭环，是拿真实样例来证明：智能体并非只能演示一回，它还要经得起验收、修正和交付。

前五关里，你已经从体验演示走到正式搭建：明确岗位、拆解流程、编写 Profile、接入工具、连上飞书。到第 6 关，重心不再是继续堆功能，而是用真实输入多跑几轮，把“我认为可用”推到“旁人也看明白、能验收、可复用”。

四个关键动作：
1. 准备测试样例：至少三份真实或接近真实的输入，覆盖日常情况、边界情况和最在意的业务场景。
2. 留下运行痕迹：把输入、执行过程、输出结果和人工验收结论记下来，旁人能看出它最近确实在干活。
3. 做一轮校对与优化：按影响程度给问题排序，回到 Profile、工具链或流程规则中逐项处理，再用同一份样例复跑。
4. 归拢交付物：公开链接、成功运行截图、操作手册和测试记录都备好，让智能体由“跑得动”变成“交得出”。

至此，必修部分结束。你手里至少有一个能独立完成任务、走通闭环的智能体：岗位明确、流程完整、具备决策能力、工具齐备，也有可核验的交付材料。

后续选修关卡会再进一步：视线不只停留在一个智能体内部，而是把它放回真实业务，看输入从何处来、产出交给谁、值不值得同其他人员、工具或智能体衔接。

选修部分更开放，难度也更高。从下一关起，不再安排必交作业；你只需参照任务目标和说明，按步骤练手。若暂时没有自己的业务场景，也可以沿用默认案例，先吃透方法，再迁移到自己的业务中。

它更接近一份进阶指南，无需一口气做完。先挑与当前智能体最相关的内容完成，日后需求变化，再回来继续探索。

整套智能体虽然完整、能做事，却未必适合直接转发。它可能依赖你的飞书空间、本地程序、账号权限、文件路径、业务资料以及固定输出位置……旁人拿到整套东西，不一定能顺利运行。

但其中有一项能力很适合单独抽出：对转录稿做清洗，再按既定结构归纳出摘要、行动项和待确认问题。它既不需要账号，也不依赖飞书空间，旁人只要有一份转录稿就能用，因而适合沉淀为 Skill。

从智能体里拆 Skill，可分三步：
1. 回看智能体流程，找出反复出现、价值较高、旁人也可能需要的那一小段能力。
2. 把它从整体流程中剥离，不要上传整套智能体；只留一个边界清楚的小能力：输入什么、处理什么、输出什么。
3. 写成旁人可复用的 Skill，讲清适合谁、解决什么问题、怎样使用、使用前后有何变化。

当然，不必自己苦想“哪个节点适合做成 Skill”。更省力的做法是：把智能体流程交给 AI，让它帮你拆节点、评估价值，并挑出最适合发布到 Skill Hub 的能力。
