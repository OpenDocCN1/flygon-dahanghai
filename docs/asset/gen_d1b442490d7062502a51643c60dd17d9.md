# n8n 自动化实战：三个能直接复用的工作流片段

在搭建自动化流程时，很多朋友最头疼的不是思路，而是具体落地的那几段配置。今天这篇文章不聊虚的，直接拆解三个高频场景的实操写法，涵盖邮箱提取、发票信息模板生成，以及网页正文的抓取与 AI 提炼。看完你就能把它们搬进自己的 n8n 工作流里。

[PRE0]

先说第一个场景：从用户输入的聊天消息里自动识别邮箱地址。这段代码的思路非常直接——拿到原始文本后，用正则表达式匹配第一个符合邮箱格式的字符串，如果匹配不到就返回 null。关键在于正则的写法覆盖了常见邮箱结构：用户名部分允许字母、数字以及点、下划线、百分号、加号和短横线，域名部分支持多级子域，顶级域名至少两位字母。这样写的好处是容错率高，不需要额外引入校验库，几行代码就能把非结构化输入转成可用的字段，方便后续节点直接调用。

[PRE1]

第二个场景是发票信息的模板化输出。这里把 Google Sheets 里的一行数据，映射成一张结构清晰的发票文本。整个模板包含几个部分：抬头部分展示发票标题、号码和开票日期；购方信息与销方信息并列呈现名称和税号，购方还额外保留了备注字段；再往下是商品或服务明细的表格，逐项列出名称、规格、单位、数量、单价、不含税金额、税率和税额。每个字段都用了空值兜底处理，数字部分统一做了精度控制——单价保留六位小数，金额类保留两位小数，税率则优先取显示值，没有的话再按小数转百分比。最下面汇总合计不含税金额、合计税额和价税合计，最后附上开票人。这种写法适合批量生成发票预览或对接打印环节，数据一变，文本自动跟着变。

[PRE2]

第三个场景稍微复杂一些，是一个完整的文章分析工作流配置。它的起点是 Firecrawl 节点，根据传入的参考文章链接抓取网页并拿到 markdown 正文。紧接着，一个 AI Agent 节点接手，系统提示词里明确定义了角色和任务：先剔除文章开头结尾的作者信息、日期、点赞在看赞赏等干扰内容，然后只针对正文做核心内容摘要，并摘录三到五句原文金句，合计字数控制在五百字以内，最后按固定格式输出。这个流程里还配置了两个语言模型节点，分别指向豆包和 Claude 的模型版本，通过统一的 API 凭证接入。整体来看，这套组合把网页抓取、内容清洗和结构化提炼串成了一条线，适合做公众号文章的快速拆解。

三个片段各有侧重，但共同点都是把重复性劳动交给流程去跑。你可以按需取用，也可以把它们拼进更大的自动化链路里。
