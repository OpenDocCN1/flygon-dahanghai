1.4 先拆剧情，再谈质量

小说文件就绪后，下一步是剧情拆解。它是整个改编流程的起点，也是决定后续剧本成色的关键环节。

所谓剧情拆解，说到底是从原文里找出两类东西：核心冲突点和情绪钩子。核心冲突点是推动故事往前走的关键事件，例如主角受辱、金手指出现、与对手正面交锋；情绪钩子则是能让观众情绪被拽起来的瞬间，比如打脸爽点、虐心痛点、真相揭开等。

项目所用的改编方法论会先判断小说类型——玄幻、都市、言情等——再按类型特征提取对应内容。比如玄幻类更关注境界突破、越级碾压，言情类更关注误会生成、虐心拉扯。

拆解结束后，系统还会自动做分集标注，把找出的剧情点按漫剧节奏分到各集，保证每一集都有足够的冲突密度和情绪强度。

1.5 一集一集写剧本

剧情拆解完成后，就可以创作单集剧本了。单集剧本是能直接用于漫剧制作的脚本，包含场景描述、角色动作、对话、特效标注等内容。

关于剧本创作：核心是把拆解出的剧情点转成视觉化脚本。这个过程会自动完成几件事：读取 breakdown.md 中标记为“未用”的剧情点；根据剧情点生成 500 到 800 字的剧本；用视觉化语言描述场景和动作；添加特效标注和卡黑结尾；保存到 scripts 文件夹；并把剧情点状态更新为“已用”。

生成的剧本会严格遵循漫剧节奏要求，保证每集有足够冲突密度和爽点，适合短视频平台观看习惯。

1.6 看懂配置逻辑

到这里，你已经走完从小说到剧本的完整改编流程。但你可能会好奇：为什么输入 /breakdown 就能自动拆解？为什么 Agent 会自动检查质量？这些是怎么实现的？

配置文件的作用

在 .claude/ 文件夹中，有几个核心配置文件，它们共同定义了整个改编流程：

CLAUDE.md 的作用：它是整个项目的总调度中心，定义主 Agent 的角色和工作流程，也就是“什么时候做什么”。这个文件告诉 Claude Code：收到 /breakdown 命令时执行剧情拆解流程；收到 /create 命令时执行剧本创作流程；拆解完成后自动调用 novelquality-agent 检查质量；剧本完成后自动调用 novelsame-agent 检查一致性。通过这个文件，Claude Code 知道自己在这个项目中扮演编剧角色，负责调用 webnovel-skill 执行专业改编，调用双校验 Agent 做质检，整个生产流程都固化其中。

skill.md 的作用：它是 webnovel-skill 的本体文件，定义这个 Skill 到底会干什么。文件规定 Skill 的能力范围，包括类型识别（识别玄幻、都市还是言情）、剧情拆解（提取冲突点和情绪钩子）、分集标注（按漫剧节奏分配剧情点）、单集剧本创作（生成 500 到 800 字视觉化剧本）、内容修订（根据反馈优化剧本）。同时规定每个阶段读哪些文件、用什么模板、参考哪些示例，确保工作流程清晰可控。

adapt-method.md 的作用：它是改编方法论文件，只管一件事：改编本身应该怎么做。文件定义整套改编科学，包括冲突识别（如何判断核心冲突、次级冲突、过渡冲突）、钩子提取（如何识别打脸蓄力、碾压爽点、金手指觉醒等情绪钩子）、密度压缩（如何把小说内容压到漫剧节奏）、分集策略（如何合理分配剧情点到各集）、节奏公式（如何保证每集有足够冲突和爽点）。

output-style.md 的作用：它专门规定 AI 输出内容“长什么样”，不管剧情对不对，只管写出来有没有画面感、节奏够不够快、爽点够不够密、能不能直接拍成漫剧。文件规定场景标识（使用※符号）、动作标识（使用△符号）、特效标识（使用【特效】标记）、卡黑结尾（每集结尾必须有悬念）、对话格式（简短有力，不超过 20 字），确保生成的剧本可直接用于漫剧制作。

示例和模板文件

examples 文件夹里有两个示例文件：plot-breakdown-example.md 展示如何写剧情点、标注集数、标注情绪钩子、管理状态，AI 会直接模仿这个结构输出；script-example.md 展示场景怎么写、动作怎么标注、特效怎么加、如何卡黑，是 AI 学习视觉语言的模板。

templates 文件夹里有两个模板文件：plot-breakdown-template.md 规定剧情拆解的固定格式，确保拆解结构统一；script-template.md 规定剧本的固定结构，保证每集都是可制作脚本。

为什么要这样设计？

因为这样方便你定制。比如：想修改改编方法，只改 adapt-method.md；想修改剧本格式，只改 output-style.md；想增加新命令，只改 CLAUDE.md。所有配置彼此独立，互不影响，易于维护和复用。

1.7 你可能遇到的问题

Q1：为什么要把小说拆成多个章节文件？

因为 Claude Code 处理单个文件有长度限制。整部小说放在一个文件里，可能超出处理能力。拆成章节文件后，系统可以逐批处理，既保证处理质量，又避开长度限制。拆分后的文件也更容易管理，可以灵活选择要改编的章节范围。
