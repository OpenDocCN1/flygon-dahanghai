2.4 小红书 Cookie 怎么拿

💡 想让 Claude Code 自动把内容发到小红书，先要让它拿到你的账号认证信息。小红书通过 Cookie 判断用户身份，所以得从浏览器里把 Cookie 取出来，再填进 xiaohongshu-mcp。

**先弄懂 Cookie 认证**

Cookie 是站点识别用户的一种机制。你在浏览器登录小红书后，平台会往浏览器里写入一段 Cookie，之后每次操作都带着它来证明“你是你”。xiaohongshu-mcp 借助这段 Cookie 模拟浏览器行为，以你的身份完成发布。

要记住，Cookie 等同于账号凭证，性质接近密码，务必妥善保存，不能交给别人。它还有有效期，到期后要重新获取。

第 1 步：取出小红书 Cookie

[PRE1]

**先打开小红书网页版并完成登录。**

启动浏览器（Chrome 或 Edge 更稳妥），访问 https://www.xiaohongshu.com，点右上角【登录】，用扫码或手机号登录。这样浏览器才会拿到你的登录 Cookie。

**接着打开开发者工具。**

登录成功后，按【F12】（Mac 用户按【Command + Option + I】）调出开发者工具，用来查看网络请求里的 Cookie。也可以右键选择【检查】进入。

[PRE2]

然后切到 Network（网络）标签。

在开发者工具顶部找到【Network】，中文界面可能叫【网络】，点进去就能看到浏览器发出的各类请求。

[PRE3]

**再刷新页面，让请求出现。**

按【F5】或点刷新按钮重新加载页面，这样 Network 列表里会捕获新的请求。

在请求列表里，点任意一个发往 [xiaohongshu.com](http://xiaohongshu.com) 的请求（一般选第一个就行），用来查看它携带的 Cookie。

[PRE4]

最后查看并复制 Cookie。

在右侧请求详情中找到【Headers】（请求头），向下滚到【Request Headers】（请求标头），找到【cookie:】这一行。点 cookie 后面的值，全选复制。它通常是一长串键值对，类似：web_session=xxx；xsecappid=xxx; a1=xxx;... 复制完整，才能拿到可用的认证信息。

[PRE5]

**安全提醒**

Cookie 安全方面：不要把 Cookie 发给任何人；不要将含 Cookie 的配置文件上传到公开代码仓库；定期更换 Cookie（建议每月重新获取一次）；如果怀疑泄露，马上在小红书 APP 退出登录，这会让所有 Cookie 失效。

账号安全方面：建议先用小号测试，避免主账号出问题；不要用自动化工具做违规操作；遵守小红书社区规范；注意发布频率，别被平台判定为机器人行为。

**2.6 常见疑问速答**

Q1：为什么用 Cookie 认证，而不是账号密码？

小红书 API 不支持直接用账号密码登录，而是靠 Cookie 验证身份。Cookie 认证更安全：它有有效期，即使泄露也会自动失效；同时不需要在代码里存明文密码，安全风险更低。

Q2：Cookie 多久过期？过期后怎么办？

小红书 Cookie 通常有效 30 到 90 天，具体看平台设置。过期后 xiaohongshu-mcp 会提示认证失败，这时重新登录小红书网页版，按前面的步骤重新获取 Cookie 并更新配置文件即可。建议定期（比如每月）主动更新一次，避免使用时突然失效。

Q3：自动发布会不会被小红书封号？

如果遵守社区规范、发布合规内容，一般不会被封。但要注意：不要发违规内容（广告、虚假信息等）；控制发布频率，避免短时间大量发布；内容要有原创性，避免重复发相同内容；不要用多个账号发布完全相同的内容。建议先用小号测试，确认流程稳定后再用主账号。

Q4：能同时管理多个小红书账号吗？

可以。为每个账号分别获取 Cookie，在配置文件里添加多个账号配置，使用时指定用哪个账号发布。但不同账号要用不同内容，避免被平台识别为批量操作；同时遵守平台规则，不要恶意营销或刷量。

Q5：生成的内容能自定义风格吗？

可以。smart-content-creator-skill 支持自定义内容风格，调用时可指定要求，比如“生成一篇专业严谨风格的笔记”或“生成一篇轻松活泼风格的笔记”。也可以修改 Skill 配置文件，设置默认风格参数。如果对生成内容不满意，可以多次生成挑最好的一篇，或者生成后手动修改再发布。
