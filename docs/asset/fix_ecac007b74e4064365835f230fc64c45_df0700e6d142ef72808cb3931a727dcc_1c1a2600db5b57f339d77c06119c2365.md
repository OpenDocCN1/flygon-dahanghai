延伸说明：
.tsx、.css、Next.js
这些是底层技术组合。AI 编程过程中，另一项要提前敲定的就是技术选型。
对没有编程背景的人而言，这些框架名字自然陌生。截图里以 .tsx、.css 结尾的文件，都是代码文件。
像 Coze 编程这类工具，已经把常用的网页框架预先固化，哪怕你不懂代码，它也会在开发时替你补上。
可若换成更通用的编程工具，比如 Claude Code 或带图形界面的 Cursor，写功能时它可能自行挑选别的框架。
网页的呈现方式与底层技术组合很多，若不提前指定，容易偏离预期。
下面给出不同应用类型对应的技术框架提示语（用通用编程工具时可照搬）：
• 网页端应用：“需要使用 nextjs、shadcn/ui、Tailwind”
• 小程序：“就使用官方的 wxml、wxss、wxjs”
• iOS App：“使用 swift 原生应用开发”
• 需要前后端分离的架构：“后端服务可以使用 go 语言实现”

### 3.3 第三步：打磨页面
这一节要做的是：用新手也能上手的办法检查页面、提出调整，必要时退回旧版本。*如果当前要改的地方还不明确，可以先跳到 3.4 补齐真实资料，等资料到位再统一优化。*
#### 3.3.1 截图加标注，把修改点讲明白
改页面时最常踩的坑，是位置描述不清。比如想把头像挪到左边，只丢一句“头像位置不对”，Coze 未必能判断是哪个元素、往哪个方向改。
更管用的方式是：**截图 + 标注 + 提示词**。
操作步骤：
1. 先截当前页面（Mac：Command+Shift+4；Windows：Win+Shift+S）
1. 在图上用红框或箭头圈出目标位置
1. 把图粘进对话框（Ctrl+V 或 Cmd+V），并写清希望怎么改

#### 3.3.2 小改走 Agent，大改先回问答
并非所有调整都适合直接让 Agent 动手。
轻量修改可以直接在 Agent 模式完成，例如：
• 挪动某个元素
• 改动一段文案
• 替换按钮文字
**涉及复杂调整，建议先切回问答模式**，把思路讨论清楚再执行，例如：
• 重排整个页面布局
• 增加一个板块或功能
• 反复改了两三次仍没解决的问题
先回问答模式的好处是：方案先说明白，确认可行再切 Agent 执行，能减少来回返工。
#### 3.3.3 右侧工具栏的四个实用按钮
**切换显示尺寸**
预览区顶部有尺寸按钮，可在桌面、平板、手机三种视图间切换。个人主页很可能被人用手机打开，建议每轮修改后都切到手机端确认。
[PRE21]
**刷新**
样式没及时更新，或预览出现异常，先点刷新试试。
[PRE22]
**重启**
刷新无效时，再尝试重启服务。适合页面完全无响应，或做了较大改动之后。
[PRE23]
**版本控制**
四个操作里**最关键**的一项，但新手常找不到入口。
点击右侧区域右上角的新标签页按钮，在打开页中进入版本控制。每条记录会写明：涉及哪些文件、本次改了什么。
