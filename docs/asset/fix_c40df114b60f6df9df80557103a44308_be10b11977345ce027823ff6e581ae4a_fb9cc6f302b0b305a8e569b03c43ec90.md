# 遇事别急着问人，先让 AI 过一遍

碰到难题时，与其立刻翻资料、找同事，不如先把手头问题交给 AI 跑一轮。这个顺序固定下来之后，很多原本棘手的事会更快有着落。

| 容易卡住的地方 | 过去常怎么做 | 更稳妥的检验口径 |
| --- | --- | --- |
| 流程描述太虚，Agent 抓不住重点 | 写一堆笼统说明 | 每道动作都以动词开头，让执行者一眼明白要干什么 |
| 判断节点缺失，Agent 自由发挥 | 等最后人工兜底 | 提前写明“达到什么状态算过关”，人也能按同一把尺子复查 |
| 步骤数量超过八道 | 继续硬写 | 先压缩成“接收→加工→产出→人工确认”四段，主干控制在八步以内 |
| 工具还没敲定 | 急着把命令写死 | 先挂“工具待接入”的标记，别在这一环死磕细节 |

| 卡住的情形 | 可以这样向 AI 开口 |
| --- | --- |
| 不确定人工流程该拆几道 | “请把我平时处理[任务名]的过程拆成不少于五步；每一步说明我做了什么、耗时多久、依据哪些材料。” |
| 那些凭感觉的判断写不出来 | “下面是我手工操作的步骤（粘贴内容）。请找出其中需要我拍板的地方，讲清判断依据，并为每个节点起草一条 Agent 可执行的规则。” |
| MUST / SHOULD 拿不准 | “这是我的工作流（粘贴内容）。请逐条判定：MUST 表示不做就会出错，SHOULD 表示尽量做但不致命，MAY 表示可选；同时说明理由。” |
| 流程太长不会瘦身 | “我的 Agent 流程共有 X 步（粘贴内容）。请指出哪些能合并、哪些可降为可选，并把主干压到八步以内。” |
| 流程图无从下手 | “请根据这份工作流（粘贴 MUST/SHOULD 步骤）生成 Mermaid 图代码，其中至少安排两个判断分支。” |

### 03. 收尾复盘：把职责翻译成动作

**Agent 工作流说到底，是把岗位卡上的职责换成执行者看得明白、能照着做、也方便复查的操作序列。**

关卡 2 已经为第一个正式 Agent 定好了岗位：服务谁、接收哪些材料、交付什么结果。这一关要把“岗位”落到“流程”：先如实还原你手工操作时的步骤，再把藏在经验里的判断、特殊情况和人工接管点写出来，最终整理成一份可执行清单。

真正让 Agent 出问题的，往往不是任务本身多难，而是流程含糊。人靠经验可以跳步、补漏、临场决定；Agent 不行，它需要你把隐形经验摊开：哪些非做不可，哪些尽量做，哪些可以省略，哪些必须停下来找人。

**本关要完成四个动作：**

1.  **还原人工流程**：先让 AI 出一版手工操作流程，再由你删掉不真实的部分、修正不准确的地方、补齐漏掉的步骤。
1.  **挖出关键判断点**：把“我一看就明白”的经验说清楚，写成可判断的条件和依据。
1.  **翻译成 Agent 工作流**：用 MUST / SHOULD / MAY，把动作、判断、异常处理和人工兜底都写成规则。
1.  **画出流程图**：把主干步骤和至少两个判断分支画出来，方便人复核，后面也能写进 Profile。

做完这一关，Agent 不只知道自己负责什么，还清楚每一步该怎么走。

下一关会结合关卡 2 和关卡 3 的成果，让 Agent 的身份、目标、规则和自检标准更完整。

**💡 新手提醒：**

前三关其实像一场招聘：

关卡 1：找到了一个新员工（Agent）

关卡 2：确定了岗位内容和规范

关卡 3：梳理了岗位的工作流程

**这一关，就是正式入职培训。**

Hermes 的 **Profile**，相当于新员工入职时拿到的《岗位说明书》。它会告诉员工：

• 你是谁？

• 你的职责是什么？

• 工作时应该遵循哪些原则？

• 遇到不同情况应该怎么处理？

以后 Agent 每次开始工作，都会先“阅读”这份说明书，再按照里面的要求执行任务。所以，Profile 写得越清楚，Agent 工作就越稳定、越符合你的预期。

但也不用追求第一次就写得非常完美。Profile 是一个持续迭代的过程，每次使用 Agent 后，根据实际效果不断补充和优化，它才会越来越稳定、越来越好用。

我们依旧会提供默认案例作为参考，带你完整跑通关卡步骤，建立对流程的理解，先拿到体感。

**❗️需要注意的是，默认案例只是帮助你学习流程、加深体感，并不能作为最终成果物提交。** 有了体感之后，再回到自己的真实工作场景，完成属于你的第一个 Agent。

3. 不同类型的 Agent，重点各有不同

前面的步骤是通用的，但不同类型的 Agent，真正需要写清楚的规则并不完全一样。你不需要把下面所有内容都写进 Profile，只需要找到和自己 Agent 最接近的类型，重点检查对应内容有没有写清楚。

**3.1 内容生产类 Agent**

例如：文章写作、短视频脚本、选题策划、社交媒体文案等。

Profile 中要重点写清楚：

• **写给谁看：**目标读者是谁，他们关心什么，能看懂什么。

• **写成什么样：**文章结构、字数范围、语气、格式和常用表达。

• **不能怎么写：**不允许出现哪些词、哪些语气和哪些表达方式。

• **信息从哪里来：**可以使用哪些资料，不能编造哪些内容。

• **如何自检：**是否跑题、是否重复、是否有空话、是否符合要求。

• **什么时候询问用户：**主题不清楚、资料不足或写作要求冲突时，不能直接猜。

这类 Agent 最容易出现的问题是：看起来写完了，但内容不符合你的风格，或者为了写得完整而编造信息。

**3.2 音视频转录与资料整理类 Agent**

例如：音视频转录、会议纪要、课程笔记、采访整理等。

Profile 中要重点写清楚：

• **支持什么输入：**音频、视频、网页链接、飞书妙记还是本地文件。

• **如何处理原内容：**是否去掉时间戳、口水话、重复内容和无意义语气词。

• **可以改到什么程度：**只整理表达，还是可以重新概括和总结。

• **哪些内容必须保留：**关键原话、数据、案例、结论、任务和负责人。

• **听不清怎么办：**无法确认的内容如何标记，不能自行编造。

• **如何交付：**输出到聊天窗口、飞书文档，还是指定文件夹。

• **如何自检：**是否漏掉重点、是否改变原意、文档结构是否正常、用户是否有权限。

这类 Agent 最重要的是：整理可以更清楚，但不能把原意改掉。

**3.3 办公整理类 Agent**

例如：周报整理、日报汇总、资料归档、报表更新、信息收集等。

Profile 中要重点写清楚：

• **需要哪些字段：**每条信息必须包含什么，哪些字段可以为空。

• **字段如何对应：**输入中的内容要分别填到哪里。

• **格式是什么：**日期、金额、姓名、链接等采用什么统一格式。

• **如何排序和分类：**按时间、部门、项目、优先级还是其他规则整理。

• **重复内容怎么办：**删除、合并还是保留最新版本。

• **信息缺失怎么办：**留空、标记待补充，还是向用户询问。

• **异常内容怎么办：**格式错误、数据冲突或无法识别时如何处理。

• **如何自检：**是否漏项、填错位置、重复录入或修改了原数据。

这类 Agent 最重要的是：内容可以简单，但字段不能放错，数据不能随便改。

**3.4 客服与销售类 Agent**

例如：售前咨询、客户跟进、社群答疑、销售回复等。

Profile 中要重点写清楚：

• **可以回答什么：**能处理哪些常见问题。

• **不能回答什么：**哪些问题超出权限，不能自行承诺。

• **使用什么语气：**正式、亲切、简洁，还是更有销售感。

• **如何判断用户需求：**用户处于咨询、犹豫、投诉还是准备购买阶段。

• **哪些话不能说：**不能虚假承诺、夸大效果或泄露隐私。

• **什么时候推荐产品：**满足什么条件后才能推荐，不能一上来就推销。

• **什么时候转人工：**投诉、退款、价格特批、合同、隐私或复杂问题必须转人工。

• **如何记录：**需要保存哪些客户信息和沟通结果。

• **如何自检：**是否答非所问、承诺过头、语气不合适或遗漏用户问题。

这类 Agent 最重要的是：先划清回复边界，再考虑如何把话说得更好。

**3.5 数据分析与判断类 Agent**

例如：用户分析、内容评分、商品筛选、风险审核、线索判断等。

Profile 中要重点写清楚：

• **根据什么判断：**使用哪些数据、条件和判断标准。

• **标准的优先级：**多个条件冲突时，先看哪一条。

• **结果如何分类：**通过、不通过、待确认，还是按照等级评分。

• **评分如何计算：**每项多少分，什么结果对应什么结论。

• **证据如何展示：**结论需要引用哪些原始信息。

• **信息不足怎么办：**不能直接下结论，要标记缺少什么。

• **模糊情况怎么办：**哪些情况必须交给人工判断。

• **如何自检：**判断依据是否充分，结论和证据是否对应。

这类 Agent 最重要的是：不能只给结果，还要说明为什么这样判断。

**3.6 流程自动化类 Agent**

例如：收集信息后自动整理、生成文件、发送消息、更新表格等。

Profile 中要重点写清楚：

• **什么时候开始执行：**用户发送指令、收到文件，还是定时启动。

• **执行顺序是什么：**每一步先做什么、后做什么。

• **需要调用哪些工具：**每个工具分别负责什么。

• **上一步失败怎么办：**重试、跳过、停止，还是请求人工处理。

• **哪些步骤不能重复：**避免重复发消息、重复建文档或重复写入数据。

• **数据如何传递：**上一步的什么结果，要交给下一步使用。

• **什么情况算完成：**文件创建成功、表格写入成功，还是消息发送成功。

• **如何留下记录：**是否需要记录执行时间、结果和失败原因。

• **什么时候请求人工：**登录失败、权限不足、数据异常或涉及重要操作时及时暂停。

这类 Agent 最重要的是：不仅要写正常流程，还要写清楚失败以后怎么办。

**3.7 文件与知识库问答类 Agent**

例如：公司知识库助手、课程答疑助手、制度查询助手等。

Profile 中要重点写清楚：

• **可以查哪些资料：**明确知识来源和文件范围。

• **资料冲突怎么办：**优先使用哪个版本，是否查看更新时间。

• **找不到答案怎么办：**直接说没有找到，不能凭经验补全。

• **如何引用来源：**回答时是否需要附上文件名、章节或链接。

• **可以回答到什么程度：**只复述资料，还是可以进一步整理和解释。

• **哪些内容不能回答：**超出资料范围、涉及隐私或权限不足的内容。

• **如何自检：**回答是否真的能在资料中找到依据，是否引用了错误版本。

这类 Agent 最重要的是：只根据已有资料回答，不知道就明确说不知道。

但是一个 Agent 也可能同时属于几种类型的综合体。

例如：
