# 4.1.2 开始搭项目

# 4.1.2.1 先和 Cursor 聊需求

记住，动手之前第一步永远是讨论。

可以这样问它：我想做一个能在浏览器里跑的网站，主题是 AI 恋爱/婚姻契合度预测；你觉得用什么技术合适？请推荐一套你最看好的技术方案，并给出对应的脚手架。[PRE3]

划重点：程序通常分成网页应用、桌面软件、小程序和 App，运行环境不同，技术选型差别很大。先告诉 Cursor 你要做哪类程序，讨论范围会小很多，效率也更高。

如果你还没想好程序跑在哪里，就先想清楚它主要拿来做什么。然后可以问 Cursor，例如：我想做贪吃蛇小游戏，做完想分享给朋友玩，或者发到网上；你建议做成网页、桌面软件，还是小程序/App？请给出最推荐的技术和脚手架。

所谓最推荐的技术，通常意味着生态成熟、资料多、踩坑概率低。脚手架可以理解成一套开发规范，用来统一技术选型和开发方式；它的好处是统一技术栈、统一开发风格，也让别人更容易接手你的项目。

# 4.1.2.2 要一份手把手教程

它具体答了什么不必细究，我们也未必看得懂；它推荐什么，我们就先用什么。但小白没有编程经验，所以还需要一份手把手教程。

可以这样发：我觉得方案不错，但我没有任何编程经验，电脑上只装了 Cursor 代码编辑器，没有其他环境。请一步一步详细告诉我该怎么做；我完成一步就告诉你，你再告诉我下一步。代码我想放在 D 盘的 projects 目录下。[PRE4]

[PRE5]

后面就按它给的步骤走。如果你做的是桌面软件，需要安装的东西会不同，但同样照着步骤完成即可。

也可以在该怎么做后面追问一句“这样做的目的是什么”，如果你想知道原因的话。把步骤拆得足够小，Cursor 才会讲得足够细；这个办法放到其他场景也适用，关键是尽量小范围讨论。代码放在哪个盘、哪个文件夹可以改，但要确认那个盘存在，比如 C、D、E 盘。

# 4.1.2.3 跟着步骤装环境

以这个案例为例，它让安装 Node.js，我们就跟着做。第一步，打开 Node.js 官网，找到 LTS 版本，点下载。[PRE6]

下载完成后双击安装包，按提示一路点 Next，最后点 Finish。[PRE7]

接着验证是否装好。Windows 上按 Win + R，输入 cmd 后回车；Mac 上按 Command（⌘）+ 空格打开 Spotlight，输入 Terminal 或“终端”并回车，打开终端窗口。[PRE8]

然后在命令行里输入 node -v 和 npm -v。[PRE9]

看到版本信息后，回去告诉 Cursor：安装好了。[PRE10]

[PRE11]

[PRE12]

如果下载很慢或失败，也可以直接把情况告诉 Cursor。[PRE13]

它给的方法里有个地址：https://mirrors.huaweicloud.com/git-for-windows/v2.47.0.windows.2/ ，按它说的打开即可。[PRE14]

[PRE15]

你可能会注意到，每条命令旁边有 Ask、Copy、Run 三个按钮。如果不想改它给的名称，直接点 Run 就行。[PRE16]

当然，点 Run 也可能因为电脑环境不同报错；把报错信息发给 Cursor，问它怎么解决。它给了不少方案，我选了个简单的。[PRE17]

把终端切换成 Command Prompt，切换后重新执行刚才的命令，比如 d:、cd d:\ 这种。[PRE18]

再点一次 Run，按 Cursor 的提示操作，能看到对应结果就算成功。看到什么不重要，因为 Cursor 给每个人推荐的技术选型未必一样。[PRE19]

[PRE20]

# 4.1.2.4 打开项目文件夹

到这里，Cursor 在当前聊天里的任务就完成了。别在这个窗口继续聊，直接在 Cursor 里打开刚创建的项目文件夹。[PRE21]

确认项目名（例如 AI-DATING-APP）显示在最上面。[PRE22]

打开后你会发现，之前的聊天记录不见了。这是因为 Cursor 的聊天记录跟着项目走；它的使命本来就是帮我们确定技术选型、把项目建出来，后面可以在项目里让它改代码。真想看旧记录，可以左上角新建窗口，它还在那里。[PRE23]

记住一句话：不懂的时候，不要直接命令 AI 做什么，而是让 AI 建议你怎么做。

打开右侧聊天框，输入类似这样的提示词：这是一个模板项目，请在根目录创建 design.md，把项目目录结构和技术要点总结进去，方便之后讨论需求时给你参考。Design 是设计的意思，文件名你也可以自己取。

这样做的目的是：讨论需求时不必让 Cursor 反复读取整个项目，读这个文件就能掌握技术背景，相当于把它当成一个懂技术的产品经理。输入提示词后使用 codebase 模式（按 Ctrl+回车，或点按钮），Cursor 会读取整个项目。[PRE24]

点击 Apply，一般会自动创建文件；如果没有，就点 Create new file。[PRE25]

点 Apply 后，Cursor 会自动把内容写进文件。稍等一会儿，再点 Accept。[PRE26]

如果目录结构那里因语法问题出现断层，可以手动把内容复制进文件。[PRE27]

文件上出现小圆点说明还没保存，记得按 Ctrl+S。

# 4.1.2.5 把点子扩成产品

只有一个 idea 显然还成不了产品，但很多人不知道怎么把 idea 变成产品，这时也可以借 AI 的力。

打开新的聊天框，输入：我有一个 AI 恋爱/婚姻契合度预测的 idea，想做成网站，但目前只有一个想法。你能帮我想一些功能点、特色，以及可以做哪些页面吗？请把讨论结果记到 product.md 这个文件里。[PRE28]

然后用同样的方式把内容保存到文件。[PRE29]

[PRE30]

这一步你可以按自己的想法增删需求。等产品设计差不多，就可以进入下一步。通常第一版不会做太多功能，但剩下的功能又舍不得丢，所以可以让 AI 把功能分阶段实现。

可以这样问：我觉得不错，但我想先做一个最小 MVP 试试效果，能不能把功能和页面重新按阶段规划一下？[PRE31]

[PRE32]

[PRE33]

[PRE34]

具体阶段按你的想法来，比如第一阶段只实现核心流程就够。

# 4.1.3 聊清需求，把项目做出来

# 4.1.3.1 先做首页设计

现在内容差不多了，可以动手实现。但还是一样，先把需求讨论清楚。

打开新的 Chat 窗口，用 codebase 模式，提示词可以这样写：请先帮我创建首页代码文件夹和 README.md 文件，后续讨论结果都写进这个 README.md；这个文件夹用来放首页代码。创建好之后，我们再讨论这个页面的详细设计。[PRE35]

[PRE36]

[PRE37]

点 Create new file 后，Cursor 会自动创建对应目录结构和文件。如果没有这个按钮，可以重新生成一次，或者按它的建议手动创建。只保留目录结构就可以。

我们只知道首页要有哪些功能，却不知道页面怎么设计，所以继续问 AI：现在可以开始讨论了，请把讨论结果写入 @README.md，方便后面写代码时参考；可以参考 @design.md 和 @product.md。先告诉我首页设计需要考虑哪些点？

这里会用到 Cursor 的 @ 功能：输入 @ 会弹出一系列指令，选 File，再选 README.md（注意别选成根路径那个）；选 @design.md 和 @product.md 也是同样操作。[PRE38]
