# 1.4 进阶技巧与 AI 能力特点

更多 Cursor 技巧，推荐看本期航海教练花生老师录制的视频👇🏻
https://www.bilibili.com/video/BV1YAtReqEkH/?spm_id_from=333.999.0.0

学习 AI 编程时，比起编程基础，更值得担心的是自己使用 AI 的能力。虽然已经能用自然语言编程，但这种交流也要建立在理解 AI 特点的基础上，才能让 AI 这个“实习生”为你所用。下面几个特点最值得在 Cursor 编程时理解：

1. 随机。大语言模型的本质是预测下一个 token，预测带有随机性。所以跟教程练习时，生成结果和示例不同很常见；同一个目标得到两个完全不同的方案也正常。想减少随机性，就用更明确的要求收敛它的预测。比如只要求做一个像 ChatGPT 的 AI 对话网站，它可能给你 HTML/CSS、React、Vue 等不同框架；新手更容易用 HTML/CSS 上手，所以可以直接要求它用对应代码语言。
2. 平庸。LLM 由大量互联网数据训练而来，通过预测下一个 token 生成内容，它不想“成功”，只想从善如流地给出和互联网训练语料一样的平均结果。但你可以要求它成功。比如对 app 设计不满意，可以要求 Cursor 按苹果设计师的标准做设计；也可以提供你偏好的设计师或网站风格，向它提要求。
3. 上下文限制。Cursor 目前接入的模型中，开启 Long Context 模式后最长有 200K 上下文。平时对话可能足够，但一个项目动辄几十上百个代码文件，每个文件几百上千行，很容易超出 AI 上下文限制，带来幻觉。所以要及时让 Cursor 把项目进展记录到特定文档中（如 readme.md），项目开始时用 @codebase 等方式，给 Cursor 补上“我们在做什么项目”的必要记忆。
4. 系统一思考。正常情况下，Cursor 总会直接满足要求：要它写代码就写，要它改 bug 就上手改。这也让很多人吐槽改 bug 很难，按下葫芦浮起瓢，同一个错误反复出现，无法完成修改。其实可以想想人类资深程序员的工作方式：他们不是“嘿，这里有个 bug，这段代码报错，那我直接改写一下”，而是理解更丰富的上下文，找关联代码，寻求不同解决思路，再选更好的方案执行，并进一步测试验证。AI 也该如此。当 bug 反复出现，你知道这不是靠系统一直觉能简单解决时，就该让 AI 停下来，用系统二思考：问题究竟是什么 -> 有哪些解决思路 -> 对比不同思路的优缺点 -> 该选哪个方案。多次实践下来，让 Cursor 思考并提供多套解决方案，形成思维链，比直接改代码效果有相当大的提升。

# 二、动手开发：做一个自己的网页 @花生

做自媒体、开发网站/插件、申请签证时，经常遇到图片大小、格式、像素限制。每次碰到问题都要去搜索引擎找工具，而找到的工具往往功能不满足，或者广告太多，或者要注册登录。为了解决自己的图像类问题，我用 Cursor 做了一个网站“图像魔方”：https://www.img2046.com/

[PRE27]

这个网站集成了图片格式转换、像素调整、图像压缩、SVG 在线预览和转换等功能。但它是像搭积木一样，一个功能一个功能搭起来的，很难在一篇教程里把所有功能都讲完。所以我们挑出最常见需求——图像压缩——来实现。你可以把这个例子当作参照，去开发任何需要的其他图像处理功能。

# 2.1 开工前的准备

# 2.1.1 建一个项目文件夹

先建一个文件夹，放桌面、C 盘或 D 盘都可以。文件夹名字就用网站功能命名：“图片压缩”。建好后打开 Cursor，选中这个文件夹。

[PRE28]

# 2.1.2 配置 .cursorrules 规则文件

我习惯给不同类型的项目准备不同的 .cursorrules 文件。.cursorrules 是一个“指导文件”，用来告诉 AI 在这个项目里该按什么方式写代码，比如风格、命名方式等。只要项目文件夹里放入 .cursorrules，Cursor 就能自动读懂你的要求；无论是补全代码还是执行命令，都会按你设定的规则来。

① 在左边根目录创建 .cursorrules 文件。
② 在 .cursorrules 中放入规范要求，要点可以这样写：

- 角色：你是拥有 20 年前端经验的高级工程师，要帮助一位不太懂技术的初中生完成网页开发；这项工作很重要，完成后可获得 10000 美元奖励。
- 目标：用用户容易理解的方式帮助完成网页设计与开发，主动推进所有工作，不要等用户反复催。
- 第一步，项目初始化：接到任何需求，先看项目根目录的 README.md 和所有代码文档，理解项目目标、架构和实现方式；没有 README 就创建一个，作为功能说明书和项目规划；在 README 中写清所有页面用途、布局结构、样式说明，让用户能轻松理解网页结构和样式。
- 第二步，需求分析和开发：理解需求时站在用户角度；像产品经理一样分析需求是否有缺漏，与用户讨论完善；选择最简单的方案满足需求。写代码时优先用 HTML5 和 CSS，不用复杂框架和语言；使用语义化 HTML 标签；做响应式设计，保证不同设备显示良好；用 CSS Flexbox 和 Grid 布局实现页面结构；每个 HTML 结构和 CSS 样式都加详细中文注释；代码符合 W3C 标准；优化图片和媒体资源加载。解决问题时全面阅读相关 HTML 和 CSS 文件，理解页面结构和样式；分析显示异常原因，提出解决思路；与用户多次交互，根据反馈调整页面设计。
- 第三步，项目总结和优化：完成后反思步骤，思考项目可能存在的问题和改进方式；更新 README，包括页面结构说明和优化建议；考虑使用 HTML5 高级特性，如 Canvas、SVG；优化页面加载性能，包括 CSS 压缩和图片优化；确保网页在主流浏览器中正常显示。
- 整个过程都遵循最新的 HTML5 和 CSS 开发最佳实践。

# 2.2 开始开发网页

# 2.2.1 把需求讲清楚

前期准备做完，就可以表达需求了。用 Command+I（或 ctrl+I）调出 Cursor 的 Composer，在里面清晰明确地说明你要什么。

一般来说，需求比较复杂时，一步步来、每次只表达一部分会更好。因为 AI 的上下文窗口有限，每次能处理的任务量也有限；为了减少出错、提高每个模块的输出效率，最好每次让它处理的任务少一些。不过图像压缩网站的需求比较简单，所以可以直接把需求说清楚，比如：

请帮我开发一个“图片压缩”网站，功能是：
1. 打开页面后，用户可以上传 PNG、JPG 等格式的图片，再按自己需要的比例压缩，让图片文件更小；
