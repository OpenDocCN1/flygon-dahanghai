类比一下：人类大脑是存储信息的容器，而 ChatGPT 应用里的 OpenAI 能力就像大脑，既能存储也能生成信息，还能产出 AI 文字和 AI 图片。

不过，ChatGPT 本身是个网站，也是 OpenAI 的一个应用。那怎么拿它来做海外工具站呢？

我们公司目前的用法是这样的：

- 用 GPT 能力做 SEO 高质量内容，类似圈友二两做的 https://www.proseoai.com/ ，专门帮谷歌 SEO 获客自动生成内容。
- 做 SEM 广告词优化、落地页文案优化。
- 做社媒营销的高传播文案优化，顺便还可以用 AI 绘画配图。
- 等等。

产品服务方面：我们做在线会议，其中脑暴会议支持 AI 扩展思路，会议结束后还能用 AI 做会议总结。

开发人员也会用 ChatGPT 写代码、定技术方案。

对于 SaaS 大型 KA 项目，会用 ChatGPT 来提供解决方案。

等等。

3\. 重点来了，普通人能做哪些 ChatGPT 相关的海外工具 IDEA？

要拆解这个问题，得看几个必要条件：

- 跟 ChatGPT 相关：市场需求得跟 ChatGPT 沾边，或者 OpenAI 的能力能更快更好地解决问题。
- 普通人能做：说明实现成本或复杂度不高。

总结下来：相对 niche（利基市场），可能是信息差、认知差，还没被太多人发现。结合这些条件，我分享几个 IDEA 方向：

1）围绕巨头 ChatGPT 做补充需求工具站

思路：ChatGPT 是新兴的顶级应用，但肯定有很多利基需求没被满足，即使有 plugin 也覆盖不到。所以围绕巨头 APP 的客群，做细分人群的需求，是有市场的。

比如需求：文字交流太麻烦，能不能直接用语音跟 GPT 对话？

实现：不就是加上“文字 -> 语音、语音 -> 文字”的基础能力吗？

总结：完善了 input / output 的方式。

延伸：翻译能不能做？苹果 Siri 能不能接通？🛰️语音能不能打通？等等。

再比如 chatgpt to notion：

需求：GPT 会话会保存，但它不是知识库，得把内容存进知识库。

实现：跟知识库应用的 API 打通，提供模块，一键保存到知识库对应分类，还能打 tag。

总结：完善了 output 的最终利用闭环。

延伸：to 印象笔记、to 飞书、to xxx 都可以做。

再比如 AIPRM for ChatGPT：

需求：需要 prompt templates，怎么更好地跟 ChatGPT 做 input。

实现：收集高质量、有分类、支持搜索的 prompt 库，像 https://sharegpt.com/ 也是这个逻辑。

总结：解决了“如何用好 ChatGPT”的问题。

延伸：AI 绘画的 prompt 有没有需求？有（https://promptheroes.cn/ 目前月 UV 1 万）。更细分人群、更专业的 prompt 模板有需求吗？中英文 prompt 有需求吗？

那怎么找到这些需求？「这一期的航海文档」讲了很多挖掘方法，我是在谷歌插件里用下面这些关键词搜出来的：

- ChatGPT To xxx
- Xxx For ChatGPT

2）利用 OpenAI 能力，做细分场景的 ChatGPT 工具站

比如 chatgpt for mail messages：

需求：老外经常写邮件，用 ChatGPT 自动生成完整的电子邮件和消息，最好还能支持 Gmail。

实现：基于 Gmail 写个插件，按客户给的 prompt，输入 topic 就自动生成内容填充。

总结：解决了老外整天写 messages / mail 的痛点。

延伸：能不能 for 各大社交媒体？比如 Twitter、Facebook；能不能 for 视频平台 YouTube？

再比如：使用 ChatGPT 做亚马逊和 Shopify 的评论分析、列表优化，还有 Shopify 评论生成器。

延伸：for xxx 基本上都有需求，国内可以 for 📕内容生产，国外也一样，Amazon 也马上会有种草内容平台。

那我是怎么找到这些需求的？其实就是搜“chatgpt for xxx”。

案例一：面向程序员的代码聚合网站 @哥飞

[PRE4]

时间要倒回 2012 年。秋玉米上线一个月后的 4 月 6 日，Code4App.com 上线了。Code4App 是一个给 iOS 开发人员用的代码下载网站。最初做这个站，是因为我搭档自己就是 iOS 开发者，他以前在 Oracle 做 JAVA，iOS 也是边学边开发。

学习期间，他积累了一百多份源代码，有实现功能的，也有实现界面特效的。他发现，想找某个功能的代码，只能靠搜索引擎或者去各种论坛搜着下载，而且下载前根本不知道代码有没有用、适配哪个系统，使用方法也得花时间摸索。

他就琢磨：如果能把每份代码都测一遍，用自己的话描述代码作用、写出使用方法、附上运行效果截图，对别的开发者一定很有价值，能帮大家省时间。后来实习设计师妹子设计了第一版界面。很快，我们花了两周多就把网站做出来，把那一百多份代码全放了上去，Code4App 就有了初始内容。然后在 V2EX 发帖宣传，大家反响很好，站长 Livid 还在 Twitter 上帮我们转发。

到了 7 月份，我们做了英文版 Code4App.net。没做任何推广，只在中文版底部放了个英文版链接。过了一段时间，慢慢被 Google 收录了。接着有 iOS 开发者通过搜索引擎找到网站，觉得好用后就成了常客，还会在 StackOverflow 回答问题时贴上我们的英文版链接。外链越来越多。

中文版 Code4App 为了体验，我们很克制，只放了一段时间广告来测试点击情况。后来发现广告费不多，就把广告代码撤了。后来有人想买 Code4App，开价我们也觉得合适，就把站卖掉了。当时我们没分析英文版的广告数据，傻乎乎地把 .net 英文站也一起卖了。

中文版放广告期间累计 PV 大概 530 万，广告费才 1250 美元。而英文站从上线到卖掉，总流量约 480 万 PV，广告费却有 4670 美元。

案例五：Instagram 中的中间件 @Seep

网站名叫 linktr.ee，创始人 Alex Zaccaria 靠这个简单网站，每年赚到大量收入，而且完全是靠自然传播获取用户。

Instagram 有个“one link policy”：在 IG 里，你不能在帖子或其他地方放链接，唯一能放链接的地方只有个人 profile 里的网站。这样一来，如果想让粉丝通过不同链接跳转到不同地方，就没法实现。

这对很多 IG 网红和商家来说很不方便。比如商家有自己的 Amazon 店铺、独立站，网红要帮不同雇主带货、宣传，都希望粉丝能跳转到不同地方，但 IG 政策限制了这种行为。linktr.ee 正好抓住了这个痛点。

linktr.ee 本质上就是一个 landing page：帮你生成一个中间页，在中间页里放不同网站的跳转链接，让粉丝跳转到不同地方。linktr.ee 的 PRO 版提供了更完整的数据追踪和页面装饰功能，帮这些 IG 用户更好追踪链接效果、突出品牌特色。

linktr.ee 没有其他盈利方式，所有收入都来自用户购买 PRO 版。
