# 2.1 命令的两种形态

先聊一聊命令的分类。Claude Code 的命令实际上有两大类：

- 项目级命令（/project:）：存放在项目的 .claude/commands/ 目录里，只对当前项目生效。
- 用户级命令（/user:）：存放在用户主目录下的 ~/.claude/commands/ 文件夹，所有项目都能用。

# 2.2 自己动手写一条命令

创建过程很简单，三步就能搞定：

1. 在对应的 commands 目录中新建一个 Markdown 文件。
2. 文件名就是命令名，比如 code-review.md 对应 /project:code-review。
3. 文件里写的内容，就是命令要执行的指令。

# 2.3 内置命令速查清单

内置命令不少，我帮你整理了一下：

- /add-dir：添加工作目录
- /clear：清空对话历史
- /compact [instructions]：精简对话内容，还能指定重点方向
- /config：查看或修改配置，也可以用来做设置
- /doctor：给 Claude Code 做一次全面体检
- /login：登录账号
- /logout：退出账号
- /mcp：查看 MCP 配置
- /memory：编辑 CLAUDE.md 文件
- /model：选择模型
- /permissions：设置允许或禁止的工具权限
- /status：查看账户和系统状态
- /resume：恢复对话
- /hooks：添加 hooks 内容
- /vim：在普通模式和 vim 模式之间切换

# 02.高级工作流与自动化

1. 子代理（Sub-Agent）：让 AI 自己组队干活

# 1.1 为什么需要子代理

想象一下，你雇了一位超级助理，也就是 Claude Code 主体。助理很能干，但所有活都压在他一个人身上：写代码、查资料、测试、部署，时间一长效率就下来了。如果助理能再找几个小帮手，每人专攻一个方向，整个团队的速度和专业度都会明显提升。

Claude Code 的 subagent 功能，做的就是这件事：让主 AI 带领一支 AI 小团队，把大任务拆分成小任务，再分配给不同专长的子代理。在 agent 里跑 agent，而且子代理面向的是主代理，不是用户本人。

这样做的价值很清晰：

- 解耦复杂任务：大问题拆成小问题，分工负责。
- 提升效率：多个子代理并行工作，比单个 Claude 更快。
- 更专业：每个子代理都有自己的专注点，能把细分任务做得更深。
- 灵活扩展：可以随时新增或替换子代理，就像调整团队成员一样。

# 1.2 配置方式一：直接用提示词驱动

在官方 subagents 配置功能推出以前，直接写提示词是并行化任务的一把利器。它的优点是子代理独占上下文，可以和主代理交互；缺点是只能依赖提示词来控制，比如通过“启动多个并行子代理”这样的关键词来触发。如果只是搜索资料之类的场景，用这种方式还是值得推荐的。

1. Hooks：让自动化落地

先放一个值得参考的 hooks 仓库：https://github.com/disler/claude-code-hooks-mastery

简单来说，Hooks 就是在特定时刻由 Claude Code 自动执行的命令，相当于给 AI 助手装上了“自动驾驶”系统。

Claude Code 一共有 4 种 Hook 类型：

- PreToolUse：在工具调用前触发，可以阻止执行。
- PostToolUse：在工具执行完成后触发。
- Notification：当 Claude Code 发送通知时触发。
- Stop：当 Claude Code 完成响应时触发。

这不就是我们想要的自动化吗？不废话，直接上手。

# 四个触发时机

相当于在流程的不同阶段埋下回调，只要对应步骤完成，就会执行你配置的命令。

- PreToolUse：工具调用前触发，能够阻止调用并反馈原因。
- PostToolUse：工具调用完成后触发。
- Notification：Claude Code 发送通知时触发。
- Stop：Claude Code 完成响应时触发。
