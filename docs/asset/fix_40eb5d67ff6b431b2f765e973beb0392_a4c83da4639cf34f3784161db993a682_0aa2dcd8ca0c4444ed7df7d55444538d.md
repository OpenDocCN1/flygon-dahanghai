# 7.2.4 用 ChatGPT 写文，记住这三点

第一点：从构思到发布，一篇大约花 1～2 小时。主要卡在 GPT-4 速度偏慢，所以尽量别在夜里写，夜间不但比白天更拖，还老碰上网络故障。

第二点：照这套方法调教完 ChatGPT，大概产出 5 篇之后就建议重新调教。依据 GPT-4 API 的输入限制来推断，对话大约能保留 25000 个 token 的上下文。token 换算成字没有定论，一般认为 1000 个 token 约合 750 个英文单词，或 400～500 个汉字。5 篇加上调教内容，通常逼近 10000 字；再写下去，ChatGPT 可能就把最初调教的东西忘掉了。所以最好上 GPT-4。GPT-3.5 的上下文只有 4096 个 token，约等于每写一篇就得重新调教一次。

第三点：用 GPT-3.5 务必多调教。它记不住上下文，逻辑性也差，经常前后脱节，甚至胡编乱造。有条件就上 GPT-4；比起 3.5，它能记住上下文，逻辑和人情味都更足，等于替我们多迈了一步。

# 第二步：让文章自己进👸号后台

上一步生成的文章会保存在文件里。接着用 RPA 操作👸号完成自动发布，流程如下：

1. 登录👸号后台。用 RPA 打开网址，通过账号密码自动登录。
2. 新建图文并粘贴文章内容。可以把文章放进指定目录，让 RPA 读取后自动粘贴到新建的图文消息中。
3. 设置格式。提前定好一套固定格式，比如字体 17px、行间距 1.75 等。按钮位置固定，RPA 很容易实现。
4. 扫码发布。最后一步需要管理员手机扫码，只能人工操作。好像可以在👸号“安全中心”关闭扫码，这样就能实现全自动发布。

# 7.3.2 批量化的两个硬伤

批量操作过程中有两个重要问题：

# 7.3.3.1 先批量造大纲

故事大纲还是用 ChatGPT 批量生成，但不是让它凭空写，因为凭空写质量不行。我的方法是让 ChatGPT 模仿已有的爆文写大纲。步骤如下：
