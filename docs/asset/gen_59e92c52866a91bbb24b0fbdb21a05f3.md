# ⛵零基础如何进入【Claude Code 编程指南】项目？

# 1. Claude Code 到底是什么

一句话理解：它像住进你电脑里的编程搭子。你把目标说清楚，它负责把想法落地。

比如你说“帮我做个个人主页，放照片和自我介绍”，过一会儿页面就能跑起来；你说“每天整理的那张表能不能自动搞定”，它可以把自动化脚本写出来。

不懂技术也完全没关系。会用美图秀秀的人不必先学 PS，会用高德地图的人也不用懂 GPS；用 Claude Code 同样不需要先掌握编程。你真正要做的，是把需求讲明白。

这次航海就是给技术零基础的新手准备的，全程不堆复杂术语，而是教你用对话让 Claude Code 把需求做出来。

21 天后，你可以做出：

- 一份亮眼的个人数字名片
- 一些实用小工具，比如批量改名、图片压缩
- 简单的小型业务系统，比如预约管理、记账工具

# 2. 项目完整操作思路

## 2.1 项目推进路线

安装 Claude Code → 学会和 Claude Code 高效对话（关键）→ 实战开发效率工具与 Web 应用（关键）→ 探索全栈开发与需求挖掘。

## 2.2 关键抓手

Claude Code 是运行在终端里的代理式编码工具。它能读懂代码库，帮你处理日常任务、解释复杂代码、走通 git 工作流，从而更快完成编码。但真正的重点不是“我一个人埋头写”，而是学会“对话式编程”，而不是“独白式编程”。所以你需要理解代理的一部分原理，才能和 AI 配合得更顺。

## 2.3 新手建议与避坑指南

- 完全没学过编程，能学会吗？可以。Claude Code 的核心是自然语言交互，你只要把需求说清楚。就像用美图秀秀不必懂 PS 原理，用它也不必先懂编程原理。航海会提供大量对话模板和实例。
- 它和 Cursor 有什么不同？Claude Code 直接在终端运行，能理解整个代码库并自主执行任务，更像一个能动手干活儿的程序员；Cursor 更偏向代码补全工具。据实测反馈，Claude Code 在处理复杂任务时明显更强。
- 要付费订阅吗？成本高不高？官方 Pro 版 20 美元/月，Max 版 100 美元/月；国内也有 DeepSeek、Qwen 等替代方案。
- 生成的代码质量怎么样？它使用 Opus 4.1 模型，属于目前编程能力最强的 AI 模型之一。关键还是学会正确提问、拆解任务，航海会重点训练这些技巧。

# 1.2 为什么要学AI编程？

常言道：未来被淘汰的，是不会用 AI 工具的人。

放到时代背景里看，AI 编程是一场“新工具革命”，主要有三点。

第一，门槛急剧下降。

以前学编程，要先啃语法、调环境，往往几个月才能写出能用的东西；现在有 Claude Code、ChatGPT、Cursor，你可以直接用自然语言写出能跑的程序，零基础也能当天看到成果。

第二，工作方式在改变。

软件开发不再只是“一个人手写代码到天亮”，而是人类负责想法、AI 负责生成。未来大部分岗位，包括非程序员，都会用“AI 辅助编程”来做自动化和数据处理。

第三，竞争优势。

不会 AI 编程的人，未来用工具的效率会比别人低几个量级；会 AI 编程的人，不仅能自己做，还能快速验证想法、做副业产品。

# 2.4 Claude code的角色定位

Claude Code 本质上是 Web 开发时代的编程助手，最适合基于 Web 技术栈和跨平台技术来做开发。

从简化能力地图能看得很清楚：它最擅长的还是 Web 相关开发。

原因在于，Claude Code 生成的代码依赖开放、通用、跨平台的运行环境。Web 技术（HTML/CSS/JavaScript）正好符合这三点：JavaScript 是浏览器唯一的原生脚本语言，几乎每台电脑、每部手机都有浏览器；Claude Code 在训练中大量接触开源前端和后端代码样本（JavaScript、Python），这些生态文档和示例公开、容易学习。所以生成结果只要用户有浏览器就能运行，不需要像 C++、Java 桌面应用那样折腾复杂的本地配置。

# 3.其他科普

# 3.1 Agentic 工作流：拆解AI Agent“思考-计划-执行”的工作模式

Agentic 工作流，是由自主智能体（Agent）驱动的工作流程。它能自主理解任务（思考）、制定解决方案（计划）、按计划执行并调整（执行），必要时还会循环迭代（反思）。

Claude Code、ChatGPT、AutoGPT、LangChain 等 AI 工具，都可以在 Agentic 工作流里扮演“智能体”的角色。

# 3.2 三步核心循环

| 阶段 | 核心问题 | AI 在做什么 | 产出 |
| --- | --- | --- | --- |
| 思考（Think） | “我要解决的是什么问题？” | 解析任务、理解上下文、分析需求 | 问题定义、假设 |
| 计划（Plan） | “我应该按什么步骤来做？” | 拆分任务、制定顺序、选择方法 | 行动计划、任务列表 |
| 执行（Act） | “我具体该怎么做？” | 按计划执行、生成结果，必要时修正 | 可用结果或下一步输入 |

# 3.3 上下文协议（Context Protocol）的原理

# 什么是上下文？

在大模型里，“上下文”指的是一次对话或任务中模型能感知到的全部信息，主要包括用户输入、历史对话、外部文档、工具返回结果。它决定了模型能不能“记住”之前说过的话，能不能关联多条信息做推理。

举个例子：你可以先问学生一个问题——“如果我今天跟你说，打开 main.py，在函数里加一个打印，你知道我要改哪份代码吗？”如果学生没看过这个项目，一定会懵：“main.py 是什么？你之前写了什么？”

这就是上下文问题。人可以通过记笔记知道上次写到哪一行；AI 模型本来没有“记忆”，每次都像第一次见你。所以需要一种机制，把项目信息、环境信息整理好，每次交给模型。这个机制就叫上下文协议（Context Protocol）。

上下文协议的核心作用：

- 防止模型“断片”：没有它，模型会忘记你之前建了什么文件、用的是什么框架。
- 减少重复沟通：你不用每次都把项目结构解释一遍。
- 提高准确性：模型生成的代码会贴合当前项目，而不是给一个通用但错误的版本。

关于上下文，还有几个细节值得知道：

- 上下文的“边界”：模型的上下文受上下文窗口大小限制，比如几万 Token。上下文协议的价值之一，就是在有限窗口里组织最关键的信息，避免无关内容挤占空间。可以顺带说一句：人类能长期记忆，而大模型的记忆更像一块有限的短时黑板。
- 上下文协议的“协议性”：它为什么叫“协议”？因为它不是随便拼接，而是有一套标准化数据格式，规定哪些信息要交给模型、怎么交。类似 TCP/IP 定义了包的格式，上下文协议定义了上下文信息的“打包和传输规则”。这样不管 Claude 还是别的 IDE 辅助工具，都能遵循这套协议来“接力”。
- 上下文协议的“动态更新”：它不是一次性给一堆信息，而是会随任务过程不断刷新。比如你刚新建了 login.py，协议会立刻更新，让模型知道多了这个文件。这也是它能保证对话连续性的原因。
- 与“长期记忆”的区别：有人会问，上下文协议是不是模型的长期记忆？可以这样区分：上下文协议是短期连续对话的上下文管理，确保这几轮能对上；长期记忆是跨会话存储，下次打开 IDE 还能记得昨天做的项目。
- 一个直观的专业比喻：机场广播。你在机场换了登机口，广播会实时把新信息告诉所有乘客。上下文协议就像“广播协议”，确保模型随时拿到最新的“登机口信息”，不会跑错地方。
