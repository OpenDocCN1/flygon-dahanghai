2. 用 Skill 提升开发效率

Skill 究竟是个什么？

用一句话说，Skill 就是给 AI 装上的外挂指令，相当于一段可以触发外部软件动作的脚本。Skill 里面还会附一份 Skill.md 说明，一般以 Markdown 形式放在提示词或配置文件中，告诉 AI 工具叫什么、怎么用、调用时要传哪些参数。

这次开发要用的 Skill 是 Ui-ux-pro-max-skill。

它能带来三方面帮助：

1. 自动做设计方案：AI 会根据项目需求，直接产出一套设计规范，把排版、配色、字体、动效全部涵盖，并自动拦掉不合理的设计。

2. 内置丰富素材：支持 67 种界面风格（极简、暗黑等），搭配上百套行业级配色和字体组合；强制遵循 99 条 UX 最佳实践，让界面达到商业标准并满足无障碍要求。

3. 技术栈覆盖广：兼容 13 种主流前端框架。做 Web 端可用 React、Vue、Tailwind，做移动端可用 SwiftUI、Flutter，都能生成对应框架的规范代码。

1. 为什么选电子木鱼

先聊需求判断。我在🛰️里用「木鱼」做关键词搜索，发现已经冒出好几个类似小程序，说明用户需求是实打实存在的。但挨个点进去体验以后，感受很一致：界面比较粗糙、动效不够自然，广告几乎占满了整屏。

[PRE28]

有人需要、有人正在用，而且现有产品普遍不好用——对标法的三条标准都满足了，这是一个值得投入的方向。

再说，电子木鱼的功能结构非常简单：一个页面、一个点按动作、一个计数显示。这样的项目对刚入门的人再合适不过，不需要纠结页面数量或功能数量，把这一下交互做好即可。

还有个常见的疑问：排行第一的功德木鱼已经做得挺好，有 1000+ 人在用，再做一个有必要吗？

说说我的判断。第一，建议先把前五名同类产品都实际体验一遍，不要只看截图就觉得漂亮。真正点进去用一下，音效是不是真实、广告会不会烦人、加载速度快不快，立刻见分晓。多数产品都是“看上去不错，用起来普通”。第二，这类产品的用户来源主要是内容传播，而不是主动搜索。很少有人会专门打开🛰️去搜「电子木鱼」，更多场景是：在📕刷到“深夜敲木鱼攒功德”的帖子觉得有趣，或者看到朋友圈有人晒「今日功德 +9999」的截图，因而产生好奇。

想跑出来，关键在两件事上。一方面让产品自带晒点：功德数字要够醒目，界面要有画面感，如果能加排行榜或成就系统，用户截图分享时就有底气，传播性自然就来了。另一方面，在📕、抖音等平台做情绪向内容。“考研前一天敲了一万下木鱼”“加班到凌晨三点，敲了一会儿竟然平静下来”——这走的是情感共鸣路线，看完很容易触发体验欲望。

坦白说，市面上多数同类产品只做了产品，传播这一环几乎空缺。先把产品打磨到八十分，再把传播做扎实，突围的机会就很大。
