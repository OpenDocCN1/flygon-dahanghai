### 2. 项目完整操作思路

#### 2.1 整体推进方式

这趟实战用 AI 开发的方式来搭内容工厂，核心做法是通过自然语言和 Claude Code 等工具对话，让开发过程一步步往前走。

装好并配置完 AI 开发工具后，先和 AI 反复沟通、把需求说清楚，再生成页面原型；接着按照“数据采集—选题分析—内容创作—发布管理”四块，逐块把功能实现出来。

每一块都走同一个循环：说需求 → AI 出方案 → 确认方案 → AI 写代码 → 测试。碰到错误，直接把浏览器控制台里的报错交给 AI 修，最后靠人机配合，快速完成从 0 到 1 的产品开发。

整个过程中，人负责产品方向和关键决策，AI 负责把代码敲出来。

#### 2.2 操作重点

环境准备与工具配置 > 搭建选题采集和分析 Agent > 开发 AI 内容二创与多平台适配 > 打通👸号、📕官方发布接口与分发 > 系统集成与工作流优化。

### 1. 让模型参与写代码，到底是怎么回事

最近半年，Vibe Coding 这个概念彻底火出了圈。今年 2 月初，OpenAI 联合创始人 Andrej Karpathy 在社交平台上提出这个想法，仅一个多月，就在开发者圈层引发了不少讨论。它之所以能火，确实有道理：编程的准入门槛被真正降低了。

过去，要把一个想法变成能用的产品，需要专门的程序员来完成需求。现在情况变了。

即使你对代码一窍不通，也能借助 AI 开发工具，把想法快速落地。这种变化不是小幅改良，而是颠覆性的重构。

在赚钱，我们见过很多生动例子。不少伙伴从没写过一行代码，却靠 Cursor、Claude Code 这类工具，实实在在做出了自己的应用：有人开发海外工具站，有人搭建自动化工作流，还有人做出了能赚钱的小程序。

这背后的差距，已经不只是效率高一点。会用 AI 开发的人和不会用的人，生产力可能相差十倍甚至百倍。一个懂得和 AI 协作的人，可以在一天内完成过去一个小团队一周的工作量。更关键的是，这种能力正在重新定义“谁能创造价值”：技术不再是壁垒，想法和执行力才是。

你不再需要把 80% 的精力花在写代码上，而可以专注真正重要的事：创意、产品设计、用户体验。代码实现交给 AI。你负责想清楚“要做什么”和“为什么这么做”，AI 负责“怎么做”，从而大幅解放时间和精力。

这次实战，大家可以一起感受 AI 编程的魅力，用 Claude Code/Codex 等工具，打造属于自己的内容工厂 Agent。

### 2. 老办法与 AI 协作法对比

老派写代码和借助模型写代码，底层是两套截然不同的协作逻辑。

过去想成为开发者，得先翻厚厚的编程书，啃下复杂术语和概念，再折腾各种框架配置。学习周期往往半年起步，时间成本高得惊人。很多人就是在这个阶段放弃的，不是因为不够聪明，而是这条路太陡。

AI 时代改写了规则。现在最核心的能力不再是记住编程语法，而是学会和 AI 对话。你要做的是清晰描述需求，用最自然的语言告诉 AI 你想要什么。AI 会根据描述生成代码，给出多种实现方案。你的工作变成从方案中挑出最合适的，然后继续对话，比如“这里的逻辑能不能调整一下”“能不能加个导出功能”。就这样一轮轮迭代，项目在你和 AI 的协作中逐渐成型。

下面从几个维度对比传统编程和 AI 辅助编程：

| 比较项 | 传统开发 | AI 协作开发 |
| --- | --- | --- |
| 工作起点 | 人写代码、定流程，逻辑由开发者拍板。 | 人把目标说清，模型出代码、补全或优化建议，形成人机配合。 |
| 写码负担 | 算法、接口、结构、细节都要从零铺。 | 重复和模板部分交给模型，人盯需求、验收和把关。 |
| 能力侧重 | 语言熟练度、算法、架构、逻辑思维。 | 除基本功外，还要会提问、会检查模型产物、会管理生成出来的系统。 |
| 推进速度 | 结构清楚的项目稳定，但重复劳动拖时间。 | 样板代码、重复逻辑、原型阶段提速明显。 |
| 质量风险 | 责任链清晰，代码易追溯。 | 产出快，但大项目里可能混入难读、冗余、隐藏 bug 或安全漏洞。 |
| 入门难度 | 语言、算法、工程思维都要花时间，新手爬坡慢。 | 新手更快看到能跑的代码，边做边学，门槛降低。 |
| 适合任务 | 高复杂、需求模糊、要创新且质量要求高的项目。 | 重复任务、快速原型、标准模块、初稿和效率优先场景。 |
| 工具形态 | 传统 IDE 加手写或模板代码。 | 代码生成、补全、语义检索、错误检测、自动测试等工具越来越常见。 |

### 3. 项目涉及的关键技术

💡 这趟实战的核心目标，是构建一个 AI 驱动的内容工厂 Agent，它包含三大核心能力：选题洞察、内容二创和快速发布。

整个工作流会涉及这些环节：

数据获取层面，根据关键词抓取👸号文章和📕笔记；

选题分析阶段，用大模型对采集内容做深度洞察；

内容二创环节，基于筛选出的优质选题进行文章创作；

最后调用官方认可的 API，实现笔记或图文的自动发布。

实现路径的本质，是把可靠的数据源、稳定的大模型服务和各平台的发布能力，用清晰的工程化方式串起来。

为了让大家更容易上手，我们选择了依赖少、门槛低的实现方式。

接下来介绍项目涉及的一些技术。这里会出现一些专业术语，但不用有心理负担。我们不需要深入研究每项技术的底层原理，只要理解它们在项目里起什么作用、解决了什么问题、处在流程哪一环即可。

#### 3.1 Next.js：项目开发框架

Next.js 是一个轻量级全栈开发框架，学习曲线平缓，能同时处理前端界面和后端逻辑，很适合快速构建完整应用，新手也能较快上手。这也是我强烈推荐它作为本次实战开发框架的原因。

这里解释一下“全栈开发框架”。传统开发模式下，做一个网站要分别学两套技术：前端负责用户看到的界面，比如页面、按钮、表单、布局；后端负责后台数据处理和业务逻辑，比如用户登录、数据存储。很多时候前端用 React/Vue，后端用 Node.js 或 Python，需要掌握两套完全不同的知识体系。

Next.js 的强大之处在于，它把前后端整合在一起，用一套技术就能同时搞定用户界面和后台数据处理，大幅降低学习成本，对新手更友好。

#### 3.2 SQLite：本地数据库选择

说到数据库，你可能听过 Supabase（基于 PostgreSQL）、MySQL 等选择。但为了降低学习成本、避免依赖外部服务，帮助大家快速搭起内容工厂，我们选了 SQLite 这个完全本地化的数据库方案。

可以把它理解成装在你电脑里的 Excel：所有数据都存在本地文件中，轻量且读写快速，适合个人使用或小规模项目。它的优点是配置简单，不需要安装独立的数据库服务器，打开就能用，基本不需要额外学习数据库概念，使用起来几乎无感。

Supabase（Postgres）则是功能更强的企业级数据库，需要独立运行，支持更复杂的查询、更高的并发访问（多人同时使用）以及更大的数据量，但使用起来略复杂，前期配置也更繁琐。

所以这次先用 SQLite 把流程跑通。等你的内容工厂真正运转起来、数据量增大，或者需要云端部署时，再升级到 Supabase。这样既能快速起步，也为未来扩展留了空间。

#### 3.3 API：打通外部服务的通道

API 是“应用程序接口”的缩写，可以把它理解为一个标准化的服务窗口：你发出清晰请求，对方按约定返回结果；内部怎么实现，不需要关心。API 把原本要手动复制粘贴的流程，变成可编程、可批量、可定时的任务。

这次实战会大量使用外部 API，比如👸号采集 API、📕采集 API、大模型 API 以及内容发布 API 等。从更宏观的视角看，一个在线产品也可以理解为多个 API 的组合与功能包装。

简单理解，API 就是不同服务之间沟通的接口，让我们能调用别人已经开发好的功能。

#### 3.4 项目中可能用到的 API 平台

**大模型 API：**

在本次实战项目中，AI 能力贯穿内容生产流程的多个环节。我们需要 AI 对采集到的👸号文章做深度分析，挖掘选题价值和爆款要素；需要 AI 根据选题自动撰写符合平台调性的内容初稿；还需要 AI 生成配套插图和封面，让内容更有视觉吸引力。要实现这些功能，就必须调用相应的大模型 API。

硅基流动（siliconflow.cn）：一个开源模型聚合平台，提供大量免费或低价的开源大模型 API 接口。本次实战中，内容创作环节的图片生成功能就采用了硅基流动免费的可灵模型。

DeepSeek（platform.deepseek.com）：国内性价比较高的商业大模型服务之一。它的 V3.1 版本在推理能力、代码生成、长文本理解等方面表现不错，价格却只有 GPT-4 的几十分之一。对于我们这种大量生成内容的场景来说，是性价比很高的选择。

火山方舟（volcengine.com）：字节跳动旗下的企业级 AI 服务平台，提供豆包等大模型 API 接口。它的优势是服务稳定、响应速度快、性价比也不错，而且豆包家族覆盖文本模型、图像模型、视频模型等多种类型。

OpenRouter（openrouter.ai）：手册中主要使用的平台，是一个大模型聚合服务，把 GPT 系列、Claude、Gemini 等几十个主流模型整合在一起。你只需要接入 OpenRouter 一个 API 接口，就能调用这些模型。

本次手册主要使用 OpenRouter，大家也可以根据自己的实际情况选择。

**数据采集 API：**

数据采集 API 是内容工厂自动化的第一环。可以把它理解成一个不眠不休的搬运工，帮我们批量获取各平台的内容数据。

以👸号采集 API 为例，你只需提供一个关键词或👸号账号名称，就能通过 API 自动获取该👸号的历史文章，包括标题、正文内容、发布时间、阅读数、点赞数等完整信息。原本需要一篇篇手动复制粘贴的工作，通过 API 几秒钟就能批量完成。

本次实战会使用 https://dajiala.com/ 平台的👸号采集 API，支持按关键词搜索👸号文章。

除了 https://dajiala.com/，市面上还有很多数据采集 API 平台可选。例如 apify.com 就是一个功能强大的通用采集平台，可以采集 Twitter、Instagram、YouTube 等几十个海外平台的数据。如果你未来要做跨平台内容分析或出海业务，apify 值得考虑。

**内容发布 API：**

如果说采集 API 是内容工厂的原料入口，那发布 API 就是产品出厂的最后一公里。内容发布 API 能把生成好的文章、图片、视频自动发送到目标平台，省去手动登录、复制粘贴、排版调整这些重复劳动。

以🛰️👸号为例，通过调用👸号发布接口，程序可以自动完成文章发布。

在我们的项目中，会使用 wx.mgxingyuan.com 实现🛰️👸号自动发布。这个平台封装了👸号复杂的 API 接口，让发布流程变得简单，你只需要传入标题、正文、封面图等参数，就能通过 API 发布。

📕发布则使用 note.limyai.com 平台，它采用生成发布链接的方式来发布笔记。

其实也可以这样理解：整个项目就是在串联和包装各种 API，最终组合成一个完整的自动化内容生产系统。

### 4. Claude Code 与 Codex 如何取舍

两者都是目前很受关注的 AI Coding 工具。Codex 速度慢一些，但代码质量可靠，定位问题和修改 Bug 的能力很强；Claude Code 响应快，前端审美和从 0 到 1 的能力比 Codex 更好一些，不过最近幻觉偏高，也一直有降智的质疑。
