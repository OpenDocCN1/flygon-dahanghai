# 2.3.3 知识库

扣子允许上传私有数据（例如本地文件或实时在线数据），再通过向量检索提取最相关的内容，让回答更精确。

# 2.3.3.1 认识知识库

大模型通常只基于公开语料训练，并不包含某个特定领域的内部资料。比如模型不会知道你公司的制度，也不了解你项目的具体进度。

但只要配置了私有知识库，模型就能只依据你提供的材料来作答。把公司制度、项目纪要等整理成知识库，之后关于制度或项目的问题，大模型都能据此给出答案。

这样一来，知识库能有效缓解大模型“一本正经胡说八道”的幻觉问题，同时填补专业领域知识的空白，让回答的准确率进一步上升。

# 2.3.3.2 知识库Bot的原理详解

大模型的上下文长度是有限制的，因此上传的资料会先被切分。假设一篇文档有8000字，每800字切一段，就会得到10个片段并分别保存。

当用户提问时，系统会按相似度把最相关的几个片段取出来，再基于这些片段生成最终答案。这套机制就是业界常说的RAG（检索增强生成）。

💡 使用限制

每个用户最多创建1000个知识库；文本型知识库最多挂载100个文档；每位用户每月最多新增2GB数据，所有知识库累计不超过10GB。

各配置项含义如下：

- 搜索策略：决定知识库内容片段的检索方式，召回片段的相关性越高，最终回复就越准确和可用。
  - 语义检索：像人类一样理解词句间的语义关系。适合需要语义关联或跨语言查询的场景。例如，“狼追小羊”和“豺狼追山羊”的语义关联度，远高于“狼追小羊”和“我爱吃炸猪排”。
  - 全文检索：基于关键词查找。适合查询特定名称、专有名词、术语、缩写词或ID等场景，例如“比尔盖茨”“特斯拉 Model Y”“SFT”“12s1w1s2系列”。
  - 混合检索：融合全文检索和语义检索的优点，对结果综合排序后再召回。

- 最大召回数量：指定从检索结果中返回多少个内容片段给大模型使用。数值越大，返回的片段越多。

[PRE33]

- 最小匹配度：只返回达到设定匹配度的内容片段，低于该阈值的结果会被过滤掉，有助于剔除低质量匹配。

[PRE34]

提示：最大召回数量和最小匹配度会直接影响输出效果，建议两者协同多轮测试，找到最优参数。

# 2.3.4 记忆能力

Coze提供持久化记忆能力，让Bot能够记住用户的对话内容和重要信息。这项能力包含三部分：

- 变量：通过创建变量保存用户个人信息，例如姓名、语言偏好等，让Bot记住这些特征，使回复更加个性化。
- 数据库：按需增删改查数据，在工作流中可通过NL2SQL方式和代码方式调用。
- 长期记忆：自动记录并总结对话信息，在回复查询时召回这些总结，再生成最终答案。工作流中用不到，这里不做深入讲解。
