## 1. 核心节点分类与功能

这一部分不要求背下来，只是让你对搭建过程中常见的入口和执行组件有个印象。建议配合第三章第 1 节【完成你的第一个 n8n 工作流（AI Agent）】边操作边理解。

————————————————————————————————————————

一条流程由两类角色构成：

- 触发节点：流程入口，决定何时、以何种方式启动；每条流程只能有一个。
- 动作节点：入口被激活后执行任务，例如处理数据、发送请求、调用模型；数量不限。

# 1. 触发节点

Manual Trigger（手动触发）：开发测试阶段最直接的方式，点 “Test workflow” 或 “Execute workflow” 即可立刻运行一次。

[PRE2]

Schedule Trigger（定时任务）：让流程按预设时间自动运行，可精确到分钟、小时、天、周，甚至指定日期；内部依靠 Cron 表达式。

Webhook（网络钩子）：生成专属链接；外部应用向这个地址发起 HTTP 请求（一般是 POST），流程立即被唤醒，同时收到请求携带的数据。

[PRE3]

Email Trigger（邮件触发）：绑定 Gmail、Outlook 等邮箱，新邮件到达后自动启动，可读取发件人、主题、正文、附件。提示：较新版本可能把它整合或改名，例如改用 IMAP 节点，本质仍是监听收件箱。

[PRE4]

On chat message（聊天消息触发）：面向聊天机器人。将 n8n 聊天窗口嵌入网站或应用后，用户发出第一条消息即触发，并捕获输入。

[PRE5]

实战场景：搭一个 n8n 版聊天机器人。用聊天消息触发作为入口，三个组件即可：On chat message、AI Agent、DeepSeek Chat Model。在 AI Agent 里，把 On chat message 的 chatInput 设为 Prompt。

AI Agent 像“大脑”或“调度员”：它不直接产出文字，而是管理对话流程——接收 Prompt、按需调用工具、借助大语言模型判断下一步，最后汇总输出。

[PRE6]

模型侧选择 DeepSeek Chat Model。它负责接收 Prompt，并调用 DeepSeek 的能力生成文本。

Set（原 Edit Fields）：最常用的数据处理节点之一，增、改、删字段都靠它。可以保留原始输入并新增字段，也可以直接改值，或删除不需要的字段。示例把“姓名”“年龄”改成 name 和 age。

[PRE14]

[PRE15]

[PRE16]

Function/Code：一个“万能节点”。当内置节点不够用时，可以用 JavaScript 或 Python 自由处理数据。

[PRE17]

[PRE18]

[PRE19]

Merge（合并）：把从不同分支流过来的多路数据汇成一条。常用模式是 Append 和 Combine。

[PRE20]

Append：按顺序拼接两路条目——先排 Input 1，再接 Input 2，不比较、不去重。Combine：按指定 key 字段，把两路中键相同的条目合成一条；没匹配上的默认不输出。

逻辑控制类：

IF：条件判断，符合条件的放行，不符合的拦截。

[PRE21]

Switch：多路径分发，根据条件把数据送到不同分支。

[PRE22]

Loop Over Items：对输入逐条重复同一套操作。

Wait：让流程暂停一段时间再继续，适合 API 限频、等待外部系统处理完成、定时发提醒等场景。

[PRE23]

热门官方集成节点：

HTTP Request：向任何支持 HTTP 协议的服务发请求，例如取第三方 API 数据、给 webhook 发通知、对接自建系统。

Google Sheets：读写、更新表格数据，可自动同步、生成报表、从表格触发操作、汇总数据。

[PRE24]

Slack/Discord：向团队频道发消息，常用于系统告警、任务完成提醒、数据报告推送、流程状态通知。

[PRE25]

OpenAI/ChatGPT：接入模型做文本处理与内容生成（也可用 gemini 节点）。

[PRE26]

社区节点：例如飞书相关组件，可从社区获取。
