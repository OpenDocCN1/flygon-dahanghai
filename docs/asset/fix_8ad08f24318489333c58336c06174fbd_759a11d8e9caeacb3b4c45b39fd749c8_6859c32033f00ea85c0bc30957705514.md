# 章节概要：

本章把航海的核心使命讲清楚：

21 天内，从完全不会到让第一款 iOS APP 落地，并试着跑通付费下载或订阅这一变现路径。

选择 iOS 应用市场的道理也很硬：审核快、用户花钱意愿足、备案流程不复杂、成本盘子相对稳定。

借 AI 开发的妙处在于：一行代码都不用会，研发时间被大幅压缩，

注意力可以挪到捕捉用户诉求和打磨产品设计上。

执行时推荐小步走、多模块拆分、AI 与人工配合推进，

说到底 AI 只是件工具，关键的判断还得人来做主。

# 1.1 项目介绍

# 1.1.1 航海目标

基础版目标：大约三周，从一无所知到把首个 iOS APP 送上架。

进阶版目标：试着跑通付费下载或订阅这类变现方式，最好能赚到第一笔 APP 收入。

# 1.1.2 为什么选择开发 iOS APP

iOS 应用市场的加分项：

审核门槛低、流程快，通过后即可向全世界分发，对个人开发者相当友好

用户的付费意愿普遍偏高，iOS 生态也已经成熟，订阅、内购、买断三条路子都走得通

多数 APP 提交时无需 ICP 备案、APP 备案，也省了软著（安卓上架必须办，200—300 元一张，前后要等 3—4 周）

开发者只需付 99 美元（约 688 元）的年费，上架越多，边际成本就越被摊薄

有一定进入门槛：得有一台 Mac、一部 iPhone，还要交 99 美元/年的开发者年费

整个开发过程中，不用装配繁杂的环境与依赖

# 1.1.3 为什么要借助 AI 开发

一行代码都不会写，也能靠 AI 做出 iOS APP

学习的门槛被削平，注意力可以省下来放在理解用户、设计功能和梳理产品逻辑上

研发耗时被极大压缩，最快两三个小时就能攒出一个 demo 拿去市场试水

# 1.1.4 总体方法论

小步快跑：先跑出最小可用版本（MVP），别一上来就贪大求全。

分块推进：功能一复杂，就拆进多个 Composer/Chat 里，一部分一部分落地。

AI 搭配人工：不能对 AI 言听计从，关键逻辑和 bug 修补终究要靠自己去跑、去判断、去复盘。

# 2.3.2.1 基本使用：Xcode 如何与 AI 编程工具联动开发 APP

第一步：点 Create New Project 新建项目，先在应用类型里选默认项，项目名称可按拼音或英文来填；Organization Identifier 栏里写 com.xxxx.xxxx，注意域名要反过来，com. 排在最前面。例如我项目叫“yuyin3”，注册的域名是 cuanxue.com，那这里就填 com.cuanxue.yuyin3。后面每次建新项目，这块信息也会用在 APP 上架创建 APP ID 的时候。

第二步：启动 AI 编程工具，打开项目根目录。yuyin3 里的第一个文件夹正是刚在 Xcode 建好的项目；我们需要打开的是 yuyin3 目录中的 yuyin3 子目录，那才是根目录。Cursor 之后生成的所有代码文件都必须落在这个目录下，打包编译才会生效。

# 2.3.2.2 基本使用：Xcode 项目文件作用

Xcode 建好项目后会出现一组目录，其中排在第一个的才是项目根目录。

1.

ContentView 文件：主视图文件，可以把它当作打开 APP 后看到的第一个页面；Xcode 初始化后，文件里会自动写入“hello world”字样。

# 💡

在 Composer 模式下，第一次生成代码时要 @ 引用 ContentView 文件

2.

yuyin3APP 文件：应用容器，打包编译到手机后装上的就是它（打包时会囊括项目全部资源）

3.

Assets 文件：用来上传 APP 图标和图片素材，格式支持 Png / jpg（上传前最好先把图片压缩一下）

4.

yuyin3：应用权限的配置文件

5.

Preview Content > Preview Assets 文件：存放预览内容，上架打包时不会带这些图片，只在预览、测试环节展示
