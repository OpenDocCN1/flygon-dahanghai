# 视频链接该进哪个字段

先说关键点：调用视频生成接口，服务器并不会把成片文件塞给你，回来的只是一条以 http 开头的地址。既然到手的是一串字符，表格里就得准备一个能装字符串的位置——文本字段。要是顺手选了"附件"列，数据类型对不上，接口一返回就报错，后面的自动化流程也会连带着跑不下去。

**字段配置操作**

把第三列原本的日期字段先清掉，再点这一列现成的【附件】，在类型清单里改勾"文本"。这样做的用意，是让列的存储方式与接口实际回传的数据结构（String）对齐，避免容器选错拖垮自动化的运行。

列名可以改成"视频链接"，也可以维持"附件"不动。比名字更重要的，是把含义写清楚：这一列收录的是能点开观看的访问地址，谁看表格都能一眼明白。

按确认保存即可。等到自动化执行到"修改记录"那一环，结果才有地方落地。

提醒一句：第三列承载的是文本，用来收录海螺或别家工具产出的视频地址。

## 2.3 工作流搭建

表格这一侧的字段打点完毕，接下来就是重头戏：把自动化工作流拼起来，让原本只会存数据的表格，也能承担一整套业务逻辑。

### 2.3.1 创建工作流

点开工作流，相当于进入一个可视化编排界面，逻辑都在这里一层层画出来。之所以不套模板、选"从空白开始"，是因为我们的需求要对接指定第三方 API，还要做字段映射，模板自带的预设逻辑反倒添乱，一张白纸配置起来最自由。

操作：找到左侧导航栏最下面的工作流图标点开，在弹窗正中间按"从空白开始"按钮。于是你得到一个没有任何预设的画布，后面的触发器和动作才有地方摆放。

### 2.3.2 配置触发器

触发器负责"听"，专门捕捉用户在表格里按下按钮的动作。为什么挑"点击按钮时"？因为它把启动权交回给人：只有你亲手点了"生成"，流程才被唤醒，API 的花费因此可控，误碰也不会白白消耗额度。

操作：菜单里找到"点击按钮时"并选中。系统由此知道，唤醒信号来自一次点击，而不是某条记录被改动。

[PRE19]

[PRE20]

进入详情页，把按钮类型指定为"按钮字段"，数据表下拉选当前这张，下方列表里勾上"生成"（也就是 2.2.2 节做好的那个）。触发器与具体按钮拴在一起之后，只有点中这一列，程序才会去读当前行的数据、开始跑流程。

选好按钮字段，选好表格，再让"生成"这一列与按钮对上。

### 2.3.3 配置 AI Agent 节点

AI Agent 是一层智能加工：用户随手写的一句话，经它扩写，变成带细节、光线与构图的完整描述。视频模型对描述精度相当挑剔，只拿几个干巴巴的词去生成，画面往往空洞、缺少层次；中间多这么一道整理与规范，成片效果会明显不同。
