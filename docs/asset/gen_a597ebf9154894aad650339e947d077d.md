# 1.1 项目背景与前景

## 1.1.1 为什么值得做“AI + Web 开发”？@彩笺

网站是产品的一种形态。我对出海建站的理解，可以压成八个字：发现需求，交付需求。

过去，建站门槛很高，大家的目光更多放在“满足需求”上，而满足需求需要一项硬技能——写代码。所以程序员日子过得不错，因为他们掌握了多数人不会的能力。规模大一些的公司，部门和产品都多，他们怎么做产品？简单说：产品经理负责前半句——找到需求；程序员负责后半句——满足需求。

时间来到2025年春天，AI能力上来了，“满足需求”这一段越来越容易。刘小排老师之前的帖子里也说过：只靠想法就能赚钱的时代到了！

## 1.1.2 赚钱空间有多大？@彩笺

在大家做第一站之前，先真实看看前景。我见过只靠流量广告费月入近5万美元的网站；也见过靠用户付费订阅、日入1000美元的AI工具站。出海几乎是变现天花板最高的方向，甚至可能没有之一。赚钱就有很低调的大佬，零编程经验，去年月入万刀。想赚到这些钱，你只需要做一件事：找到需求，满足需求。

💡 @良辰美：

不断上线网站的过程，就是反复找需求、满足需求的过程。

对新手来说，“找需求”稍难，它更吃产品经理和用户调研相关的能力。AI可以辅助你找需求，但核心动作仍靠你的洞察，取决于你对需求的敏感度；有产品经理、用户调研方面的认知和经验会很有帮助。

AI现在几乎能帮你完成“满足需求”，也就是做出MVP，快速验证你找到的需求是不是真的。AI写的代码偏初级，但基本可用。在AI帮助下，一个有基本识字能力的人就能做出网站或APP。新手要跨的第一道门槛，是把一个网站做上线，而且越熟练越好。

新手还要破除对代码的恐惧，因为你不必看懂，让AI给你复述就行。

新手初期重点任务，是熟悉网站怎么上线，也就是域名注册、网站托管、代码托管这三类平台。选项和方法很多，这里只举最简单的一种。

怎么找需求并满足需求？很多人以为要不停调研，或者一直打磨产品。真实可行的路线是：在上线产品的过程中验证——需求有没有找到？是不是真需求？有没有被满足？能不能靠收费来满足？

所以“找到需求，满足需求”的含义，可能就是快速上线网站。只有大量MVP验证，你才能尽快找到并满足需求。

干耗着读实战手册，或者在互联网上乱逛，也许有助于找需求，但不执行、不上站、没有MVP，就无法验证需求，也就没有钱赚。

对什么都不懂的新手来说，可以照着手册里粗糙的示例网站，零基础快速上线第一个Web网站。这里提一句：找需求、满足需求时，哪怕网站很简陋，也能赚不少钱，比如diskprices.com，这也是我的亲身经历。

写下这句话的我，零基础编程经验。用AI搭的简陋网站快速满足需求时赚到的钱，远比我花几万块找外包团队优化精美网站赚得多。

所以新手别怕过程复杂，更别怕什么都不懂，先照着步骤上个站。哪怕先做个“垃圾”出来，在不断优化和上站的过程里，也能挖到宝藏：找到需求，满足需求。

有一定基础的程序员或老站长，可能觉得本篇太简单，请移步往届实战手册，重点关注进阶版：AI工具站。可参考《9月航海 | 出海工具站 | 实战手册》《3月航海 | 出海第一站 | 实战手册》。

# 2.1 网站的基本组成

## 2.1.1 域名（Domain）：它是什么、去哪儿买？@彩笺

域名就是大家嘴里说的网站地址，baidu.com就是百度的域名，也是网站的外部入口。想一想，别人得知道你的地址才能找到你。域名全球唯一，通过这个名字能找到你，也只能找到你的“地址”。我建议去cf（Cloudflare）购买。市面上卖域名的平台很多，cf对开发网站最方便。域名可以等网站实现之后再买，不着急。

## 2.1.2 服务器（Hosting）：云端部署是什么、有哪些免费托管平台

服务器是承载你运行代码的空间。你自己家有地址，也得有对应的房子。现在很多免费平台可以部署代码、托管网站，比如Vercel、Cloudflare、Netlify等。大多数平台部署步骤相似：+MM188166M（李李）长期更新

1. 注册账号；
2. 上传网站文件，或关联GitHub仓库；
3. 一键部署后获得访问网址；
4. 如果有自定义域名，还能在平台后台绑定。

## 2.1.3 代码（Code）：网站的核心灵魂，静态页与动态页有何不同

网站的外观和交互能力，最终都由代码定下来。可以把它想成菜谱，决定了你做出来的美食味道。

静态网页给每个访客看同一套内容，像一份印好的报纸。优势是打开快、相对安全、部署简单、成本低。适合个人博客、作品集或公司官网。

动态网页会随操作、登录状态变化，像聊天软件一样随时刷新。优势是功能更丰富，能实现登录、评论、购物车等；但需要数据库和后端配合，开发更复杂。适合电商、社交等带用户系统的站点。

第一次做网站，可以先从静态网站上手，熟悉流程后再尝试动态功能。

# 2.2 编程语言入门常识+MM188166M（李李）长期更新

## 2.2.1 HTML/CSS/JavaScript：零基础该抓住哪些关键点？

网页可以类比成一个人：HTML负责搭骨架，页面上有哪些元素——标题、段落、图片、链接、按钮——都由它安排，关键概念是标签、属性、嵌套；CSS负责外观，排版、配色、尺寸、字体都归它管，核心是选择器、属性、值；JavaScript负责大脑，让页面能交互、能动态反馈，比如按钮点击后弹提示、表单填写时校验、动画播放等。

## 2.2.2 前端和后端，怎么简单区分

前端是浏览器里用户看得到、点得着的部分，包括页面布局、视觉效果和交互逻辑。主要用HTML、CSS、JavaScript，就像餐厅的大堂和菜单。

后端跑在服务器上，负责数据存储、用户认证和业务逻辑。常见语言有PHP、Python、Node.js等，就像餐厅的厨房和仓库。

## 2.3.3 还有哪些AI工具：bolt.new、trickle.so、GitHub Copilot等

## 2.3.4 本地环境怎么配（Node.js、npm、Git 简装入门）

1. Node.js：像一个专门“播放”JavaScript代码的工具。以前通常只能在浏览器里运行JavaScript，有了Node.js，你的电脑就能直接执行JavaScript程序。
2. npm：装软件的“应用商店”，帮你下载别人写好的代码模块，不用自己重新造轮子。

三者关系：Node.js是环境，npm是在Node环境中获取工具的方式，Git负责记录代码变化历史。

# 2.4 怎么让AI替你写代码、改代码？

如果AI反复给的结果都不合意，可以先让AI帮你总结一下，再新建会话，重新描述问题所在，重新问AI解决；或者换大模型，比如Claude、ChatGPT、Deepseek，让它们相互参考着尝试。

## 2.4.1 向AI提需求时，提示词抓住什么

先说你自己的话：不要给自己设限，你想做什么就写什么，哪怕杂乱无章、前后矛盾。跟AI不断交互的过程中，你的想法会逐渐清晰，在不断总结中，提示词也会越来越全面、结构清晰。

也可以上结构化写法：有圈友喜欢用格式规则的提示词，包含技术架构、背景角色、目标输出等。熟练掌握一套自己总结出来的提示词，有助于提高跟AI沟通的效率。

## 2.4.2 AI给出代码后，本地怎么简单测试

如果是HTML代码，可以直接在浏览器打开查看网页内容和源代码，推荐用Notepad++这种轻量化富文本编辑器修改，或者直接在github.com仓库的代码文件里改。

如果是next.js这类带后端、多组件的代码，我其实很少在本地调试。没有编程基础总会搞错，只能依赖AI不断截图和询问，复制它给出的代码做测试。
