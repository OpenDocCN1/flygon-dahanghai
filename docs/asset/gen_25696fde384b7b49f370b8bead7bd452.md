# 2.4 Coze 工作流拆解

搭建工作流这件事，按时间线可以切成三个阶段来看。

# 2.4.1 规划阶段：

先把关键任务拎出来，定策略，想清楚目标是什么、打算怎么落地。

然后把整体任务拆成若干个便于管理的子任务，理清它们谁先谁后、谁依赖谁。

再为每个子任务规划具体的执行方案。

这一步可以说是一整件事里最要紧的——你得先弄明白自己到底要什么。

举个例子：怎么用 coze 搭一条高水准的自动化 xx 赛道📕内容生产线？

一步一步确认目标：

总任务：📕内容自动产出

输出标准：爆款标题 + 文案 + 配图

子任务1：生成爆款标题

子任务2：生成配图

子任务3：生成发布文案

其中子任务1还能再拆：热门话题抓取 + 改写；子任务2则会用到图片工作流。

在总目标和最终输出标准之下完成拆解，同时把子任务之间的逻辑顺序定下来。

# 2.4.2 执行阶段：

把各项功能逐步开发出来并测试。

在 Coze 平台上搭工作流架构，设定节点之间的逻辑关系。

细致配置每个子任务节点，保证它们各自都能有效运转。

[PRE31]

可以看到，搭好的工作流是由一个个小板块拼起来的，每个板块都能单独“试运行”。

这里的顺序是：先跑小节点，单点测试通过了再跑整体流程。

任何一个环节报错，最终都会导致没有“输出”。

试运行的时候你也会发现，工作流和写代码一个道理——跑不起来，就一定是哪里出了问题。

这个阶段的工作流一般不会一次成型，得反复测：

换个大模型，结果就不一样；

工作流拉得太长，跑出来的结果就不稳定；

某个数据抓错了，后面直接全错……

后续航海进入提效场景实操时，如果在这儿卡住了，放平心态，一步一步来，该走的弯路一步都省不了。

# 2.4.3 完善阶段：

全面检验并提升工作流的效果。

对工作流做整体试运行，找出功能实现和性能表现上的瓶颈。

通过持续测试和迭代不断优化，直到满足预定性能标准。

到了这个阶段，工作流已经用在业务里了，随之而来的是一连串新问题：

跑了，这个选题数据不好，得换热门话题信息源；

跑了，这类图片点击率不高，得换新风格；

跑了，LLM 说话太僵硬，不够自然；

跑了，数据太好私域承接不过来……

根据运营数据，我们会回头调整和迭代工作流。这部分工作通常由运营人员、数据分析、异常监控等几个模块承担，也要持续监控和维护。

搭工作流是种树，完善维护工作流是养树。

# 2.5 coze工作流跨平台使用/BOT装载

工作流搓完了，难道只能在 coze 工作流测试里用？想在🛰️里调用怎么办？想和飞书文档直接联动又怎么办？

很简单，很直接，官方功能一键搞定。把工作流发布成 BOT 推送到其他平台，就能跨平台调用了。

不过要注意，不同发布平台各有属性和默认设置，有些平台上不仅你自己能用，别人也能用。

# 2.5.1 常用发布平台

常用的发布平台包括：

1、扣子商店

完全公开，发布后所有人都能看到。

2、豆包

默认展示在豆包商店，其他人可以搜索到并使用；也可以在豆包商店配置里隐藏，设成仅自己可用或仅通过链接访问。

3、飞书

默认出现在对应账号的工作台中。如果飞书是企业版，需要配置使用人员，不会出现在应用中心，但可以通过“分享”给其他人用。

4、抖音

小程序可以搜索到并进行对话，也能挂载到短视频里。

5、🛰️

分小程序、客服、服务号、订阅号四条路径。小程序和抖音类似，搜索即可对话。客服是内置功能，不公开的话外部完全找不到。订阅号、服务号如果账号名和 BOT 名毫无关联，搜索是找不到已发布的 BOT 的，隐私度相对较高，可以作为私有功能，通过👸号消息对话来使用。

6、API/SDK

可供外部其他软件调用，需要一定的开发能力。

# 2.5.3 LLM模式发布

LLM 是工作流的默认发布模式，没做其他设置的话，就会以这个模式发布成 BOT。

它的特点是：工作流外面还会再套一个大模型。用户和 BOT 对话时，由 BOT 判断要不要调用引用的工作流；不调用的话，就走默认回复。

# 2.5.4单工作流模式发布

如果你的工作流是“单一输入”“固定模式”，不需要外部大模型来判断，就是 A 到 B 一条直线，那可以选“单 agent（工作流）模式”，发布后输出结果会更稳定。

[PRE36]

但经常会碰到一种情况：在“开始”模块设了 2 条或更多输入，结果提示“此工作流无法使用此种方式发布”。

原因是：单 agent 模式只接受开始输入为默认“bot_user_input”的工作流，开始节点上有其他参数的工作流都用不了这个模式。

那已经设了其他参数怎么办？

情况1：虽然加了另一个参数（比如“url”），但“bot_user_input”也闲置着，测试和使用时“bot_user_input”都不填内容。这种只需把后面引用到“url”输入的节点，改为引用默认的“bot_user_input”参数，再删掉“url”即可。

情况2：确实需要多个输入参数才能跑。这种还是用 LLM 模式发布，但上传工作流的位置改成“快捷指令”，在快捷指令里设置点击此处调用工作流。

# 2.5.5 多工作流模式

这种模式可以引用多个工作流，也可以引用其他 BOT 来参与流程操作。

工作流之间能形成上下关联，也就是说，工作流可以接工作流，也可以工作流接 BOT 再接工作流。

更复杂的任务就能系统化地运转起来。

# 2.5.6 BOT发布后修改

如果没动 BOT 的主逻辑，只是改了内部的工作流、图像流之类，这时候不用重新发布。

顺带一提，这个方式也能绕过一些 BOT 发布时会遇到的敏感词、图像流底图中的二维码等审核环节。
