# 嘴上说“再想想”，其实你早有答案

当你说出“再想想”这三个字，脑子里往往已经有一套没摆上台面的评判逻辑。这一关的任务，就是把它完整地掏出来。

💡 有件事先记着：要是你选的事情里包含某些固定运算——利润、成本、天数、人数这类——眼下先放一放。稍后这些运算会由脚本接手，让 AI 把精力集中在判断上。

## 3. 把你的评判逻辑梳理成 Skill

前面两步走完，你手上既有一个待验证的实例，也备好了一份测试样本。接下来就是这一关的重头戏：把你脑子里那套评判逻辑给梳理出来。

### 3.1 为什么评判逻辑非得梳理一遍？

有人会想：我自己的逻辑，我自己还能不门儿清？可真让你张嘴答一句“你的评判逻辑是啥”，大多只能蹦出“要有利润”“要有需求”“风险别太大”这种泛泛之谈。这些话本身没错，但基本落不到实处，没法用来支撑一次具体决断。

真正能用的逻辑，通常要对着具体案例，才会被一点点逼出来。就好比上一关做写作 Skill，不少人开头也说不清自己的写作风格，硬是被 AI 一环扣一环追问，才恍然发现自己原来揣着那么多习惯。这一关走的也是同一条路。下面这段 Prompt 不会让你一上来就做总结，而是像记者采访那样，一个问题一个问题地挖，把埋在经验里的评判逻辑逐个翻出来。[PRE4]

### 3.2 用“一问一答”逼出真逻辑

下面这段话不短，务必原封不动复制，一次性发出去。跟上一关做写作 Skill 的流程差不多，发出去以后 AI 会扮演采访者，每次只抛一个问题。你答完一个，它才会递上下一个。

⬇️ 复制下面这段，在 AI 里新开一个任务窗口发出去：

```plaintext
[PRE5]
## ---name: 【按我判的事起个名，中文英文都行，比如 my-product-check 或者 选品把关】
description: 帮我判断【填我第一步答的那件事】。当我说【填两三句我平时真会说的话】这类话时使用。

# 【给这个 skill 起的中文名，比如“选品把关”】

## 我判的是什么
（一句话：什么场景下、判断什么）

## 判错的代价
（我第一步第 3 问答的，写在这儿提醒你判得严一点）

## 硬指标（这几条不过就是不行）
（第三步分出来的“能算的”，逐条列。有数字就写数字，没有就写“什么情况下肯定不做”）

## 软判断（要结合情况看的）
（第三步分出来的“得想的”，逐条列，每条写清楚看什么）

## 我踩过的坑
（我在第二步里提到的吃过亏的事，原样记下来）

## 怎么给我结论
每次判断按这个格式回我：
1. 结论：能做 / 不能做 / 拿不准
2. 理由：命中了哪几条标准，逐条对着说
3. 拿不准的时候，直接说拿不准，并且告诉我还缺什么信息

别打太极，也别因为怕我不高兴就往好里说。
[PRE6]
```

### 3.3 给 Skill 配上案例库与运算脚本

采访收尾，你手里已经有了一套属于自己的评判逻辑。但光有逻辑还差口气。现实生活中的很多判断，除了看规矩，还得回头翻自己以前撞见过的相似情形。所以这一步，我们给 Skill 添上 references（资料夹）和 scripts（脚本）。

- **SKILL.md** 装规矩（硬指标、软判断），这是你的逻辑底盘。
- **资料夹**装实际案例：哪一年碰上了什么事、你当时怎么拍的板、后来结果如何。
- **脚本**接管固定运算：凡是涉及数字的，统统丢给脚本。

规矩是定死的，经历是流动的。往后每做一次决断、每吃一回亏，都往资料夹里塞一条，这个 Skill 就会越来越贴合你。将来它做判断时，不光对规矩，还会翻你的老经验。

⬇️ 复制下面这段发给 AI，用来新建资料夹：

```plaintext
[PRE7]
```

这几句和关卡 5 那句“必须先读”是同一个理儿：光把文件建起来不够，还得讲明白三件事——什么时候去读、读完要不要照做、翻不到又怎么办。

有些判断，除了靠经验，还会牵扯到固定运算。如果涉及数字或固定算法，就交给脚本处理。比如：
- 利润有没有达标；
- 人数够不够；
- 成本有没有超预算；
- 时间有没有超过限制。

可参考下面的示例：

| 你是做什么的 | 带数字的硬指标长这样 | 怎么算 |
| --- | --- | --- |
| 卖货的 | 一件落不到 8 块不做 | 落多少 = 售价 − 进价 − 运费 |
| 开店的 | 活动摊到每个客人头上超过 3 块不做 | 摊多少 = 活动总花费 ÷ 预计来的客人数 |
| 上班的 | 要占我超过 3 天的活不接 | 占几天 = 拆成几件小事，每件几个钟头，加起来 |
| 做知识付费的 | 问的人不到 10 个不单独做课 | 数一数：群里问过这问题的有几个人 |

这类运算每次结果都是唯一的，犯不着让 AI 去猜。你的判断里要是有这类规则，就交给脚本办；没有也丝毫不要紧，这一步直接跨过去。

## 4. 拿真实案例给 Skill 过一遍筛子

Skill 刚出炉，别急着收官。真正要紧的，是查一件事：它究竟是踩着你的逻辑在走，还是凭 AI 自己的阅历在应付。所以，把先前备好的那个案例亮出来。

测之前，务必新开一个对话窗口，别顺着刚才采访那一轮往下聊。原因在于，采访过程中 AI 已经把你刚讲过的不少话都记在脑子里了。要是接着测，它多半会顺着聊天内容作答，这也证明不了 Skill 真学会了你的东西。另起一局，才更贴近日后真实使用的场景。

先别把自己的倾向抖给 AI，只把它当时写好的“我在纠结什么”发过去。

⬇️ 复制下面这段，新开对话发出去（【】里的内容记得替换）：

```plaintext
[PRE11]
```

这一关盯的不是结论，是理由。不是看它判没判对，而是看它凭什么这么判。回到你做 Skill 的那个对话窗口，让 AI 把 SKILL.md 调出来，对着三块内容逐一比对：硬指标、软判断、我踩过的坑。再把 AI 给出的每一条理由，一条一条往上对。

符合下面这些情况的，记 1 条：[PRE12]

✅ 能在这三块里找到对应的逻辑（哪怕换了种讲法）
❌ 只是一些放之四海皆准的套话，比如“建议综合评估市场需求”“需要考虑投入产出比”
❌ 只是把你题目里的内容换个说法重述一遍

要是一条都没对上，也别慌，这说明生成 Skill 时采访环节你给出的标准还不够细。下一关会教你怎么细化检查。

除了评判逻辑，还可以盯两个地方：
① 有没有戳到你真正犯难的点。比如你担心的是“涌来的全是薅羊毛的客户”，它有没有识别出来。如果没有，可以继续往里补标准，让 Skill 下回也能虑及这类情况。
② 有没有提醒你一个自己先前没想到的视角。要是有，说明这轮采访不光理顺了你的经验，还顺手帮你挖出了原本没意识到的评判逻辑。这种案例很值得留存，也是这一关最有价值的收益。

## 5. 结果不理想？按这个路径自查

如果上一步验下来发现：
- AI 给的理由，多半是“正确的废话”；
- 或者几乎没引用你的评判逻辑。

先别急，多数情况都能归到下面两种缘由。

### 5.1 这条逻辑，你压根没吐口

这是出现频率最高的一类。很多经验你已经习以为常，觉得“这还用说”，于是采访那会儿根根没提。比如：
- 卖货的人，从来不碰带电产品；
- 开店的人，不做需要额外添置设备的新品；
- 做服务的人，不接临时改需求的客户。

这些规则在你脑中早已是默认值，但 Skill 压根不知道。查起来也简单，回头看 AI 给出的理由。要是从头到尾都没提到这条逻辑，十有八九就是你当时没告诉它。

### 5.2 逻辑写进去了，AI 却晾着不用

还有一类情况更隐蔽。翻开 SKILL.md，那条逻辑明明白纸黑字搁在那儿，AI 判断时却偏偏不引。想确认是不是这个缘由，可以让 AI 把“硬指标”那一节逐字念一遍，再一条一条说明当前案例满不满足每一条。它要是连标准都没念利索，或者直接漏掉其中某一条，那就说明它判断时压根没用上这条规矩。别直愣愣问它“你用了哪些标准？”——它很可能当场编几个听着像回事的答案来糊弄你，证明不了它真用了。

如果只是这一次判断出了岔子，可以顺手补一句：

```plaintext
[PRE13]
```

这样一来，它一般会重新掂量一遍，把这条逻辑也纳入考虑。但这只修了眼下这一轮对话，Skill 本身纹丝未动。下一回碰到类似问题，它照样可能把这条规矩漏到脑后。真正的解法放在下一关，我们会学怎样安全地动 Skill。不是随手添一句话，而是：
- 修改标准；
- 保存版本；
- 用同一个案例重验；
- 确认新添的规则没有祸及原有判断。

这一关，先把问题揪出来，就算完成任务。
[PRE14]

### 03. 本关常见卡点

碰上问题别急着撒手，可以先向 AI 求援。本期推荐优先用 Codex 或 WorkBuddy，把报错信息、截图或者你的需求，新开一个任务窗口丢给它们，让 AI 帮你捋原因、排查故障、甚至直接替你摆平。[PRE15]

慢慢养出“先问 AI、再求人”的习惯，很多麻烦自己就消解了。
