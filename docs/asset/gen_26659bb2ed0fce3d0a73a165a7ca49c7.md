**为什么要绕这一下？**

多数AI的默认协作方式，是你抛问题、它给答案。你提问的角度，等于替它划定了思考范围。范围一旦偏了，比如只盯着“怎么追热点”，它就会在错误框架里交出一份表面完整、落地却没用的方案。

把提问权交还给AI，信息优势也跟着倒过来，原因有三点：

- **你是新手，AI是“老手”**：你是第一次提这个需求，但AI的训练数据里已经见过大量同类案例，它清楚常见坑和关键决策点。
- **经验只在“被提问”时激活**：在“你问它答”模式里，AI的经验是沉默的；只有让它来提问，它才会根据经验追问你容易漏掉的地方，比如“你数据最好的内容类型是什么？”
- **追问能挖出更多价值**：每个问题都像一根探针，把你脑子里已有但没结构化的想法抽出来。很多需求不是你不知道，而是你没想到要说。比如AI问“灵感从哪来”，你才意识到“我都是刷笔记时随手记的”，这直接决定了Agent的输入源。

第三步：和AI聊起来，在它的追问中梳理Agent的核心维度。

AI开始提问后，你诚实回答即可。它追问的方向，基本就是搭Agent必须搞清的五个维度。你会在回答中不知不觉把它们定义清楚：

1. 核心痛点：到底要解决什么问题？避免做无用功。
2. 最小范围：当前最值得先做哪一段？确保能完成。
3. 输入数据：需要什么信息，从哪里来？确保Agent有粮可加工。
4. 处理流程：中间需要哪些步骤？确保逻辑通畅。
5. 输出位置：结果落到哪里、长什么样？确保结果可用。

聊需求这场对话，其实已经在做Agent方案设计了。拆解需求这个动作，会把搭Agent所需的关键信息都问出来。

输入输出、处理流程、输出位置，并不是你另外要掌握的能力，它们会在你和AI交流、拆解需求时自然产生。需求拆得够清楚，这些东西就都有了。

到这一步，很多新手会犯嘀咕：“聊完了，然后呢？这些技术细节我不会啊。”

记住这个核心认知：

技术门槛不用你扛。

- 你的角色是“产品经理/老板”，核心产出是一份清晰的需求定义，也就是上面五个维度。
- AI的角色是“技术专家/员工”，职责是把你的需求定义翻译成可执行的技术方案，并生成Agent。

聊得差不多时，你只需要让AI收束成最小方案，再让它去开发Agent。

因为AI会基于完整聊天记录理解你的全部意图，直接给出包含具体工具、步骤、配置方法的方案。那些“输入输出”“处理流程”的技术实现，是AI根据你的需求描述自动完成的，不是你额外要学的。

**整套动作可以压缩成一条线：AI开启提问模式（确定需求）——梳理核心维度——产出Demo——AI生成Agent**

第四步：把话题收成最小Demo

聊完后，你可能会得到一堆功能点。但你不能全做，塞的功能越多，Agent越容易在流程里打结。

必须收束：把所有聊过的功能砍到最小，只保留最核心的一条链路，先跑通。

这就是“最小Demo”：不是最终产品，而是一个能验证想法、可以跑起来的最简版本。像先搭一间能通电的小屋，确认地基没问题，再扩建。

AI编程工具会理解你的需求，自动生成代码、配置技能（Skill）、串联工作流，把这个Agent给你“搭”出来。你可能需要和它进行几轮调试和微调，但核心生产力是它，不是你。

## 2.3 Agent与Skill是什么关系（拓展内容）

后面章节会出现两个词：Skill和Agent。它们很像，但不是一回事。先说清楚，后面就不绕。

**Skill = 一个单一能力**

比如“把今天的日报总结成结构化要点”，这就是一个Skill。它做一件事，做得稳定，可以被反复调用。你可以把Skill理解为一个“专项技能”：分析日报是一个Skill，提取小红书爆款标题是一个Skill，把网页正文转成Markdown也是一个Skill。

**Agent = 把多个Skill串起来自动跑的“员工”**

比如：每天定时读取日报.txt → 调用“日报分析”Skill → 把结果写到汇总文档 → 同步到飞书。整条链路不用你点“继续”，它自己从头跑到尾。

在接下来的日报案例中，两者大约有90%是重合的——一个Skill自己也能“分析总结”。

Agent多出来的那10%，恰恰是关键部分：

- 自动输入：自己去读文件/抓网页/拉数据，不用你手动喂。
- 自动触发：定时跑、监听变化跑，不用你每次点开。
- 多步联动：上一步结果自动接到下一步，跨工具跨平台串成一条流水线。

先有Skill，再有Agent，这是搭智能体最自然的顺序。
