### 1. 项目概览

#### 1.1 这套工具到底能做什么

先说结论：它是一套不太挑基础的 AI 流程工具，擅长把业务动作成批、自动地跑起来。比如一次性收集大量📕选题，或者成批整理直播话术。你不必把它当成复杂的系统开发平台，学习重点在“工具用法 + 场景组合”，掌握后就能给日常工作或业务加速。

看几个例子：

- “把这 100 个视频链接中的文案全部抓出来” → 大约一分钟完成；
- “判断这 200 张商品主图各自主打什么卖点” → AI 自动识别并加上标签；
- “每隔一小时把主播话术得分推送给运营” → 配置一次，后面不用盯。

它内部已经接了 DeepSeek、豆包、Kimi 等模型。更关键的是，它既能一次处理很多行任务，也能在同一行里让多个模型分工协作。

设想一下：填入 100 个选题，DeepSeek 负责写文案，信息提取字段负责拆分段落，智能绘图负责生成封面——一分钟左右就能拿到 100 篇📕笔记的初稿。这种速度，靠手工很难做到。

飞书方面看重赚钱社区的专业沉淀与持续价值，给本期航海开了定向支持。加入【多维表格 AI 实战航海】的圈友，可以领取飞书多维表格面向赚钱圈友开放的专属权益，学习和实操体验都会更进一步。

#### 1.2 为什么值得花时间学

#### 2.1 路径总览

#### 2.2 四个关键抓手

重点 1：先吃透五项核心能力

- 模型处理：成批调用大模型处理数据；
- 数据可视化：拖拽搭建仪表盘和看板；
- 多人协作：实时同步、自动推送消息；
- 个性化定制：丰富的字段、视图、插件；
- 数据安全：精细化的行列权限控制。

理解这五点，才能判断它到底能帮你做什么。

重点 2：熟悉 6 个常用快捷字段

这 6 个字段可以覆盖约 90% 的应用场景：

- DeepSeek：写脚本、做分析、生成内容；
- 图片理解：识别图片、提取文字和卖点；
- 自定义 AI 填充：免费快速，适合分类和格式转化；
- 智能标签：把分析结果标签化；
- 视频文案提取：一键提取抖音、📕、YouTube 视频内容；
- 豆包多模态 1.6：理解视频内容，用来拉片。

重点 3：把数据链路串起来

它真正好用的地方，是让字段一个接一个传递结果。例如：

用视频文案提取拿到原始文案 → 用 DeepSeek 分析脚本结构 → 用智能标签给脚本打标签 → 用仪表盘做可视化展示。上一环产出的内容，直接成为下一环的原料，效率才会最大化。

重点 4：让自动化接手重复动作

自动化的底层逻辑无非两件事：什么情况下触发，触发后做什么。

- 新增记录时，自动生成分析结果；
- 定时触发，自动推送数据报告；
- 字段变更时，自动通知相关人员。

这些配置好后，系统可以自己运行，不需要人一直盯着。

#### 2.3 新手提醒与避坑清单

避坑 1：先想清楚要解决什么问题

不要为了用而用。先问自己：眼下有哪些重复性工作？哪些数据需要整理分析？哪些流程值得自动化？问题明确了，再去找方案。

避坑 2：字段命名要规范

如果字段叫“正文内容”，而代码里写的是“正文”，就可能报错。建议命名简洁统一，例如“标题”“正文”“链接”，尽量避免中英文混用。

避坑 3：先小规模测试，再批量运行

DeepSeek 和豆包多模态按 Token 计费，会产生成本。建议先手动跑几条数据，确认结果符合预期，再开启“自动更新”批量生成。

避坑 4：复杂逻辑拆成多个字段

不要指望一个智能字段完成所有事情。比如“分析 + 打标签 + 生成建议”，拆成 3 个字段分别处理，效果通常更好，调试也更方便。

避坑 5：善用官方文档和 AI 助手

遇到不会的功能，可以直接问豆包或 ChatGPT：“多维表格怎么设置 XX 功能”。也可以查飞书官方帮助文档，内容写得很详细。

#### 2.4 出发前准备

硬件要求：一台能上网的电脑即可。

时间准备：建议每天投入 2—3 小时，持续 21 天。

账号准备：注册飞书账号，开通多维表格（免费）。

心态准备：把它当成“能自动干活的 Excel”，不要想得太复杂。

### 1. 它和飞书是什么关系

它并不只是记录数据的表格，而是把“数据库内核 + AI 智能 + 业务系统”融合起来的高效生产力工具。它具备百万级大数据处理能力和企业级安全管控，不懂代码的人也能通过拖拽，零门槛搭建包含自动化流程、AI 内容生成和专业 BI 仪表盘的业务管理系统。

飞书（海外版名 Lark）是字节跳动（ByteDance）旗下的一款企业级一站式协作平台。可以把它理解成“企业🛰️/钉钉 + Slack + Google Docs + Zoom + Trello”的超级集合体。它的核心理念是“All in one”：把即时沟通（IM）、日历、云文档、视频会议、OKR（目标管理）以及多维表格等工具全部打通，在一个 App 里完成工作，提升组织与团队协作效率。

现在多维表格已经从飞书 App 里独立出来，大幅降低了使用门槛。无论你是个人用户，还是仍在使用钉钉/🛰️的企业，都不必下载飞书 App 也能直接使用它。它从一个“内部组件”变成了面向全网、人人可用的独立生产力工具。

多维表格是表格 + 数据库 + 智能大脑的融合，能帮你轻松构建业务系统、管理海量数据。它的优点包括：

- 零门槛：无需下载飞书 App，也能使用专业级多维表格能力；
- AI 赋能：以很低门槛解锁工作中的 AI 场景，自动生成文案、图片、视频，会用表格就会用 AI；
- 专业 BI：不用做图表，把数据“拖进”仪表盘，就能拥有企业级专业数据驾驶舱；
- 海量模板：一键导入项目、CRM、分析模板，即刻上手；
- 高性能：百万行单表容量，全行业领先的数据库底座能力；
- 安全可控：颗粒级权限管控，每一个单元格都能被管控。

#### 3.3 协作：多人共同维护的业务系统

**表单视图是另一个有辨识度的能力**：它能把数据表直接变成填写页面，而且可以单独分享。录入者不必面对复杂表格，按表单逐项填写即可。每个项目都能附说明和填写指引；更关键的是，填写者全程看不到表格全貌也能录入，数据会自动汇入表格、画册、看板、数据看板等展示形态。对数据安全来说，这一点很有价值。

#### 3.5 多维表格把数据安全放在很重的位置

作为企业级应用，多维表格在安全上做得比较扎实。高级权限能对行、列做细粒度控制，不同权限的人看到的范围、视图、看板都会随权限变化。

比如借助「数据权限规则」，按用户、部门、角色动态匹配：销售表里，每个人只看到自己负责区域；「字段级权限」则能把薪资、客户手机号等敏感信息精确隐藏或设为只读。

它还支持先模拟权限配置后的效果。正式分享前，可以切到他人视角，检查不同权限下的展示和操作限制是否符合预期，降低配置出错风险。

当视图要分享给供应商、客户等外部伙伴时，高级权限能清晰限定操作边界——只能看不能改，或仅能操作指定字段，同时守住内部数据安全。

**高级权限**是一项重要却不太显眼的能力。它没有 AI 那种科幻感，也不如看板视觉冲击强，但始终在背后守护企业数据安全，称得上是多维表格最核心的底层能力之一。

![](img/c7f21b01e27d2e7e2c55ae88813be3ba.png)

总结：它只是长得像表，内核是业务平台

强大的数据管理能力：能存、能分析、能可视化；支持多维度录入、管理和洞察，拖拽之间完成数据透视；跨表关联与计算也能处理复杂关系。

高效的协作功能：多人同时编辑，实时同步；批注讨论随写随看；历史记录一键回溯；团队始终拿到最新版本，协作效率明显提升。

高度的个性化定制：字段、视图、看板、插件齐备；按业务需要搭专属系统；同一份数据可切换为看板、甘特图、画册、表单等形态；一张表管个性化业务。

自动化操作：不写代码就能同步项目进展、推送通知；连接飞书通知、邮件、待办等应用；把业务系统与日常办公工具串起来，省人力提效率。

严格的安全性：高级权限按行、列精细设置；不同使用者看到的内容、单元格、看板因权限不同；还能按条件动态同步。

#### 引用内容违规排查

文字内容：先看指令与引用字段合计是否超过 1 万字；再确认文字里有没有涉黄、涉政或擦边信息，比如“泰迪”这类词；还可暂时移除引用字段，把指令换成“讲一个笑话”，若此时能正常生成，多半说明原指令或引用字段过长、含违规内容。

图片内容：检查图片是否超过 10m；确认格式在支持范围内：JPG、JPEG、PNG、GIF、WEBP、BMP、TIFF、ICO、DIB、ICNS、SGI、JPEG2000；再看图片和指令是否含涉黄、涉政或擦边内容。也可把引用图片换成猫咪或狗狗图，若能正常输出，则原图可能存在超长、违规或模糊到无法识别的问题。

#### 3.3 提炼分镜提示词

这个列属于“自定义AI自动填充”，任务是从3.2的长篇结构化报告里，精准拆出某个分镜（如分镜1）的提示词。视频生成模型一次只能吃一个具体画面描述，所以必须把多镜头长文本切成独立短指令，并清掉时间戳、编号、表格符号等杂物。

操作：

① 建提取列。点列头加号，在“探索字段捷径”里选“自定义AI自动填充”，相当于建一个文本清洗与提取单元。

③ 写提取指令。在指令文本框填入下面的清洗规则（见代码块），用自然语言设过滤条件，保证结果纯净。

Plain Text

```
`提取分镜头1的描述，只要提示词，不要其他多余的东西，不要带编号和时间`
```

#### 3.4 生成新视频

#### 1.1 爆款短命，复刻两难
投过抖音流量的人都懂：爆款素材难做，创意、内容、情绪点都得踩准。更麻烦的是，爆款跑出来后热度常常几天就掉，生命周期很短。

过去为了续命，常用“复刻”。可复刻很吃手艺：改得少，平台会判重复搬运而限流；改得多，原片爆点又可能丢，转化跑不出来。很多编导因此卡住。

现在可以交给 AI。它偶尔写错，但给一份好范本、把要求讲清，它就能快速仿写新版本，并保住原亮点。有时它给出的比喻还挺巧，既降低重复感，又抓住重点。

当然，要让 AI 写出高质量脚本，你得先会拆任务：明确自己想复刻的点。只有知道改哪里，AI 才能准确执行。常见有四条路：

💡

- 仿写母版：沿用参考素材的结构，文案再仿照改写；
- 精修母版：把偏长的爆款内容压缩优化，留住核心爆点；
- 新增母版：保留原片开头与结尾，在中间补充卖点；
- 重组母版：打散原脚本框架，做较大幅度创新，但守住最核心的爆点。

以前受人力时间限制，编导往往只能“做减法”，从四条路里挑最稳的一条试。现在有 AI，可以“做加法”，甚至四条全上。把一条爆款扔给 AI，它能很快写出多个不同版本，最后挑最好的一条，再认真拍摄剪辑。

#### 2.1 直播话术管理的痛点
做直播运营，多少都遇到过这些情况：

- 主播个性强，爱自由发挥，不愿按运营框架讲；
- 运营指出话术问题，主播容易觉得是在针对自己，双方起矛盾；
- 抽查话术费时费力，甚至要运营专门安排时间盯直播间；
- 白班主播知道运营在看，会认真播；夜班没人看，就容易放飞。

这些问题会让直播间效率低、业绩不稳、团队气氛紧张。过去想做一次复盘很辛苦：既要花时间跟播，沟通时还得照顾主播情绪。

现在 AI 能帮忙解决。借助 AI，可以做到：

- 按运营要求自动分析主播话术，生成分析报告，以文字推送给主播或负责人，并用飞书文档呈现，方便阅读查看；
- 根据分析结果自动给主播话术打分，把结果量化；
- 自动给出话术改进建议，并推送到主播的飞书。

#### 2.4 实战：搭出话术诊断流水线

**2.4.1 先铺好数据底座**

原始素材的入口由三列承担：一段长文本存话术、一个人员/单选列标记主播、一个日期列记录时间。为什么用多维表格？长文本不怕多，时间戳还能自动落，后续模型复盘时能还原当时的语境。

**具体操作**

- 话术列：新建一张多维表格，在列头“+”处添加“多行文本”，列名写成“主播话术内容”。内容来源可以是场控录一段十分钟的直播，再转成文字。

**3.3.4 拆解识图指令：文案、代言人、卖点**

这一节要分别建立三个识图字段：主图文案提取、代言人分析、核心卖点提取。分开建的好处是每个字段只处理一个分析维度，输出更聚焦，信息不容易串在一起。

**操作流程**

**主图文案提取**：新增“AI 图片理解（豆包）”字段，命名为“主图分析”。绑定账号后，在配置面板的“原图”下拉中指定“主图图片”。自定义指令填写：请提取这张图片中的文字，尽量完整，不要遗漏。关闭自动更新，确认。

目的：把图片里的促销语、参数等非结构化内容转成可检索文本，为后续关键词分析提供原料。

```
`请你帮我提取这张图片里的文字，尽可能详细，不要有任何遗漏`
```

**代言人分析**：添加新列，名称为“代言人”，类型设为文本；在字段捷径入口选“AI 图片理解（豆包）”，原图同样指向“主图图片”。指令写：请判断该产品画面中是否出现代言人。若出现，返回代言人姓名；若没有，返回“无”。开启自动更新，确认。

目的：把代言人信息转成统一字段，便于后续比较不同明星的带货表现，或观察代言人与销量的关系。

```
`请你帮我分析一下这个产品是否有代言人。
如果有则返回：代言人的名字；
如果没有则直接返回：无`
```

**核心卖点提取**：再添加一列，列名“核心卖点”，类型文本；字段捷径选“AI 图片理解（豆包）”，绑定账号，原图仍选“主图图片”。指令写：这张主图最核心的卖点是什么？以字体最大或最醒目的信息为准，直接返回结果，不要附加解释。

目的：模拟消费者第一眼的注意力落点，抓住商家最想突出的营销信息。

```
`这张主图上面，最核心的卖点是什么，字体最大或者最显眼的，直接返回结果，不要有多余的其他文字`
```

**保存与试跑**：确认配置后，保存时选择“仅保存配置”。回到表格，先手动运行第一行，用一两张图验证效果。结果符合预期后，再开启整列自动更新，最后打开列头的自动更新开关。

这样做能控制 token 消耗，避免指令还没调准就全量运行。确认模型理解无误，再让它批量处理。

沿着这个思路，还能从主图中提取更多信息，例如是否带赠品、赠品是什么、是否露出价格、画面构图如何等。

![](img/2d8d33fa5ff312e3d7c217deb405ada2.png)

**3.3.5 DeepSeek 归纳与标签化**

这一组能力由 DeepSeek R1 文本分析字段和智能标签字段组成。DeepSeek 负责推理归纳，把前面得到的卖点、文案等碎片信息整理成使用场景和用户痛点；智能标签则把结果量化成可统计的标签。

**操作流程**

**先让 DeepSeek 做分析**

将主图分析、核心卖点和商品标题汇总到一个 Word 文档，再交给 DeepSeek，针对你关心的问题提问。

如果觉得外部对话结果不够细，可以用飞书多维表格里的 DeepSeek 字段，逐个产品分析核心卖点、使用场景、用户痛点，再用信息提取字段把三类内容拆出来，便于后续统计。

**DeepSeek 深度分析**：添加新列，点列头“+”，在字段捷径中搜索 DeepSeek-R1。绑定账号后，在指令大文本框右上角点引用按钮，引入产品名和主图分析字段。

在指令框写入详细提示词：

**提示：提示词只是参考，也可让豆包、Gemini、GPT 等工具协助生成。**

```
`这是产品的标题：【点击右上角蓝色+号引用产品名】

请你根据以上的内容回答我的问题：
1.这个产品最核心的3个卖点是什么？
2.这个产品针对的使用场景是什么？
3.这个产品解决了用户的哪些痛点？`
```

向下滚动面板，启用“获取更多信息”，勾选“思考过程”和“输出结果”，打开自动更新，保存确认。这样可借助大模型的逻辑推理，从碎片信息中提炼结构化营销洞察。

**信息结构化提取**：再开一列，名称“产品卖点”，类型文本，字段捷径选“信息提取”。在“选择需要提取的字段”中，指定上一步 DeepSeek R1 的输出。

“提取信息”填“产品卖点”；“自定义提取要求”可写“格式必须统一”。打开自动更新，确认。

**按同样方法**再建“使用场景”和“用户痛点”两列，只需把提取信息改成对应名称。这样能把长报告拆成独立数据项，方便后续打标签和统计。

**3.3.6 智能标签：统一卖点口径**

智能标签字段的价值，是把上一步得到的长句、非结构化文本，映射到预先定义的标准关键词上。口径统一后，诸如“杀菌快”“灭菌迅速”都能归入“高效杀菌”，仪表盘统计出的占比才可靠。

把数据源换成 DeepSeek 归纳出的核心卖点，并且只围绕卖点提问，结果会清楚不少。不过，仅看这一层，只能知道哪些卖点被提及得多，无法判断具体产品对应哪些卖点。接下来可继续用多维表格的智能标签功能处理。

**提示：提示词只是参考，也可让豆包、Gemini、GPT 等工具协助生成。**

`高效杀菌/除菌
快速起效
多效合一
温和安全
持久留香/防臭
强力去污
适配全机型/场景
环保天然
免拆洗/免刷洗
高性价比组合`
```

展开“自定义标签要求”，填写：按匹配程度排序，只保留匹配度最高的 3 个标签。

`按匹配程度排序，只匹配匹配度最高的3个标签`

智能标签跑完后，会得到一张带标签的表：既能看出哪些卖点被提得最多，也能看到每个产品对应的卖点标签，便于判断标签排名，还可直接接入飞书多维表格仪表盘继续分析。

## 03. 多维表格联动 Coze：抓取📕笔记

### 1. 本节目标

本节通过“扣子工作流调用”字段捷径，把飞书多维表格和 Coze 连接起来。

最终效果：在多维表格中粘贴一条📕笔记链接，系统自动抓取标题与正文，并回填到表中。

链路分两端：

- Coze 工作流：去📕取数据，输出所需字段。
- 飞书多维表格：保存链接、触发工作流、接收并展示结果。

需要完成三件事：

- 在 Coze 创建一个最小工作流：开始 → 📕插件 → 结束。
- 取得该工作流的“访问令牌”和“工作流 ID”。
- 在多维表格中配置“扣子工作流调用”字段，把链接传入工作流，再把结果接回表格。

### 2. 学习价值

多维表格本身就是一个能力很强的数据库。能接入的数据源越多，可落地的业务场景越丰富。通过这个案例，可以掌握多维表格与扣子连接的方法，理解两者配合的思路，并把 Coze 解析出的📕笔记传回多维表格。

**多维表格连接 Coze 至少有四种方式**。这里推荐 Coze 连接器，也就是现成的字段捷径：门槛低、上手快、基础功能覆盖较全，还能直接提取数据，用户无需自行处理，适合新手入门。

#### 3.1 搭建📕提取工作流

目标：工作流输入为“📕链接”，输出为“标题”和“正文”。

整个工作流只包含三个节点：“开始”“📕提取”“结束”。搭好后结构如下：

- 开始 → xhs_note_detail_no_cookie（📕提取）→ 结束
- 开始：接收输入参数（📕链接）
- 插件节点：调用官方插件抓取📕内容，免去自己写接口
- 结束：选择要返回给表格的字段

**3.1.1 新建扣子工作流**

这一步是在 Coze 上创建一个空白工作流，相当于先准备画布，后续节点都在这块画布上搭建。

登录扣子开发平台（coze.cn/home），从左侧菜单进入【资源库】，再点右上角【+ 资源】，在下拉菜单选择【工作流】。弹出窗口里填写工作流名称和描述，例如“📕提取测试”，确认后系统自动进入编辑画布，等待配置节点。

![](img/64b236826615eb4926c48119fa3ce95f.png)

**3.1.2 设置开始节点**

开始节点负责接收外部参数。本案例中，它接收飞书传来的“📕链接”。需要定义一个名为 input 的变量作为入口，保证飞书发来的数据能被工作流识别并接收。

![](img/60cc7da4a0e106daafd366950f6ed3ed.png)

# 📕笔记自动进飞书表格

先把入口参数定下来。画布左端找到【开始】节点，点开右侧属性区，在【输入】栏目按【+】新增一项。变量名写成 input，类型不动，仍是 str.String（字符串）。入口参数名到这一步就固定了，后面都靠它读取链接。确认后，节点表面会显示 输入 str.input。提醒一句：input 这个叫法之后会多次出现，不要换成别的。

![](img/de309e792f9baa5b11dfc34c729ca8e8.png)

### 3.1.3 挂载📕取数插件

这个环节负责读取笔记详情。调用 Coze 已经封装好的官方插件，传入链接就能拿到标题、正文等结构化信息，不必自己手写 HTTP 请求，省事也稳妥。

操作：画布中间的加号入口可以插入新环节，点它，在弹出列表里挑【插件】。

![](img/3d0b794a8d152af77766cd2e9256eb01.png)

在检索栏里打“📕”，找到 xhs_note_detail_no_cookie，点右边那个【添加】，把它放进流程。

![](img/2ef26f7bcf89f14fa948fbe2fcc3d226.png)

接着配置该插件的 url 参数：点输入框旁的引用图标，选 开始节点 下的 input。这样入口链接就交给了插件。换句话说，流程收到的 input，会作为请求📕的地址。

![](img/66add61c4727b11e12c5b6a2296f56a7.png)

### 3.1.4 结束节点只回传标题和正文

收尾节点干的是“挑数据、再回传”的活。插件带回来的字段很多，含 ID、时间、作者等，最终只留标题与正文两项。配置好结束节点后，就能从结果里挑出这两项，再交给飞书表格。

操作：选中最右端的【结束】节点，确认它跟在📕插件后面。输出变量区域按两次加号，建两个槽位。

第一项命名为 content，值引用 xhs_note_detail_no_cookie 下的 data.note_desc，也就是笔记正文。

第二项命名为 title，值引用同一插件下的 data.note_display_title，也就是笔记标题。

配置完成后，结束节点会显示：输出 str.content str.title。

### 3.2 多维表格接入字段捷径

#### 3.2.1 新建多维表格

这里要把表格做成一个可触发的入口。在飞书多维表格里放一个能唤起 Coze 流程的“按钮”：表格中填入链接，后台自动运行 AI 流程并把结果写回来。

第二列命名为 扣子，字段类型选 探索字段捷径，搜索“扣子”，选中 扣子工作流调用。这里引入飞书官方 API 组件，把表格与 Coze 连接起来。

随后继续配置该字段，依次处理“认证令牌”“工作流 ID”“参数字段”“参数名称”。

![](img/43b2c8cd0e420bbbb197c8319af2aa18.png)

#### 3.2.2 获取并配置 Coze 访问令牌

这一步是让飞书有资格调用 Coze。在 Coze 后台生成访问令牌并填入飞书，API 请求才不会被拒。

操作：登录扣子开发平台，左侧菜单最下方找 API 管理（也可直接访问 coze.cn/open/playground）。在页面选“授权”，切到 个人访问令牌 选项卡，右上角点 添加。

![](img/45edf36c85ee7e906e999ac8c02cdc90.png)

弹窗中填写令牌名称（如“123”），过期时间设长一些，权限选 全选，访问空间建议选 所有工作空间。确认后系统会展示一串令牌，仅显示这一回，务必复制保存。

![](img/f5a40675328ea8b81150dde22e73467d.png)

页面会展示刚创建的个人访问令牌。该令牌只出现一次，点复制，存到安全位置（如本地 txt 文件）。

![](img/76bb71d38857fd8a63289da6f8460bc3.png)

回到飞书多维表格字段配置，在“扣子工作流调用”的“认证令牌”输入框粘贴刚复制的字符串。这样飞书对 Coze 的访问权限就配置好了。

![](img/4e5fe467324530c24c8da69b87f32a04.png)

#### 3.2.3 获取并配置工作流 ID

这一步是告诉飞书该跑哪条流程。Coze 账号下可能有多条流程，需要明确指定要运行的那一条。工作流 ID 就是该任务的唯一标识。

操作：回到 Coze，进入前面做好的“📕提取”流程编辑界面，查看浏览器地址栏，找到 workflow_id= 后紧跟的数字串（不要包含 & 后面的内容），复制。

回到飞书多维表格配置页，把该 ID 填入“扣子工作流调用”的“工作流 ID”中，确定要调用的具体流程。

![](img/7e04d32161dd30d226d988f864df9bdb.png)

#### 3.2.4 配置参数字段与名称

这一步把表格列和流程变量对应起来：表格哪一列的数据，传给流程里的哪个变量。

操作：在 参数字段 下拉框选择第一列 📕笔记链接，指定数据来源。

在 参数名称 框填入 input。这里必须写 input，因为 3.1.2 节定义开始节点变量时用的就是 input。只有表格发送的参数名与流程接收名完全一致，传输才不会失败。

![](img/c8ca831c3ba11c7188edc1a71d94d8ef.png)

API 只收 JSON，还要说明回传哪些字段展示到表格里。

操作：在 请求模板 框按 JSON 格式填写 {"input": "引用字段"}。引号内点右侧 引用字段 按钮，选择“📕笔记链接”，最终类似 {"input": 📕笔记链接 }。这样表格中的链接会被包装成标准 JSON 数据包发给 API。

Plain Text

```
`{&quot;input&quot;:&quot;小红书笔记链接&quot;}`
```

在 输出结果 1 和 输出结果 2 框分别填 title 和 content，指定从 API 返回结果中抓取标题与正文显示到表格。

Plain Text

```
`title
content`
```

![](img/76b9658e45d11a208cf4d110846c182e.png)

勾选 获取更多信息（通常含完整响应数据等）和 自动更新，点 确认 保存。这样链接修改时数据会自动刷新，同时保留原始数据备用。

#### 3.3 粘贴📕笔记链接，测试效果

这一步跑一条链接，并把返回结果整理成可读文本。API 直接返回的 content 可能带复杂格式，或被识别成 JSON 对象，需要借助辅助字段解析成纯文本，便于阅读。

操作：在第一列 📕笔记链接 粘贴一条真实笔记 URL，稍等片刻，“扣子”列显示“运行中”，随后自动生成 扣子。输出结果 1（标题）和 扣子。完整响应数据 等新列。实际运行通过，说明飞书与 Coze 已打通。

配置时，JSON 字符串 选 扣子。完整响应数据，字段取值方式 填 content，勾选自动更新并保存。这样复杂 JSON 会被解析，正文文本能清晰呈现在表格中。

这个产品叫「人生知识库」，用来收藏对自己有价值的文章，反复阅读、学习，提升自己。日积月累，它会变成个人知识宝库，随时可以调阅。

#### 2.2 需求来源

项目需求来自日常信息获取与管理中的真实痛点，主要有三方面：

（1）收藏来源分散，管理不成体系

现状：日常浏览的内容散落在🛰️👸号、📕、龙哥盟等多个平台。

痛点：各平台收藏夹彼此独立，信息碎片化，需要时难以快速检索和查阅，收藏的内容容易被遗忘。希望能聚合到一起，快速找到，最好还能分类收藏。

（2）收藏动作麻烦，手机端不顺手

现状：看赚钱帖子时，在移动端看到优质内容，直接在原平台收藏，手机上打开不方便；转发到🛰️文件传输助手等方式又不利于长久保存。

痛点：缺少跨平台、操作便捷的移动端统一入口，收藏过程耗时，体验割裂。

（3）长文读起来费时，筛选成本高

现状：面对长篇干货文章，受时间或环境限制，往往无法一次读完，但又希望先了解核心内容，再决定是否深入阅读。

痛点：缺少辅助阅读工具，无法快速获取文章主旨，导致在低价值内容上浪费时间。

#### 2.3 需求分析

基于上述痛点，核心需求可提炼为三点：

+ 收藏快：手机端就能高效保存，覆盖常用渠道。
+ 摘要准：迅速抓住文章主旨，帮助判断是否细读。
+ 管理成体系：建立分类规则，收藏内容分门别类，方便查找。

明确真实需求后，思路就清晰了：把需求拆成具体功能，规划好流程即可落地。

### 3 产品设计方案

#### 3.1 如何实现快捷收藏？

（1）手机端怎么快捷收藏？

绝大部分阅读场景都在手机上。经过探索，iPhone 自带的“快捷指令”不仅能自动化操作，还支持发送 HTTP 请求，可以把复杂的数据处理过程都放在后台，快捷指令只做上传和接收。

结论：利用 iOS 快捷指令作为入口，实现数据上传与结果展示。

（2）后台怎么扒取各平台内容？

# 零代码知识库搭建指南：收藏、分类、AI 摘要全自动

很多人听到“自动抓取内容”就以为要写爬虫。其实，Coze（扣子）已经把很多现成插件准备好了，可以直接对接📕、🛰️👸号、飞书云文档等内容源；它还支持通过 API 接收快捷指令发来的数据，并把处理结果回传给快捷指令。不懂代码也没关系，会像搭积木一样把组件连起来就行。

一句话：用 Coze 工作流 + 插件，就能自动把各平台内容抓进来。

（3）数据存哪里？手机怎么读？

Coze 和飞书同为字节系产品，打通起来很方便。Coze 里就有不少面向飞书多维表格的插件。多维表格不仅能当数据库用，网页端打开即用，还自带移动端界面，不用额外开发也能在手机上获得不错的阅读体验。

一句话：内容存进飞书多维表格，手机上用飞书 App 查看。

#### 3.2 怎么快速抓住文章重点？

（1）AI 摘要从哪来？

Coze 里调用大模型做摘要需要付费；而飞书多维表格本身内置 AI，部分模型每月提供 30 万次免费额度。从“低成本搭建”的角度看，用表格自带的 AI 明显更划算。

一句话：内容进表后，让表格里的 AI 自动出摘要。

（2）摘要结果去哪儿看？

想要“收藏即查看”的顺畅体验，可以让快捷指令收到反馈后打开一个网址，从而唤起飞书 App 跳转到多维表格。刚收藏的内容和 AI 摘要都会直接呈现在眼前。

一句话：用网址唤起飞书 App，进多维表格看摘要。

#### 3.3 文章分类体系怎么建？

文章的分类往往不止一个维度，比如平台、主题、形式等，只靠文件夹很难灵活管理。多维表格的“多选”字段支持给同一篇文章打多个标签，之后通过筛选就能快速定位。

一句话：收藏后借助多选字段搭标签体系，筛选归类更省事。

动作：在手机上刷到👸号、📕等内容时，复制文章链接。

**4.1.1 创建一个多维表格**

这一步是在给知识库搭骨架：用多维表格做一个标准化容器，把不同渠道的文章、视频和笔记都收进来。先把标题、链接、标签、状态等列定义清楚，每条收藏就有固定位置，后续管理、检索和自动化处理都会更顺利。可以按模板搭。

（1）配置字段

如果你已经熟悉多维表格，可以直接看后面的“速查版”；想弄清每个字段的含义，就跟着文字版一步步做。

文字版：

先在飞书云文档里点【新建】→【多维表格】，会得到一张带默认字段的初始表。

① 标题
把第一列的默认文本字段改名为“标题”，类型保持文本。这一列是每条记录的唯一标识，也是后续引用和跳转的基础。
建议把默认的第 2～4 列直接右键删除，免得后面操作时干扰。

② 封面链接
点列头右侧的“+”号，新建列，命名为“封面链接”，类型选文本。

③ 封面
再次点“+”号，新建列，命名为“封面”，进入【探索字段捷径】，选择“链接转附件”。引用字段选“封面链接”，生成范围建议选“自定义行数”并填 1，勾选“自动更新”，确认后在弹窗里点“仅保存配置”。
说明：“仅保存配置”不会让已有记录马上生成图片；“生成”才会让最前面指定数量的记录立即更新出图。
这样一来，系统会自动访问链接并把图片下载到表格里，卡片或画廊模式就能直接展示，不用手动上传。

④ 原文链接
新建列，命名为“原文链接”，类型选“超链接”。它可以保存文章原始出处，想看排版、评论或溯源时，点一下就能回到原网页。

⑤ 标签
新建列，命名为“标签”，类型选“多选”。在“选项内容”区域点“+添加选项”，依次维护需要的分类名。
建议分类名前加 Emoji，让表格更有辨识度，比如：

```
`💄时尚美妆
🌍旅游出行
🍜美食消费
📚学习教育
💹商业财经
💼职场
💴搞钱项目`
```

如果自己拿不准 Emoji，可以把分类发给 DeepSeek，让它帮你配：

```
`时尚美妆

美食消费

```

⑥ 阅读状态
新建列，命名为“阅读状态”，类型选“单选”。手动添加三个选项：⏳未读完、✔️已通读、🔥已精读。这列用于标记学习进度，在看板视图里可以快速看出哪些内容已经消化。

```
`⏳未读完
✔️已通读
🔥已精读`
```

⑦ 内容评分
新建列，命名为“内容评分”，在字段类型中搜索“评分”，默认满分 5 分。读完后可以主观打分，分值高的内容之后可以筛选出来反复精读。

⑧ 收藏备注
新建列，命名为“收藏备注”，类型选“文本”。用来记录收藏时的想法或灵感，相当于给文章贴一张便利贴。

⑨ 文章总结
先新建一个文本列“正文”，再新建“文章总结”列，在【探索字段捷径】中选“自定义 AI 填充”。
把下面的提示词粘贴到“输入指令”框，并在“文章内容：”处分别点击右上角“+引用字段”，引用“标题”和“正文”两个字段。自定义行数选“整行”，确定后在弹窗中点击“生成”。

飞书给这个 AI 模型的免费额度为每天 3 万次、每月 30 万次，日常使用足够。

```
`请用最易懂的方式总结下面这篇文章。
要求如下：
1.  **先用一两句话告诉我这篇文章最核心讲了什么。**
2.  **然后分点列出文章主要讲了哪几件事。**
3.  **最后提炼出最重要的结论或建议。**
输出格式要求如下：
**一、文章总结**
具体的总结内容。
**二、文章概述**

    if (params.input_title) fields[&#x27;标题&#x27;] = params.input_title;
    
    if (params.input_url) {
        fields[&#x27;原文链接&#x27;] = {
            text: &quot;查看原文&quot;,
            link: params.input_url
        };
    }
    
    if (params.input_content) {
        fields[&#x27;正文&#x27;] = params.input_content;
    }
    
    if (params.input_banner) fields[&#x27;封面链接&#x27;] = params.input_banner;
    
    if (params.input_video) {
        fields[&#x27;视频链接&#x27;] = {
            text: &quot;查看视频&quot;,
            link: params.input_video
        };
    }
    
    if (params.input_images) fields[&#x27;图片链接&#x27;] = params.input_images;
    
    // 记录时间（始终存在）
    fields[&#x27;记录时间&#x27;] = currentTimeStamp;
    
    // 构建最终body
    const body = JSON.stringify([{ fields }]);
  
    // 返回所有输出变量
    return { 
        body, 
        time_record, 
    };
}`
```

### 2. 工作流里的 AI Agent

这也是一项刚上线的能力，本节理论内容同样引自官方文档。

流程中的 AI Agent，是飞书新加的一个强 AI 节点。把它放进流程里，复杂的业务处理就能交给模型去做。

这个节点能看懂并调用各类工具——发消息、写新记录、抽签、生成随机数之类都在其列。如果还嫌不够，可以通过自定义 MCP（模型上下文协议）工具给它继续扩装。

面对具体任务，它会自己拆解步骤、挑选工具去执行。它还带记忆，能读取群聊或私聊里的前情，从而摸清任务来龙去脉。

凡是需要结合上下文临场判断、再联合多件工具一起干的活儿，都适合用它。比如下面这几类：

+ 会查表数据的飞书消息机器人
+ 每天定时把各项目进展汇总成一份小结
+ 自动建任务的机器人
+ 自动抽取并按统一格式整理数据的机器人

![](img/47463fc63f5bd56187965f6c81127e9d.png)

模型是它的心脏，记忆和工具调用则长在两侧。配置时得填好这几块：

**主节点**：写给模型的指令放在这里，输入处能引用前面步骤产出的数据，输出格式也可以在此规定。

**模型子节点**：挑一个模型，再调它的随机程度、回复长度上限等参数。

**记忆子节点**：若流程由收到飞书消息来触发，可以在这里规定带给模型的历史轮数。

**工具子节点**：各类工具挂在这里，自定义的 MCP 工具同样能加。

跑起来之后，模型按主节点里的指令自行排布步骤、调用挂在工具子节点上的能力，把任务办完，再照约定的格式交回结果。此外，配置项和日志都做得比较齐，流程是否按预期走、走过哪些环节，可以查得清楚。

#### 2.2 先做准备

动手配流程之前，先在表里把三类字段立起来：收输入、起流程、存结果。下面把这三个关键字段按统一标准逐一定好。

**2.2.1 字段一：写创意的地方**

这一列是文本型，用来收纳你输入的创意或提示词，也是后面交给模型加工的原料。之所以选文本，是因为它不卡格式——中英混排、数字、标点都容得下，短到几个关键词、长到整段描述都能装，正好应付提示词形态多变的情况。

**怎么设置**

建一张新表，在类型清单里挑「文本」。这步是定下存放形式，保证模型读到的是最朴素的字符串。

把第一列的标题改成「动物」。这步是给这一列一个明确语义，后面流程里引用变量时，一眼就能认出它是入口那头的数据。

其余项不必动，直接确认保存。至此这一列立好了，马上就能开始录入，主要用来写创意。

![](img/b5421548bd89c5be53befa9d5afe6369.png)

2.2.2 字段二：启动按钮

这一列是按钮型，作用是让人手动把自动化跑起来，等于把每一行数据的处置权交回给使用者。之所以不用自动触发，是因为视频生成既要花接口费用、又耗时间；若一改内容就自动开跑，误触几次便是白花的钱。改用按钮，则可以等确认无误之后再明确发起，按需执行。

**怎么设置**

点开第二列列头的图标，在类型里选「按钮」。这等于给表格添了一个能点的控件，它不再只是存数据，还能触发动作。

按钮文字一栏写「生成」，再挑个显眼的颜色。这样一眼就知道它是干什么用的，操作区和数据区也就分开了。

别的先不碰，也不必急着挂流程——此时后台流程还没影，先占好位置，等搭完之后再回来做关联。

等流程建好，在执行步骤的选项里把它和这一列绑上（见第二张图）。

2.2.3 字段三：存视频地址

# 视频链接该进哪个字段

先说关键点：调用视频生成接口，服务器并不会把成片文件塞给你，回来的只是一条以 http 开头的地址。既然到手的是一串字符，表格里就得准备一个能装字符串的位置——文本字段。要是顺手选了"附件"列，数据类型对不上，接口一返回就报错，后面的自动化流程也会连带着跑不下去。

**字段配置操作**

把第三列原本的日期字段先清掉，再点这一列现成的【附件】，在类型清单里改勾"文本"。这样做的用意，是让列的存储方式与接口实际回传的数据结构（String）对齐，避免容器选错拖垮自动化的运行。

列名可以改成"视频链接"，也可以维持"附件"不动。比名字更重要的，是把含义写清楚：这一列收录的是能点开观看的访问地址，谁看表格都能一眼明白。

按确认保存即可。等到自动化执行到"修改记录"那一环，结果才有地方落地。

提醒一句：第三列承载的是文本，用来收录海螺或别家工具产出的视频地址。

## 2.2.4 怎样拿到 fal 平台的海螺 API Key

**提示**：下面讲的是整个 HTTP 节点的配置，其中最要紧的环节，是拿到 fal 那边的海螺 API Key。只不过海螺的充值要走海外渠道，门槛不低，所以这次搭建工作流，我们换成云雾平台的 API 来演示。你要是已经有办法给海螺充值，继续往下看即可；暂时充不了，也没关系，直接跳到下一个环节，跟着学搭建就好。视频里演示的节点，用的同样是海螺 API。

**案例一：让多维表格的工作流来跑这套流程**

在 AI Agent 下方按一下加号，从菜单里挑中用于对外发出 HTTP 请求的那个节点。加上它，等于给流程装了一个出口，先前整理好的 Prompt 就由它递送到远端服务器。

![](img/86133b5a0b9c30712a19f579757b2e46.png)

打开上面提到的海螺页面（https://fal.ai/models/fal-ai/minimax/hailuo-02/standard/text-to-video），切到 API 标签，再选 HTTP（CURL）。页面下方会冒出一段 submit a request，那串内容就是我们待会儿要照着填的请求。建议按下面示范的思路逐条比对，摸清规律之后，再碰上同类接口，你自己也能填得出来。

![](img/514f582ea6ef57a9368ee48ffd13b3e8.png)

方法一栏定为 POST。提交数据、新建任务这类动作都归它管，也是 RESTful 接口的通行做法。

地址处填 https://queue.fal.run/fal-ai/minimax/hailuo-02/standard/text-to-video 。有了它，请求才知道该投递到哪儿：FAL.AI 上那个 Minimax Hailuo-02 模型，负责把文字转成视频。

（示例代码，纯文本）

```
`https://queue.fal.run/fal-ai/minimax/hailuo-02/standard/text-to-video`
```

到 Headers 里点添加，键写 Authorization，值则是先打 Key，空一格，再接上你自己的 API_KEY。这是确认身份的环节：密钥好比门票，服务器凭它判断你有没有资格发起调用，以及账单最终算到谁头上。别忘了 Key 与密钥中间那个空格。

（示例代码，纯文本）

```
`Authorization
Key空格你的API_KEY`
```

本次要用的，正是 fal 平台上的海螺接口。想拿到对应的 API Key，可以这样走：

先访问官方模型页 https://fal.ai/models/fal-ai/minimax/hailuo-02/standard/text-to-video

在加号处点进去，就是积分充值界面，挑好数额，点下 quick buy 付款。

![](img/cf6f786c23541f52a37ff77be03d0316.png)

接着按引导生成属于你的 API Key。要留意：这类 Key 只展示一次，务必当场复制保存，页面不会再显示第二回。

`{

### 2.3.3 配置 AI Agent 节点

AI Agent 是一层智能加工：用户随手写的一句话，经它扩写，变成带细节、光线与构图的完整描述。视频模型对描述精度相当挑剔，只拿几个干巴巴的词去生成，画面往往空洞、缺少层次；中间多这么一道整理与规范，成片效果会明显不同。

![](img/c584a3941d722a49a5c7c59d0b975e74.png)

3.3.8 组合图（双轴趋势对比）

+   紫色柱状代表总量（比如活动带来的线索数）；

+   黄色折线代表转化率（有效线索占比）；

# 二、多维表格的商业变现机会和实操案例

## 01. 多维表格的商业变现机会

### 1.对超级个体

对于超级个体来说，多维表格至少能够有以下的 3 个机会

#### 机会一：产品化 （Productization） - 交付“数字工具”

**卖表格模板：这里主要分为两种类型，一种是做一些 toC 场景的多维表格，例如记账、电子**衣橱、旅游规划、个人成长等等，比较大众化的需求，客单价比较低，但是比较容易成交。

第二种是做些 toB 场景，相对比较专业的多维表格，例如社媒数据分析、达人管理系统、直播复盘系统等等，这种相对来说客单价就高一些，能去到几百块，但是就需要有垂直行业的专家经验，并且把这种专家经验沉淀成表格模板的形式。

#### 机会二：服务化 （Servitization） - 交付“定制劳动”

**卖定制表格表格服务：顾名思义，在闲鱼或者小红书之类的平台发布商品或内容吸引客户，然后根据客户的需求定制，相对卖模板**交付更重一些，需要有比较强的沟通能力，定制表格的客单价也会高很多，根据表格的复杂程度 1000 元到 5000 元不等。

虽然交付比较重，但是这是一个很好的积累案例的过程，在经过客户允许，数据进行脱敏的情况下，把制作表格的过程内容化、把制作好的表格再次打包成模板去二次销售，这样就能实现一鱼多吃，把利润最大化。

#### 机会三：顾问化 （Consulting） - 交付“商业解决方案”

**卖某垂直领域的解决方案：现在市面上的 AI 应用普遍都有一个痛点，懂 AI 的人不懂业务，所以做出来的 **AI 工具普遍是华而不实，在实际的业务场景中很难去落地，懂业务的人不懂 AI，有时候可能有好的想法但是却不知道如何实现。

多维表格的出现就很好的降低了业务专家搭建 AI 应用的门槛，使得一些过去在传统行业（例如餐饮行业、制造业、教育行业）有专家经验的人，可以利用多维表格去为一些同行业的企业做赋能，一个人就能够去 搭建出一套系统，改进业务流程，为一些中小企业服务，做一个系统架构师或是 AI 效能顾问等，这个客单价就会高很多，上万甚至几万都是很正常的。

### 2.对中小企业

仪表盘的功能，对中小企业很有用，抖音直播的数据大盘是用多维表格的仪表盘功能

#### （1）定制化开发服务：打造“轻量级行业系统”

这是最直接的变现方式，核心逻辑是利用多维表格灵活且开发成本低的特性，为中小企业提供能够替代昂贵传统软件的解决方案。

**垂直行业“小系统”替代：**

目前市面上许多进销存或客户管理软件价格昂贵且功能过于复杂，中小企业往往难以有效利用。你可以针对特定行业的具体痛点，搭建一套完全适配其业务流程的多维表格系统。

例如，为装修公司搭建施工进度管理系统，以解决监管困难的问题；或者为电商公司搭建从选品、拍摄到上架的全流程管理系统。这种服务的核心价值在于，企业只需为符合自身业务流程的功能付费，无需为冗余功能买单。

数字化SOP（标准作业程序）落地：

许多企业虽然拥有标准作业程序文档，但往往因为缺乏执行力而使其闲置。你可以将这些纸质或文档形式的制度转化为多维表格中的自动化流程。

例如，将员工入职流程设置为自动化任务，系统会在员工填表后自动开通账号、发送欢迎信并指派老师。这种服务将静态的制度转化为动态的执行流，由系统自动推动人员完成任务。

#### （2）数据咨询与商业智能服务：提供决策支持

基于多维表格的数据集中管理和实时看板功能，你可以向企业管理者出售基于数据的决策依据。

**数据清洗与仪表盘搭建服务：**

很多企业管理者面临数据分散在不同文件或部门的情况，导致无法及时获取关键经营数据。你可以通过服务帮助企业梳理数据结构，清洗历史数据，并利用多维表格搭建可视化的数据仪表盘。这让管理者能够随时在手机端查看企业的实时盈亏和经营状况，不再依赖滞后的手工报表。

**自动化预警系统配置 ：**

企业经营中往往存在风险发现滞后的问题，如库存不足或合同到期未续约。你可以通过配置复杂的自动化规则，针对关键业务指标设置预警线。例如，当利润率低于特定数值时，系统自动发送消息通知管理群；或当关键客户长时间未跟进时，自动提醒负责人。这种服务能够帮助企业及时发现并处理潜在风险。

#### （3）陪跑与培训服务：提升企业内部能力

基于多维表格易于上手的特性，许多企业更倾向于培养内部团队来维护系统，这衍生出了培训与顾问需求。

**企业数字化顾问：**

这种模式不直接交付最终的系统，而是以技术顾问的身份按周期收费。你需要定期与企业梳理业务逻辑，指导企业内部的业务骨干搭建系统，并协助解决函数公式或接口对接等技术难题。其价值在于帮助企业培养出具备数字化能力的内部人才，实现能力的转移。

**特定场景的实战训练营：**

你可以针对特定岗位开设高价值的实战课程，例如行政人力资源效率提升课程或项目经理自动化管理课程。这些课程不讲解枯燥的功能菜单，而是直接演示如何使用多维表格解决该岗位面临的具体业务难题，注重实战应用。

#### （4）规模化产品销售：标准化模板与插件

当你积累了丰富的行业经验后，可以将解决方案标准化，从而实现产品的规模化销售。

**行业标准化模板：**

你可以将已经验证成熟的系统（如MCN机构内容管理系统）进行脱敏处理，封装成标准模板进行销售。这些模板可以发布在平台的模板市场，也可以通过私域流量进行销售，利用低价高效的模板吸引客户。

**跨系统数据连接服务：**

多维表格虽然功能强大，但往往难以与财务软件或电商后台直接打通。你可以利用 n8n 等自动化工具或 API 技术，搭建多维表格与其他专业软件之间的数据桥梁。这种服务可以按照接口数量或维护周期收费，解决了企业内部数据互通的难题。

# 别再一张张手动传图了，这段 Python 脚本全帮你搞定

经常写文章、搭站点的人，多半都绕不开图片托管这件事。一张张手动上传，费时间不说，还容易漏传、传错。下面这套 Python 小工具，就是围绕图床自动上传做的一站式方案，从格式检查到批量处理，再到上传后的信息查询，基本都覆盖到了。

**先过格式关，再谈上传**

脚本先把常见图片后缀收进一个白名单：jpg、jpeg、png、gif、bmp、webp。上传前会先拆出文件扩展名，转成小写后比对；只要不在名单里，立刻打印“不支持的图片格式”并返回空字符串，不会把无效文件硬塞给接口。检查通过后，才会提示文件有效，进入下一步。

**单张上传：一条完整链路**

真正上传时，脚本会先打印“准备上传到图床”，然后打开图片文件，以二进制方式读取。接口地址指向 imgloc 的上传端点，请求头里带上 `X-API-Key` 做身份验证，表单字段名为 `source`，同时附带文件名和对应的 MIME 类型，比如 `image/png`。请求超时被设置为 60 秒，避免网络卡住时一直干等。

响应回来之后，脚本会分两层判断：先看 HTTP 状态码是不是 200，再看返回 JSON 里的 `status_code` 是否也为 200。两层都通过，才去取 `image.url`；拿到链接就打印成功信息和查看地址，并把 URL 返回给调用方。任何一环出问题都有对应提示，包括响应里找不到图片 URL、业务状态码异常、HTTP 非 200、请求超时、网络请求异常，以及其它未预料的错误。每种情况都会输出错误信息并返回空字符串，不会让程序悄悄失败。

**整个文件夹，一次搞定**

如果你有一整个目录的图片要传，可以用文件夹批量上传函数。它先确认路径存在，再确认它确实是个目录；如果路径不存在或者指向的是文件，都会直接报错。接着扫描目录下的所有文件，逐个判断后缀是否在白名单里，把符合条件的收集起来。如果一张图都没找到，会给出警告并返回空。

找到图片后，脚本按顺序逐张调用单张上传逻辑，每传完一张就记录结果，成功和失败都会打印出来。两张之间还会停 0.5 秒，防止请求太密集被接口拒绝。全部结束后统计成功数量，并把所有成功链接用英文逗号拼成一个字符串返回。

**指定多张，也能批量处理**

除了按文件夹扫描，脚本还支持直接传入多张图片的路径，路径之间用逗号分隔。它会先解析并去掉首尾空白，再逐个检查文件是否存在、是否为普通文件。无效路径会被跳过并提示，如果最后一张有效图都没有，同样返回空字符串。有效文件会依次上传，节奏和文件夹模式一致：逐张处理、记录成败、中间短暂延迟，最后用逗号拼接链接返回。

**上传之后，还能查信息**

脚本里还留了一个获取图床图片信息的入口。它从图片 URL 中截取最后一段，再去掉扩展名，得到图片 ID，然后基于这个 ID 返回基础信息。对于需要回查图片详情的场景，这一步挺实用。

整体来看，这套代码把格式校验、单张上传、文件夹批量、多文件批量以及信息查询串成了一条线，异常分支也铺得比较全。你只需要准备好图床 API 密钥，剩下的交给脚本跑就行。

```python
BASE_URL = "http://127.0.0.1:54345"
HEADERS = {"Content-Type": "application/json"}

def create_window():
    payload = {
        "name": "google",
        "remark": "",
        "proxyMethod": 2,  # 2 自定义代理，3 提取 IP
        "proxyType": "noproxy",  # 可选 noproxy/http/https/socks5/ssh
        "host": "",
        "port": "",
        "proxyUserName": "",
        "browserFingerPrint": {
            "coreVersion": "124"  # Win7/Win8/WinServer 2012 不支持 112 及以上内核
        }
    }
    res = requests.post(f"{BASE_URL}/browser/update",
                        data=json.dumps(payload), headers=HEADERS).json()
    browser_id = res["data"]["id"]
    print(browser_id)
    return browser_id
```

# 四步搭好一条 Claude 直连工作流

想在 Coze 里直接调用 OpenRouter 上的 Claude？其实不用复杂的编排，四个节点就能搭通。这条工作流的结构非常清晰：开始 → HTTP 请求 → 代码 → 结束。下面逐个拆开来看。

**第一步：开始节点，把变量提前暴露**

入口节点只负责接收三个字符串类型的输入，而且全部为必填项：`OPENROUTER_API_`、`Prompt`、`input`。其中第一个填你的 OpenRouter 密钥，第二个用作系统提示词，第三个则是每轮实际要处理的内容。这三个值不在流程内写死，所以后期换模型、改语气、换输入，都不用改动节点结构。

**第二步：HTTP 请求，真正调用模型**

这一站以 POST 方式请求 `https://openrouter.ai/api/v1/chat/completions`，鉴权方式选 Bearer，Token 直接引用开始节点传入的 `OPENROUTER_API_`。请求体为 JSON，字段不多，但每个都必须写对：

- `model` 指定为 `anthropic/claude-sonnet-4.5`，也就是本次要用的模型；
- `messages` 是两条消息：`system` 角色填入 `{{block_output_100001.Prompt}}`，`user` 角色写明「输入信息为：{{block_output_100001.input}}，输出结果」。

请求设置上，失败重试设为 3 次，超时上限为 120 秒。这个节点会返回三项结果：响应体 `body`、状态码 `statusCode` 和响应头 `headers`。如果不想被网络波动打断，这组重试和超时参数值得保留。

**第三步：代码节点，把正文抽出来**

模型返回的内容嵌套在接口响应里，需要从中提取。代码节点用 Python 的异步函数 `main` 接收上游传来的 `body`，从以下路径取出正文：

`body['choices'][0]['message']['content']`

再把它赋值给输出变量 `content`。这段逻辑很简单，但作用关键：后面的节点只需要处理纯文本，不必关心接口的封装格式。

**第四步：结束节点，只返回一样东西**

终点采用 `returnVariables` 模式，只声明一个输出参数 `output`，值直接指向代码节点产出的 `content`。因此，整条工作流最终的返回值就是一段干净的模型回答，没有多余内容。

**这套设计的好处**

它把「调用模型」和「提取结果」拆成两步：HTTP 请求负责通信，代码节点负责解析，开始节点负责注入变量。以后如果想调整提示词，只要在调用时传新的 `Prompt` 即可，不必改动流程结构。一套接线，可以换着花样使用。
