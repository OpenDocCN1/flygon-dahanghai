# 10.7 T_T：IT 人加班困局，从原因找解法

不少读者问过：长期加班后，休息、放空和复盘的空间被一再压缩，IT 从业者大概更明显，这局面怎么破？

我的建议是，先别急着套时间管理方法，而要回到“加班为什么变多”这件事上。不同成因对应不同办法，关键是养成拆原因的意识与能力。下面举几类常见情况，供大家对照。

先看执行者角色。上级分派是否合理？工作量有没有超载？该不该申请更多资源？交给你的任务是否正好落在陌生领域？若答案偏向“是”，别闷头硬扛，该反馈就反馈，把事实和依据摆出来。领导会协调资源帮你把事顺利做完——这本来就是他的职责；他也更希望你提前同步、及时获取他的支持，这样他才能对进度保持可控。说白了，该开口时要开口。

再看时间被切碎的情况。有些会议去不去都行，有些事做不做都不影响大局，这类占用可以练着礼貌拒绝。若白天空转太多、效率被浪费，那时间管理实践正好派上用场，帮你把无效消耗收回来。

能力或经验不足时，短期内靠加班补课有其合理性，但再往下走，就绕不开高效学习的方法。

项目层面也常见。做过大项目的人都知道，突发状况、潜在风险、没识别出的依赖、外部资源变动，都会拖慢进度，逼着大家用加班去填坑。项目一旦偏离既定计划，前面投入的时间也可能被浪费。所以计划评估要尽量准：背景、痛点、人手数量与经验、时间安排、事项边界、工具、依赖关系、风险及规避措施，都要心里有数，计划才可控；之后执行要严格按计划走。项目收尾时做复盘，把这次踩过的坑沉淀成下次的经验，后续管理会更顺，A 类事项被动延期带来的加班也会减少。

另外，IT 人尤其值得盘一盘：日常工作里哪些重复劳动可以自动化替代？多借助提效工具，比如截图工具 Snipaste、信息记录工具 ediary。

总体看，加班问题可能牵涉目标、计划制定、执行情况、个人精力、习惯、回顾等多个环节。用 PDCA 循环持续打磨：Plan 计划、Do 执行、Check 检查、Act 修正。有效经验要总结、输出、肯定并标准化；没解决的遗留问题，放进下一轮 PDCA。等这套动作变成能力和习惯，你会感觉越来越轻松。
