# 11.2 先下水，再谈变现 @颜过

做小众市场，别一上来就凭空造需求。更稳的路子是：先盯住已经有人跑通、并且真赚到钱的方向，再顺着往下挖。最快的切入口往往是差评——看看那些抱怨里有没有你能解决的问题。只要切得准，变现距离就会被拉近。

有句话很实在：想学会游泳，总得先下水；不然泳姿再标准也白搭。先行原则也是这个理。围绕 PDF 这类大工具，周边需求并不少，用户盘子也够大。先攒种子用户，哪怕只让第一批人愿意掏第一块钱，也比空谈强；随后再扩展其他需求，盈利只是时间问题。

既然要先下水，路径就别绕：先模仿成熟做法，优先把核心需求跑通，支付环节尤其要落地。Chrome 插件早先还能走 Google Pay，如今官方支付通道不再支持，但第三方仍可接入，支付里的坑后面再细说。

拿 PDFXYZ 这个小工具来说，朋友 L 是用中间服务器实现的，PDF 基本能做到无损呈现。清晰度之所以关键，是因为 PDF 可能由文字、图片乃至多种格式拼合而成。这个方案能接住客户的真实需求，但也绕不开服务器上传下载链路，以及文件体积门槛：文件一大，下载时间就长，插件体验会极差，卡在那里半天动不了，所以只能把大小限制在 10M。

朋友 Y 则直接用 JS API 实现，可文件下载下来会模糊，客户的核心需求实现得还差一些；同样存在上传下载问题，不过这种方案的文件大小限制能放宽到 30M。两条路径的差异，本身就是业务流程里的坑：核心体验、文件体积、上传下载、清晰度，每一项都会反过来影响插件体验。
