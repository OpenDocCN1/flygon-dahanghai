### 1.AI 辅助编程是什么

**最近半**年时间，Vibe Coding 这个概念彻底火出了圈。今年 2 月初，OpenAI 联合创始人 Andrej Karpathy 在社交平台上提出的这个想法，短短一个多月就在开发者圈层掀起了一场不小的风波。它火的有道理，因为真正降低了编程的准入门槛。

过去要把想法变成能用的产品，要有专门的程序员去完成需求。但现在不一样了。

**即**使你对代码一窍不通，也能借助 AI 编程工具快速把想法落地。这种变化不是渐进式的改良，而是颠覆性的重构。

**就在生财来说，我们看到了太多生动的例子，不少圈友从来没写过一行代码，却靠着 Cursor、Claude Code** 这些工具，实实在在地做出了自己的应用。有人用它开发了海外工具站，有人搭建了自动化工作流，有人甚至做出了能赚钱的小程序。

这里面的差距已经不是效率高一点那么简单了。会用 AI 编程和不会用 AI 编程的人，生产力的差距可能是十倍、甚至百倍的量级。一个懂得如何和 AI 协作的人，可以在一天内完成过去一个小团队一周的工作量。更关键的是，这种能力正在重新定义"谁能创造价值”，技术不再是壁垒，想法和执行力才是。

你不再需要把 80%的精力花在写代码上，而是可以专注于真正重要的事情，那就是创意、产品设计、用户体验。代码实现？交给 AI。你负责想清楚"要做什么"和"为什么这么做"，AI 负责怎么做，极大解放你的时间精力。

### 2.AI 辅助编程与传统编程的区别

传统编程和 AI 辅助编程，本质上是两种完全不同的工作方式。

过去要成为开发者，你得先翻厚厚的编程书，啃下复杂的专业术语和概念，再折腾各种框架配置。学习周期动辄半年起步，投入的时间成本高得惊人。很多人就是在这个阶段放弃了，不是因为不够聪明，而是因为这条路实在太陡峭。

但 AI 时代彻底改写了这个游戏规则。现在的核心能力不再是记住成编程语法，而是学会和 AI 对话。你需要做的是清晰地描述你的需求，用最自然的语言告诉 AI 你想要什么。AI 会基于你的描述生成代码，给出多种实现方案。你的工作变成了从这些方案中挑选最合适的那个，然后继续对话，比如："这里的逻辑能不能调整一下""能不能加个导出功能"。就这样一轮轮迭代，项目在你和 AI 的协作中逐渐成型。

下面对传统编程和 AI 辅助编程进行一些维度对对比：

| 维度 | 传统编程 | AI 辅助编程 |
| --- | --- | --- |
| 定义 / 驱动方式 | 开发者手动编写代码、设定逻辑、定义流程，代码主要由人决定“做什么、怎么做”。 | 开发者更多地借助人工智能工具（如大语言模型、代码生成/补全助手）来生成、建议、优化代码，变成“人 + AI” 人机协同的形式完成一个项目。 |
| 编码工作量 | 程序员需要从头定义算法、流程、结构、接口、细节。 | 很多重复、模板化或样式化的编码任务可由 AI 自动完成，人主要负责提需求、验证、监督。 |
| 专注点 /技能要求 | 强调编程语言熟练、逻辑思维、数据结构、算法、架构能力。 | 除了传统技能，还越来越强调如何与 AI 协作、如何给出「好的提示词」、如何验证 AI 产出的代码、如何管理 AI 生成的系统。 |
| 速度／效率 | 在可预见、结构化明确的项目中效率较高，但面对大量重复或模板化任务耗时。 | AI 辅助可显著提高开发速度，尤其在 boilerplate、重复逻辑、原型阶段表现强。 |
| 代码质量／可维护性 | 代码结构、逻辑可被开发者理解、维护责任清晰。 | 生成速度快，对于大型的项目 AI 生成代码可能带来可读性差、结构重复、隐藏缺陷或安全风险。 |
| 学习门槛／入门 | 学习编程语言、算法、工程思维需要一定时间；新手可能起步慢。 | 借助 AI 辅助，新手可以更快产生可运行代码，降低起步门槛。我们可以以学代练，在AI编程的过程中掌握编程 |
| 适用场景 | 适合高复杂度、需求模糊、需创新、对质量有高要求的项目。 | 适合重复性任务、快速原型开发、标准模块生成、初稿编写、提高开发效率的场合。 |
| 工具／生态变化 | 传统 IDE + 手写/模板代码模式。 | 大量 AI coding工具（比如代码生成、补全、生成、语义搜索、错误检测、自动测试等）正在普及。 |

### 3.AI 辅助编程中涉及的技术

💡

**本**次航海的核心目标，就是构建一个 AI 驱动的内容工厂 agent，这个系统包含三大核心能力：选题洞察、内容二创和快速发布。

整个工作流程会涉及以下环节：

数据获取层面，我们会根据关键词抓取公众号文章和小红书笔记；

选题分析阶段，利用大模型对采集到的内容进行深度洞察；

内容二创环节，基于筛选出的优质选题进行文章创作；

最后通过调用官方认可的 API 实现笔记或图文的自动发布

**这个的实现路径本质上是把可靠的数据源、稳定的大模型服务和各平**台的发布能力，用清晰的工程化方式串起来。

为了让大家更容易上手，我们选择了依赖少门槛低的方式去实现。

**接下**来我们介绍项目涉及的一些技术。这里可能会出现一些专业术语，但大家不需要有心理负担，我们不需要深入研究每个技术的底层原理，只需要理解它们在项目中的作用，知道它们解决了什么问题、在流程中处于哪一环即可

#### 3.1 Next.js：我们的开发框架

Next.js 是一个轻量级的全栈开发框架，学习曲线平缓，能同时处理前端界面和后端逻辑，非常适合快速构建完整应用，新手小白上手极快。这也是我强烈推荐它作为本次航海的开发框架的原因。

这里也解释一下什么是"全栈开发框架"——传统的开发模式下，做一个网站需要分别学习两套技术，一是前端负责用户看到的界面（比如页面、按钮、表单、布局），后端负责后台的数据处理和业务逻辑（比如用户登录、数据存储）。

很多时候前端用 React/Vue，后端用 Node.js 或 Python，需要掌握两套完全不同的知识体系。

而 Next.js 的强大之处就在于，它把前端和后端整合在了一起，让你用一套技术就能同时搞定用户看到的界面和后台数据处理，大大降低了学习成本，对新手的友好程度更高。

#### 3.2 SQLite：本地化数据库方案

说到数据库，你可能听过 Supabase（基于 PostgreSQL）、MySQL 等多种选择。但为了降低学习成本，避免依赖外部服务，帮助大家快速搭建起内容工厂，我们选择了 SQLite 这个完全本地化的数据库解决方案。

我们可以理解为，SQLite 就像是一个装在你电脑里的 Excel，所有数据都存在一个本地文件中，轻量而且读写快速，适合个人使用或小规模项目，优点是配置简单、不需要安装独立的数据库服务器，打开即用，我们不需要付出额外的学习成本去理解数据库的概念，它的使用基本是无感知的。

而 Supabase（Postgres） 则是一个功能更强大的企业级数据库，需要独立运行，支持更复杂的查询、更高的并发访问（多人同时使用），以及更大的数据量，但是使用起来略复杂，前期需要繁琐的配置。

所以这次航海我们先用 SQLite 把流程跑通，等你的内容工厂真正运转起来、数据量增大或者需要云端部署的时候，再升级到 Supabase，这样既能快速起步，又保留了未来的扩展空间。

#### 3.3 API：连接外部能力的桥梁

API 是“应用程序接口”的缩写，我们可以把它理解为一个标准化的服务窗口。你发出清晰的请求，对方按约定返回结果；至于内部是如何实现的，我们不需要关心，API 把原本需要你手动复制粘贴的流程，变成可编程、可批量、可定时的任务。

这次航海中我们会大量使用外部 API 服务，如上面提到的公众号采集 API、小红书采集 API、大模型 API 以及内容发布 API 等。从更宏观的视角看，一个在线产品可以理解为就是多个 API 的组合与功能包装。

**简单理解，API 就是不同服务之间沟通的**接口，让我们能调用别人已经开发好的功能。

#### 3.4 我们可能会用到的 API 平台

**大模型 API：**

在我们本次的航海项目中，AI 能力贯穿了整个内容生产流程的各个环节。我们需要 AI 对采集到的公众号文章进行深度分析，挖掘其中的选题价值和爆款要素；需要 AI 根据选题自动撰写符合平台调性的内容初稿；还需要 AI 生成配套的插图和封面，让内容更具视觉吸引力。要实现这些功能，就必须调用相应的大模型 API。

硅基流动 （siliconflow.cn） ：是一个开源模型聚合平台，提供了大量免费或低价的开源大模型 API 接口。在我们这次航海项目中，内容创作环节的图片生成功能就采用了硅基流动免费的可灵模型。

DeepSeek （platform.deepseek.com） 是国内最具性价比的商业大模型服务之一。它的 V3.1 版本在推理能力、代码生成、长文本理解等方面表现优异，价格却只有 GPT-4 的几十分之一，对于我们大量内容生成的场景来说是性价比最高的选择之一。

火山方舟 （volcengine.com） 是字节跳动旗下的企业级 AI 服务平台，提供豆包等大模型的 API 接口。它的优势在于服务稳定性好、响应速度快性价比也不错，而且豆包家族百花齐放，文本模型，图像模型，视频模型应有尽有。

OpenRouter （openrouter.ai） ：是我们在手册中主要使用的平台，它是一个大模型聚合服务，把 GPT 系列、Claude、Gemini、等几十个主流模型整合在一起。你只需要接入 OpenRouter 一个 API 接口，就能调用所有这些模型。

**本次我们手册中主要使用的是 OpenRou**ter，大家可以根据自己的实际情况选用。

**数据采集 API**

数据采集 API 是实现内容工厂自动化的第一环，我们可以把他理解成一个不眠不休的搬运工，帮我们批量获取各个平台的内容数据。

以公众号采集 API 为例，你只需要提供一个关键词或者公众号账号名称，就可以通过 API 自动获取该公众号的所有历史文章，包括标题、正文内容、发布时间、阅读数、点赞数等完整信息。这些原本需要你一篇篇手动复制粘贴的工作，通过 API 几秒钟就能批量完成。

在我们这次航海项目中，会使用 https://dajiala.com/ 平台的公众号采集 API。支持按关键词搜索公众号文章。

**除了 h**ttps://dajiala.com/，市面上还有很多数据采集 API 平台可供选择，比如 apify.com 就是一个功能强大的通用采集平台，它可以采集 Twitter、Instagram、YouTube 等几十个海外平台的数据。如果你未来需要做跨平台的内容分析或出海业务，apify 会是一个值得考虑的选择。

**内容发布 API**

如果说采集 API 是内容工厂的原料入口，那发布 API 就是产品出厂的最后一公里。内容发布 API 能够把你生成好的文章、图片、视频自动发送到目标平台，完全省去手动登录、复制粘贴、排版调整这些重复劳动。

以微信公众号为例，通过调用公众号的发布接口，你的程序可以自动完成文章发布。

**在我们的项目中，会使用 wx.mgxingyuan.com 来实现微信公众号的自动发布功能。这个平台封装了**公众号复杂的 API 接口，让发布流程变得非常简单，你只需要传入标题、正文、封面图等参数，就可以通过 API 进行发布。

**小红书发布则会使用 note.limyai.com 平台**，它采用生成发布链接的方式进行笔记发布。

**其**实也可以这样理解：我们的整个项目就是在串联和包装各种 API，最终组合成一个完整的自动化内容生产系统。

### 4.Claude code 和Codex 的区别

两者都是目前炙手可热的 AI coding 工具，Codex 速度慢，但是代码质量可靠，定位问题修改 bug 能力一流；Claude Code 响应迅速，前端审美能力和从 0-1 的能力比 codex 要好一些，但是最近幻觉较高，一直饱受降智的质疑。

Codex 的话 ChatGPT 会员可以直接使用，用量比 cc 更大，20 美元/月的 plus 会员基本已经量大管饱，而且 gpt-5-hign 的修 bug 能力无与伦比，缺点就是速度慢，经常一个任务耗时半小时甚至更久，工具成熟度稍逊于 Claude Code。

综合来看的话，Claude Code 依然是目前最优秀的 AI 命令行编程工具，它的工具成熟度最高，使用体验流畅，不管是各种 subagent，自定义 slash，hook 等各种工具/细节能力都要优于目前的 Codex，但是最近一段时间 Claude Code 频繁降智，高峰期切换低成本模型，官方多次承认过模型问题，但是从社区和真实体感看，依然和之前的 CC 差了不少。

**选择**建议：预算充足就两个都用，追求质量选 Codex，追求快和平衡就选 Claude Code。用 Claude Code 0-1 写代码，Codex 审查解决 bug ，用这种互补方式最大化两者优势。

### 1.开发环境介绍

#### 1.1VS Code 是什么

VS Code 是由微软公司 2015 年推出的一款免费开源和跨平台的现代化代码编辑器。它完美支持 Windows、macOS 不管你使用什么系统的电脑，都能获得一致的开发体验。

**VS Code 最大的特点是轻量但功能强大。基本支持几乎所有主流编程语言，包括 TypeScript、Python、Java、等数十种语言，安装包通常只有几十兆，启动速度极快，但**功能丝毫不逊色于专业级 IDE，尤其是它强大的扩展生态，你可以根据自己的需求安装各种扩展，比如我们这次的 Claude Code 和 Codex 也都有对应的 VSCode 插件，可以让我们快速上手。

#### 1.2 Node.js 是什么

在了解 Node.js 之前，我们需要知道一个背景：JavaScript 这门语言最初是为浏览器设计的，只能在网页中运行。而 Node.js 的出现彻底改变了这一切，它可让 JavaScript 代码可以脱离浏览器，直接在服务器上运行。

Node.js 是一个基于 Chrome V8 引擎的 JavaScript 运行时环境。简单来说，它就是一个可以在你的电脑上执行 JavaScript 代码的平台。

那为什么我们需要 Node.js

这次航海中，Node.js 扮演着多个关键的角色

首先，它是运行 Next.js 项目的必需环境。Next.js 本身就是一个基于 Node.js 构建的 React 框架，没有 Node.js，我们的项目无法启动。

另外 Node.js 自带的包管理工具（npm 或 yarn）是我们安装和管理项目依赖的核心工具。几乎所有的第三方库、框架、开发工具都通过它来安装和更新，比如我们这次用到的 Claude Code 和 Codex。可以说 Node.js 是整个前端开发工具链的基石。

**Node.js 的核心优势**

Node.js 采用事件驱动、非阻塞 I/O 模型，这使得它特别适合处理高并发场景。虽然我们在学习阶段可能感受不深，但这种特性让 Node.js 在真实的生产环境中能够高效处理大量用户请求。Node.js 还有一个优势就是生态系统的繁荣。npm 是世界上最大的软件注册表，拥有超过两百万个开源包。这意味着几乎任何功能需求，你都能找到现成的解决方案，大大提高了开发效率。

VS Code 和 Node.js 构成了我们开发环境的两大支柱。VS Code 是我们写代码的地方，提供了舒适高效的编辑体验；Node.js 则是代码运行的引擎，提供了执行环境和工具支持。掌握这两个工具，你就为后续的学习打下了坚实的基础。下面的章节我们将详细介绍如何安装和配置这些工具，让你的开发环境真正运转起来。

Claude Code yolo 模式（自动挡模式）

我们在使用 cc 的过程中经常会出现要求我们手动确认文件修改的场景，这种频繁的人工干预会打断我们的思路。

这种情况下我们就可以使用 yolo 模式了，它可以解放我们的双手，让 cc 进行入到自动工作模式。

YOLO 模式通过一行启动命令开启：

claude --dangerously-skip-permissions

如果我们发现 cc 左下角提示了一个“bypass permissions on"，代表我们的 YOLO 模式已经启动成功了

![](img/24c4497b6a2cf9b8ab412bd04a1ab630.png)

yolo 模式非常适合我们从 0-1 新建项目，这种模式下我们不需要频繁地去接受变动，让我们写代码像德芙一样丝滑。

那我们发现每次输入这么长的一堆很麻烦，那我们能不能默认使用 claude 就是 yolo 模式呢？解决方案很简单，就是配置终端别名。

当然了无需自己实现，我们只需向 cc 发出这样的指令：

Plain Text

```
`请帮我在终端配置一个别名，使得输入claude时自动执行claude --dangerously-skip-permissions命令`
```

这样我们发现执行 claude 进入中断后左下角也有 YOLO 模式的提醒了

下面是我自己写提示词的一些小感悟，希望对大家有用：

**我们启动新项目的时候，第一个提示词最关键，它的作用**是要帮助我们明确功能边界，生成项目原型。

我的建议是先在 Claude 或 ChatGPT 中反复对话，把产品功能范围彻底想清楚，最好生成一份需求文档，然后拿这份文档到 Claude Code 中沟通对齐。需求是需要不断迭代的，不要指望一次性说清楚所有细节。

**这个**流程其实和传统软件开发一脉相承，只是角色发生了变化。以往是对齐产品经理和程序员之间的信息差，现在是对齐我们和 AI 之间的信息差。只有理解一致，才能确保结果可控，这是确定性的前提。

后续提示词可以简单划分为三大类型：

**一**是纠正：当 AI 理解出现偏差时及时调整方向。AI 再聪明也会误解需求，发现问题立即指出比事后返工效率高得多。

**二**是确认：如果 AI 理解准确无误，直接确认让它继续执行后续步骤即可。不需要画蛇添足，信任 AI 的执行能力。

**三是**补充：AI 虽然能力强大，但它缺少我们现实世界的业务上下文。根据 AI 的回复适时补充关键信息，比单纯依赖 AI 脑补更靠谱。这种上下文补充往往决定 AI 生成的项目是不是符合我们的预期。

最后一点，在 vibe codign 的时候，我们完全不需要精雕细琢提示词，那些动辄几百字的"提示词工程"已经过时了。核心原则是 限定功能范围+明确技术栈要求，要尽量简洁表达，AI 会自动补充常识性内容。如果有必要可以按顺序列举业务流程，比如第一步做什么、第二步做什么。

简洁和详细不是对立关系，而是互补的。简洁是指不说废话，砍掉那些又臭又长的裹脚布式描述；详细是指在关键点上不惜笔墨，比如必要的补充文档、明确要求的输出格式、严格禁止的操作范围。该说的一定要说清楚，不该说的坚决不啰嗦。

以上是我在 AI 编程中总结的提示词常用方式，核心就是把自己当成产品经理，把 AI 当成开发团队，用最高效的方式对齐信息、消除歧义、迭代优化。不要迷信复杂的提示词技巧，理解 AI 的工作方式，用人话说清楚需求，就是最好的提示词。

希望这些经验对大家有所帮助。

function generateImageUrls(keywords: string[], count: number): string[] {
  const images = []
  for (let i = 0; i &lt; count; i++) {
    const keyword = keywords[i % keywords.length] || &#x27;creative&#x27;
    images.push(`https://source.unsplash.com/800x600/?${encodeURIComponent(keyword)}`)

  return images
