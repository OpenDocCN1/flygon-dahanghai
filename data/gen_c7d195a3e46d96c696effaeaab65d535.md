# 真正带得走的，不是案例，是方法

你从拆开别人的 Skill、动手改它开始，慢慢弄明白 SKILL.md、references、scripts 各自管什么，然后从零搭出了自己的写作 Skill。

再往后，你又做出了判断类 Skill，让 AI 学会调资料、跑脚本、存经验，并在测试、迭代、优化里反复打磨。

到最后，你把一个 Skill 整理成能安装、能分享、能长期维护的成品，发到 SkillHub，完成了自己的第一个 Skill 成果。

更关键的是，你已经拿到了一套做 Skill 的方法。

下次碰到新场景，你会自然开始想：

• 这件事，值不值得做成一个 Skill？
• 哪些规则该写进 SKILL.md？
• 哪些经验适合沉到 references？
• 哪些固定计算交给 scripts？
• 怎么测试、修改、持续迭代，让它越来越贴合自己的工作方式？

最值钱的并非那两个案例，而是这套能力。

以后不管写作、判断还是别的场景，你都能用同样的路径，把自己的经验一点点沉淀成新的 Skill。

**回头看看，这一路你已经做到：**

✅ 能装好一个 Skill，也能亲自试出它靠不靠谱；
✅ 能拆开 Skill 看结构，明白每个文件各管什么；
✅ 能独立从零做出自己的 Skill；
✅ 能给 Skill 补资料、挂脚本、写判断规则；
✅ 能拿真实案例去测、去改、去优化 Skill；
✅ 能整理、发布并分享自己的 Skill。

到这里，必修篇收尾了。

但真正好用的 Skill，从来不是在课程里做出来的，而是在之后一次次真实工作里慢慢长出来的。

以后再遇到那种反复出现、每次都要重新处理的问题，先问自己：这事能不能沉淀成一个 Skill？

也许，它就会成为你的下一个能力资产。

如果想继续挑战，后面的选修关卡会带你建自己的 Skill 资产库，学怎么管理、改造优秀 Skill，也会邀请你动手创作，把经验和想法真正落成一个好 Skill。

如果你已经想把这些方法用回工作，那就从今天开始。

**最重要的，不是把这门课学完，而是让每一次新实践，都变成下一个 Skill 的起点。**

# 选修篇：Skill 上手之后，进阶还能怎么玩

## 关卡 9：搭建属于你的 Skill 能力库

### 00. 这一关的任务卡

**🎯 目标：** 把自己装过、做过的 Skill 梳理清楚，学会按真实需求去找、去筛、去验证外部 Skill，最后形成一份能持续更新的个人 Skill 清单。

**🗒️ 要做什么：**

• 盘点当前装过和做过的 Skill，列成清单；
• 找出自己眼下真正缺的一项能力，别只追热门；
• 从工具市场、SkillHub 等渠道挑一个外部 Skill；
• 用前面学过的方法判断它靠不靠谱，再拿真实任务验证一次；
• 记下来源、用途、触发方式和注意事项，更新清单。

💡 新手提醒：这一关是选修，不设作业提交。你可以按自己的实际需求，挑有用的任务自行完成。

### 01. 这一关抓什么重点

前面你已经从体验、拆解别人的 Skill，到做出自己的写作 Skill、判断 Skill，再不断迭代优化，手里有了第一批 Skill。

可等 Skill 越攒越多，新问题就来了：

自己做过哪些？什么时候该用哪一个？还缺什么能力？

不整理，很容易出现：

• 做过一个好用的 Skill，过段时间忘了；
• 遇到新问题，又做一个功能差不多的；
• 外面明明有人做好了，却不知道去哪找。

所以从这一关起，我们不再学“怎么做单个 Skill”，而是学“怎么管一组 Skill”。

就像电脑里的软件：有自己做的，有别人分享的；有的天天用，有的偶尔用。

关键不是装得越多越好，而是清楚：

• 现在有哪些 Skill；
• 每个分别解决什么问题；
• 缺什么能力，再补什么 Skill。

这一关主要做三件事：

1. 整理已有 Skill，建一份自己的 Skill 清单；
2. 按真实需求，从外部挑一个值得装的 Skill；
3. 用真实任务验证它，再更新自己的 Skill 库。

做到这里，你就不只是会做 Skill，而是开始拥有一套能成长、能积累的 Skill 能力库。

**2. 挑一个适合自己的 Skill**

前面你已经学会从零做一个 Skill，也试着把自己的经验沉淀成 Skill。不过，从零搭一个 Skill，设计、调试、验证都要花不少时间。

其实，不是每个需求都值得重做一遍。

很多常见场景，已经有人做出了成熟 Skill。遇到这些情况，与其重复造轮子，不如直接安装、验证，然后开始用。

接着看怎么挑一个值得装、也真正适合自己的 Skill。

以后遇到新需求，先判断：

• 已经有人做好了，就直接装来用；
• 没人做，或者现有 Skill 满足不了，再自己从零做。

这样，做 Skill 的效率会越来越高，也能把时间花在真正值得自己沉淀的新能力上。

2.1 怎么挑 Skill

**第一步：先想清楚自己缺什么**

不存在一个所有人都必须装的 Skill。

做电商、做设计、做运营的人，遇到的问题完全不一样。

所以挑之前，先问自己两个问题：

• 我现在最常重复做的是什么？
• 哪件事最希望 AI 帮我省时间？

需求清楚了，再去找对应 Skill。

2.3 用起来，再改造它

装好之后，别只看介绍，拿一个真实任务跑一遍。

先验证它能不能解决你的问题，再想：

• 哪些地方已经很好用？
• 哪些地方不符合自己的习惯？
• 有没有自己的资料要补进去？
• 有没有规则要调整？
• 有没有重复检查可以交给脚本？

很多 Skill 第一次装时，都只是一个“通用版”。

真正好用的 Skill，往往是在一次次使用中，结合自己的工作场景慢慢调出来的。

如果觉得它基本符合需求，可以继续改造，让它更适合自己。

通过和 AI 对话，让它在原 Skill 基础上改，让它更贴合你的工作习惯。比如：

• 改 description，让触发方式更符合自己的习惯；
• 补 references/，加入自己的资料和案例；
• 改 SKILL.md 里的规则，让它更符合自己的工作流程；
• 加 scripts/，把固定、重复的检查交给脚本。

经过这些调整，它就不再只是别人分享的 Skill，而是真正属于你的 Skill。

💡 安装前，再确认一下是否适合自己的工具

有些 Skill 不是不好，而是和你当前的工具不一定兼容。

比如：

• 需要额外配置 API Key；
• 需要安装额外环境或命令行工具；
• 需要能访问本地文件；
• 需要支持图片理解、图片生成等模型能力。

这些不是 Skill 本身的问题，只是使用门槛会更高。

如果刚开始学，优先选安装简单、能直接验证效果的 Skill。

**真正适合自己的 Skill，不一定是功能最多的，而是能在你的工具里稳定运行，并真正解决你的问题。**

3. 让 Skill 资产库持续长下去

以后你的 Skill 只会越来越多。

真正有价值的，不是做了多少个，而是这些 Skill 能不能持续积累、不断复用。

建议养成几个小习惯：

① 新增一个，就记一笔

不管自己做的还是别人那装的，都顺手让 AI 记下源信息：

• Skill 名称
• 主要用途
• 来源（自己制作 / SkillHub / 技能市场 / GitHub 等）
• 作者（如果有）
• 下载或创建时间
• 当前版本（如果有）
• 是否已经改造成自己的版本

如果页面写了使用、修改或分享限制，也建议一起保存。

这样以后 Skill 更新、排查问题、分享给别人，或者想找回原作者时，都能快速确认自己用的是哪个版本，以及能不能修改、转发。

② 真用过，再决定留不留

不是每个 Skill 都值得一直留着。

建议至少拿真实任务跑一遍，再决定：

• 会长期用，留下；
• 和其他 Skill 重复，可以合并；
• 已经不用了，就删掉或归档。

让自己的 Skill 库保持简单，比一直堆着更重要。

③ 每轮迭代，都更新自己的版本

Skill 不会一次就做到最好。

以后每遇到新需求、新经验，都可以继续优化：

• 补新的 references；
• 加新的 scripts；
• 改提示词和判断规则；
• 修使用中发现的问题。

不用重做一个，而是在原来的基础上持续迭代。

这样，它会越来越符合你的工作方式。

④ 遇到新需求：先找，再改，最后自己做

以后碰到新工作场景，不妨养成这个习惯：

1. 先看自己的 Skill 资产库有没有类似的；
2. 没有，再去 SkillHub 或其他 Skill 市场找；
3. 找到了，先改造成适合自己的版本；
4. 实在没有，再从零做。

这样，做 Skill 的效率会越来越高，也会把更多时间花在真正值得沉淀的新能力上。

Skill 资产库不是收藏夹，而是你的能力库。

里面留下的每一个 Skill，都应该是真正帮过你、能持续复用、并随经验不断成长的能力资产。

### 04. 这一关收个尾

🎉 恭喜你！你已经从“会做一个 Skill”，走到“会管一组 Skill”，开始搭建自己的 Skill 能力库。

这一关做完，你应该已经发现：Skill 越来越多以后，真正重要的不只是会不会再做一个新的。

你亲手做了一次盘点：把装过、做过的 Skill 理出来，看清每个分别解决什么问题、什么时候该调用、哪些还在用、哪些可能重复或闲置。

尤其是当你开始用清单或能力地图来管理它们时，应该能感觉到：Skill 不再是一堆散在文件夹里的工具，而是一套能持续更新、持续复用的能力资产。

这一步最重要的，不是装更多 Skill，而是知道自己真正缺什么。

看到外面有很多现成 Skill，不用一股脑全收藏。先从自己的真实任务出发：哪件事最常重复，哪件事最希望 AI 帮你省时间，哪类能力现在缺口明显。

需求想清楚了，再去 Skill 市场、SkillHub 或开源社区挑；挑到之后，也别只看介绍，拿真实任务跑一遍，确认它真的适合你的工具、你的场景和你的工作习惯。

合适，就记录下来继续用；差一点，就把它改造成更适合自己的版本；实在没有现成的，再回到前面几关的方法，从零做一个。

**核心三个动作：**

1. **盘点已有 Skill**：把装过、体验过和自己做过的 Skill 整理成清单，写清名称、用途、触发方式、来源，以及是否包含 references/ 和 scripts/。
2. **按真实需求挑 Skill**：先判断自己缺什么能力，再去外部渠道找；重点看是否持续维护、描述是否匹配、是否适合当前工具，而不是盲目追热门。
3. **用真实任务验证并改造**：装好后跑一次真实任务，看它能不能解决问题；需要的话，就调整 description、补资料、改规则或加脚本，让它慢慢变成自己的版本。

这一关虽然是选修，但它是在帮你把前面做出来的东西真正收进系统里。

从现在开始，你不只是拥有几个单独的 Skill，而是有一套能不断扩展的 Skill 能力库：新增一个，记录一个；用过一次，判断一次；迭代一轮，更新一轮。

**下一关，我们会把这套能力放到一个更自由的舞台上：Skill 创作大赛。**

你可以从零创作一个全新的 Skill，也可以继续打磨现在已经做出来的 Skill，把它变成一个更完整、更值得展示和分享的作品。

### 00. 任务卡
