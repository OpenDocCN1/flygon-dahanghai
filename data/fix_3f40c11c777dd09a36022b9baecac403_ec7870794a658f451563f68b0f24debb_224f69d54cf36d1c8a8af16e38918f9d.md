6. 换素材，不换链路

不想用播客地址，也可以换自己的素材。原则是只换链接或文件，不换工具链，仍然是“获取→转写→保存文本”。几个可直接替换的方向：

方向 A：YouTube 视频转录
• 素材：公开的 YouTube 视频地址（最好有人声，不要纯音乐）
• 把步骤 2 提示词里的链接换成你的 YouTube 地址，其他不变

方向 B：B 站视频转录
• 素材：公开的 B 站视频地址
• 把步骤 2 的提示词换成你的链接。注意：B 站有些视频自带字幕，Agent 可能优先取字幕而不是跑语音识别——这反而更省事，字幕通常比 ASR 更准

方向 C：本地音频文件转录
• 素材：电脑里已有的音频文件（.mp3、.m4a、.wav 均可）
• 把步骤 2 的提示词改成：“用 whisper 把这个音频文件转成文字：[文件路径]，去掉时间戳，保存为转录结果.md”
• 不需要 yt-dlp 下载，直接转录

不管选哪个方向，判定依据一致：Agent 自己获取（或读取）、自己转录、自己保存出一份文本文件。完整跑通一次，本关即通过。

### 02. 常见卡点与处理办法

遇到问题先别放弃，优先问 AI。推荐用 Codex 或 WorkBuddy：新建一个任务窗口，把报错、截图或需求丢给它们，让 AI 帮你分析、排查，甚至直接处理。
[PRE24]

久而久之，先问 AI、再找人的习惯会帮你解决不少问题。

| 常见卡点 | 默认动作 | 判定依据 |
| --- | --- | --- |
| 下载器提示“无法访问” | 先确认目标地址无需登录、没有区域门槛；必要时换公开地址再试 | 新地址可顺利拉取 |
| 语音模型装不上 | 把错误回显交给 Codex；常见原因是 Python 低于 3.8 或 pip 过旧 | 运行 python3 -c "import faster_whisper" 无异常 |
| 输出乱码或空文件 | 先怀疑容器格式；请 Codex 用 ffmpeg 转成 .wav 后重跑 | 重转后出现可读文本 |
| 处理时间过长 | 素材超长；本关控制在十分钟以内。任务已启动就等首次模型加载完成 | 下次缩短素材，或等 Codex 返回完成 |
| 文本错字多 | 本关只验证链路，不追求字字准确；纠错会在关卡 4 的 Profile 中展开 | 大意可辨即可 |
| 不确定是否通关 | 以可见产物为准：Codex 自行处理并落盘新文件 | 截图能同时展示输入、处理、输出 |
| 一上来就做复杂功能 | 先别改示例，默认演示走通；后续关卡再逐步升级 | 本关只要求完整跑通一轮 |

### 03. 本关收束

所谓最小 Agent，就是先让 AI 替你完成一次看得见的任务。本关用【音视频转录 Agent】演示，把“输入—处理—输出”整条链路走一遍。只要它能接任务、调工具、生成文件，并且你能用截图证明产物存在，第一个最小 Agent 就成立了。

四件关键事：
1. 准备明确输入：选公开可访问、长度适中的音视频，让 Agent 有活可干。
2. 搭好对话入口：用 Codex 创建 Hermes Agent 和飞书 Bot，完成私聊或群聊接通测试。
3. 发布具体任务：把下载、转录、保存文件这些动作讲清楚，让 Agent 按步骤执行。
4. 检查可见输出与边界：确认转录文件存在，再让 Agent 说明自己能做什么、不能做什么。

跑完这一关，你会得到一个真实体感：Agent 不是抽象名词，而是一条可验证的工作链路。如果觉得演示还不够好，甚至离真正替你干活还有距离，这很正常。本关目标不是造出完美 Agent，而是先建立体感：理解它如何运作，以及一条完整链路怎样跑通。下一关会从演示转向你自己的重复工作，找出第一个真正需要的 Agent 员工，并决定它服务谁、接收什么输入、交付什么结果。

### 01. 这一关的关键

关卡 1 你已经用 Codex、Hermes 和飞书跑通了一个最小演示：给链接，Agent 下载、转录，并产出一份结果文件。很多人到这里会问：Codex 本身一句话就能办到的事，为什么还要绕到 Hermes 和飞书里再搭一个 Agent？第一次接触 Agent 的人，基本都会冒出这个疑问。

答案在于两类事情不一样：单次交付，和拥有一个能长期在岗的 AI 员工。偶尔处理一段音视频，打开 Codex 聊两句让 AI 做完即可；但若这项工作天天出现、反复执行，还想让别人也能用、能维护、能持续优化，那就值得把它做成 Agent。它要有岗位、有固定流程、有稳定入口，还要能积累规则和经验。这样无论是你还是团队成员，都能直接派活，不必每次从头解释。

所以本期重点不是教 AI 帮你干一票，而是教你怎么养出一个能长期在岗的 AI 员工。你会看到，这个员工眼下更像刚报到的实习生：音视频转录的基础动作能做，但文字准确度有限，内容只是原始稿，没有重点提炼；文件也留在本地，线上修改、多人同步、长期沉淀都不方便。这很正常。实习生要成长，得有人告诉他：负责哪类活、接什么输入、按什么顺序做、交什么结果，什么情况下必须停下来确认。Agent 同理，清晰的岗位定义、稳定流程、交付标准、人工兜底，一个都不能少，它才会从“跑通一次”走向“真正承担一项工作”。

因此本关先做定位：第一个正式 Agent 员工服务谁、解决什么问题、交出什么成果，先写明白。你产出的岗位卡会直接进入关卡 3（拆工序）和关卡 4（写大脑）。定位越清楚，后面流程和 Profile（岗位说明书）越好落笔。

如果你对 Agent 还没有概念，别担心，我们仍会给案例，带你走完整套搭建流程。默认案例接着关卡 1 的【音视频转录助手】往下做：把那个“能干点基础活”的实习生，往“能胜任音频转录岗位”的员工方向培养。如果你暂时没想好自己的 Agent 做什么，先跟案例走，把流程理解清楚；找到感觉后，再回到真实工作里设计你的第一个 Agent。

❗️ 默认案例的作用是练流程、找体感，不是最终交付物。本期要做的，是能接真实工作的 Agent，让它成为你的第一个 AI 员工，而不是完成一次练习就结束。
