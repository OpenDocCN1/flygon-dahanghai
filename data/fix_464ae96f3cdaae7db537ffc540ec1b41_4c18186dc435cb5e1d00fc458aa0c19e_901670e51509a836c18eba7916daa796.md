# 2.4.1 提需求时，有哪些提示词技巧？

一类走口语化路线。别给自己设限制，想做什么就写什么，哪怕句子乱成一团、前后互相矛盾也没关系。跟 AI 聊着聊着，你的想法会越来越明确，那些杂乱表达也会在反复归纳中变成结构完整、条理清晰的提示词。

另一类走结构化路线。不少圈友习惯用固定格式，把技术架构、角色背景、预期输出等栏目逐一填满。只要形成一套属于自己的模板，跟 AI 的配合会顺畅得多。

# 2.4.2 AI 返回的代码，在本地怎么跑起来？

HTML 类的页面最简单：浏览器直接打开，既能看渲染效果也能翻源码。要修改的话，Notepad++ 这种轻量编辑器就能搞定；或者登录 GitHub 仓库，在代码文件里直接改。

Next.js 这类带后端、由多个组件组成的工程，我基本不在本地调试——没有编程基础的人操作起来容易出错。通常的做法是：把问题截图发给 AI，描述清楚需求，再把它返回的代码片段复制过去反复测试。

# 2.4.3 遇到报错时，怎样让 AI 对症下药？

第一步，准备一份持续更新的网站地图，把它作为背景信息交给 AI，过程中还要请 AI 不时做二次校正。

第二步，出错时把报错画面拍下来，文字性错误也一并复制发送。描述问题请遵循这个公式：预期的结果 + 当前的报错信息 + 你已经尝试过的操作（把具体代码附上）。

第三步，让 AI 把所有可能的出错原因都列出来，然后逐个给出解法，你再去实际验证。这套方法能解决绝大多数报错；只有非常复杂、或提问者缺了某块编程基础知识的问题才可能卡住，这种时候发到航海群，交给技术大牛处理。

# 3.1 游戏站是什么？靠什么变现？

核心观念先摆正：我们不是做游戏开发，而是去捕捉那些可能爆火的新游戏名字，围绕它们把网站搭起来，把搜索流量引过来。

互联网上早已存在海量现成游戏网站，作品就摆在那里，拿过来用即可。怎么拿？只要理解一个关键词——iframe。它的作用相当于在页面里开一扇内嵌的「窗」，窗外展示的是来自其他站点的网页、视频、地图甚至在线游戏，访客不必离开当前页面，就能直接观看和操作这些内容。

这类站点的优势非常清晰：

- 不需要开发技能：你只负责把现成的 HTML5 游戏聚合起来
- 玩家粘性强：游戏自带娱乐属性，用户愿意多待一会儿
- 维护负担轻：隔段时间补几条新游戏链接，内容就保持新鲜

说到变现，首推 AdSense。绑定招商银行（境内大陆发行）的储蓄卡，美元就能直接入账；五万美元以内的收入免人工审核，系统自动记账，申报环节同样自动通过，之后美元购汇成人民币，随时提现。

其他变现路径也一并列出：

1. 广告分成：把 AdSense 或其他广告联盟的代码挂进游戏页面，靠展示产生收益
2. 会员订阅：向玩家出售去除广告或独家内容的付费资格
3. 游戏内购：与开发者约定分成，从游戏内付费中分一杯羹
4. 推广佣金：替其他游戏平台带去流量，按效果获得奖励
5. 定制搭建：为企业客户打造品牌定制版游戏站

# 3.2 小游戏从哪里找？又如何嵌入自家网站？

寻找 HTML5 游戏有三条渠道：

1. GitHub 上有大量开源项目，游戏代码随意下载
2. itch.io、Kongregate 等平台聚集了众多可嵌入的作品
3. 开发者论坛里也能找到愿意分享或授权使用的游戏

嵌入的核心还是 IFRAME。把它想象成自家页面上升起的一扇「魔法窗」，玩家无需跳转就能在窗口里玩到别的网站的游戏，甚至意识不到已经离开了你的站点。借由这扇窗，访客留在你的页面上浏览、点击，AdSense 广告因此获得展示，收益也就跟着 24 小时滚动起来。

# 3.4 进阶：从单页扩展到多页面游戏站

前文已经走通了单页小游戏的上线流程，从域名购买到托管配置都有了清晰认知。但如果想让网站真正做大、获得持续稳定的流量，就必须上线更多网页、更多游戏，把它做成一个规模化的游戏站。接下来结合前面的经验，拆解多页面游戏站的搭建方法：核心结构如何规划、游戏怎么批量添加、用户体验如何丰富。

# 3.4.1 网站结构：分类、导航与页面管理

从单页变成多页后，网站骨架的重要性立刻凸显。合理清晰的结构，既方便玩家快速找到目标游戏，也有利于搜索引擎理解整个站点。可以从三个维度入手：

1. 游戏分类与归纳

不同风格的作品吸引不同人群。可以按玩法类型划分，比如动作、射击、益智、策略、体育；也可以按题材划分，比如恐怖、二次元、像素风。首页或主菜单栏最好放一个「游戏分类」入口，让玩家按兴趣点选。

2. 导航与菜单设计

页面顶部设置全局导航菜单，把主要分类或频道列出来。为了体验更好，首页再加一个搜索框，让用户直接搜索游戏名或关键词。

3. 数据库或页面管理

如果使用 WordPress 等 CMS，可以建一个名为「游戏」的自定义文章类型（Custom Post Type），一篇文章对应一款游戏，内容包含介绍、截图、iframe 嵌入等。

如果使用静态网站生成器或手写 HTML，就按游戏类型分目录存放，文件名与 URL 结构要保证可读性和层次感。

规划到位后，每款新游戏都会拥有简洁美观的 URL，用户分享链接方便，搜索引擎收录和排名也更受益。

# 3.4.2 批量添加游戏：模板化与自动化

多页面模式下，「批量加游戏」往往是耗时最重的环节。每加一款都要手写 HTML，还要同步处理样式、简介、图片，不仅工作量大，还容易反复出错。下面几条思路可以显著提升效率：

1. 通用模板页面

先做出一个通用的游戏页模板，例如包含：

- 标题（H1）
- 一句话介绍
- iframe 容纳区
- 玩法说明与操作提示

新增游戏时，复制模板，只改游戏名、iframe 地址、缩略图这几个字段即可，重复劳动大幅减少。

2. iframe 嵌入标准化

给 iframe 设定统一的宽高，或使用 responsive 自适应写法，确保手机端显示正常。比如定义一个公共样式 .game-iframe { width: 100%; height: 600px; }，所有嵌入游戏就能保持一致的版式。
