### 01. 完整测试与持续打磨
上一关结束时，你的 Agent 已经配好基础项，也至少跑成功过一次任务。现在要验证的是：它能否稳定接住真实工作。

做法可以概括为：拿更贴近实际工作的样本，把流程从头到尾走一遍，留下运行痕迹，再由人检查；发现问题就修，修完再测。

**1. 准备 3 个测试样本**
先挑 3 个你真实工作中会碰到的输入，别为了测试临时硬编一个。样本越贴近实际，越容易把 Agent 的短板暴露出来。

| 样本 | 适合放什么 | 验证目标 |
|---|---|---|
| 样本 1 | 日常最常碰到、最有代表性的那类输入 | 看主流程能否顺畅跑完 |
| 样本 2 | 稍微复杂或处在边界的输入 | 看异常兜底和边缘情况处理 |
| 样本 3 | 你最在意的真实业务场景 | 看它对你的工作是否真有用 |

准备时，也建议顺手记下三点相关思考。
以小D（音视频转录 Agent）为例：样本 1 选一期约 10 分钟的公开播客链接，验证常规流程；样本 2 用一条 10 到 20 分钟的 B 站公开视频链接，验证视频链接识别与下载；样本 3 拿一条 2 小时的 YouTube 链接，验证长音视频分段处理和转录稳定性。
如果你的 Agent 不是音视频转录类，也可以照这个逻辑来。日报 Agent 可以准备：日常日报素材、信息不完整的日报素材、你真实要提交给团队的那份日报。客服回复 Agent 可以准备：常见客户问题、情绪强烈或信息不全的问题、你最担心回复出错的真实问题。

| 不合格 | 只有配置截图、只有脚本截图，看不出“Agent 真的干活了” |

**5. 进阶优化：让 Agent 更稳定地进入真实工作流**
完成前面的测试和简单优化后，你的 Agent 已经“能用了”。但“能用”和“好用”之间还有距离。
一个真正能进入日常工作流的 Agent，不只是跑通一两次任务，还要做到：结果越来越稳定；出错时能被发现；重要动作不会误执行；能在固定时间或固定条件下自动运行；后续出问题时，能继续迭代和回滚。
所以，还可以从下面两个方向继续优化。

**5.1 让 Agent 的结果越来越正确**
Agent 刚跑出来的结果，多半不会一上来就完美，甚至离你心里的标准还有距离。关键动作是反复迭代 Profile：每次发现输出不对，就和 Agent 沟通，把规则继续改细。
可以按这五点来做：
1. 记录每次“输出不对”的具体表现，比如漏掉关键案例、标题太模糊、格式没按要求来、输出顺序不稳定；
2. 找到 Profile 里对应的那条规则，看看是规则没写、写得太模糊，还是写了但 Agent 没有稳定遵守；
3. 把规则改得更具体、可验证，比如把“标题要具体”改成“标题必须包含真实内容中的关键词，不能使用‘其他有效观点’这类模糊标题”；
4. 用同一个输入再跑一次，看问题是否修好；
5. 每次只改一个问题，确认一个问题修好后再处理下一个。
以音视频转录 Agent 为例：如果转录稿经常把“龙哥盟”识别成“升财有数”，可以在 Profile 的质量标准里加一条：清洗环节必须纠正常见 ASR 错词，例如把“升财有数”改回“龙哥盟”，把“一仁”改回“龙哥”。
如果它经常漏掉会议里的行动项，可以加一条：必须把会议中出现的行动项单独提取出来，写清负责人、事项、截止时间；如果原文没有明确负责人或截止时间，必须标注“未明确”。
如果输出格式经常变，可以加一条：必须按固定结构输出，一级标题为“会议摘要、关键结论、行动项、待确认问题”，不得自行新增或删除一级标题。
Profile 不可能一稿定型，它得在真实使用里慢慢长出来。每修掉一个错误，Agent 就离可靠更近一步。

**5.2 让 Agent 长期可靠地工作**
基础配置完成后，你已经能手动发命令或消息让 Agent 执行任务。这说明它可以按你的指示，接管一部分工作了。
但要想让它真正融入日常流程，光靠手动喊它还不够。还得结合业务场景，补上这些设定：何时启动、资料从哪来、结果发往何处、出问题如何处理、哪些动作必须先征得人工同意。并非每个 Agent 都要全配，但这些设置会决定它只是临时搭把手，还是能长期稳定干活的数字员工。
进阶能力不必一次配齐。若开局就追求自动触发、自动读资料、自动判断、自动发布、自动复盘全都要，反而更容易翻车。更稳妥的路径是先跑通一条最小工作流，再按真实使用中的堵点逐项补齐。
可以考虑按这个顺序来：
1. 先稳定输入：明确 Agent 每次从哪里拿资料，比如飞书文档、多维表格、固定文件夹，还是你手动发给它；
2. 再稳定输出：明确结果写到哪里，比如飞书群、飞书文档、多维表格，还是本地文件；
3. 再加人工确认：如果 Agent 会对外发送、修改数据、触达客户，建议先加一道“确认后再执行”；
4. 再加异常提醒和运行日志：保证它出错时你能知道，后续也能查到问题发生在哪一步；
5. 最后考虑自动触发：等手动运行稳定后，再配置定时任务或事件触发，让 Agent 自动进入工作流。
要不要现在做进阶配置？可以先问自己几个问题：
• 这个任务是不是会重复发生？
• 输入资料是不是来自固定位置？
• 输出结果是不是需要沉淀到固定位置？
• 这个任务失败时，我需不需要第一时间知道？
• Agent 有没有可能误发、误删、误改？
• 后续我是否需要查看它以前做过什么？
• 这个流程以后是否可能交给别人一起用？
如果有 2 个以上回答“是”，就可以考虑补一项进阶配置。如果你只是刚刚跑通第一个 Agent，可以先不急，先手动运行 2-3 次，在实际体验中发现需求。
比如：总是忘记运行，就先加定时触发；每次复制资料很麻烦，就先固定输入来源；结果散落在对话里不好找，就先固定输出位置；担心它误发给客户，就先加人工确认；经常不知道哪里失败，就先加运行日志和异常提醒。
先让 Agent 稳定帮你完成一件事，再慢慢把它养成一个更可靠的数字员工。

### 02. 把你的 Agent 包装成可展示成果
**1. 写使用说明书**
走到这里，Agent 基本能正常运转了。可一旦你希望同事共用、客户直接使用，或把它包装成产品/服务出售，问题就来了：外部使用者不清楚它的用途、用法和适用场景。
所以，还需要为它写一份使用说明书。这份说明书就像一个产品的使用指南，帮助别人快速了解：
• 它擅长解决什么？
• 在哪些场景下最合适？
• 输入应该给什么？
• 最终会产出什么？
