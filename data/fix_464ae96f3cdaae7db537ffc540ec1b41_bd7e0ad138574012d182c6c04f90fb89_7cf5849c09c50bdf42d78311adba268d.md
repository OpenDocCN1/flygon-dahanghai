# 2.4 AI 交出的代码不满意，怎么继续往下推？

假如来回几轮之后，它仍然给不出你想要的东西，不妨分两步处理：先让它把现有内容归纳成一份摘要，再另起一个对话窗口，把卡点重新讲明白再问一遍；或者干脆换一匹模型——Gemini 2.5 Pro、Claude 4、ChatGPT、DeepSeek 都可以拉进来交叉比对，几家轮着试，突破口往往就冒出来了。

# 2.4.1 描述需求时，提示语怎么写效率更高？

口语式表达：别给自己套框框。想做什么就直接打出来，即便东一句西一句、前后打架也没关系。随着对话一轮轮推进，你心里那幅图会越来越清楚，提示语也会在反复梳理中变得更有条理、更完整。

模板式表达：也有圈友偏爱按固定格式来写，把技术栈、角色背景、期望产出这些栏目逐条填满。只要能沉淀出一套自己顺手的框架，与 AI 协作的顺畅度会明显上一个台阶。

# 2.4.2 AI 返回的代码，在电脑上怎么快速验证？

HTML 一类的成品：拿浏览器点开就能看到渲染结果，也能顺手翻翻源码；要动刀的话，Notepad++ 这种体量轻的编辑器足够应付，或者干脆在 GitHub 的仓库页面里直接改。

Next.js 这类带服务端、拆成多个组件的工程：我本人几乎不在本机折腾——没有编程底子很容易越弄越乱，更常见的做法是把问题截屏丢给 AI，再照着它返回的片段一段段复制回去试。

# 2.4.3 碰到报错，怎么让 AI 精准修补？

第一件事：手里要有一份持续迭代的站点地图，把它当作背景资料喂给 AI，并且隔一阵子请它回头校对一遍。

第二件事：出错的时候，把报错画面截下来，能复制的报错文字也一并附上，再把处境说清楚。描述可以套这个公式——想要达成的效果 + 此刻的报错内容 + 已经试过的动作（附上相应代码）。

第三件事：让 AI 先把可能的成因列全，再逐条给方案，然后一条条落地验证。这套打法能搞定绝大部分故障；剩下那些格外绕、或者提问者本身缺了某块编程常识的硬骨头，就搬到航海群里请技术老手出马。

# 3.1 游戏站是什么？钱从哪来？

我们不做游戏，我们做的是「借势」：找到那些可能走红的新游戏名，围绕这个词搭一个站点，把搜索流量接过来。

网上早就有大量站点在提供现成作品，直接取用就行。取用的关键动作只有一个词——iframe。

iframe 的作用，是在一个页面里再嵌一层页面或内容。可以把它想成在自家墙上开的一格窗，透过它能看到别处的网页、影像、地图，甚至一整款线上游戏；访客不必离开你的站，就能在其中观看与操作。

这类站点的好处集中在三处：

- 不必会做游戏：HTML5 作品都是现成的，你只负责归拢
- 访客留得住：好玩本身就是黏性，停留时长自然上去了
- 维护省力：补几条新链接，新鲜度就保住了

收入渠道上，首推 AdSense。手里有招商银行（境内大陆发行）的储蓄卡就能收美元，五万美元以内无需人工核验，系统自动入账；入账申报同样自动放行，之后结汇成人民币即可取出。

除了广告，还有几条路：

1. 广告分成：接 Google AdSense 或其他广告平台，在页面里放广告位
2. 会员服务：卖「免广告」或「独家内容」的付费资格
3. 游戏内购：与开发方分成，玩家在游戏内消费的部分切一块
4. 导流佣金：替别的平台带流量，按效果拿钱
5. 定制项目：给企业客户做带品牌元素的游戏站

2. 发布平台：itch.io、Kongregate 这类站点上，可嵌入的作品很多
3. 开发者聚集地：论坛与社区里，常有人愿意共享或授权使用

接入靠的仍是 IFRAME。把它当成自家站里的一格「传送窗」：玩家不必感知跳转，就能在你这里玩到别处托管的内容。人留住了，点击与浏览就产生了，页面上的 AdSense 广告位也就开始替你 24 小时不间断地赚。

# 3.4 进阶：从一个页面扩成一整站

上一节里，我们已经把一个单页小游戏推上线，也走通了从买域名到配置托管的全部环节。但若真想做大做强、拿到稳定且可持续的流量，就得让更多页面、更多游戏一起上线，把它做成有规模的游戏站。下面沿用前面的思路，聊聊多页面站的搭建：结构怎么规划、游戏怎么批量加、互动体验怎么做得更丰富。

# 3.4.1 结构规划：分类、导航与页面管理

一旦决定从单页扩成多页，站内结构的分量就上来了。清晰合理的骨架，既能让玩家快速找到想玩的内容，也能帮搜索引擎读懂你的站。可以从三处着手：

1. 游戏分类与归纳

不同风格的作品吸引的人群不同。可以按类型切分，比如动作、射击、益智、策略、体育；也可以按题材切分，比如恐怖、二次元、像素风。建议在首页或主菜单栏留一个「分类」入口，让玩家按兴趣挑。

2. 导航与菜单设计

页面顶部铺一条全局导航，把主要频道列出来。为了体验更顺，首页最好再放个搜索框，让人直接搜游戏名或关键字。

3. 数据库或页面管理

若用 WordPress 或其他 CMS，可以建一个「游戏」自定义文章类型（Custom Post Type），每篇文章承载一款作品的简介、截图、Iframe 嵌入等内容。

若用静态生成器或手写 HTML，那就按类型分目录存放，并确保文件名与 URL 结构既好读又有层次。

这样规划下来，每款新游戏都能拿到一条简洁好记的 URL，玩家分享方便，搜索引擎收录与排名也受益。

# 3.4.2 批量加游戏：模板与自动化怎么做？

多页面站里，「批量加游戏」往往最耗时间。要是每款都手写一遍 HTML，还要连带改样式、写简介、配图，工作量会非常吓人，重复性错误也容易冒出来。下面给几个实用思路：

1. 通用模板页

先做一版通用页面骨架，例如包含：

- 标题（H1）
- 简介或一句话描述
- Iframe 容器
- 操作说明与玩法提示

上新品时，复制这份骨架，只替换几个要素（游戏名、Iframe 链接、缩略图），重复劳动就省掉一大截。

2. Iframe 嵌入标准化

给 Iframe 定好统一的宽高，或采用自适应（responsive）写法，保证手机端也显示正常。举个例子：用一个公共 CSS 类 .game-iframe { width: 100%; height: 600px; }，所有嵌入内容就能保持一致的版式风格。
