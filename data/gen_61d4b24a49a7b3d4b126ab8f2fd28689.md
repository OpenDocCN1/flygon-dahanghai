# 脚本管确定，AI 管判断

先看一个常被忽略的差别。

那些检查结果并不是模型自己生成的。模型触发脚本，脚本算完再回传。

关卡 4 拆解 gzh-design 时，你看到的 scripts/ 文件夹，装的就是这些脚本程序。

差别在哪？

• 模型说：“我查过了，没问题。”这是它的判断，是否认真查过，你很难核实。
• 脚本给出：“共检查 136 处。”这是程序算出的数字，输入不变，跑一百次仍是 136。

模型擅长表达结果，脚本负责计算结果。

这一关，就是给 Skill 补上这种能力。

你可能想到关卡 3 加过的“体检 Skill”。两者不是一回事。

那次是内容生成完后，再调 content-risk-detector 做检查，说到底仍是调用另一个 Skill。

**本关新增的是脚本程序本身的能力。**

统计、计算、格式转换这些追求稳定答案的活，应该交给脚本执行，不必让 AI 去推断。

| 对比项 | 关卡 3 的体检 | 本关的脚本 |
| --- | --- | --- |
| 规则由谁定 | 平台规则（哪些词不能发） | 你自己的禁忌（哪些话你不想说） |
| 谁在执行 | AI 阅读，可能漏看 | 程序计数，漏不掉 |
| 结果稳定性 | 同一篇查两次，说法可能不同 | 跑一百次也一致 |

判断标准只有一条：相同输入必须永远得到相同输出，这类规则就交给脚本。

[PRE0]

这些适合脚本的规则，说到底有个共同特征：答案唯一。

看“家人们”有没有出现，本质是关键词计数；看一个段落是否超过三行，本质是数行数；看是否连续出现三个感叹号，本质是数字符。

不用懂语义，只要照规则核对，因此天生适合程序执行。

**2. 哪些内容该交给脚本**

打开关卡 2 做好的 my-writing-style，定位「我的禁区」。

先别急着上脚本，先自问：这条规则不理解意思、只看字面，能不能判断？

能，就适合交给脚本。

例如：

| 禁区（各行业例子） | 谁来查 | 为什么 |
| --- | --- | --- |
| 不许出现“家人们”“宝子们”（卖货） | 脚本程序 | 这几个字在不在，没有第二种答案 |
| 不许写“最好吃”“第一”（开店，广告法不允许） | 脚本程序 | 同样，只看字在不在 |
| 不许出现客户真名（上班） | 脚本程序 | 同上 |
| 不许承诺“包学会”“一定涨粉”（知识付费） | 脚本程序 | 同上 |
| 一段不超过三行 | 脚本程序 | 数得出来 |
| 不许连续打两个以上感叹号 | 脚本程序 | 同上 |
| 读着别太端着 | AI | “端着”没法拿字符去比 |
| 开头别太平淡 | AI | 同上 |
| 别替我编经历 | AI | 得对着资料看，关卡 5 那份文件管这事 |

判断标准只有一条：相同输入必须永远得到相同输出，这类规则就交给脚本。

头一回不必把全部禁区都脚本化。先选两三条最关键、最容易判定的规则，让 Skill 先稳定运行，之后再逐步增加。

要是“我的禁区”写得比较虚，比如“不要 AI 味”“不要太官方”，一时找不到能交给脚本的条目，也不要紧。先把要求拆细：

• 某些口头禅不出现；
• 每段不超过三行；
• 感叹号不连续超过三个。

规则越具体，脚本越容易自动核对。

本关拿写作 Skill 举例，但方法通用：只要一件事需要每次稳定执行、不能依赖 AI 现场发挥，就可以考虑让脚本做。

碰到问题别先泄气，先问 AI。本期建议优先用 Codex 或 WorkBuddy：新开一个任务窗口，把报错、截图或需求发过去，让 AI 帮你分析、排查，甚至直接处理。

### 04. 这一关小结

完成这一关，你手上的 Skill 不再只会写规则、读资料，还多了一项本领：把不同性质的任务分派给更合适的工具。

你也会发现，并非所有事都该让 AI 包办。

某个词是否出现、字数够不够、格式对不对、段落有没有超过三行，这类规则固定、答案唯一的检查，更适合脚本；至于怎么表达、语气像不像你、判断是否合理，这些要结合上下文和场景，仍应交由 AI。

关键不在于代码写得多复杂，而在于换一种思路：

能固定计算、固定核对的，给脚本；需要理解、判断与创造的，给 AI。

以后搭更复杂的 Skill，你不会再把所有事都丢给 AI 临场发挥，而会分清：哪些让 AI 思考，哪些写成脚本去执行。

**核心三个动作：**

1. 挑出机器能查的规则：从“我的禁区”中筛出标准清楚、每次检查方式一致的内容。
2. 让 AI 写成脚本：把规则变成可重复运行的程序，放进 scripts/，并让 Skill 知道何时调用。
3. 当场跑一遍验证：确认脚本真的被执行，输出能点出具体问题，而不是只信 AI 说“我查过了”。

做完这一关，你完成了第一次 Skill 脚本能力搭建，也明白了：Skill 不止能写规则、放资料，还能调程序做稳定检查。

### 01. 本关重点

前六关下来，你已经有一个真正能用的 Skill：它会按你的风格写内容、引用真实资料、自动检查固定规则。到这里，你掌握了 Skill 最基础也最常见的用法——处理文字。

可如果 Skill 只会写内容，省下的多半还是“动手”时间。更有价值的是把脑子里的经验沉淀下来，帮你思考。

很多时候，真正耗时间的不是写，而是判断：

• 今天接不接这个客户？
• 这个选题值不值得做？
• 这批新品要不要上？
• 这个合作方案划不划算？

它们没有标准答案，却反复出现，每次都得重新分析。

因此这一关做一个 Skill，专门解决“怎么判断”。

你把判断逻辑、历史案例和决策标准交给它。以后再遇到类似情况，不用从头分析，只要提供信息，它按你的标准给出判断、解释理由，并提醒过去类似案例，最终决定仍由你做。

当然，一个 Skill 不可能一次替代你全部判断。行业里的经验、例外和临场判断很多，很难全装进去。

所以别追求“万能助手”。先挑一件隔三差五就要拿主意、判错容易吃亏的小事，把它做好。越具体，越容易做出来，也越容易用起来。

卖货的，隔几天要判断一批新品值不值得上；开店的，常要判断一个活动值不值得参加；做内容的，反复判断一个选题值不值得做。

做成后什么样？仍以卖货为例：供应商再推新品，你把品名、进价、起订量发过去，它按你的标准给出判断和理由，还会提醒你过去在哪类产品上踩过类似的坑。

秤还是那杆秤，只是不必每次从头称起。

[PRE12]

写作风格沉淀的是你怎么表达；判断类 Skill 沉淀的是你积累的判断经验。前者更多模仿你的表达方式；后者保存你一次次踩坑、总结、复盘后形成的判断标准。因此，这一关尽量用真实案例来做，做出来的 Skill 才真正有价值。

### 02. 动手做一个判断 Skill

1. 找一件值得交给 Skill 判断的事

前面说过，一个 Skill 很难装下多年积累的经验、判断和例外。所以一开始别想做万能判断器。

真正好用的判断类 Skill，常只解决一件具体小事。

标准就三条：

• 会反复遇到；
• 每次都需重新分析；
• 判断错容易吃亏。

满足这三条，就值得先做成 Skill。

不必是天天发生的大事。一个月碰上一两回、每次却要犹豫半天的，反而最合适。

下面几个行业举例，可找最接近的参考：

| 你的行当 | 可挑的判断 | 何时用得上 |
| --- | --- | --- |
| 卖货的 | 新品上不上 / 价格怎么定 / 差评怎么回 | 供应商推新品、想调价、客户在评论区发难 |
| 开店的 | 新品上不上 / 活动值不值得做 / 兼职留不留 | 想加新口味、平台推团购、试用期小工是否留下 |
| 上班的 | 需求接不接 / 活派给谁 / 汇报说到什么程度 | 别的部门甩活、人手不够、跟老板过进度 |
| 知识付费的 | 学员问题要不要单独做课 / 合作接不接 | 群里有人提问、有人来谈分销 |

若还是不知道挑什么，翻最近聊天记录。凡是你回过“我想想”“我再看看”“我过两天回复你”，或当时犹豫的事，大概率就是它。
