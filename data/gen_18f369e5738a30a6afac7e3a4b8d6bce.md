# 四步搭好一条 Claude 直连工作流

想在 Coze 里直接调用 OpenRouter 上的 Claude？其实不用复杂的编排，四个节点就能搭通。这条工作流的结构非常清晰：开始 → HTTP 请求 → 代码 → 结束。下面逐个拆开来看。

**第一步：开始节点，把变量提前暴露**

入口节点只负责接收三个字符串类型的输入，而且全部为必填项：`OPENROUTER_API_`、`Prompt`、`input`。其中第一个填你的 OpenRouter 密钥，第二个用作系统提示词，第三个则是每轮实际要处理的内容。这三个值不在流程内写死，所以后期换模型、改语气、换输入，都不用改动节点结构。

**第二步：HTTP 请求，真正调用模型**

这一站以 POST 方式请求 `https://openrouter.ai/api/v1/chat/completions`，鉴权方式选 Bearer，Token 直接引用开始节点传入的 `OPENROUTER_API_`。请求体为 JSON，字段不多，但每个都必须写对：

- `model` 指定为 `anthropic/claude-sonnet-4.5`，也就是本次要用的模型；
- `messages` 是两条消息：`system` 角色填入 `{{block_output_100001.Prompt}}`，`user` 角色写明「输入信息为：{{block_output_100001.input}}，输出结果」。

请求设置上，失败重试设为 3 次，超时上限为 120 秒。这个节点会返回三项结果：响应体 `body`、状态码 `statusCode` 和响应头 `headers`。如果不想被网络波动打断，这组重试和超时参数值得保留。

**第三步：代码节点，把正文抽出来**

模型返回的内容嵌套在接口响应里，需要从中提取。代码节点用 Python 的异步函数 `main` 接收上游传来的 `body`，从以下路径取出正文：

`body['choices'][0]['message']['content']`

再把它赋值给输出变量 `content`。这段逻辑很简单，但作用关键：后面的节点只需要处理纯文本，不必关心接口的封装格式。

**第四步：结束节点，只返回一样东西**

终点采用 `returnVariables` 模式，只声明一个输出参数 `output`，值直接指向代码节点产出的 `content`。因此，整条工作流最终的返回值就是一段干净的模型回答，没有多余内容。

**这套设计的好处**

它把「调用模型」和「提取结果」拆成两步：HTTP 请求负责通信，代码节点负责解析，开始节点负责注入变量。以后如果想调整提示词，只要在调用时传新的 `Prompt` 即可，不必改动流程结构。一套接线，可以换着花样使用。
