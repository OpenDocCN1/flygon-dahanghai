## 换素材练习，但不要换流程

如果你不想继续使用上述播客链接，完全可以用自己的音视频材料。但请遵守一条规矩：只换链接/文件，不换工具链，依旧沿用“下载→转录→保存文字”的路线。以下是几个可以直接替换的任务方向：

- 方向A：YouTube视频转录。准备一个公开的YouTube视频链接（最好包含人声，不要纯音乐）。把步骤2提示词里的链接换成你的YouTube链接，其他保持不变。
- 方向B：B站视频转录。准备一个B站公开视频链接，替换掉步骤2提示词里的链接。特别提醒：B站不少视频自带字幕，Agent可能优先抓字幕而不是执行语音识别——这其实是更优方案，字幕通常比ASR转录更准确。
- 方向C：本地音频文件转录。准备一个电脑本地已有的音频文件（.mp3、.m4a、.wav均可）。将步骤2提示词修改为：“用whisper把这个音频文件转成文字：[文件路径]，去掉时间戳，保存为转录结果.md”。这种情况下无需yt-dlp下载，直接开始转录。

无论你选择哪个方向，判定标准都是一样的：Agent自己下载（或读取）素材、自己完成转录、自己保存文字文件。只要完整跑通一次，本关即告通过。

慢慢养成“先找AI、再找人”的习惯，你会发现很多难题都能迎刃而解。

| 常见卡点 | 默认操作 | 通过标准 |
| --- | --- | --- |
| yt-dlp下载失败，报“无法访问” | 先检查链接是否公开可访问，部分视频需要登录或存在地区限制；换一条公开链接再试 | 换链接后能正常下载 |
| whisper安装报错 | 把报错信息交给Codex排查。常见原因：Python版本过低（需3.8以上）、pip版本陈旧 | 终端运行 python3 -c "import faster_whisper" 不报错 |
| 转录结果乱码或空文件 | 怀疑是音频格式不支持，请Codex先用ffmpeg将音频转为.wav再转录 | 转换格式后重新转录，能看到文字 |
| 转录太慢、等待时间过长 | 音频太长，本关建议用10分钟以内的短音频；如果已在运行则耐心等待，首次加载模型会偏慢 | 下次改用短音频，或Codex告知转录已经完成 |
| 转录文字错别字较多 | 这是正常现象，本关不追求完美转录，只求“跑通”；错字纠正留到关卡4写Profile时再处理 | 能大致看出音频内容就算成功 |
| 不确定是否完成 | 看有没有可见输出——只要Codex自动处理并生成新文件，就算完成 | 截图能证明“输入→处理→输出”三步齐全 |
| 想一次性做很复杂的东西 | 先不改动案例，用默认Demo跑通再说；关卡2-6会教你逐步完善 | 本关只求“完整跑通一次” |

## 总结：最小Agent如何成立

最小Agent的本质，就是先让AI为你完整完成一次看得见的任务。本关通过【音视频转录助手】Demo，把“输入→处理→输出”的链路完整贯通。只要Agent能够接收任务、调用工具、生成文件，并让你用截图证明结果存在，第一个最小Agent就算成立。

四步核心动作：
1. 明确输入：选一条公开可访问、时长适中的音视频，让Agent有素材可处理；
2. 搭建入口：用Codex创建Hermes Agent和飞书Bot，完成私聊或群聊的接通测试；
3. 下达指令：把下载、转录、保存文件等步骤描述清楚，让Agent按部就班执行；
4. 核对输出与边界：确认转录结果文件已生成，并让Agent说明自己能做什么、不能做什么。

走完这一关，你应该已经形成了第一份真实体感：Agent不是一个抽象名词，而是一条可以验证的工作链路。即便觉得这个Demo还很稚嫩，甚至离真正替你分忧还有距离，也不必焦虑——本关的目标从来不是打造一个完美的Agent，而是先建立起直观感受：它如何运作，一条完整链路如何打通。

### 01. 本章重点：为什么需要Agent这个“正式员工”

在关卡1，你已经通过Codex + Hermes +飞书，体验了一个最小Agent Demo：把音视频链接交给它，它就能下载并转录，然后生成一份结果文件。看到这里，你可能会产生一个疑惑：既然直接用Codex对话就能完成这些事，为什么还要引入Hermes和飞书，多此一举地搭一个Agent？

其实，跑通一次任务和配备一名长期在岗的AI员工，是两种完全不同的命题。当你只是偶尔需要转换一段音频时，直接让Codex处理就够了；但当这项工作每天都会发生、需要反复执行，甚至希望团队成员也能共用、并可以长期维护与迭代时，你就需要把它固化成一个Agent。Agent有独立的岗位、固定的工作流程、稳定的入口，还能持续沉淀规则与经验。今后无论自己还是同事，只要把任务丢给它就行，无需每次重复解释背景。

因此，本周课程真正想教给你的，不是“用AI完成一次性任务”，而是“如何培养一名可以长期在职的AI员工”。

你会发现，这位AI员工目前还很像刚入职的实习生：能做基础转录步骤，但文字未必精准；内容只是原始记录，没有重点提炼；文件也只在本地，线上修改、多人同步与长期沉淀都不方便。这并没有错。实习生要成长，需要有人告诉他：负责哪类工作、接收什么信息、按什么流程执行、提交什么成果，以及遇到什么情况必须停下来请示。Agent也是如此。只有在岗位定义、工作流程、交付标准和人工兜底这四件事上足够清晰，它才能从“能跑一次Demo”进化为“能扛住一项具体工作”。

所以这一关，我们把“定岗”放在首位：你要为第一个正式Agent员工明确服务对象、要解决的问题和要交付的成果。这张岗位卡将直接交给后的关卡3（拆工序）和关卡4（写大脑）使用。岗位描述越清楚，后续流程与Profile（岗位说明书）自然越好写。

如果你还对Agent搭建没有头绪，别担心，我们提供了默认案例。案例依旧沿用关卡1的【音视频转录助手】Demo，把一个“基本能做事的AI实习生”，逐步培养成能胜任转录岗位的AI员工。

假使你暂时没有想好自己的Agent岗位，也不妨先跟着案例走一遍流程，理解整体思路。拿到体感以后，再回到真实工作场景，设计第一个属于你的Agent。

❗️ **再次提醒**：默认案例只会帮你练习流程、建立体感，不能作为最终成果提交。本期真正目标，是做出一个能承担你真实工作的Agent——让它变成你手下的第一位AI员工，而不只是一次模拟练习的产物。
