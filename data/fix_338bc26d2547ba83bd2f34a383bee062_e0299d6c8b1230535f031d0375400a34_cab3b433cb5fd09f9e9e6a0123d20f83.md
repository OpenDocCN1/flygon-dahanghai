# 营销地址别空着，AdMob 验证更顺畅

AI 帮你写好的 HTML 页面传到服务器之后，App Store 后台那个“营销地址”最好别留白。原因在于：只要计划接入 Google 的广告变现，Google 在做 App 验证时会访问这个链接；地址为空，验证文件可能抓不到，审核流程平添波折。手头没有服务器也无需纠结，飞书、腾讯文档，甚至 CSDN 上的专栏，都能临时顶上。

# 5.3 版权归属与合规设定

# 5.3.1 版权内容的填写方式

# 5.3.1.1 为什么值得认真填

版权声明是 App 知识产权布局里绕不开的一环。信息填得准确，一方面满足合规要求，另一方面也给自己的劳动成果加了一层保障。

# 5.3.1.2 谁来做版权方

# 5.3.1.2.1 单人开发的情形

以个人身份上架时，直接写身份证上的名字最稳妥。中文字、英文字母、拼音拼写都成立，不过跟注册 Apple 开发者账号时填的名字统一，后续核对会省事。张三、Zhang San、Sanford Zhang 这几种形式都行。

# 5.3.1.2.2 公司或小团队

若 App 由企业出品，版权方一栏应落公司营业执照上的全称。没注册公司、以小组形式协作的，写团队名也可以，但动笔前最好查一遍商标库，确认这个名字没被别人抢先注册。

# 5.3.1.3 在 Xcode 里落地

1. 先把 Xcode 中对应的工程打开。
2. 左侧导航栏里定位到项目条目。
3. 切进主 target。
4. 打开“Info”分页。
5. 需要改两处：工程配置内的 Copyright 一栏，以及 Info.plist 的 NSHumanReadableCopyright 字段。

# 5.3.2 声明该怎么写

# 5.3.2.1 通用写法

业界通行的模板长这样：

Copyright © [年份] [版权所有者名称]。 All rights reserved.

个人开发者的例子：Copyright © 2025 Zhang San。 All rights reserved.

企业出品则把署名换成公司全称，如 Copyright © 2025 科技有限公司。 All rights reserved.

# 5.3.2.2 年份的门道

刚上线就写当年，例如 Copyright © 2025；产品持续迭代的，用起止区间更清楚，如 Copyright © 2020-2025；每逢大版本更新，把末尾年份往前推一推即可。

# 5.3.2.3 App 内哪里露出

1. “关于”界面承载完整声明。
2. 启动画面底部可以放一行精简版，非必选。
3. 商店描述末尾同样值得附上。

# 5.3.2.4 后台信息对齐

1. 进入 App Store Connect 并完成登录。
2. 选中目标 App。
3. 找到“App 信息”，其中的“版权”一栏需与 App 内展示的文字对得上。

# 5.3.3 几条法律层面的提醒

署名务必真实，化名、未注册的商业名称都不建议使用。项目里引入过第三方库或素材的，记得在合适位置标注对方权利。版权登记并非强制，但在部分司法辖区，完成注册能换来更充分的法律救济。

# 5.3.4 高频疑问

问：拼音署名行不行？

答：没问题，不过与开发者账号名称保持一致更省心，同时要确认这就是你在法律文书里会用的名字。

问：要不要去做版权登记？

答：软件著作权自作品完成那刻起就已产生；不过在有些国家或地区，走完登记流程能在维权和诉讼时多一分底气。

问：年份需要跟着改吗？

答：需要。出现实质性改动就同步更新，区间写法（如 2020-2025）是常见做法。

# 6.1.5 沙盒账号怎么用

新建沙盒账号的路径：开发者后台 > 用户与访问 > 沙盒，挑一个此前没绑定过 Apple ID 的邮箱填进去；随后到邮箱里完成验证；再用这个账号登录 iCloud 站点，把账号信息补全。

TestFlight 测试步骤：

1. 手机装上 App Store 里的 TestFlight。
2. 先在系统设置里登出常用的 Apple ID，等系统弹窗出现时改用沙盒账号。
3. App 传上 TestFlight 后在真机跑一遍，确认订阅页能正常展示、下单流程能走完，并逐项验证续费提醒、自动续费、到期降级、会员升级、取消后的表现。
