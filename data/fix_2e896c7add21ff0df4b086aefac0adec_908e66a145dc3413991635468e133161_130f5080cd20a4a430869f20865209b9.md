1. 案例五：接入成熟 API，功能落地更快【Claude 开发】

前四个案例基本围绕自建 APP 展开，项目多为本地存储型，不依赖外部服务。可有些需求——像自动抠图、按描述替换画面内容——底层算法门槛很高，硬写并不现实。更合理的路径是调用成熟平台提供的 API：这类平台汇聚了文本、图像、视频等模型，拿来做一层包装型产品完全可行。

1、https://fal.ai 【图像、视频类模型丰富】

2、https://openrouter.ai/【较常用】

3、https://replicate.com/【图像、视频、文本模型都有】

说明：到 8 月 16 日，这些平台多数已不再提供免费额度；有条件的可以用 visa/master 充值，或到闲鱼找代充。

与第三方平台交互的流程图：

客户端：即你手上的那款 APP。

服务端：承载用户数据并与 APP 通信的云服务器，承担登录校验、会员体系等职责。

第三方平台：提供特定能力的服务方。

1. 初识 Sourcetree

GIT 是版本管理工具，通常以命令方式使用，学习门槛不低。常见命令：

将远端仓库复制到本地：git clone <远程仓库URL>

把当前目录改动一次性放入暂存区：git add .

提交暂存区内容并附说明：git commit -m "提交说明"

拉取远端最新代码并并入当前分支：git pull

查看提交记录：git log --oneline

检查工作区状态：git status

.....

新手面对 git 有门槛，但看不懂也没关系，可视化工具 Sourcetree 可以帮忙。

Sourcetree 相当于给 Git 命令行套了一层可视化界面，不敲命令也能完成版本管理。

下载地址：https://www.sourcetreeapp.com/

a. 安装后，选择“本地”→“新建”→“添加已经存在的本地仓库”。

[PRE38]

b. 双击打开后，界面如下：

c. 勾选要暂存的变更 → 填写本次提交说明 → 点“提交”。

d. 在历史页能看到保存记录；如果后面的改动不想要了，可直接退回该版本。

比如选中目标节点，右键 → 将 main 重置到这次提交。

三种模式可理解为：

软合并：main 回到该节点，后续改动保留在暂存区。

混合合并：main 回到该节点，后续改动保留在工作区（非暂存区）。

强行合并：该节点之后的修改全部丢弃，直接回到该节点。

建议各试一次，体会差别。
