第一次做智能体，建议别一上来就追求复杂。先用一条测试地址把整体流程走通，熟悉每个环节的操作手感；等心里有底了，再换上自己真正要处理的音视频地址重新执行一次。这样你能更直观地看到 AI 在真实任务里如何干活。

6. 换素材，不换链路

如果你不想用上面的播客链接，可以换自己的音视频素材。原则是：只换链接或文件，不换工具链，依然走“下载→转录→保存”的流程。以下是几个可以直接替换的方向：

方向 A：YouTube 视频转录
• 素材：一个公开的 YouTube 视频地址（建议选有人讲话的内容，不要纯音乐）。
• 把步骤 2 提示词中的链接换成你的 YouTube 地址，其他不变。

方向 B：B 站视频转录
• 素材：一个 B 站公开视频地址。
• 把步骤 2 的提示词替换成你的链接。注意：B 站不少视频自带字幕，智能体可能优先拿字幕而不是跑语音识别；这其实更好，字幕通常比 ASR 更准确。

方向 C：本地音频文件转录
• 素材：电脑上已有的音频文件（.mp3、.m4a、.wav 都行）。
• 把步骤 2 的提示词改成：“用 whisper 把这个音频文件转成文字：[文件路径]，去掉时间戳，保存为转录结果.md”。
• 不需要 yt-dlp 下载，直接转录。

无论选哪个方向，判断标准都不变：智能体自己下载（或读取）素材、自己转录、自己保存出文字文件。只要完整跑通一次，本关就算过了。

### 02. 常见卡点与处理方法

遇到问题先别急着放弃，优先问 AI。本期推荐使用 Codex 或 WorkBuddy：新开一个任务窗口，把报错信息、截图或你的需求发过去，让它们帮你分析原因、排查问题，甚至直接解决。
[PRE24]

慢慢养成“先问 AI、再找人”的习惯，很多问题都能解决。

| 常见卡点 | 默认动作 | 通过标志 |
| --- | --- | --- |
| yt-dlp 下载失败，提示无法访问 | 确认 URL 是否公网可访问、无需登录且没有地区限制；不行就换一个公开地址 | 换地址后能正常下载 |
| whisper 安装报错 | 把报错信息发给 Codex 排查；常见原因是 Python 低于 3.8、pip 版本过旧 | 终端执行 python3 -c "import faster_whisper" 无报错 |
| 转录结果乱码或空文件 | 可能是音频格式不支持；请 Codex 先用 ffmpeg 转成 .wav，再重新转录 | 转码后能有可读文字 |
| 转录太慢 | 音频太长；本关建议用 10 分钟内的短音频。已经在跑就继续等，首次加载模型会比较慢 | 下次换短音频，或 Codex 返回完成 |
| 文字错别字多 | 正常现象，本关不追求完美；纠错会在关卡 4 写 Profile 时再处理 | 能大致看出音频内容就算成功 |
| 不确定是否完成 | 看有没有可见产物：Codex 自己处理→自己生成新文件 | 截图能证明输入→处理→输出三步都有 |
| 想一口气做复杂功能 | 先别改案例，用默认 Demo 跑通；关卡 2-6 会逐步教你 | 本关只求完整跑通一次 |

### 03. 小结：最小智能体怎么算成立

最小智能体这件事，本质上是让 AI 先替你完成一次看得见的任务。本关用【音视频转录助手】这个 Demo，把从输入到处理再到输出的链路完整走了一遍。只要智能体能接任务、调工具、生成文件，并且你能用截图证明结果存在，第一个最小智能体就算成立了。

四个核心动作：
1. 准备明确输入：选一个公开可访问、长度适中的音视频，让智能体有材料可处理。
2. 搭好可对话入口：用 Codex 创建 Hermes Agent 和飞书 Bot，完成私聊或群聊接通测试。
3. 发布具体任务：把下载、转录、保存文件这些步骤说清楚，让智能体按流程执行。
4. 检查可见输出和边界：确认转录结果文件存在，再让智能体说清自己能做什么、不能做什么。

跑完这一关，你已经有了第一份真实体感：智能体不是抽象概念，而是一条可以被验证的工作链路。如果觉得这个 Demo 还比较粗糙，甚至离真正替你干活还有距离，这都很正常。这一关的目标不是做出一个完美的智能体，而是先建立体感：明白它如何工作，以及一条完整链路怎么跑通。

下一关会从 Demo 走向你自己的重复工作，找出第一个真正需要的智能体员工，并决定它服务谁、接收什么输入、交付什么结果。

### 01. 核心认知

关卡 1 里，你已经通过 Codex、Hermes Agent 和飞书跑通了一个最小智能体演示：把音视频链接交给它，它就能完成下载和转录，并生成一份结果文件。这时你可能会有个疑问：既然 Codex 一句话就能做完这些事，为什么还要接入 Hermes 和飞书，再搭一个智能体？很多第一次接触的人都会有这个疑问。

原因很简单：完成一次任务，和拥有一个能长期工作的 AI 员工，是两回事。偶尔处理一段音视频，直接用 Codex 对话就够了；但如果这项工作每天都会出现、需要反复执行，甚至希望别人也能用、能维护和持续优化，那就值得把它沉淀成一个真正的智能体。它有自己的岗位、固定的工作流程、稳定的入口，也能持续积累规则和经验。之后无论是你自己还是团队成员，都可以直接把任务交给它，不用每次重新解释。

所以本期想教的不是“怎么让 AI 完成一次任务”，而是“怎么培养一个能长期在岗的 AI 员工”。

你会发现，这个 AI 员工现在就像一个刚入职的实习生：转录基础动作能做，但文字可能不准，内容只是原始稿，没有重点整理；文件也保存在本地，不方便线上修改、多人同步和长期沉淀。这很正常。实习生要把事情做好，需要有人告诉它：负责哪类工作、接收什么输入、按什么步骤处理、交付什么结果，以及什么情况必须停下来确认。智能体也一样，要有清晰的岗位定义、稳定的工作流程、明确的交付标准和必要的人工兜底，才能从“能跑一次演示”变成“能承担一项具体工作”。

所以这一关先定岗位：把第一个正式智能体员工服务谁、解决什么问题、交付什么成果写清楚。你在这里完成的岗位卡，会直接交给后面的关卡 3（拆工序）和关卡 4（写大脑）。岗位越清楚，后面的流程和 Profile 越好写。

如果你对怎么做智能体还没有概念，也没关系，我们准备了默认案例，带你完整走一遍搭建流程。默认案例继续沿用关卡 1 的【音视频转录助手】，在这个 Demo 的基础上，把一个“基本能干活的 AI 实习生”，培养成真正胜任音频转录岗位的 AI 员工。

如果暂时没想好你的智能体做什么，先跟着案例走，建立理解；有了体感后，再回到自己的真实场景，设计第一个智能体。

❗️ 默认案例只用于练流程，不能作为最终成果提交。本期真正目标，是做一个能替你完成真实工作的智能体，让它成为你的第一个 AI 员工，而不是完成一次案例练习。
