**视频生成流水线，一条工作流跑通**

把创意变成一支成片，中间要跨过多少道坎？这条 n8n 工作流给出的答案是：让请求、等待、判断、合并、落表各就各位，一条链路跑到底。

触发方式很直接——手动点击执行。工作流启动后，先由 AI Agent 接手，它背后挂着两件“装备”：DeepSeek Chat Model 负责内容生成，Structured Output Parser 负责把模型输出整理成结构化的数据，方便后续节点直接取用。

拿到结构化结果，流程兵分两路。第一路发起视频请求，进入等待节点，等够了再去查任务进展；第二路同样先发请求，短暂停留后转向状态查询节点。这里的查询走的是 kie.ai 的 veo 记录接口——`/api/v1/veo/record-info`，以 taskId 作为查询参数，认证采用 HTTP Header 方式，凭据名为 Kie API Key。

两条支线各自带着一个条件判断节点把守。以第二路为例，判断逻辑盯住返回数据里的 successFlag：数值严格等于 1、大小写敏感，才算通过。通过就汇入合并节点；没通过则退回等待节点，继续下一轮轮询。第一路的 If1 也扮演同样的分流角色，把“继续等”和“可以合并”分开处理。

两路结果在 Merge 节点汇合，随后交给剪辑合并视频节点加工，再进入“等待最终视频”环节。等完之后，查询视频合并状态节点会做一次总判断：成片就绪，就请求最终视频，接着由 Date & Time 节点打上时间标记，最后通过 Append row in sheet 写入表格存档；若是还没好，就回到等待节点再等一轮，直到条件满足。

整条工作流按 v1 执行顺序编排，模板凭据设置已经完成，目前处于未激活状态。换句话说，骨架已经搭好，只差按下启用键。
