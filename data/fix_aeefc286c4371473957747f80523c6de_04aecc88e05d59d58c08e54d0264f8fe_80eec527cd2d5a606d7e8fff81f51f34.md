2. AI 测评：用真实体验回答关键问题

做 AI 测评，真正要回答的，不是罗列一个工具有哪些功能，也不是丢下一句“好用”或“不好用”，而是帮用户判断：

• 这个工具能搞定我在意的任务吗？
• 实际用起来到底怎么样？
• 最后拿到的结果够不够好？
• 它更适合谁？适合什么场景？

**来看一个实际例子：**《笑死｜在 Codex 上看剪辑师帮我剪视频有多爽》

[PRE5]

**这次测的是什么任务？**

作者没有只讲 Codex 和 ChatCut 有什么功能，而是拿自己的真实素材做了一次完整测试。

任务设置是：把珠峰东坡徒步时拍下的两段素材，剪成一条 6 分钟以内的人文纪录片，允许配字幕、加特效和复古胶片颗粒。

原始素材有两段：

• 藏族同胞制作酥油茶的过程；
• 作者在海拔约 4300 米处采访一位藏族小孩的画面。

[PRE6]

**过程是怎么展示的？**

视频把 AI 的完整工作过程摊开呈现：读取两段素材，安装和补齐所需插件，做语音转写，理清视频主线，压缩采访中的停顿，添加字幕和复古胶片颗粒，还根据作者后来补充的要求，修正了一段竖屏素材的方向。

整个初剪大约花了一个半小时。

这说明作者不是看了一遍官方演示，而是真的把工具放进自己的工作流，让它从头到尾跑完了一整件事。

[PRE7]

**最终结果怎么样？**

AI 确实产出了一条初剪版，主线有精简，停顿有压缩，字幕和画面也都处理过，但效果并不完美。

评论区有人点出：

• 部分转场不够自然；
• 有些镜头重复；
• 镜头选择还不够成熟；
• 完成粗剪可以，但还缺成熟剪辑师的“网感”；
• 更适合访谈、纪录片这类内容，不一定适合节奏很快的爆款短视频。

**为什么这算 AI 测评？**

因为它展示了一条完整的真实使用链路：

真实任务 → 原始素材 → 执行过程 → 修改过程 → 最终结果 → 优点与问题

用户看完后，不只是知道“AI 能剪视频”，还会知道：它目前能替你完成哪些步骤，大概需要多久，成果能不能直接拿来用，哪些地方仍要人工处理，以及自己是否具备喂给它的素材和编导能力。

这才是测评真正该提供的价值。

**这篇内容有什么不足？**

即使过程很完整，这次测试也只能说明：在这一次任务、这一批素材和这一组要求下，工具跑出了这样的结果。它不能直接证明 AI 可以稳定接管所有视频剪辑。

换成另一批素材，结果可能就不同；换一种视频类型，效果可能也不一样；作者的提示词和编导能力会影响产出；插件、模型或产品版本升级后，表现也可能变。

所以写测评时，最好交代清楚测试条件，别把单次结果写成放之四海皆准的结论。

**什么人适合做这种测评？**

你需要满足几个条件：手上有一个自己真正想完成的任务；愿意把输入、过程、修改和结果都保留下来；对最终结果有基本判断力；不只晒成功，也肯讲问题；并且能分得清“一次测试结果”和“普遍结论”的区别。

案例 1：多款 Agent 横向对比 👉🏻《6 款 Agent 实测，小白首选谁？》

这篇把 Codex、WorkBuddy、Claude Code、ZCode、Trae 和 OpenClaw 放在一起比较。它没有逐个报功能，而是围绕一个具体问题：第一次用 Agent，小白该选哪一款？

这属于多工具综合选型测评：不一定要评出一个人人适用的第一名，而是帮不同情况的人找到更合适的工具。

不过写这类内容时要说明一点：作者有没有真的用同一个任务测试所有工具？如果没有，就不能把综合体验包装成严格的同任务对比实验。

3. AI 教程：让用户从“看懂”到“做出来”

AI 教程的重点，不是把自己怎么操作录下来，而是帮用户完成一件具体的事：

• 开始前要准备什么？
• 第一步从哪里开始？
• 每一步具体做什么？
• 做完之后能得到什么？
• 中途失败了怎么办？

**来看一个具体例子：**《Codex 全新保姆级教程（GPT-5.6 重磅升级后）》

[PRE17]

**这篇教程要带用户完成什么？**

这是一支约 14 分钟的 Codex 新手教程。作者从下载和安装开始，一步步演示了新版界面、项目模式、额度、对话栏和预览框、初始化设置、整理文件夹、Computer Use、可视化看板，以及 Skill 和 CLI 等案例。

用户看完后，不只是知道 Codex 有哪些功能，还能跟着视频从安装、设置走到第一次使用。

[PRE18]

**它串起了哪些关键步骤？**

教程按照实际操作顺序展开：下载安装 → 认识界面 → 初始化 → 建立项目 → 输入任务 → 查看结果。

基础操作之后，作者又展示了整理文件夹、Computer Use、可视化看板、Skill 等具体例子。

这样用户既能看到工具怎么设置，也能看到工具最终能帮自己做什么。

[PRE19]

[PRE20]

**为什么说它是 AI 教程？**

因为它不是只解释“Codex 是什么”，而是在带用户走完一套可以跟着做的流程。

AI 科普解决的是：我听懂了吗？
AI 教程还要再解决：我能照着做出来吗？

这篇内容同时给到了操作入口、关键步骤和真实结果，已经具备教程的基本结构：明确目标 → 准备条件 → 分步操作 → 展示结果。

**评论区暴露了哪些问题？**

评论区里有不少具体疑问：国内怎么下载？为什么下载后的界面不一样？为什么自己的版本没有聊天功能？为什么界面是英文？手机能不能装？额度够不够？应该用账号登录还是 API 登录？

这些问题说明，作者虽然自己走通了，但不同用户的设备、版本、账号和网络环境并不一样。

一份更完整的教程，除了展示成功路径，还应该尽量交代：适用的系统和版本、开始前要准备什么、账号和付费要求、不同版本的界面差异、常见失败情况，以及工具更新后哪些步骤已经变了。

[PRE21]

[PRE22]

**这类教程有什么风险？**

AI 工具的更新速度很快。作者发布时还正确的下载入口、界面布局和功能位置，过一段时间可能就变了。

用户拿着旧教程操作，可能会遇到：下载到不同版本，找不到视频里的按钮，登录方式已经改变，原来的功能被移动或下线，原来的提示词也得不到相同结果。

因此，做工具教程最好标注测试时间、工具版本和使用环境。工具发生大版本更新后，也要及时补充说明。

**什么人适合做这类教程？**

你需要具备这些条件：自己已经从头到尾完整跑通过；关键步骤能再次复现；知道开始前要准备什么；能预判新手最容易在哪一步卡住；愿意补充失败情况和解决办法；工具更新后愿意回头检查教程还对不对。

下面再放几个 AI 教程的例子，你可以自己拆着看：

案例 1：零基础完整学会一个工具 👉🏻《20 分钟学会 Codex！“零基础”终极教程》

这是一篇面向零基础用户的长教程。作者希望用户从最基础的安装开始，逐步认识 Codex，再通过具体案例理解怎么用。

这属于完整工具入门教程：从用户第一次接触工具开始，带他完成安装、设置、基础操作和第一个任务。

这种教程覆盖比较全，但制作成本也高。作者不仅要跑通功能，还要提前判断新手会卡在哪一步。

评论区已经出现“安装后为什么变成 ChatGPT”“是否还需要单独安装 Codex”等问题，说明产品更新后，旧教程里的部分步骤已经变了。

这也提醒我们：教程不是发布后就永久有效，工具发生较大更新后，要及时补充、修改或下架已经失效的步骤。

案例 2：围绕一个明确成品做教程 👉🏻《用 Skill 做爱马仕丝巾画风格短片｜附教程》

这篇不是全面介绍某个工具，而是带用户完成一个明确作品：用 Skill 做出爱马仕丝巾画风格的短片。

这属于项目型教程：先展示要做出的效果，说明使用什么工具和 Skill，展示关键输入和生成过程，最后展示完成的短片。

这种教程的好处是，用户一开始就能看到最终结果，快速判断自己想不想学；做完以后，也容易判断自己是否成功。

不过，如果完成作品必须使用作者没有公开的 Skill，或者核心材料要私信才能拿到，用户就很难只靠这篇教程复现。

因此，做项目型教程时，要说明：哪些工具可以直接用，哪些素材要提前准备，Skill 或提示词能否公开获得，以及从生成图片到形成短片，中间还做了哪些处理。

这类教程通常包括：先说明想做一个什么工具，把需求告诉 AI，查看第一次生成的结果，根据问题继续改，最后得到一个能用的页面。

评论区里，大量用户都在问“话术”或“提示词”，也有人反馈手机打开后页面是空的。

这说明：如果不公开关键提示词，用户很难复现；如果只展示成功结果，不说明设备限制和失败处理，教程就没有真正写完整。

制作类似教程时，至少应该提供：使用的工具和版本，完整或可修改的提示词，第一次生成的结果，后续修改方法，页面如何保存、发布或访问，手机和电脑端的差异，以及常见失败及解决办法。
