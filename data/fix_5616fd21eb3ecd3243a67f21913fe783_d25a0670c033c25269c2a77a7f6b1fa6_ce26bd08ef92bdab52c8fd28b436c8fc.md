# 从零到上线：AI 视觉站的后端、登录、生成与存储配置

如果你准备做图像或视频生成类网站，后端鉴权、第三方登录、模型调用、文件存放以及线上发布，都是绕不开的几道坎。下面按实际落地顺序，把一套可运行的方案拆开讲。先看底座——Supabase。

Supabase 在开源后端平台里很有代表性，常被视为 Firebase 的开放替代。它以 PostgreSQL 为数据核心，向上提供账号认证、消息能力、边缘函数以及对象存储；数据表结构确定后，REST 与 GraphQL 接口可以自动生成。开发者不必从零维护一整套后端，能把精力放回界面和交互体验。该项目在 PostgreSQL 圈子里人气很高，免费档就能启动，因而被大量早期团队采用。

为什么选它：
- 开放源码、无授权费，数据落在 PostgreSQL 里，迁移路径清楚，不会轻易被平台锁死。
- 认证、存储、函数等能力打包提供，重复造轮子的时间明显减少。
- 社区活跃，版本持续演进。
- 需要更强掌控或成本优化时，也可以自己部署。

## 1. AI 模型接入（Replicate）

### 1. 接入 Replicate

视觉生成站离不开模型。Replicate 模型库覆盖面广，运行也稳定，适合做外部生成能力。

它是什么：一个可运行、可微调 AI 模型的平台，通过 API 调用图像、文本、视频、音乐、语音等开源模型。部署与使用流程被封装起来，开发者不必啃完复杂算法细节，也能把模型接进产品，效率和成本都更可控。

选择它的理由：
- 模型使用门槛被压低，普通开发者也能上手。
- 团队能把时间放在产品层，而不是训练模型上。
- 账单跟随调用次数，不必先扛重资产基础设施。
- SDK 覆盖多种语言，接入成本低。

### 1. 获取 Webhook 秘钥

图像或视频生成往往要等。用户可能在等待时关掉页面或断网，最终结果就丢了。Webhook 用来兜底：任务完成后，Replicate 主动发成功通知和结果 URL，我们收到后落库；用户再回来，仍能看到成品。

Webhook 的本质是 HTTP 回调：某个事件出现时，服务向指定地址推送数据，通常是 JSON，不需要客户端反复轮询，实时性更好，也节省请求。

对视觉站的价值：
- 任务完成即告知，响应更快。
- 可自动串联压缩、分类、审核、站内推送等后续动作。
- 少做无效轮询，服务器压力更低。
- 关键通知不丢，体验和稳定性都更好。

Replicate 这边设置不复杂：Account Settings 里点 Show signing key，把密钥复制到 REPLICATE_WEBHOOK_SECRET。

## 1. 接入 Cloudflare R2

### 1. 开通 Cloudflare R2 服务

生成出来的图片和视频需要落地存储，这里用对象存储。Cloudflare R2 兼容 Amazon S3 API，突出优势是出口流量不计费，能省下传统云存储的一大块传输成本。它依托 Cloudflare 全球 350 多个节点，访问延迟低、吞吐高，还能和 Cloudflare Workers 结合做边缘处理。

R2 的亮点：
- 数据外传不收流量费，整体成本更可控。
- 支持 S3 协议，已有 S3 应用迁移和集成更顺手。
- 全球分布式节点，适合面向多地区用户。
- 可与 Workers 联动，边缘计算和自动化扩展更灵活。
- 静态数据走 AES-256，传输用 TLS/SSL。
- 只按存储量和操作次数计费，规则透明。
- 免费额度包含 10 GB 容量及千万级请求，开发测试和中小项目够用。

免费范围：每月 10 GB 存储；上传与列表操作每月 100 万次免单；下载和读取每月 1000 万次免单；数据流出不产生流量账单。超出部分才收费，单价不高。

开通：Cloudflare 官网用 Google 账号登录，左侧进 R2 对象存储概述，按提示绑卡开通。
