3.4 请 Codex 配置并核验自动点名

人工交接通过后，打开操作手册第 06 节，把“自动交接配置与验收提示词”发送给 Codex。访问权限、角色 ID、结构化的 @ 写法、防重复与防循环均由 Codex 核查，你不必手工查参数。

若 Codex 发现平台权限尚未开通，或应用改动后需要重新发布，它会每次只请你完成一个必须由人确认的动作。完成后请 Codex 继续，真实群消息测试不可跳过。

核查完毕，Codex 必须返回一张核验表：

| 核验点 | 实际证据 | 结论 |
| --- | --- | --- |
| 下游是否收到上游角色的明确提及 | 真实群消息与下游回应 | 通过 / 未通过 |
| 上游是否使用下游角色的正确 ID | 上游应用查到的群成员记录 | 通过 / 未通过 |
| 消息中是否为可点击的真实 @ 提及 | 群内实际消息 | 通过 / 未通过 |
| 同一个交接触发标识（handoff_id）第二次抵达时，是否再次处理 | 第二次到达后的表现 | 通过 / 未通过 |
| 下游结束后是否反向点名上游 | 下游完成后的群消息 | 通过 / 未通过 |

只有核验表全部通过，本节才算完成；仅配置文件正确不算数，必须有真实群消息作证。具体提示词与排查动作见操作手册第 06 节。

6.2 何时可转为日常做法

首次自动交接通过后，再做几轮稳定性测试。满足以下条件，才可日常化：

• 上游角色连续几次输出结构一致的交付消息；

• 下游角色能明确回复接收通过或退回；

• 没有重复点名与循环触发；

• 权限和结果链接保持稳定；

• 异常时能暂停并通知人。
