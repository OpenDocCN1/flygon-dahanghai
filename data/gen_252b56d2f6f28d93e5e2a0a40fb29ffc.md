# AI Agent 做小程序：从想法到上线

这次用 Codex 做示范。像 WorkBuddy、Claude Code 这类能读取项目目录、能直接新建和修改文件、还能执行命令的 AI 编程工具，也都能照着走。只会在聊天框里吐代码、还要你手动复制保存的普通聊天模式，效率会低不少。

适合上手的三类工具：

- 最顺手：Codex、Claude Code、WorkBuddy 等本地编程 Agent，整套流程基本相通。
- 也能用：在 IDE、项目目录或 Agent 模式下工作的 Kimi、Cursor、Trae。
- 不太合适：只能聊天、碰不到本地项目文件的网页 AI。

筛选工具其实只看四件事：

1. 能不能打开并读取本地项目。
2. 能不能直接新建、修改文件。
3. 能不能运行检查命令并读到结果。
4. 能不能根据🛰️开发者工具报出的错误继续定点修。

## 9. 升级为🛰️云开发

云函数不是非做不可。新手建议先做纯前端代码工具，等用户积累到一定数量，再升级成云函数。

为什么要接云开发？

- 本地存储只留在当前设备，清缓存、卸载或换手机都可能丢。
- 云端数据能跟着🛰️用户走，换设备也能重新读取。
- 云函数可以通过 OPENID 自动区分用户，不需要设计登录页。
- 服务端能再次校验金额、杯数等数据，降低前端篡改风险。
- 后续做统计、运营配置和多人测试会更方便。

所以别一开始就接云开发。先用本地 MVP 验证功能和用户需求，确认有人持续使用后再升级。

3. 新建 transactions 集合，权限设为所有用户不可读写。

transactions 是云数据库里的一个数据集合，可以理解成一张专门保存饮品记录的数据表。每次用户完成打卡，就往 transactions 新增一条记录，例如：[PRE33]

各字段作用：

- drinkType：咖啡、奶茶等饮品类型
- cups：杯数
- unitPrice：单杯价格
- amount：本次总金额
- date：消费日期
- _openid：这条记录属于哪个🛰️用户
- createTime：记录创建时间

小程序会利用这些记录计算：本月总花费、本月总杯数、打卡天数、平均每杯价格、每天的杯量格子、饮品类型汇总和饮品人格。

操作步骤：

1. 点顶部“云开发”。[PRE34]
2. 进入已创建的云环境，点“数据库”，点“+”或“新建集合”。[PRE35]
3. 集合名称填：transactions。
4. 集合权限选择“所有用户不可读写”，确认创建。[PRE36]

创建过程中遇到问题，直接问 AI；上面这些流程，也都是 AI 告诉我的。[PRE37][PRE38]

建好后，把集合名称 transactions 和环境 ID 交给 AI，让 AI 配置代码。
