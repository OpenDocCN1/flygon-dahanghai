# 6. 前后端调试技巧

AI 不是万能的，也会“犯傻”。当它解决不了时，就需要我们自己动手调试。掌握一些基础调试技巧非常重要。

# 6.1 前端调试：浏览器开发者工具

a. 断点调试
- 打开 Sources 面板，在行号上点击就能加断点。
- 支持条件断点：右键 -> “Add conditional breakpoint”。
- 典型场景：让代码在某个变量满足条件时才停下。

b. 监视变量
- 在调试面板添加变量，实时观察它的值变化。

c. 逐步执行
- Step over（F10）：逐行执行。
- Step into（F11）：进入函数内部。
- Step out（Shift+F11）：执行到函数结束再返回。

[PRE15]

d. 网络请求调试
- 查看请求是否成功：状态码、请求头、响应体。
- 过滤 XHR/fetch 请求，专门调试接口调用。
- Replay XHR：重复发送同一个请求。

[PRE16]

e. 本地存储调试
- 包括 localStorage / sessionStorage / cookies / IndexedDB。
- 常用来模拟登录态、修改缓存数据。

f. 样式调试
- 实时修改 CSS 样式。
- 追踪 DOM 节点变化：右键 -> Break on -> attribute modifications。

[PRE17]

小问题 -> console / 断点
中等问题 -> Network / Application / Source Map
复杂问题 -> 性能分析 / 移动端远程调试 / Mock API
线上问题 -> 日志 & 错误监控

# 6.2 后端调试

# 6.2.1 基础调试技巧

a. 日志调试（最常用）
- 用 console.log / print / logger.info 等输出关键变量。
- 日志分级：DEBUG、INFO、WARN、ERROR、FATAL。
- 建议使用 winston、log4j、pino 等专业日志库，支持 JSON 格式化和日志轮转。

b. 断点调试
- 在 VSCode、IntelliJ、PyCharm 等 IDE 里设置断点。
- 逐步执行函数，查看变量值和调用栈。
- 适用于复杂业务逻辑或难以定位的 bug。

c. 调试工具 / REPL
- Node.js：node inspect 或 ndb。
- Python：pdb / ipdb。
- Java：JDWP 协议，远程 attach 调试。

# 6.2.2 后端特有调试技巧

1. 接口调试
- 用 Postman / Insomnia / curl 模拟请求，验证接口逻辑。
- 配合 Fiddler / Charles 抓包，调试 HTTP/HTTPS 请求。

2. 数据库调试
- 在 SQL 执行前后打印 SQL 和参数。
- 慎用 ORM 的 lazy load，调试时开启 SQL 日志。
- 用事务回滚测试逻辑，避免污染真实数据。

3. 远程调试
- 服务器运行时可 attach 调试器（Java：-agentlib:jdwp，Node：--inspect）。
- Docker 容器里用 docker exec -it 配合调试工具进入环境。

4. 配置与环境调试
- 打印当前加载的配置文件和环境变量。
- 常见 bug：本地 dev 配置和 prod 配置不一致。
- 用 .env 或配置中心管理环境。

# 7. 持续交付：CI/CD

产品需要持续迭代，一天发布几次也不稀奇。如果每次都手动打包、上传服务器，效率太低。CI/CD（持续集成/持续部署）就是用来自动化整个流程的。

CI（持续集成）：把代码提交到 GitHub 后，自动触发构建和测试，避免新代码引入 bug。
CD（持续部署）：代码通过所有测试后，自动部署到服务器，实现“提交即上线”的痛快体验。

这次航海营会用到两种 CI/CD 工具：

Vercel：自带 CI/CD 流程，对 Next.js 项目配置简单、开箱即用。
GitHub Actions：功能更强大、更灵活，可以自定义任意复杂的部署流程，比如部署到自己的服务器。

1. AI 编程入门

# 1. AI 编程的发展历程

AI 编程工具的进化速度非常快：

早期（GPT-3 时代）：通过网页问答或 API 生成代码片段，交互体验有限。

中期（Copilot 时代）：以 VS Code 插件存在，能根据上下文自动补全代码，交互自然了很多。

现在（Agent 时代）：以 Cursor、Trae、Claude Code 为代表，能理解整个项目，进行跨文件重构、调试，甚至执行部署命令，形成一个完整的开发闭环。

AI 编程能力的关键限制之一是上下文长度。模型一次性“看到”的代码越多，对你的意图理解就越准。Claude Code 的突出优势就在于超长上下文管理，这也是它处理复杂任务时表现出色的原因。

# 2. AI 编程工具使用

# 2.1 Trae

Trae 的核心特性是直观交互和精准的上下文引用。

Chat 模式：像和人聊天一样对代码库提问，获取建议或优化方案。

上下文引用：对话中用 @ 引用某个文件或整个项目，让 AI 修改更精准。

代码变更预览：AI 改动后会以 diff 形式展示，你可以选择接受或拒绝，安全性高。

# 2.2 Claude Code

# 2.2.1 Claude Code 是什么？

- 理解整个代码库，而不只是当前文件。
- 执行跨文件的重构和调试。
- 帮你写 PR、运行测试、修复 bug。
- 与 Git、CI/CD、数据库、API 等工具链深度协作。
- 用自然语言交互，让 AI 成为代码仓库的“伙伴”。

独特的代码理解方式：

与常见 AI 编程工具不同，Claude Code 理解代码库时，不做任何索引，也不用 RAG（检索增强生成）。它的工作方式更像新人加入团队后熟悉项目——靠主动探索，称为“智能体式搜索”。它会用 glob、grep、find 等命令在代码库中穿梭，阅读文件，理解结构和逻辑。

这意味着模型可以先搜索一轮，再根据结果判断“我可能还需要知道几件事”，于是继续搜索，逐步构建起对代码库的整体认知。

# 2.2.2 Claude Code 使用技巧

1. 项目初始化（/init）

用 Claude Code 写新项目时，先通过 /init 初始化，让 CC 理解项目的业务逻辑、功能、技术栈、启动方式等。之后执行任务时，CC 会自动加载这个文件来读取项目信息。

CLAUDE.md 是一个特殊文件，Claude 每次对话都会自动把它拉入上下文。

它可以存储这些信息：

- 项目的业务逻辑
- 核心文件和实用函数
- 代码风格指南、存储库规则
- 开发者环境设置、测试说明
- 项目特有的意外行为或警告
- 其他信息

[PRE21]

1. 常用命令

- /init：生成 CLAUDE.md 项目记忆文件
- /clear：清空会话历史
- /compact：压缩会话历史
- /model：切换模型
- /permissions：查看/更新权限
- /status：查看账户/系统状态
- /resume：恢复对话

1. 自动模式

[PRE22]

在 Claude Code CLI 中，--dangerously-skip-permissions 是跳过权限检查的标志。

Claude Code 执行某些操作时（比如读写文件、运行 shell 命令、调用外部工具），默认会弹出权限提示，让你确认是否允许。这是安全保护，防止 AI 在不知情时修改关键文件、删除数据或执行危险命令。

启用 --dangerously-skip-permissions 后，Claude Code 不再询问，直接按自己的判断执行操作。它会：
- 直接访问/修改文件
- 直接运行 Bash 命令
- 直接调用已配置的 MCP 工具

1. 提示词技巧

规则约束：
CC 也有 AI 的通病：幻觉、一本正经地胡说八道、自作聪明、爱 mock 数据、爱模拟结果、写冗余代码，像个新手。所以要在 CLAUDE.md 里给它约束规则，比如你的编码风格、常用技术栈等。

[PRE23]

善用上下文：
Claude Code 支持读取当前目录的全部代码，建议在项目根目录启动，这样它能更准确理解依赖关系。

分步描述复杂任务：
任务过大时，拆成多个小步骤让 Claude Code 逐步完成，减少错误率。

有效管理上下文：
模型有 20 万 token 的上下文窗口，但长时间会话仍可能被填满。当右下角出现“上下文即将用完”的警告时，两个选择：
- /clear：清空当前会话，重新开始。
- /compact：启动内部提示，让模型把当前会话总结成摘要，再用摘要作为新会话的“种子”，无缝继续工作。

构建高效工作流：
先计划，后执行。不要直接命令“修复这个 bug”，而是说“我遇到了这个 bug，先调查原因，给我一个修复计划”，这样你可以在它动手前验证思路。

利用待办事项（To-Do List）：复杂任务中 Claude 会生成待办列表。观察列表，发现方向不对就按 Escape 打断，调整计划。

拥抱测试驱动开发（TDD）：让 Claude 小范围修改、运行测试、检查代码规范、然后提交。小步快跑能确保项目不偏离轨道。
