## 3.2.6 进阶可选：把日报 Skill 变成日报 Agent

走到这里，你手里其实还是一个「日报Skill」：你喂内容，它返回结构化分析。可每次结果还得你自己复制，这份重复劳动并没有消失。

前面说过：Skill解决的是“这件事能做”，Agent解决的是“这件事每天自己做完”。

如果在分析之后再接上“自动保存”，链路就会从Skill升级为一个最小Agent：你发内容 → 它自动分析 → 自动写入固定位置 → 回你一句确认。

接下来，让Codex把“自动保存”挂到Skill后面。存在哪里没有统一答案，挑一个你每天都会打开的地方即可：

• 桌面日报.txt：最省心的兜底方案，先跑通再说

• 飞书文档 / Notion：适合常记笔记、爱复盘的人

• Obsidian：适合已有本地知识库的人，能和笔记网络直接联动

• 桌面.md文件 + 本地html网页：适合完全本地、不愿登录任何平台的人（下面用这种演示）

## 3.3 关键节点复盘

走到这里，一个最小但完整的日报Agent已经搭出来了：在对话框输入 → 自动分析 → 自动落到你每天都会打开的位置。

回头梳理一下，这条链路是这样长出来的：

1. 拆需求：让AI反过来问你，把模糊念头聊清楚
2. 收束Demo：把发散的对话压成一份图纸
3. 固化Skill：把分析能力沉淀为可复用技能
4. 接上自动保存：从Skill升级为Agent

跑通之后，建议按自己的需要继续扩展。每个人的日报内容、工作流和展示偏好都不同，这个Agent应该贴合你的习惯，而不是照搬教程。

下面几个方向可以试试：

• 换存储方式：从html换成飞书 / Obsidian，看哪个更顺手

• 换分析视角：额外标出“今天卡在哪”“明天先做什么”“本周累计推进”

• 接其他输入源：例如自动读取🛰️、会议录音转写

• 串更长链路：日报 → 周报 → 月度复盘，让AI替你汇总

## 4. 收尾与练习

### 4.1 回顾要点

执行能力 = 把重复劳动交给AI，一个人也能像一支队伍。

核心就四个动作：启动提问 → 梳理维度 → 收束成Demo → 生成Agent。

对应的底层技能，是所有能力里最关键的一项——需求定义能力。

搭Agent并不是技术活。你的核心价值不在敲代码，而在于“反转提问权”：让AI扮演顾问来追问你，把“到底要解决什么问题、先做哪一段、输入输出是什么”这些维度聊透。方向错了，AI写得再快也是白费。

恭喜你！到这里，你得到的不只是一个日报Agent，更重要的是一套方法——通过和AI聊需求，就能做出Agent。之后完全可以按自己的需求继续开发。

掌握这项底层技能后，第三章的“表达能力”（比如内容生成）和第四章的“积累能力”（比如知识库），都可以被你封装成专属Skill，再组合成更强大的Agent。那时你就不只是内容的“生产者”，而是工作流的“架构师”。

**第一步：找到你的场景**

想想日常工作里最让你烦的那件重复事，直接拿它练手。

如果一时没有头绪，可以参考：

• 内容改写Agent：把好文章改成你的风格

• 会议纪要Agent：把零散会议笔记整理成结构化纪要

• 客户跟进Agent：把聊天记录整理成跟进摘要

• 数据日报Agent：把零散数据整理成固定格式报告

**第二步：拆解需求**

打开Codex，用第二部分的方法，让AI不断追问，帮你弄明白自己到底要什么。

**第三步：收束 + 固化**

让AI把讨论结果压成一个最小demo，再整理成可复用的skill。

**第四步：验证**

拿一段自己的真实输入跑一次，看看结果是否符合预期。

**完成标准：**

1. 能说清楚你的Agent要解决什么问题
2. 有一份收束好的最小demo定义
3. 有一个可复用的skill
4. 用真实输入至少跑通一次
