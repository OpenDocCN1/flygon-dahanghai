# Sora登场：当“看见”不再等于“相信”

视频合成赛道最近被Sora搅热了。它被视为一个关键节点，但节点旁边也摆着一道现实考题：现实空间与数字空间都可能被仿制时，我们凭什么判断眼前内容是真是假？出门问问的负责人李志飞、普林斯顿学者阿尔温德·纳拉亚南，都绕不开这个追问。与其说这是远虑，不如说它已经钻进日常。

合成门槛被压低后，造假成本跟着跳水，普通人的眼睛越来越难当场拆穿。隐私泄露、版权摩擦、谣言扩散、骗局升级，便会接连冒头。香港那桩换脸合成骗局，涉案金额约两亿港币，离谱程度不输悬疑片；前年，美国一批写作者把OpenAI告上法院，以群体诉讼方式主张自己的文字未获许可就被拿去训练模型。生成式内容的安全议题，不是“以后再说”，而是“正在发生”。

那路该怎么走？平台与开发团队得先扛责任。OpenAI尝试嵌入水印、组织红队演练、提升内容辨别能力，希望把滥用空间压小；国内不少内容平台也在鼓励发布者自愿给生成式内容加标识。方向值得肯定，但只靠这些还不够。技术跑得像高铁，规则更新却常像慢车，中间落差越拉越大。

监管必须提速。FTC曾提出限制借AI伪装他人的规则，这是积极信号，却远未覆盖全局。更多司法辖区需要跟进，逐步拼出一套跨国规则体系，给技术研发和落地应用划出硬边界。

大众媒介素养也得补课。要让普通人形成条件反射：刷到一段视频，先别急着信，更别急着转；多问来源、多查一步，这就是数字生活的防身动作。

再往深处看，人类或许要换一套判断坐标。纳拉亚南提醒，我们可能得接受一个新判断：看起来像真的，不再等于就是真的。听着扎心，却是技术递来的必答题——重写真实、信任与安全的定义，并在新的技术底座上重建社会信用。

Sora是智能技术的一次大跨步，也把红利与风险装进同一枚硬币的两面。便利被放大，隐患也被放大。守住人类的安全感与信任感，不能指望某家公司或某个国家单打独斗，需要平台、政府、学校、家庭和每个用户一起补位。别只顾着为技术欢呼，也别因为风险就因噎废食。真正难的是：我们能否在享受Sora的同时，把“真实”重新锚定。

# 3.8.1 商业计划书概述

# 3.8.1.1 定义和作用

什么是商业计划书？

# 💡

一句话说清：它是一份把企业目标、打法、市场判断、运营安排和财务预估讲明白的关键文档。初创团队找钱、成长企业调战略，都常用得上。对外可用于路演宣讲、融资沟通；对内可用于股东会战略说明、销售策略讲演和员工培训。

BP的作用

融资路演：向投资方讲清企业价值、商业模式、市场前景和竞争优势，帮助对方判断是否值得下注。

战略规划：帮高层明确目标、制定策略、规划未来，把长短期动作排成一张路线图。

运营管理：为日常经营提供指导，把经营计划、管理流程和制度规范落到位，保证组织高效有序。

市场营销：分析需求、研究对手、确定目标市场，做好产品定位、价格策略和渠道选择。

培训管理：作为员工培训与管理的参考材料，让基层员工理解公司目标、战略、文化和管理制度，缩小与高层之间的信息差。

# 3.8.1.2 基本结构和组成部分

BP的构成（标准基础版）

公司简介：约15%。写清公司简介、创业宗旨、发展历程、核心团队成员。

市场分析：约30%。回答市场在哪里、市场有多大、目标市场及客群是谁。

产品/服务介绍：约30%。讲清产品与服务、特色亮点、竞争力、价格。

财务分析：约15%。包含收入预测、成本预测、利润与损失表、现金流量表等。

融资计划：约10%。说明融资金额、资金用途、股权分配、退出方式。

# 💡

公司简介

主要内容包括：①概述简介 ②核心团队 ③组织架构 ④发展历程。

可套用通用模板，沟通需求时发给客户，让对方按模板补充并反馈。

公司简介内容模板：

[公司名称] 专注于 [简述主要业务或产品/服务]。我们的愿景是 [公司长远愿景]，使命是 [公司使命]。基于市场分析与战略定位，我们计划在 [目标市场] 中占据 [市场份额或地位]，并预计在未来 [时间周期] 内实现 [财务目标或里程碑]。

公司简介通常2—4页。

# 💡

市场分析

先明确核心问题：市场分析到底为什么做？

它的作用是：锁定目标市场、定义目标客群，讲清市场现状、问题、需求与痛点；分析市场规模，预测增长趋势并给出佐证。让听众看到，你对所在行业、市场环境、市场空间和竞争格局有清晰、冷静、客观、全面且现实的认知。

如果是ToG业务，市场分析可写政策要求、国家相关行业政策、红头文件、建设发展规划、重要讲话等，相关材料通常可在公开互联网找到。

竞争对手分析

点名典型对手，做基本画像，明确差异点，梳理自身优势劣势、机会与威胁，找准自己的赛道。

市场分析要牢记一句万能公式：

目标什么领域市场；面向什么样的目标客群；在什么业务或场景下；解决或满足什么业务痛点；提供什么核心产品或服务。

至少3部分，1—3页篇幅。

主要形式：①视频 ②系统截图 ③产品实拍 ④成果照片。

# 3.8.2 案例分析

下面这个案例是真实BP对外宣讲路演的演讲稿PPT。视觉风格不算花哨，属于常规企业常用的科技蓝，中规中矩。业务方向是一家科技公司，依靠政府关系，主要面向政府相关单位/部门做项目，研发软件并提供技术支持，属于ToG技术服务供应商。虽然PPT视觉效果一般（ToG客户偏好这种风格），但讲演时故事连贯、通顺、合理，技术服务能力讲得清楚，实际案例均为真实应用，最终获得了资方认可和政府领导认同。

BP编写从需求沟通到落地交付，通常分4步：

客户需求关键点提取 → 制定大纲确定风格 → 编写内容 → 定稿沟通交付。

下面用写手与客户的沟通场景，拆解BP从沟通、整理、设计、编写到交付的全流程，帮大家理解各环节要做什么、从什么角度思考、需要沟通哪些内容。

# 3.8.2.1 第一步：客户需求关键点提取

从沟通中提取需求关键点：

客户：“你好！大概说一下，我这个BP是公司总经理拿去和投资人讲，路演用的，但不是大会，就是一些有意向合作企业、投资人了解我们；另外我们也会在工会内部宣讲，当作企业介绍，在工会商会内部宣传自己。我们是哈尔滨本地科技公司，主要做软件研发、系统集成服务，客户主要是政府机构部门，给他们做软件平台开发、大数据应用组件等，也包括硬件设备，结合物联网设备开发相应应用。还有科技孵化园区，我们帮他们做软件应用，辅助他们为中小型企业日常运营管理提供支撑服务。”

这段话信息点很多，可总结为：

①BP目的是对外宣讲，寻找合作伙伴与融资，核心是企业宣传和产品服务宣传。

②哈尔滨本地企业，做本地化服务的科技公司。

③主营业务有两块：一是ToG业务，有一定政府背景资源关系，做软件系统研发、数据服务研发产品；二是ToB业务，为本地的科技孵化园区构建软件管理服务平台，横向复制推广卖给其他科技园区。

以上为核心信息。从数据挖掘角度看，接下来要围绕第③点展开，尽可能多获取信息或资料。

这一阶段客户也会发参考资料。部分内容涉及客户隐私，文件省略。后续写作中会说明哪些用了客户文件，不影响学习案例。
