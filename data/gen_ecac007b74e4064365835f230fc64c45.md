这些属于技术选型，用 AI 编程时还有一项重要确认，就是技术选型。

对非程序员、非技术背景的人来说，这些框架听着陌生。比如截图里 .tsx、.css 结尾的文件，都是代码文件。

Coze 编程这类工具已经帮你把常见的网页框架固化好了，就算不懂编程，它也会在开发时自动补上这些框架。

但如果你用的是更通用的编程工具，比如 Claude Code 或者图形界面的 Cursor，写页面功能时它可能会挑别的框架。

网页的呈现形式和底层技术框架有很多种，不指定的话，很容易跑偏。

下面是不同应用类型对应的技术框架提示词（用通用编程工具开发时可以直接照抄）：

• 网页端应用：“需要使用 nextjs、shadcn/ui、Tailwind”

• 小程序：“就使用官方的 wxml、wxss、wxjs”

• iOS App：“使用 swift 原生应用开发”

• 需要前后端分离的架构：“后端服务可以使用 go 语言实现”

### 3.3 第三步：页面优化

这一节要完成的是：用新手也能操作的方法检查页面、提出修改，必要时回退版本。*如果你觉得当前要改的地方还不太明确，也可以先跳到 3.4 补充真实资料，等资料补完再统一调整。*

#### 3.3.1 截图标注，把要改的地方说清楚

改页面最容易踩的坑，是位置说不明白。比如想把头像挪到左边，只发一句“头像位置不对”，Coze 未必知道是哪个位置、往哪儿改。

更有效的做法是：**截图 + 标注 + 提示词**。

具体步骤：

1. 截一张当前页面的图（Mac 用 Command+Shift+4，Windows 用 Win+Shift+S）

1. 在图上用红框或箭头标出要改的位置

1. 把截图粘贴进对话框（Ctrl+V 或 Cmd+V），同时写清楚怎么改

#### 3.3.2 判断用 Agent 改还是先回问答讨论

不是所有改动都适合直接交给 Agent 执行。

小改动可以直接用 Agent 模式，比如：

• 调整某个元素的位置

• 修改一段文字

• 换一个按钮文案

**复杂改动建议先切回问答模式**，把方案讨论清楚再执行，比如：

• 改整个页面的布局结构

• 新增一个板块或功能

• 改了两三次还没成功的问题

切回问答模式的好处是：先把方案说清楚，确认可行后再切 Agent 执行，减少来回返工。

#### 3.3.3 右侧工具栏里四个好用的操作

**不同尺寸显示**

点击预览区顶部的尺寸按钮，可以切换桌面端、平板端、手机端的显示效果。个人主页很可能被别人在手机上打开，建议每改完一轮都切一次手机端确认。

[PRE21]

**刷新**

页面样式一时没更新，或者预览显示有点异常，先刷新试一下。

[PRE22]

**重启**

刷新没用时，可以试试重启服务。适合页面完全不响应、或者做了较大修改之后。

[PRE23]

**版本控制**

这是四个操作里**最重要的**，但新手常常不知道在哪里找到它。

点击右侧区域右上角的新标签页按钮，在打开的页面里进入版本控制。每条记录包括：改了哪些文件、这次改动做了什么。
