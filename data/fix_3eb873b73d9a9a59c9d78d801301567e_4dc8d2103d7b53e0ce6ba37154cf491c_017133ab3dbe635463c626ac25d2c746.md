基本结构很简单：一条 n8n 工作流由两类组件组成——

触发节点（Trigger Nodes）：流程的起点，负责决定它何时、以何种方式被激活。每条工作流只能有一个。

动作节点（Action Nodes）：触发之后负责执行具体任务，比如处理数据、发请求、调用 AI 模型等。数量没有限制。

# 1. 触发器家族

Manual Trigger（手动触发）：最直接的触发方式，在开发或测试时，手动点击『Test workflow』或『Execute workflow』按钮，让流程立即运行一次。

[PRE2]

Schedule Trigger（定时任务）：让流程按预设的时间表自动开跑，可精确到分钟、小时、天、周甚至某个日期。内部基于 Cron 表达式实现，这是一种强大的时间描述语言。

Webhook（网络钩子）：生成一个专属 URL，外部应用向该地址发送 HTTP 请求（通常是 POST）时，流程会立刻被触发，并接收到请求附带的数据。

[PRE3]

Email Trigger（邮件触发）：连接一个邮箱账户（如 Gmail、Outlook），收到新邮件后自动触发，能读取发件人、主题、正文和附件等信息。提示：在较新版本中，该节点可能被整合或改名，例如改用 IMAP 节点，核心都是监听收件箱。

[PRE4]

On chat message（聊天消息触发）：专门为聊天机器人设计。把 n8n 的聊天组件嵌入网站或应用后，用户发送第一条消息即可触发，并捕获用户的输入内容。

[PRE5]

实战场景：做一个 n8n 版 AI 对话机器人。用聊天消息触发作为入口，只需三个节点：On chat message、AI Agent 和 DeepSeek Chat Model。在 AI Agent 的配置中，把 On chat message 输出的 chatInput 字段设为 Prompt。

AI Agent 相当于『AI 大脑』或协调员：它不直接生产文字，核心是统筹整个对话——接收 Prompt、按需调用工具、利用大语言模型判断下一步动作，最后汇总结果。

[PRE6]

模型选择 DeepSeek Chat Model——一个具体的 LLM 节点，输入 Prompt，借助 DeepSeek 的能力生成文本回复。

Set（曾用名 Edit Fields）：最常用的数据处理节点之一，增字段、改字段、删字段都是它。你可以保留原始输入并新增字段，也可以直接改字段值，或移除不需要的字段。示例中把『姓名』和『年龄』字段重命名为 name 和 age。

[PRE14]

[PRE15]

[PRE16]

Function/Code：一个『万能节点』——当内置节点都不够用时，可以在这里用 JS 或 Python 自由操作数据。

[PRE17]

[PRE18]

[PRE19]

Merge（合并）：把分叉处理的多路数据汇成一股。常用的模式有 Append 和 Combine。

[PRE20]

Append 模式按原顺序把两批条目接起来——Input 1 全部排前面，Input 2 全部排后面，不比对、不删重。Combine 模式则按指定的 key 字段，把两路中键相等的条目合成一条，键对不上的默认忽略。

逻辑控制类节点：

IF 负责做判断，符合条件的放行，不需要的直接拦下。

[PRE21]

Switch 把不同情况的数据送到对应路径去处理。

Loop Over Items 会把这批数据逐条跑一遍同样的处理逻辑。

Wait 让流程在原地等等，约好的时间到了再往下走。适合 API 调用限频、等待外部系统处理完毕、定时发送提醒等场景。

[PRE23]

热门官方集成节点：

HTTP Request：只要是走 HTTP 协议的服务，它都能帮你把请求发过去，比如取第三方 API 数据、给 webhook 发通知、对接自建系统。

Google Sheets：能在 Google 表格里读写、刷新数据，也能自动同步、出报表、收汇总。

[PRE24]

Slack/Discord：向团队频道推送消息，常用于系统告警、任务完成提醒、数据日报推送。

[PRE25]

OpenAI/ChatGPT：接上 ChatGPT 等模型后，就能完成文本加工、内容产出这些事（也可配合 gemini 节点）。

[PRE26]

社区节点：例如飞书相关节点，可直接在社区中获取。
