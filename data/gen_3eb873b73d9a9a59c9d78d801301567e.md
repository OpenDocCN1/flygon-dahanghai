前言：

n8n 的 Workflow 由两类核心部件组成：

触发节点（Trigger Nodes）：工作流的起点，决定流程何时、以何种方式被激活。一个工作流有且只有一个触发节点。

动作节点（Action Nodes）：触发节点被激活后，负责执行具体任务的节点，比如处理数据、发送请求、调用 AI 模型等。一个工作流可以包含任意多个动作节点。

# 1. 触发类节点

触发节点（Trigger Nodes）：

Manual Trigger（手动触发）：最基础、也最简单的一种触发方式。它的作用是在开发和测试工作流时，让你手动点一下 “Test workflow” 或 “Execute workflow” 按钮，立刻运行一次流程。

[PRE2]

Schedule Trigger（定时任务）：让工作流按照预设时间表自动运行。你可以把它设成每分钟、每小时、每天、每周，甚至指定日期和时间执行。它内部使用 Cron 表达式，这是一种很强的时间定义语言。

Webhook（网络钩子）：Webhook 节点会生成一个专属 URL。只要外部应用或服务向这个 URL 发出 HTTP 请求（通常是 POST 请求），n8n 工作流就会被立即触发，同时还能接收请求里附带的数据。

[PRE3]

Email Trigger（邮件触发）：这个节点可以连接邮箱账户（例如 Gmail、Outlook）。当邮箱收到新邮件时，工作流会自动触发，并且能读取发件人、主题、正文内容和附件等信息。

PS：在较新的 n8n 版本中，这个节点可能已经被整合，或者名称有所不同，例如通过 IMAP 节点来实现。它的核心功能是监控邮箱收件箱。

[PRE4]

On chat message（聊天对话框触发）：这是专门为聊天机器人设计的触发器。当你把 n8n 的聊天机器人嵌入网站或应用后，只要用户在那个聊天框里发出第一条消息，这个节点就会被触发，并捕获用户输入的内容。

[PRE5]

实际场景运用：工作流实操案例常用节点（建议搭配入门工作流中的第一个工作流来学习）

我们利用聊天对话框触发，来实现一个 n8n 版本的 AI 对话机器人。

需要用到三个节点：On chat message、AI Agent、DeepSeek Chat Model。

配置 AI Agent 节点时，需要把 On chat message 节点的 chatInput 作为 Prompt。

AI Agent：它更像一个“AI 大脑”或“任务协调员”。这个节点本身不直接生成内容，而是负责管理与 AI 模型的整个对话流程。它可以接收输入（Prompt），调用一个或多个工具（Tools），并借助大语言模型（LLM）判断下一步该做什么，最终输出结果。

Merge（合并）：这个节点用来把两个或多个从不同节点分支流过来的数据流合并成一个。

常用的 Mode 是 Append、Combine。

[PRE20]

Append：把两路输入的 item 首尾相接输出——先输出 Input 1 的所有 item，再输出 Input 2 的所有 item。不会做去重或匹配。

Combine：按你指定的字段（key），把两路输入里“键相同”的 item 合并成一个 item。没有匹配到的项默认不会输出。

逻辑控制节点：

IF：条件分支。

[PRE21]

作用：筛选符合条件的数据，是一个逻辑判断模块，用来过滤不需要的内容。

Switch：多路径路由。

根据条件把数据分发到不同的执行路径。

[PRE22]

Loop Over Items：循环处理。

对输入的每个数据项重复执行相同操作。

Wait：延时等待。

暂停工作流执行一段时间后再继续。适合一些依赖后端服务时长的场景：API 调用限频控制、等待外部系统处理完成、定时发送提醒消息。
