1.1 本质定位：自主执行型代理

OpenClaw 由开发者 Peter Steinberger 打造，定位是开源的自主执行型智能代理引擎。按 Wikipedia 的说法，它是一个免费开源的自主人工智能代理项目，主要用户界面放在消息平台上，如 WhatsApp、Telegram、Discord、Slack 等。

这背后依赖它的核心能力：

• **本地跑**：资料由你掌握，不经过他人服务器。
• **多渠道 Gateway 中枢**：用一个 Gateway 进程连接 WhatsApp、Telegram、Discord、iMessage。
• **插件渠道**：通过扩展包接入 Mattermost 等更多渠道。
• **多智能体路由**：按智能体、工作区或发送者隔离会话。
• **媒体支持**：可收发图片、音频与文档。
• **Web 控制界面**：浏览器仪表板，用于聊天、配置、会话和节点管理。
• **移动节点**：配对 iOS、Android 节点，支持 Canvas。

1.2 OpenClaw 如何运转

[PRE4]

OpenClaw 借 Gateway 网关把聊天应用与 AI 智能体连起来。会话、路由和渠道连接，都以 Gateway 为统一权威依据。

核心组件包括：

1. Gateway 网关
   ◦ 对接飞书、企微、🐧、Telegram 等聊天平台
   ◦ 管理会话与消息路由
   ◦ 默认地址：http://127.0.0.1:18789/
   ◦ 配置文件：~/.openclaw/openclaw.json

2. AI 智能体
   ◦ 支持 Claude、GPT、Gemini、DeepSeek、Kimi 等模型
   ◦ 可本地运行，也可远程调用

3. Skills 技能系统
   ◦ 覆盖文件管理、知识管理、自动化等
   ◦ 支持自定义开发

4. ClawHub
   ◦ 技能市场，可下载、分享 Skills

💡 Gateway 网关是什么？它是 OpenClaw 的核心服务，相当于“总控台”：接收飞书、企微、🐧、Telegram 等平台消息；把消息交给 AI 智能体处理；再把回复发回对应平台；同时管理会话与上下文。正因 Gateway 统一管理连接，你才能在不同平台上使用 OpenClaw。

[PRE5]

1.3 OpenClaw 的四层结构

1. 消息渠道（Channels）：Telegram、Discord、Slack、飞书、CLI 等多种接入方式。
2. 智能决策核心（Brain）：LLM 推理、任务拆解与规划、工具选择与调用。
3. 技能插件系统（Skills）：文件操作、Shell 命令、浏览器控制、API 集成等。
4. 记忆与身份系统（Memory & Identity）：由一组 Markdown 文件构成，如 IDENTITY.md（身份）、SOUL.md（性格）、USER.md（你的信息）、MEMORY.md（长期记忆）等。

这种分层让 OpenClaw 既灵活又可控。

[PRE6]

**延伸理解：价值与成本**

优势：
• 并行探索：多个 Sub-agent 可同时搜索、分析、汇总，速度优于串行。
• 上下文隔离：子任务在干净上下文中执行，减少“上下文退化”。
• 推理算力扩展：突破单 Agent 的上下文窗口限制。

成本：
• Token 成本会从 1x 升到 15x。
• Agent 之间传递信息会损失上下文细节，形成“电话游戏”效应。
• 多 Agent 并行时，可能出现隐式决策冲突。

Anthropic 曾总结：有的团队花几个月搭复杂多智能体架构，最后发现把单智能体提示词打磨好，效果也能追平。

判断标准：低耦合任务，如搜索、信息收集，适合拆分；高耦合任务，如架构设计、核心编码，保持单一更稳妥。

[PRE7]

**延伸理解：应用场景**

个人效率：每天早晨自动推送天气、日历、邮件简报；自动给邮件分类并标注优先级。

开发者工作流：PR 提交后自动做代码审查；函数签名变更时自动更新 API 文档。

企业级应用：多渠道客户支持自动化；每周自动生成数据分析报告。

2. 装起来：部署与安装

2.1 云上一键部署

对多数人而言，云部署最省心：不必在本地电脑安装，浏览器里就能完成。

目前国内主流云厂商都提供 OpenClaw 一键部署，但实际体验差异不小。先看总览，再讲最推荐的方案。表 3-1 汇总了国内云厂商方案。

**表 3-1 国内云厂商方案速览**

| 平台 | 入门配置 | 费用 | 预置模型 | 生态绑定 | 适用人群 |
| --- | --- | --- | --- | --- | --- |
| 腾讯云 | 2 核 2GB | 99 元/年 | 否 | 不绑定，自由配 Key | 综合首选 |

看完表格，别急着被阿里云 9.9 元/月、火山引擎 9.9 元/月起吸引，实际使用没那么简单。

**阿里云**的 9.9 元/月属于限时秒杀，需要抢且限购；抢不到时常规价并不便宜，续费还比新购高不少。它内置模型走百炼 Coding Plan，基本绑定阿里自家模型生态。

**火山引擎**的问题更明显。虽然标着活动价 9.9 元/月，但方舟 Coding Plan 价格不低——2 核 2GB 服务器加模型套餐，每月实际支出很容易超过 100 元，同样绑定字节模型生态。

相比之下，**腾讯云**更实在。99 元/年的 2 核 2GB 轻量应用服务器，折合每月不到 **9 块钱**。价格稳定，不用抢，支持续费同价，不必担心“续费刺客”。最关键的是，它不绑定模型生态：买完服务器后，可自由配置任何模型厂商的 API Key，如 DeepSeek、Kimi、Claude、GPT。实际使用中这一点很重要，因为你很可能需要在不同模型间切换和尝试。

因此，云部署首选推荐腾讯云。下面以腾讯云为例，逐步走一遍。

技术小贴士：“2 核 2G”是什么？

“2 核”指服务器有 2 个 CPU 核心，决定同时能处理多少任务；“2G”指 2GB 内存，决定能同时在“脑子”里装多少东西。对 OpenClaw 来说，2 核 2G 完全够用——真正消耗算力的推理交给外部 AI 模型，服务器主要负责调度与转发，负担很轻。
